Content-based recommendation

Content-based recommendation matches item attributes to a user’s preferences or previously liked items. It does not require other users to have rated the same item.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Useful when item descriptions/features are available, including new items with no interaction history.

Scenario cueSuitable choiceWhy it fits
New catalogue items have useful descriptionsContent-based modelNo collaborative rating overlap is required
User has diverse separate interestsSeveral profiles or liked-item matchingOne mean can hide distinct preferences

2. How it works — what happens and why

  • Content-based recommendation uses item descriptions as evidence. A movie can be represented by genre, director or a text vector, and the user can be represented in that same feature space through preferences or liked items. Unlike CF, similarity is not derived from other users rating the same products.
  • Averaging liked items creates a prototype, but a single average can erase several different interests. Someone who likes technical textbooks and comedy novels need not want an item halfway between them. Comparing candidates with several liked items or separate profiles can preserve these modes.
  • Content features help new items before ratings arrive, provided their descriptions are available. They do not solve a new-user profile with no preferences or history. Recommending only close matches also narrows variety, so the lecture suggests controlled randomness or excluding items that are too similar when serendipity matters.
Implementation steps and their purpose
  1. Extract structured item features or text vectors.
  2. Build a user profile from declared preferences or liked items.
  3. Use the same feature representation for both.
  4. Compute similarity and rank unseen eligible items.
  5. Add controlled variety and evaluate relevance.

4. Design the solution and check the result

Data, components and application

  • Overspecialisation → bounded exploration/diversity → repeatedly similar items reduce discovery.
  • Poor metadata → improve extraction/semantic representation → missing useful attributes weakens matching.

How to evaluate it

Measure relevant recommendations and diversity, not rating error if no rating is predicted. Check new-user profile availability.

Build the answer in this order

  1. Identify features.
  2. Build profile.
  3. Match/rank.
  4. Discuss metadata, cold start and variety.

Common wrong answers and the exact correction
  • Item-based CF uses interaction patterns; content-based filtering uses item attributes.
  • New-item support still needs useful content.

6. Turn understanding into an exam answer

  • “I encode film attributes and the user’s liked-film profile in the same space, rank unseen candidates by cosine similarity and explain the matching attributes.”
  • “For a new item this works from metadata; for a new user I first need preferences or a fallback, and I assess diversity as well as relevance.”

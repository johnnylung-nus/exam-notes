C092

Basis vectors and energy compaction

A basis defines how a signal is represented. Energy compaction seeks a few components that preserve much of the signal with low reconstruction error.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when raw sensor vectors are large or redundant and a compact representation is needed.

Scenario cueSuitable choiceWhy it fits
Many correlated signal dimensionsCompact learned basisCan reduce redundancy and computation.
Small feature difference drives a rare classRetain/test that detailLow energy does not mean unimportant for decisions.

2. How it works — what happens and why

  • A coordinate value depends on the chosen basis. Changing basis can concentrate useful variation into fewer coefficients without changing the underlying signal when all components are retained.
  • For an orthonormal basis, dot products give the component weights; reconstruction adds each basis vector scaled by its corresponding weight.
  • Energy compaction seeks directions that reduce total reconstruction error. It does not directly optimize recommendation accuracy or a particular class boundary.
  • Dropping components is the compression step; the task must tolerate the discarded information, including potentially small but important anomalies.
Implementation steps and their purpose
  1. Prepare comparable signal vectors.
  2. Choose or learn basis directions.
  3. Project each signal to obtain component weights.
  4. Retain the useful components.
  5. Reconstruct using their weighted sum.
  6. Compare reconstruction loss and downstream usefulness.

3. Change basis, then remove one component

Worked study example: Lecture two-dimensional example; basis directions are unit vectors at rotated angles.

What this tells us: The first-only representation saves one coefficient but loses a specific difference between the original coordinates. Whether that difference matters depends on the target problem.

4. Design the solution and check the result

Data, components and application

  • Too few directions → keep more components → preserves important variation.
  • Unrepresentative training signals → learn on representative data → basis may otherwise fit the wrong patterns.
  • Low-variance but important event lost → evaluate the target task → energy retained is not identical to task relevance.

How to evaluate it

Check reconstruction squared error, size/computation savings and classification or detection quality.

Build the answer in this order

  1. Need compact representation.
  2. Basis and projection.
  3. Retain components and reconstruct.
  4. Measure information loss and task value.

5. Diagnose the proposed model — change and justify

  • A component weight is not the basis vector.
  • Energy compaction is not the recommendation problem solved by MF.

6. Turn understanding into an exam answer

  • Using both rotated basis directions reconstructs [1,2] exactly.
  • Keeping only the first gives [1.5,1.5], so the squared residual is .5.
  • I select representation size using both reconstruction loss and the task’s held-out performance.

C093

Supervised representation learning

Supervised representation learning uses labelled task examples to learn features useful for prediction. Transfer can freeze an encoder or fine-tune it.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when sensor labels exist or a pretrained model can help with a smaller target dataset.

Scenario cueSuitable choiceWhy it fits
Few labels, useful pretrained featuresTry frozen adaptationFewer adjustable parameters can reduce fitting risk.
Enough target data and clear feature mismatchCompare fine-tuningRepresentation can adapt to new signal characteristics.

2. How it works — what happens and why

  • In supervised representation learning, prediction error from labelled examples updates the feature extractor so its representations support the target classes.
  • Frozen adaptation updates only a new output mapping; fine-tuning also changes some or all pretrained feature weights. These have different data and overfitting demands.
  • The target dataset must contain relevant class variation. An unchanged pretrained model may be fast to reuse but can preserve unsuitable domain features.
  • A validation comparison determines whether extra trainable capacity helps; fine-tuning is not inherently better when target labels are scarce.
Implementation steps and their purpose
  1. Define the target labels and prepare representative data.
  2. Start from an appropriate representation model.
  3. For linear adaptation, freeze the encoder and train the new output mapping.
  4. For fine-tuning, continue training the representation on target data.
  5. Compare both approaches on held-out target cases.

3. Track exactly which parameters change

4. Design the solution and check the result

Data, components and application

  • Few target examples → start with frozen features → fewer trainable parameters can reduce fitting risk.
  • Domain mismatch → consider fine-tuning → adapts features to new signals.
  • Validation degradation → reduce capacity/training or retain frozen features → target labels may not support extensive updates.

How to evaluate it

Check target-task errors, class coverage, resource cost and training/validation gap.

Build the answer in this order

  1. Labels and deployment task.
  2. Frozen versus adapted representation.
  3. Explain data/capacity trade-off.
  4. Compare on unseen target cases.

5. Diagnose the proposed model — change and justify

Common wrong answers and the exact correction
  • Pretraining and target-task training are different stages.
  • Fine-tuning is not just attaching a new output layer.

6. Turn understanding into an exam answer

  • I first train a new output mapping while freezing the pretrained encoder.
  • If target-domain validation shows a representation mismatch, I compare fine-tuning under the same held-out split.
  • I choose the configuration balancing target quality, capacity and deployment cost.

C094

Self-supervised representation learning

Self-supervised learning creates a training target from the data itself. A pretext task learns features that are later assessed on a real downstream task.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when unlabelled sensor recordings are plentiful but human annotation is expensive or scarce.

Scenario cueSuitable choiceWhy it fits
Large unlabelled pool, scarce annotationsSelf-supervised pretrainingUses structure without annotating every pretraining item.
No useful downstream improvementChange pretext/representation choiceLower pretraining loss alone is not the objective the user needs.

2. How it works — what happens and why

  • Self-supervision creates a learning problem from structure already in the data, such as reconstructing a signal or matching related views.
  • The pretext target is not the final real-world label. Success on that target indicates learned structure, not automatically good activity or fault recognition.
  • The learned encoder transfers to a downstream task where labelled data may still be needed to learn or evaluate the task mapping.
  • The chosen pretext task defines which information is retained. It can also reward shortcuts unrelated to the scenario if pairs, corruption or context are poorly chosen.
Implementation steps and their purpose
  1. Collect representative unlabelled inputs.
  2. Choose a data-derived pretext task.
  3. Train an encoder with that objective.
  4. Use the learned representation for the target task.
  5. Add target labels where needed.
  6. Evaluate on independent target cases.

3. Separate pretraining data, targets and downstream labels

Worked study example: Illustrative sensor activity dataset; counts demonstrate role separation rather than an expected performance guarantee.

What this tells us: The 10,000 windows are not 10,000 human-labelled activity examples. Their value comes from the self-generated training signal and whether it helps the actual target task.

4. Design the solution and check the result

Data, components and application

  • Pretext solved using irrelevant cues → choose task/augmentation carefully → learned features may miss the target concept.
  • No target evaluation → test with downstream labels → low pretraining loss does not establish usefulness.
  • Different deployment domain → adapt and re-evaluate → transfer is not guaranteed.

How to evaluate it

Compare downstream performance with a baseline using the same target-label budget, and check representation robustness.

Build the answer in this order

  1. Available unlabelled data.
  2. Pretext objective.
  3. Reuse for downstream task.
  4. Evaluate target benefit.

5. Diagnose the proposed model — change and justify

Common wrong answers and the exact correction
  • Self-supervised has a learning signal; it is not “no target”.
  • Target tasks may still need human labels.

6. Turn understanding into an exam answer

  • I generate pretraining targets from the sensor data itself, then reuse the encoder for labelled activity recognition.
  • The downstream task still needs labelled evaluation cases.
  • I judge the approach by target-task improvement under the same label budget, not pretext loss alone.

C095

Autoencoders and reconstruction

An autoencoder has an encoder that creates a representation and a decoder that reconstructs the input. Training minimizes reconstruction error.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use for learning sensor features or a compact code when no class label is needed for the pretraining task.

Scenario cueSuitable choiceWhy it fits
Need compact nonlinear features without class labelsUnder-complete autoencoderLearns to retain information useful for reconstructing representative inputs.
Need class predictionAdd/evaluate a supervised mappingThe code is not already a guaranteed class label.

2. How it works — what happens and why

  • An encoder maps the input into a code; a decoder maps that code back to a reconstruction. The training target is the input itself, not a class label.
  • Reconstruction loss compares original and output values. The bottleneck or other constraints encourage a useful representation rather than an arbitrary copy.
  • An under-complete code has fewer dimensions than the input. An over-complete code can still learn features, but it is not compression merely because it is called an autoencoder.
  • The encoder’s code can feed a later classifier; reconstruction training and supervised task learning remain distinct objectives.
Implementation steps and their purpose
  1. Prepare representative inputs.
  2. Choose encoder, code size and decoder.
  3. Use the original input as the reconstruction target.
  4. Train by reducing input–output differences.
  5. Extract the code for downstream use.
  6. Check reconstruction and feature usefulness on unseen data.

3. Calculate a reconstruction loss on actual values

Data, components and application

  • Code too small → increase capacity if useful details vanish → compression trades detail for size.
  • Model copies everything → constrain representation appropriately → copying alone need not learn useful abstraction.
  • Good reconstruction but poor classifier → evaluate downstream features → reconstruction and class separation differ.

How to evaluate it

Use held-out reconstruction error plus downstream classification/retrieval where applicable; compare raw-input baseline.

Build the answer in this order

  1. Why learn a representation?
  2. Encoder → code → decoder.
  3. Reconstruction target/loss.
  4. Check compression and downstream value.

Common wrong answers and the exact correction
  • Under-complete has fewer code dimensions; over-complete need not compress.
  • An autoencoder is not automatically PCA.

6. Turn understanding into an exam answer

  • I train an encoder–decoder with the original sensor window as target and minimize reconstruction error.
  • For the illustrated vectors, MSE is .625.
  • I assess both held-out reconstruction and downstream activity/fault quality before calling the representation useful.

C096

Denoising autoencoders

A denoising autoencoder receives a corrupted input but is trained to reconstruct the original clean input.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when sensor noise should be removed while retaining the underlying useful structure.

Scenario cueSuitable choiceWhy it fits
Known realistic additive sensor noiseTrain with similar corruptionsTeaches robustness to expected acquisition variation.
Rare sharp fault carries useful detailPreserve/check the transientThe model must not remove the event as if it were noise.

2. How it works — what happens and why

  • Denoising training changes the input but keeps the target clean. This forces the model to learn stable structure instead of rewarding reproduction of the added corruption.
  • The corruption should resemble plausible deployment noise without destroying the underlying target event; unrealistic noise can teach the wrong invariance.
  • At runtime the encoder/decoder sees noisy data without the clean target. Clean references are a training/evaluation resource, not a required live input.
  • A lower reconstruction error can coexist with lost event details, so inspect transients and the actual sensing decision after denoising.
Implementation steps and their purpose
  1. Start with representative clean training signals.
  2. Add realistic corruption to create model inputs.
  3. Keep the clean originals as targets.
  4. Train encoder and decoder to reduce clean-target reconstruction error.
  5. Test on unseen noisy signals.
  6. Check whether important event details survive.

3. Distinguish corrupted input from clean target

4. Design the solution and check the result

Data, components and application

  • Training noise unrealistic → use corruption resembling deployment → improves relevance.
  • Over-smoothing → inspect important transients → a smoother signal may erase faults.
  • Noisy target used by mistake → preserve clean target → the learning objective must reward denoising.

How to evaluate it

Compare reconstruction against available clean references and evaluate the final sensing task under realistic noise.

Build the answer in this order

  1. Noise problem.
  2. Corrupted input and clean target.
  3. Reconstruction objective.
  4. Check detail preservation and task benefit.

5. Diagnose the proposed model — change and justify

  • Denoising does not guarantee correct anomaly classification.

6. Turn understanding into an exam answer

  • The model receives a corrupted window and is trained against its clean paired original.
  • The illustrated clean-target MSE is approximately .0067.
  • I test both reconstruction quality and preservation of the event the sensing system must recognize.

C097

Contrastive learning

Contrastive learning shapes the representation: positive pairs should be similar, while negative pairs should be less similar.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when the desired invariance can be specified through paired views instead of a class label for every input.

Scenario cueSuitable choiceWhy it fits
Target should ignore mild sensor noisePositive noisy viewsEncourages stable activity representation.
Magnitude defines severity/classAvoid magnitude-changing positivesOtherwise the objective erases the required distinction.

2. How it works — what happens and why

  • Contrastive learning teaches what should be close in feature space by constructing positive pairs and what should be separated using negative pairs.
  • The pair rule encodes the intended invariance. Two views of one window may be positive only if the transformation preserves the activity/fault meaning.
  • Incorrect negative construction can push together-class examples apart; incorrect positives can merge different classes. Pair quality is part of the learning problem.
  • The contrastive objective is not reconstruction. A representation can ignore irrelevant variation while preserving task-relevant differences without reproducing every input value.
Implementation steps and their purpose
  1. Define what should count as the same underlying event/object.
  2. Create positive pairs with valid augmentation or context.
  3. Select appropriate negative pairs.
  4. Train the encoder to bring positives together and separate negatives.
  5. Test learned features on the target task.

3. Check pair meaning before training

4. Design the solution and check the result

Data, components and application

  • Augmentation changes the class → constrain transformations → positives must retain target meaning.
  • False negatives → inspect pair construction → semantically similar inputs should not be forced apart unnecessarily.
  • Good pair loss but weak task result → evaluate downstream labels → pretext success alone is insufficient.

How to evaluate it

Assess retrieval/neighbour quality, downstream prediction and robustness to the intended transformations.

Build the answer in this order

  1. What must remain similar?
  2. Positive/negative construction.
  3. Representation objective.
  4. Downstream benefit and pair errors.

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Good contrastive loss, poor classificationPairs encode the wrong conceptRedesign augmentation/context around target meaningThe pretext objective taught an unwanted invariance.

Common wrong answers and the exact correction
  • Contrastive learning does not reconstruct every input by definition.
  • Choose invariance for the actual sensing task.

6. Turn understanding into an exam answer

  • I define positive pairs as views preserving the target activity and negatives as justified different examples.
  • I avoid transformations that alter class-defining magnitude or timing.
  • I evaluate downstream classification and robustness, not contrastive loss alone.

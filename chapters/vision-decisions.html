C066

Vision cognition pipeline

Vision cognition goes beyond naming objects: pixels become features, objects, relations, context and a useful decision.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Use when a scenario needs a judgement or action from images, not just an object label.

Scenario cueSuitable choiceWhy it fits
Need object presence onlyDetectionBoxes and labels may be sufficient.
Need area/coverage measurementSegmentation or suitable region reasoningPixel/region detail supports the actual decision.

2. How it works — what happens and why

  • The camera observes pixels, not compliance. A pipeline must extract the relevant objects and relationships before applying the rule that defines correct behaviour.
  • Perception can detect a mask yet miss whether it covers the nose. The judgement therefore needs more detailed location/coverage information.
  • Domain rules supply the meaning of the observation: which equipment is required, where it belongs and what missing evidence prevents a conclusion.
  • Uncertainty should identify its source, such as an occluded region, rather than merely attach a confident-sounding label to an incomplete view.
Implementation steps and their purpose
  1. Define what decision the user needs.
  2. Capture suitable images.
  3. Extract relevant objects, regions or measurements.
  4. Represent relations and apply domain knowledge.
  5. Produce a judgement with uncertainty.
  6. Trigger the specified action or review.

4. Design the solution and check the result

Data, components and application

  • Poor lighting/occlusion → improve capture or request another view → missing evidence cannot support a confident judgement.
  • Object detected but placement wrong → inspect regions/relations → presence alone does not prove compliance.
  • Unsupported inference → separate visible evidence from interpretation → exposes uncertainty.

How to evaluate it

Check perception, interpretation, judgement, usability and consequences of errors separately.

Build the answer in this order

  1. Required decision.
  2. Perception output needed.
  3. Rules/context → decision.
  4. Check failure and response.

  • Do not invent hidden details from one image.

6. Turn understanding into an exam answer

  • The camera supplies pixels; recognition extracts PPE items and placement relationships needed by the checklist.
  • Detecting a mask is insufficient to prove correct wearing because nose/mouth coverage must also be checked.
  • If a required region is occluded, request another view or review instead of asserting that the item is absent.

C067

Marr’s three levels

Marr’s analysis separates what problem is solved, which representations/processes solve it, and how the solution is physically implemented.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use to explain a vision-system design at the right level rather than mixing the goal, algorithm and hardware.

Scenario cueSuitable choiceWhy it fits
Question asks system purposeState goal and required output firstThe computational problem anchors later design choices.
Question asks realizationDiscuss device and runtime constraintsHardware is meaningful after required processing is specified.

2. How it works — what happens and why

  • The computational level defines the problem and success criterion. Hardware names do not explain why the task is being solved.
  • The algorithmic level selects representations and processes that can produce that result. Changing the representation can remove information required by the goal.
  • The implementation level realizes the process using cameras, models, devices and interfaces under practical constraints.
  • Marr’s analysis levels differ from the processing sequence early vision → recognition → cognition; one is a way to analyze a solution, the other describes processing roles.
Implementation steps and their purpose
  1. Computational level: state the goal and why it matters.
  2. Algorithmic level: choose representations and operations.
  3. Implementation level: identify camera, device and software deployment.
  4. Check that the selected operations actually support the goal.

3. Explain one PPE system at three levels

What this tells us: “Use a camera” answers how evidence is captured, not what judgement is required. “Use deep learning” still leaves the representation and decision logic unspecified.

4. Design the solution and check the result

Data, components and application

  • Hardware listed as goal → separate levels → makes the answer address the question.
  • Algorithm without decision criteria → define required compliance knowledge → connects processing to the goal.
  • Over-detailed implementation → match requested abstraction → avoids wasting exam time.

How to evaluate it

Trace one required output through all three levels; check feasibility and whether the algorithm answers the stated problem.

Build the answer in this order

  1. What and why?
  2. Representations and processing?
  3. Physical realization?
  4. Does the design meet the goal?

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Excellent detector, wrong task resultAlgorithm solves object presence onlyAdd needed spatial/coverage representationThe computational objective is correctness of wearing.
Detailed hardware but no decision ruleImplementation replaces reasoning explanationState algorithm and criteriaThe reader must see how outputs follow from inputs.
Common wrong answers and the exact correction
  • Do not confuse these three analysis levels with early vision → recognition → cognition.
  • Primal sketch, 2.5D sketch and 3D model are another lecture distinction.

6. Turn understanding into an exam answer

  • At computational level, the goal is to judge whether required PPE is worn correctly.
  • At algorithmic level, detect items, extract placement/coverage and apply the checklist.
  • At implementation level, realize the pipeline with the camera, model, device and dashboard under response-time constraints.

C068

Detection vs segmentation

Classification labels the whole image; detection returns object boxes and labels; segmentation assigns labels to pixels.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Choose the output detail the task needs. Measurement of exact areas usually needs segmentation rather than only detection.

Scenario cueSuitable choiceWhy it fits
Find object locationDetectionA labelled box can satisfy localization.
Measure coverage or relative region sizeSegmentationThe decision needs per-region boundaries/counts.

2. How it works — what happens and why

  • The desired measurement determines the visual task. An image-level label cannot supply a pupil area or an object boundary.
  • Detection localizes a candidate region with a box; segmentation separates object pixels from background. A box normally includes non-object pixels.
  • The sample’s normalized size is pupil-pixel count divided by iris-pixel count. Both regions must be consistently defined before the ratio is meaningful.
  • A later formula can be perfectly computed from incorrect masks; evaluation must inspect measurement quality as well as arithmetic.
Implementation steps and their purpose
  1. Identify the requested output: class, location or boundary.
  2. Choose classification, detection or segmentation accordingly.
  3. Prepare matching labels for training/evaluation.
  4. Convert model outputs into the required measurements or decisions.
  5. Inspect difficult capture conditions.

3. Pupil/iris measurement needs more than an eye label

Worked study example: Illustrative pixel counts using the sample paper’s pupil-to-iris representation.

What this tells us: The ratio is information derived from recognized regions, not raw camera pixels. If segmentation misses 50 pupil pixels, the ratio changes even though the final division is correct.

4. Design the solution and check the result

Data, components and application

  • Boxes include background → segment the region → improves area measurements.
  • Tiny/occluded objects → improve capture and representative examples → reduces missed regions.
  • Good object score but wrong decision → evaluate the derived measurement too → downstream errors matter.

How to evaluate it

Check the relevant labels/boxes/masks, boundary errors and final measurement or task correctness.

Build the answer in this order

  1. Required information.
  2. Choose output granularity.
  3. Model output → measurement.
  4. Evaluate downstream consequence.

Changing view changes ratio unexpectedlyRegions inconsistently recognizedInspect masks/capture conditionsBad measurements propagate into the rule.
Common wrong answers and the exact correction
  • A bounding box is not an exact object boundary.
  • Detection success does not establish the correctness of a later rule.

6. Turn understanding into an exam answer

  • Use segmentation when the question requires pupil/iris pixel counts; a whole-image label or bounding box alone is insufficient.
  • For 200 pupil pixels and 1,000 iris pixels, the defined relative size is 0.20.
  • Check recognized regions and counts as well as the final ratio because correct arithmetic can still use incorrect measurements.

C069

Visual attention and context

Visual attention selects relevant regions. Bottom-up attention follows striking image features; top-down attention follows the task and context.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when a full scene contains distractions or recognition depends on surrounding relationships.

Scenario cueSuitable choiceWhy it fits
Locate visually unusual regionSaliency-based guidanceUseful when conspicuous features are the target.
Inspect a specified conditionTask/context guidanceThe question determines which evidence matters.

2. How it works — what happens and why

  • Bottom-up attention is attracted by image properties such as brightness, contrast and orientation. The most visually striking region need not be relevant to the task.
  • Top-down attention uses the current target, scene layout and expected relationships to direct processing toward useful evidence.
  • Context can help disambiguate an object, but it must not manufacture an object that is not actually visible.
  • Self-attention learns relationships among image patches. It is not a guarantee that the model’s focus matches a human explanation or the desired safety criterion.
Implementation steps and their purpose
  1. State the target and task.
  2. Identify useful visual cues such as contrast or edges.
  3. Use likely location and scene context to focus processing.
  4. Inspect the selected regions and related objects.
  5. Retain uncertainty when context conflicts with evidence.

3. Choose relevant evidence in a cluttered scene

Worked study example: Illustrative PPE inspection: a bright poster competes with a worker’s face for attention.

All steps shown
CueAttention typeUseful consequenceLimitation
Bright high-contrast posterBottom-upQuickly attracts visual processingNot relevant to mask coverage
Task asks nose coverageTop-downFocus on face and mask relationRequires task/context specification
Expected gloves in work areaContext guidancePrioritizes hands for inspectionDoes not prove gloves are present
Hand behind bodyMissing evidenceRecognize uncertaintyAttention cannot recover hidden pixels

What this tells us: The right answer explains why the selected region contributes to the question. “The model uses attention” alone does not establish that it checks the necessary relationship.

4. Design the solution and check the result

Data, components and application

  • Bright distractor selected → use task/context guidance → saliency alone may miss the relevant object.
  • Expected object imagined → verify visible evidence → context is guidance, not proof.
  • Relevant region hidden → request another view → attention cannot recover absent pixels.

How to evaluate it

Check whether relevant objects/relations are found under distraction, unusual context and changed camera angles.

Build the answer in this order

  1. Task and target.
  2. Bottom-up cues versus top-down guidance.
  3. Context-supported interpretation.
  4. Test distractors and uncertainty.

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Distractor dominatesSaliency mistaken for relevanceAdd task-guided target constraintsVisual prominence and decision usefulness differ.
Expected item hallucinatedPrior knowledge replaces observationRequire visible evidence or uncertaintyA likely object is not an observed object.
Common wrong answers and the exact correction
  • Self-attention is learned relationships between patches; it is not identical to visual saliency.
  • Expected does not mean observed.

6. Turn understanding into an exam answer

  • Bottom-up attention follows contrast or brightness, while top-down attention follows the PPE inspection task.
  • Context can guide the search toward the face or hands, but does not prove that a required item is present.
  • Validate the selected regions and report missing evidence when the relevant area is outside the frame.

C070

Vision-language models

A vision-language model (VLM) processes image/video and text together. It can link questions to visual regions and generate descriptions or judgements.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use for image questions or visual reasoning where language and scene information must interact.

Scenario cueSuitable choiceWhy it fits
Need broad image question answeringVLM with grounded outputLanguage can specify which relationship to inspect.
Need a fixed precise measurementDedicated recognition/measurement pipelineIts output can directly match the required numeric quantity.

2. How it works — what happens and why

  • A VLM combines image and language representations so a question can guide which visual evidence and relations are relevant.
  • Grounding connects words such as “mask” or “person on the left” to particular image regions; reasoning interprets their relationships under the requested rule.
  • Generation expresses the result, but fluent text can mention details unsupported by the image. Evidence and inference must therefore be separated.
  • A carefully constrained prompt helps specify the task and response structure; it does not turn uncertain visual evidence into certainty.
Implementation steps and their purpose
  1. Provide the image and a precise task prompt.
  2. Ask what is visibly present.
  3. Ground referenced objects in relevant regions.
  4. Apply the required relationships or domain rules.
  5. Separate evidence, inference and uncertainty in the output.

3. Use evidence, inference and uncertainty as separate outputs

Worked study example: Lecture PPE questioning style; example observations and answer structure are illustrative.

All steps shown
Output sectionExample statementWhat supports it
Observable evidenceA mask is visible on the faceVisible item/region

InferencePlacement may not satisfy the specified coverage ruleRelationship plus checklist knowledge
UncertaintyOne hand is outside the frameMissing view prevents glove verification
Next stepRequest another view/reviewer checkSpecific evidence gap

What this tells us: This is a justified visual judgement structure, not a substitute for the domain’s approved rule. The system should not invent unseen equipment or interpret a hidden region as definitely absent.

4. Design the solution and check the result

Data, components and application

  • Hallucinated details → require evidence-grounded output → fluent language can exceed visual evidence.
  • Wrong relation → check object locations/coverage → detected objects alone do not resolve the question.
  • Unseen setting → test representative cases → broad pretraining does not prove domain reliability.

How to evaluate it

Evaluate objects, grounding, relation/judgement accuracy and usefulness of uncertainty to the user.

Build the answer in this order

  1. Question → required visual evidence.
  2. Ground entities/relations.
  3. Apply case knowledge.
  4. Evaluate judgement and missing information.

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Plausible invented detailGeneration overreaches available pixelsRequire observable evidence and missing-information sectionSeparates inference from fact.
Correct objects, wrong answerRelationships or rules ignoredEvaluate grounding and judgement separatelyObject recognition is only part of reasoning.
Common wrong answers and the exact correction
  • A plausible caption does not prove correct reasoning.
  • Use a VLM only if it serves the case requirements.

6. Turn understanding into an exam answer

  • A VLM should ground the question’s objects in image regions and assess the required relation under the domain rule.
  • Separate observable evidence, inference and uncertainty so unsupported visual details are not reported as facts.
  • Evaluate object grounding and the final judgement separately under poor lighting, occlusion and unusual views.

C128

Ensemble diversity and voting

An ensemble combines several model predictions. It helps most when the individual models are useful and make different errors, so their mistakes can partly cancel.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Choose from the scenario

Use when a single model is unstable or several complementary sources of predictive evidence are available.

Scenario cueSuitable choiceWhy it fits
Different models capture different purchase patternsValidate voting or out-of-fold stackingComplementary errors may improve coverage beyond the best single representation.

Trace complementary errors and voting

Worked study example: Illustrative labels and predictions for four validation cases. Each model is correct on three cases, but its error occurs on a different case.

All steps shown
Case/true labelModel A / B / CMajority
Case 1: 10 / 1 / 11: correct
Case 2: 00 / 1 / 00: correct
Case 3: 11 / 1 / 01: correct

AccuracyEach model 3/4 = 75%Vote 4/4 = 100% here

What this tells us: This small example explains error cancellation, not a guarantee of future improvement. If all three missed case 1, voting would also miss it.

The distinction that changes the answer

  • Combining models helps when their errors differ on relevant cases. Three copies of the same decision function offer no new evidence; diversity must coexist with reasonable individual predictive ability.
  • Majority voting combines hard decisions, while probability averaging retains confidence information. A learned stacker uses base-model outputs as features and therefore needs out-of-fold training predictions to avoid learning from memorized scores.
  • The strongest component is the practical baseline. Ensemble accuracy alone does not settle value if extra inference cost, difficult maintenance or increased false alarms outweigh the improvement.

Compare component and committee error

accuracy = correct decisions / cases
cases
the same four held-out examples for every model
  1. Each component is correct on3/4 cases=75%.
  2. Its one error occurs on a different example.
  3. Majority vote is correct on4/4 here.
  4. If all three share one wrong decision,the vote also fails there.

Interpret the result: Useful diversity, not model count alone, provides the benefit.

What would make the choice wrong?

What you observeWhy it happensWhat to changeWhy that helps
Ensemble adds cost but no validation improvementBase models make highly correlated errorsInspect disagreement and remove redundant componentsExtra copies of the same mistakes cannot cancel those mistakes.
Common wrong answers and the exact correction
  • Diversity alone is insufficient if all models are poor
  • Stacking needs a learned combiner, unlike fixed voting.

Apply the distinction

Data, components and application

  • Highly correlated errors → diversify models or training samples → gain complementary evidence
  • One weak model hurts → remove or reweight after validation → avoid blind averaging
  • Stacking leakage → use out-of-fold base predictions → keep combiner training honest

How to evaluate it

Compare target metrics and resource cost; a tiny accuracy gain may not justify much higher latency.

Build the answer in this order

  1. Identify the single-model weakness
  2. Explain useful diversity
  3. Specify combination
  4. Validate benefit and business cost

An answer you could write

  • “The models are useful individually and their validation errors differ, so aggregation may reduce mistakes.”
  • “I compare against the best component and include recall, false-alarm cost and latency in the choice.”

C129

Bagging and bootstrap sampling

Bagging trains models on bootstrap samples and aggregates their predictions. A bootstrap sample is drawn with replacement, so some observations repeat and some are left out.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Follow one bootstrap and valid out-of-bag voters

Worked study example: Illustrative training IDs are A,B,C,D,E. Each bootstrap has five draws; duplicates are expected.

All steps shown
ModelBootstrap drawOmitted records
Tree 1A,A,C,E,CB,D
Tree 2B,C,D,D,EA
Tree 3A,C,C,D,EB
OOB prediction for BUse Tree 1 and Tree 3 onlyTree 2 trained on B and cannot vote here
Illustrative B votesTree 1:1, Tree 3:1OOB prediction 1

What this tells us: OOB evaluation is observation-specific; there is not one universal leftover set used by every model.

Expected unique-case fraction

unique fraction = 1 − (1−1/n)ⁿ
n
number of original training observations and draws in a standard bootstrap
  1. An observation is missed by one draw with probability1−1/n.
  2. It is missed by all n draws with probability(1−1/n)ⁿ.
  3. For large n,this is about36.8%,leaving about63.2% unique in-bag cases.
  4. OOB votes must exclude models trained on that case.

Interpret the result: Draw count is n; unique-case count is smaller because of repeats.

What information this representation preserves

  • Bootstrap sampling draws with replacement from the training records. A standard bootstrap has as many draws as the original dataset but fewer unique cases; about 63.2% are represented on average, with the remainder available out-of-bag for that tree.
  • Bagged models train independently. Their predictions are combined without the next model explicitly correcting the previous one; this separates bagging from boosting and makes independent fitting possible.
  • For an observation’s out-of-bag prediction, use only models whose bootstrap omitted that observation. Repeatedly optimizing against out-of-bag scores still makes them development evidence, so a separate final test remains useful when available.
Implementation steps and their purpose
  1. Draw a same-size sample with replacement from training data
  2. Train one base model
  3. Repeat independently for many models
  4. Vote for classification or average numeric predictions
  5. Use out-of-bag predictions or validation data to estimate quality

Prepare the data and validate the representation

Data, components and application

  • Base models repeat identical errors → increase meaningful diversity → averaging cannot cancel shared bias
  • Correlated observations leak across evaluation → split by entity first → preserve independence
  • Too few models → add models until validation stabilizes → reduce sampling variability

How to evaluate it

Use out-of-bag estimates for development and a final untouched test set when available; match metrics to the application.

Build the answer in this order

  1. Explain replacement
  2. Describe independent training
  3. State aggregation
  4. Explain why variance falls

Choose the representation from the task

Useful for reducing variance of unstable learners such as deep decision trees.

Scenario cueSuitable choiceWhy it fits
A tree changes substantially under small training changesUse bagging as a variance-reduction candidateIndependent bootstrapped fits can average unstable responses without forcing every tree to use the same sample.

Information loss, noise and failure cases

What you observeWhy it happensWhat to changeWhy that helps

Common wrong answers and the exact correction
  • Bagging is not sequential mistake reweighting
  • The lecture two-thirds description is an approximation, not the definition of bootstrap sample size.

An answer you could write

  • “I draw training cases with replacement, train independent learners and aggregate their predictions.”
  • “For record B, only the trees whose draws excluded B contribute to its OOB estimate.”

C130

Random forests and feature importance

A random forest combines bootstrapped decision trees and randomly limits candidate features at each split. This creates tree diversity beyond ordinary bagging.

DiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Follow feature availability across two trees

Worked study example: Illustrative candidates are PageValue, BounceRate and ProductRelated. Random subsets vary by node; the numbers below are toy impurity reductions, not the sample paper’s exact fitted forest.

All steps shown
NodeCandidates inspectedChosen split/gain
Tree 1 rootPageValue, BounceRatePageValue: 0.18
Tree 1 next nodeProductRelated, BounceRateBounceRate: 0.05
Tree 2 rootProductRelated, BounceRateProductRelated: 0.12
Tree 2 next nodePageValue, ProductRelatedProductRelated: 0.04
ProductRelated contribution0 in Tree1; 0.16 in Tree2Useful beyond one tree’s path

What this tells us: Feature subsampling can make trees explore different explanations, creating useful diversity. It does not establish that ProductRelated causes a purchase.

What information this representation preserves

  • Random forest adds feature randomization to bootstrap sampling. At each split, a tree considers only a random candidate subset, reducing the chance that one strong feature makes every tree follow the same early decisions.
  • A final prediction aggregates trees, not their importance scores. Impurity importance totals a feature’s contribution to training-node purification; permutation importance instead measures validation deterioration when its information is disrupted.
  • Importance is model-dependent and can be redistributed across correlated inputs. A feature unused by one tree may still help other trees correct errors in different data regions, so removing it requires a retrained comparison.
Implementation steps and their purpose
  1. Prepare training features and labels
  2. Draw a bootstrap sample for each tree
  3. At each split consider a random subset of features
  4. Grow the tree
  5. Vote across trees or average regression outputs
  6. Estimate quality and examine feature importance

Prepare the data and validate the representation

Data, components and application

  • Highly correlated trees → reduce candidate features per split → encourage diversity
  • Importance suggests a removable feature → retrain and validate removal → ranking alone does not prove redundancy
  • Too much complexity → tune leaf size/depth → control generalization

How to evaluate it

Compare held-out recall, precision and business cost; inspect importance stability and out-of-bag estimates during development.

Build the answer in this order

  1. State both randomness sources
  2. Explain prediction aggregation
  3. Interpret importance cautiously
  4. Validate any feature-removal proposal

Choose the representation from the task

Useful for nonlinear tabular classification or regression with interactions; a strong baseline when interpretability of one small tree is not essential.

Scenario cueSuitable choiceWhy it fits
A single purchase tree appears unstable or incompleteCompare a random forest and inspect held-out errorsSampling both cases and split candidates can reduce correlated tree errors.

Information loss, noise and failure cases

What you observeWhy it happensWhat to changeWhy that helps
Importance ranking changes when a similar feature is addedCorrelated inputs share predictive informationTest removal by retraining on the same validation designRanking differences alone do not prove one variable is useless or causal.
Common wrong answers and the exact correction
  • Importance is not causation
  • Random forests can overfit and do not guarantee unbiased importance rankings.

An answer you could write

  • “Random forests vary both training cases and candidate features at each split.”
  • “I test the reduced feature set on held-out cases rather than removing variables solely from one importance ranking.”

Boosting and AdaBoost

Boosting adds learners sequentially to improve the current ensemble. AdaBoost increases emphasis on training observations that previous learners classified incorrectly, then combines learners using performance-based weights.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Update example weights

α = ½ln((1−e)/e); new weight ∝ old weight×exp(±α)
α
learner vote strength
e
weighted error0.25
±α
positive for a mistake,negative for a correct case
  1. α=½ln3≈0.549.
  2. Correct raw weight0.25×exp(−0.549)≈0.144.
  3. Mistaken raw weight0.25×exp(0.549)≈0.433.
  4. Normalize:three correct cases about1/6 each;D about1/2.

Interpret the result: Later models focus more on previously missed cases.

Trace the first AdaBoost reweighting

Worked study example: Illustrative four binary cases initially weigh 0.25 each. A weak learner misclassifies only case D, so weighted error is 0.25. Use vote weight 0.5×ln((1−error)/error).

All steps shown
QuantityCalculationResult
Learner vote weight0.5×ln(0.75/0.25)Approximately 0.549
Correct-case raw weight0.25×exp(−0.549)Approximately 0.144 each
Wrong-case raw weight0.25×exp(0.549)Approximately 0.433
Normalize total3×0.144+0.433 ≈ 0.866A,B,C about 1/6 each; D about 1/2

What this tells us: Case D now holds half the next round’s weight. A later tree may use a feature absent from the first tree because it separates D-like cases.

Why the calculation works

  • AdaBoost focuses later learners on cases the current learner found difficult. Example weights are updated after each fit; the sequence is dependent, unlike independent bagging.
  • A learner with lower weighted error receives a stronger vote. Misclassified cases increase in relative weight, so the next weak learner has more incentive to distinguish them using different splits or features.
  • Repeatedly emphasizing difficult cases is valuable when they contain real missed structure, but harmful when the difficulty comes from incorrect labels or irreducible noise. Validation and data inspection are therefore important even with shallow weak learners.
Implementation steps and their purpose
  1. Start with equal observation weights
  2. Fit a weak classifier
  3. Calculate its weighted error
  4. Increase relative weight of misclassified observations
  5. Fit the next learner on the revised weighting
  6. Combine learner votes with learned weights

Use the result and check it

Data, components and application

  • Noisy or mislabeled hard cases dominate → clean labels and limit model complexity → avoid repeatedly fitting errors
  • Too many rounds → validate early stopping/learning rate → control overfitting
  • Unstable importance interpretation → compare held-out changes → do not infer a universal feature truth

How to evaluate it

Compare business-relevant recall/precision, not only training accuracy; use the same held-out cases for fair model comparison.

Build the answer in this order

  1. Explain the earlier model weakness
  2. Describe sequential reweighting
  3. Interpret ensemble prediction
  4. Validate improvement

Common wrong answers and the exact correction
  • AdaBoost differs from independent bagging
  • Boosting importance need not match the first split of one tree.

When would this calculation be useful?

Useful when several weak but informative learners can form a stronger classifier.

Scenario cueSuitable choiceWhy it fits

  • “AdaBoost increases the relative influence of misclassified examples before fitting the next learner.”
  • “A changed importance ranking can reflect useful correction; I confirm improvements on the same held-out purchase cases.”

C132

Gradient boosting

Gradient boosting builds an additive model sequentially. Each new learner addresses the current loss errors; with squared-error regression this corresponds to learning the remaining residuals.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Add one correction learner

new prediction = old prediction + η×correction
η
learning rate0.1
correction
new learner fitted to remaining residual structure
  1. Targets[10,20,30];old predictions[20,20,20].
  2. Residuals[−10,0,10];new learner predicts[−8,1,7].
  3. Add0.1 times the correction:[19.2,20.1,20.7].
  4. MSE falls from66.67 to57.05 on these training cases.

Interpret the result: Validation chooses rounds; falling training error alone does not justify more trees.

Fit and apply a residual correction

Worked study example: Illustrative regression targets are [10,20,30]. Start with their mean 20 for every case. A small new tree approximates residuals as [−8,1,7]. Learning rate is 0.1.

All steps shown
CaseOld prediction/residualUpdated prediction/residual
Target 1020 / −1020+0.1×(−8)=19.2 / −9.2

What this tells us: The learner need not reproduce every residual exactly to reduce the loss. Further rounds fit what remains, under validation control.

Why the calculation works

  • Gradient boosting changes the ensemble prediction in the direction that reduces a chosen loss. With squared error, the needed correction is the residual: actual target minus current prediction.
  • A new learner fits correction targets derived from the current ensemble, then contributes a scaled update. The learning rate controls each learner’s influence; more small steps can generalize differently from a few large corrections.
  • For other losses the correction is based on the loss gradient, not always the raw residual. This is why saying every boosting method reweights mistakes exactly like AdaBoost is incorrect.
Implementation steps and their purpose
  1. Choose a task-appropriate differentiable loss
  2. Start with a simple constant prediction
  3. Calculate what changes would reduce current loss
  4. Fit a small learner to those correction targets
  5. Add a scaled correction using a learning rate
  6. Monitor validation performance across rounds

Use the result and check it

Data, components and application

  • Training improves while validation declines → fewer rounds or early stopping → avoid fitting noise
  • Large updates → lower learning rate → make gradual corrections
  • Deep trees → reduce depth → restrict interactions and capacity

How to evaluate it

Use held-out RMSE/MAE for regression or suitable classification metrics and loss; compare model size and latency.

Build the answer in this order

  1. Identify target and loss
  2. Explain sequential corrections
  3. Justify learning rate and depth
  4. Check validation optimum

Common calculation and modelling mistakes

What you observeWhy it happensWhat to changeWhy that helps
Training loss keeps falling while validation risesToo many corrections fit training noiseStop at the validation optimum and consider smaller depth/rateThe additive model can become too flexible even when each individual learner is small.
Common wrong answers and the exact correction
  • Residual fitting is the squared-loss special case
  • Gradient boosting is not simply reweighting observations exactly as AdaBoost does.

When would this calculation be useful?

Useful for strong nonlinear tabular prediction where shallow trees can gradually correct systematic errors.

Scenario cueSuitable choiceWhy it fits
Numeric target has nonlinear remaining errorsFit shallow correction trees sequentiallyEach new learner can model residual structure left by the current prediction.

An answer you could write

  • “Under squared loss, I fit the remaining residuals and add a scaled correction.”
  • “The example lowers mean squared error from 66.67 to 57.05; I choose the number of rounds using validation, not that training reduction alone.”

C133

Mixture of experts / neuro-fuzzy systems

Mixture of experts uses specialist models and a gating mechanism that selects or weights specialists for each input. Neuro-fuzzy systems combine neural learning with fuzzy rules or membership functions.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Choose from the scenario

Use when the data has distinct operating regions, or when learned prediction must work with interpretable fuzzy knowledge.

Scenario cueSuitable choiceWhy it fits
Different operating regimes have different relationshipsConsider gated regional expertsTheir input-dependent combination can adapt to the regime rather than forcing one global fit.

A gate combines regional expert predictions

Worked study example: Illustrative low-load expert predicts temperature 40 and high-load expert predicts 80. The gate produces normalized weights from the observed operating state.

All steps shown
Operating caseExpert weightsCombined prediction
Mostly low-load0.8 low, 0.2 high0.8×40+0.2×80 = 48
Mostly high-load0.1 low, 0.9 high0.1×40+0.9×80 = 76
Fixed equal vote0.5,0.5 regardless of inputAlways 60: no input-dependent routing

What this tells us: Specialization is useful only if regional experts and the gate together beat an appropriate simpler baseline. The gate’s decision is part of the model, not a hand-waved selector.

The distinction that changes the answer

  • In a mixture of experts, the gate is input-dependent: the same experts can receive different weights for different cases. A fixed majority vote is not the same mechanism, even if several models are involved.
  • Specialists must receive enough relevant training cases. If the gate always selects one expert, the other experts cannot develop useful expertise; if regions are too narrow, their estimates may be unsupported.
  • A neuro-fuzzy system combines membership-based rule processing with learned parameters. Membership degree expresses graded belonging to a fuzzy set, not automatically a probability that the final class is true. Neural learning can tune those memberships or rule strengths.

prediction = Σ(gᵢ×expertᵢ)

  3. A fixed equal blend would always yield60.

Interpret the result: A useful gate needs adequate specialist coverage and routing validation.

What would make the choice wrong?

What you observeWhy it happensWhat to changeWhy that helps
One expert receives almost all casesGate collapses or training is unbalancedInspect routing and ensure useful specialist coverageA nominal multi-expert architecture gives little benefit when only one expert actually learns or predicts.
Common wrong answers and the exact correction
  • A fixed majority vote is not input-dependent gating
  • Not every hybrid model is a mixture of experts.

Apply the distinction

Data, components and application

  • Gate routes nearly everything to one expert → inspect routing balance → ensure specialists receive useful training
  • Few examples per specialist → simplify or share information → avoid unreliable experts
  • Fuzzy rules conflict → review and tune → preserve meaningful behavior

How to evaluate it

Evaluate overall performance, individual operating regions, routing costs and rule plausibility.

Build the answer in this order

  1. Explain why specialization helps
  2. Draw gate and experts or rule/learning components
  3. Describe training
  4. Evaluate difficult regions separately

An answer you could write

  • “For the low-load example the gate weights 40 and 80 as 0.8 and 0.2, giving 48.”
  • “I evaluate regime-specific errors and routing behavior, not just average error across all operating conditions.”

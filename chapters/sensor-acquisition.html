C083

Signals, sensors, and sensing pipeline

A sensor captures a physical quantity; a signal records its variation. Sense making turns the measurements into useful findings and actions.

Worked study example: Illustrative water-system monitoring based on the lecture’s pressure-sensor application; thresholds are not supplied or asserted.

What this tells us: A pressure drop may have several causes. The system should report the supported finding and evidence rather than claim a specific failure without a validated mapping.

What information this representation preserves

  • Start from the required finding rather than a favourite sensor. A sensor is useful only if its signal contains evidence about that finding.
  • Placement and range determine what is observable. A high-performing model cannot reliably recover a physical quantity that the sensor never captured.
  • Raw readings become features; recognition connects them to an event; decision logic connects the event to an action with user value.
  • A complete design includes expected failure and feedback: an alert that no one can interpret or act on does not solve the original problem.
Implementation steps and their purpose
  1. State the event or condition the user needs to know.
  2. Choose a sensor that observes relevant evidence.
  3. Specify placement, signal and acquisition rate.
  4. Process/extract useful features.
  5. Map features to a finding.
  6. Define the resulting alert, recommendation or action.

Prepare the data and validate the representation

Data, components and application

  • Wrong measurement chosen → link sensor to required finding → prevents collecting irrelevant data.
  • Poor deployment → choose suitable placement/range → signal quality begins at capture.
  • Numbers without action → define decision and user response → connects sensing to value.

How to evaluate it

Check measurement quality, finding correctness, useful action, latency and error consequences.

Build the answer in this order

  1. User need.
  2. Sensor → acquired signal.
  3. Processing → finding.
  4. Action and evaluation.

What the question requires

  1. Keep relative size as pupil pixels / iris pixels.
  2. Check the fractional scale against the threshold.
  3. Apply absolute value to the whole left–right difference.
  4. State the percentage interpretation and strictness.

Proposed answer points

C084

Sampling and aliasing

Sampling converts a continuous-time signal into readings at intervals. Undersampling can make different original signals appear identical: aliasing.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Minimum sampling rate under the lecture assumption

fs ≥ 2 fmax
fs
samples recorded per second
fmax
highest relevant signal frequency in hertz
  1. Lecture voice example:fmax=4,000 Hz.
  2. Twice the highest frequency=8,000 samples/second.
  3. A4,000 samples/second recording does not meet the condition.
  4. Resaving/interpolating that recording at16,000 does not restore uniquely lost original frequencies.

Interpret the result: Ideal stated minimum:8 kHz; verify acquisition assumptions.

Apply the sampling rule before recording

Worked study example: Lecture voice example assumes relevant frequencies extend up to 4,000 Hz; numerical alternatives are illustrative.

All steps shown
Capture choiceSamples per secondComparison to 2×4,000Implication
4 kHz4,000Below 8,000Does not satisfy ideal preservation condition
8 kHz8,000Meets stated ideal minimumBoundary under lecture assumptions
16 kHz16,000Above ideal minimumMore sampling headroom and larger data
Resave 4 kHz capture as 16 kHzMore stored/interpolated pointsOriginal evidence unchangedCannot uniquely reverse aliasing

What this tells us: The sampling condition is about original signal information, not how many data rows a software interpolation later creates.

Why the calculation works

  • Sampling records values at intervals, so fast variation can be confused with slower variation if the intervals are too wide.
  • The lecture’s ideal minimum rule uses twice the highest frequency to preserve a band-limited signal; do not automatically substitute bandwidth when the highest frequency differs.
  • Aliasing happens during acquisition. A later transform may clearly display the wrong apparent frequency without revealing the missing original.
  • The remedy must address capture conditions: suitable rate and removal of unwanted frequencies above the supported range before sampling.
Implementation steps and their purpose
  1. Identify the highest frequency that must be preserved.
  2. Choose a sampling rate meeting the lecture’s twice-highest-frequency rule.
  3. Avoid unwanted above-range components before sampling.
  4. Record consistently and retain timing.
  5. Check that the digitized signal preserves task-relevant behaviour.

Use the result and check it

Data, components and application

  • Rate too low → acquire faster → prevents irreversible loss of frequency identity.
  • Rate chosen from bandwidth alone → check frequency-range assumptions → highest frequency and bandwidth are not always equal.
  • Already aliased recording → reacquire appropriately → later interpolation cannot uniquely recover lost evidence.

How to evaluate it

Check represented frequencies, timing consistency and final task performance; test fast events explicitly.

Build the answer in this order

  1. Fastest relevant variation.
  2. Required acquisition rate.
  3. Aliasing consequence and remedy.
  4. Verify preserved information.

  • A lower rate risks aliasing, so the digitized pattern may misrepresent the original variation.
  • I verify capture rate and signal range before trusting frequency features.

C085

Periodic / even / odd signals

Periodic signals repeat after a fixed interval. Even signals mirror around time zero; odd signals reverse sign as time is reversed.

Use when identifying signal structure or choosing a representation suited to repetition and symmetry.

Scenario cueSuitable choiceWhy it fits
Question asks repeating structureCheck a candidate interval across the signalThe definition requires one consistent repetition period.
Question asks even/oddCompare paired times around stated zeroThis tests symmetry rather than repetition.

Test definitions on actual paired values

Worked study example: Illustrative simple sequences/functions; this is definition checking, not a model-fitting result.

All steps shown
Signal/property testedComparisonResult
cos(t): time reversalcos(−t)=cos(t)Even
sin(t): time reversalsin(−t)=−sin(t)Odd
cos(t): shift by 2πcos(t+2π)=cos(t)Periodic
Single isolated positive pulseNo fixed repeat across full rangeNot periodic
Repeated positive pulsesMay repeat while never negativePeriodicity does not imply oddness

What this tells us: Do not answer “odd because it has negative values”. Oddness requires paired-time sign reversal across the defined signal, including consistency at the origin.

The distinction that changes the answer

  • Periodicity asks whether the full signal repeats after one fixed positive interval. Similar local shapes are insufficient if their spacing continually changes.
  • Even symmetry compares values at t and −t; odd symmetry compares opposite signs at those paired times. These are independent of whether the signal repeats.
  • The origin matters when testing symmetry: shifting a waveform can change whether it appears even or odd around time zero.
  • Noisy, finite recordings allow a practical evidence-based judgement, not proof that a physical process repeats forever.

What would make the choice wrong?

What you observeWhy it happensWhat to changeWhy that helps
False periodicity claimOnly two similar snippets inspectedCheck spacing and rest of recordOne resemblance does not establish repeated structure.
False evenness claimSymmetry judged around a convenient shifted centreUse stated time originThe definition is relative to zero.
Common wrong answers and the exact correction
  • Periodic and even/odd describe different properties.
  • Even does not mean positive and odd does not mean negative.

Apply the distinction

Data, components and application

  • Noise hides repetition → inspect enough cycles → one short window can mislead.
  • Symmetry judged visually → compare paired times/values → confirms the definition.
  • Periodic assumed forever → state the observed range → finite data supports limited claims.

How to evaluate it

Check candidate periods and paired-time values using the whole available signal range.

Build the answer in this order

  1. Observed pattern.
  2. Test repetition.
  3. Test symmetry.
  4. Explain relevance to representation.

An answer you could write

  • I classify a signal as periodic only when one fixed positive interval repeats its values across the defined range.
  • Evenness requires equal paired-time values; oddness requires equal magnitude with opposite sign.
  • A noisy finite record supports an observed repetition pattern, not an unlimited guarantee.

C086

Superposition and signal decomposition

Superposition builds a signal by scaling and adding simpler components. Decomposition works in the other direction to make complex behaviour easier to analyze.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Linear combination

x = 2A + 3B
A
constant component[1,1,1]
B
changing component[1,0,−1]
x
reconstructed signal
  1. ScaleA:[2,2,2].
  2. ScaleB:[3,0,−3].
  3. Add samplewise:[5,2,−1].
  4. If only2A is retained, residual x−2A=[3,0,−3].

Interpret the result: Full combination reconstructs[5,2,−1]; omission loses variation.

Build a small signal from two components

Worked study example: Illustrative three-sample arithmetic demonstrating scaling/addition.

All steps shown
TermVector valuesContribution
Component A[1,1,1]Constant pattern
Component B[1,0,−1]Changing pattern
2×A[2,2,2]Constant contribution
3×B[3,0,−3]Changing contribution
Sum[5,2,−1]Reconstructed signal
Keep only 2×A[2,2,2]Misses [3,0,−3] variation

What this tells us: The components and their weights jointly specify the representation. The weight 3 is not itself the changing component; it scales that component.

Why the calculation works

  • A linear combination scales components and adds them. The weights say how much of each basis component contributes to the signal.
  • Decomposition chooses a representation where useful structure is easier to inspect; reconstruction returns to the original representation by adding weighted components.
  • Keeping every component can reproduce the signal, while dropping components produces an approximation whose errors must be assessed.
  • Superposition is conditional on linear behaviour. Products of two input signals are not the same operation as adding scaled signals.
Implementation steps and their purpose
  1. State the observed signal and relevant component types.
  2. Choose a suitable basis or component representation.
  3. Find component weights.
  4. Study useful components separately.
  5. Add weighted components to reconstruct or approximate the signal.
  6. Check what information the approximation loses.

Use the result and check it

Data, components and application

  • Wrong basis → choose components matched to the signal/task → improves interpretability.
  • Too few components → retain additional useful ones → reduces reconstruction loss.
  • Assuming linearity without checking → state the linear-system condition → superposition is not universal.

How to evaluate it

Compare reconstructed with original signal and check whether retained components preserve the task-relevant event.

Build the answer in this order

  1. Complex signal problem.
  2. Decomposition choice.
  3. Component interpretation or reconstruction.
  4. Information retained versus lost.

Use when a sensor signal combines multiple patterns and a simpler component representation is useful.

An answer you could write

  • I express the signal as scaled components and add them to reconstruct the readings.
  • Dropping the changing component here replaces [5,2,−1] with [2,2,2], losing the variation.
  • I choose retained components using reconstruction error and the actual target task.

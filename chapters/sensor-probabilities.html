C090

Signal distributions and statistics

A distribution describes likely readings; statistics summarize observed data. A class-specific distribution can support probabilistic sensor classification.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when deciding which class best explains measured features, such as vibration and acoustic categories.

Scenario cueSuitable choiceWhy it fits
Question asks only predicted classCompare unnormalized productsThe common normalization denominator does not change ranking.
Question asks probabilitiesNormalize all competing scoresRaw products do not sum to one.

2. How it works — what happens and why

  • Bayesian classification compares how well each cause explains the observed readings, adjusted by how common that cause is in the training data.
  • The prior is the class proportion; a likelihood is the feature probability within that class. Reversing these conditional probabilities changes the calculation.
  • Naive Bayes multiplies feature likelihoods conditional on the class. Its simplifying independence assumption is not the claim that vibration and acoustic are always unrelated.
  • Unnormalized scores are sufficient to rank classes, but probabilities require division by the sum of competing scores under the stated model.
Implementation steps and their purpose
  1. Prepare relevant features and reliable class labels.
  2. Estimate class priors from training counts.
  3. Estimate each feature’s likelihood within each class.
  4. For Naive Bayes, state conditional independence given class.
  5. Multiply prior by feature likelihoods.
  6. Normalize scores if probabilities are requested and choose the larger.

4. Design the solution and check the result

Data, components and application

  • Class imbalance → include priors → avoids treating unequal class frequencies as equal.
  • Correlated features → question the independence assumption → duplicated evidence can distort scores.
  • Poor distribution fit → inspect data and choose suitable model → one Gaussian may not fit multiple groups.

How to evaluate it

Check held-out predictions, class-specific errors and whether probabilities reflect actual outcomes.

Build the answer in this order

  1. Given readings and classes.
  2. Prior and likelihood counts.
  3. Score/normalize.
  4. Prediction, assumption and validation.

6. Turn understanding into an exam answer

  • Assuming vibration and acoustic are conditionally independent given the cause, multiply each prior by its two likelihoods.
  • Carryback scores 1/15 and Mistracking scores 1/9; normalization gives .375 and .625.
  • Therefore predict Mistracking, subject to validating the model and its independence assumption.

C091

Gaussian mixtures / expectation maximization

A Gaussian mixture models several overlapping groups. Expectation maximization (EM) alternates estimating hidden group membership and updating model parameters.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when one distribution is too simple and the data’s component labels are unknown.

Scenario cueSuitable choiceWhy it fits
Labels unknown, distribution multimodalMixture plus EMJointly estimates membership and component parameters.
True class labels suppliedUse them directly for supervised estimatesNo need to pretend known labels are hidden.

2. How it works — what happens and why

  • EM solves a circular estimation problem: component distributions require memberships, while memberships require distributions. Initialization breaks the circle and iteration refines both.
  • The E-step assigns probabilities, not necessarily hard labels. Each observation can contribute fractionally to several components.
  • The M-step treats those probabilities as weights when updating distributions and mixture proportions. Counts are therefore weighted totals rather than ordinary integers.
  • A mixture model describes multiple subpopulations; its fitted components are not automatically meaningful real-world classes without interpretation and validation.
Implementation steps and their purpose
  1. Choose component count and initialize parameters/mixture proportions.
  2. E-step: estimate each observation’s probability of belonging to each component.
  3. M-step: update component parameters using those weighted memberships.
  4. Update mixture proportions.
  5. Repeat until the stopping condition.
  6. Check sensitivity to initialization and fit.

4. Design the solution and check the result

Data, components and application

  • Unknown labels → soft memberships → each observation can contribute to both components.
  • Poor initialization → compare plausible starts → one run may give a poor solution.
  • Too simple model → assess component count → multiple peaks may need multiple components.

How to evaluate it

Inspect fit, convergence and stability; evaluate downstream classification if that is the goal.

Build the answer in this order

  1. Mixed data without labels.
  2. Initialize.
  3. Estimate memberships ↔ update distributions.
  4. Check fit and limitations.

6. Turn understanding into an exam answer

  • I initialize component distributions and mixture shares, then alternate membership estimation and weighted parameter updates.
  • A six receives Yellow membership .8 and Blue .2 under the given initial values.
  • I assess convergence and stability and do not treat inferred components as verified labels automatically.

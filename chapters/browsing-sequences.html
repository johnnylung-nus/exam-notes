C117

RNN sequence representation

An RNN processes an ordered sequence while carrying a hidden state from one step to the next. The same recurrent weights are reused, so the current representation depends on earlier observations.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Use when order matters, such as browsing events, speech, text or a sensor time series.

Scenario cueSuitable choiceWhy it fits
Raw ordered browsing events are availableCompare RNN/LSTM against aggregate-feature baselineAdditional sequence complexity is justified only by better held-out prediction or decision value.

2. How it works — what happens and why

  • An RNN updates a hidden state from the current event and previous state. Reusing the update across time supports variable-length sequences without learning separate weights for every position.
  • Order changes the state trajectory. Aggregate counts cannot distinguish product→help from help→product, even though those patterns may have different purchase implications. Sequence models are justified by this extra information, not merely by the existence of timestamps.
  • Define the prediction time before constructing examples. Later checkout events cannot be used to predict an earlier purchase decision; padding must also be distinguished from genuine zero-valued events so it does not become artificial history.
Implementation steps and their purpose
  1. Define what one sequence and one time step mean
  2. Sort events in time
  3. Encode step features and scale numeric measurements
  4. Pad and mask unequal lengths when batching
  5. Feed the sequence to recurrent units
  6. Choose sequence-level or per-step output

3. Same counts, different sequence summary

Worked study example: Illustrative recurrence is new state = 0.5×previous state + event value, beginning at zero. Product event has value 1; help event has value 0. This simplifies order effects, not an actual fitted RNN.

4. Design the solution and check the result

Data, components and application

  • Randomly shuffled steps → restore temporal order → preserve the pattern
  • Future events in inputs → restrict to prediction-time information → prevent leakage
  • Long dependencies → consider LSTM → improve memory handling

How to evaluate it

Split by session/user or time as required; assess held-out task metrics rather than isolated time-step accuracy alone.

7. Where this is tested in the sample papers

ISY5002 Q1(d) — Sequence model, input construction and combination

What the question requires

  1. Choose LSTM for ordered session events.
  2. Represent each session as an ordered sequence with a purchase label.
  3. Encode page/source, scale duration, pad/mask and split without future leakage.
  4. Combine outputs with earlier models without training-score leakage.

Proposed answer points

  • Clickstream sequence → LSTM → Dense sigmoid → purchase score; use binary cross-entropy for the binary label.
  • For stacking, generate LSTM training scores out of sample, add them to the earlier model’s inputs, and compare against that model on validation data.

Avoid: Do not use post-purchase/future events when predicting an earlier intervention. In-sample base-model scores can leak into a stacked learner.

C118

LSTM and stacked recurrent networks

LSTM is a recurrent model with a memory cell and gates controlling what is kept, added and exposed. This helps learn longer dependencies than a plain RNN. Stacked recurrent layers learn successive sequence representations.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Use for ordered data when earlier events can influence a later decision, such as a purchase at the end of browsing.

Scenario cueSuitable choiceWhy it fits
Earlier events influence a late purchase outcomeUse LSTM with a binary purchase head as a candidateGates can preserve relevant earlier evidence across intermediate events.

2. How it works — what happens and why

  • LSTM uses a memory cell with an additive update. The forget gate controls retained old memory, the input gate controls writing candidate information, and the output gate controls how memory is exposed as hidden state.
  • Gate values are learned responses between zero and one, not fixed verbal rules. Selective memory helps longer dependencies but does not preserve every event unchanged or remove every optimization difficulty.
  • A stacked recurrent layer usually needs the earlier layer’s sequence of states, not only one final vector. For a session-level target, the final layer may provide one summary to a sigmoid output. Stacking predictions into another model requires a separate leakage-safe training design.
Implementation steps and their purpose
  1. Build one correctly ordered sequence per case
  2. Encode categories, scale numeric features and pad/mask
  3. Use LSTM units to summarize relevant history
  4. Pass sequence outputs onward when stacking recurrent layers
  5. Attach a target-appropriate final head
  6. Train with validation monitoring

3. Trace a selective memory update

Worked study example: Illustrative single coordinate: old memory 0.8; forget gate 0.9; candidate information 0.5; input gate 0.2; output gate 0.7.

All steps shown
OperationCalculationResult
Retain0.9×0.80.72
Write0.2×0.50.10
New memory0.72+0.100.82

What this tells us: Most old evidence remains and only a little new information is added. The hidden state exposes a bounded, gated view rather than simply returning the whole memory.

4. Design the solution and check the result

Data, components and application

  • Too many recurrent units → reduce width and stop early → control overfitting
  • Long irrelevant histories → choose a prediction window → reduce noise
  • Leakage in stacking → generate scores from held-out folds → avoid training on memorized predictions

How to evaluate it

Compare against a simple aggregate-feature baseline using recall, precision and business costs.

Common wrong answers and the exact correction
  • LSTM does not eliminate every gradient or data problem
  • The slide gate description contains a wording inconsistency: input gates add information, forget gates control retained memory.

6. Turn understanding into an exam answer

  • “Forget, input and output gates respectively retain, write and expose information.”
  • “I combine LSTM scores with earlier features using out-of-fold training predictions and compare held-out performance.”

L1 / L2 regularization

L1 and L2 add weight penalties to prediction loss. L1 encourages some weights to become exactly zero; L2 discourages large weights and usually spreads influence across smaller nonzero weights.

Use when training fits too closely to limited or noisy data; L1 can also support feature selection in suitable models.

What this tells us: L2 discourages a single very large coefficient. Real fitting still balances this preference against the predictive contribution of each input.

The distinction that changes the answer

  • Regularization adds a complexity penalty to prediction loss. It can deliberately accept a larger training prediction error to improve new-case performance; comparing only the penalized objective across different strengths can be misleading.
  • L1 penalizes absolute weight sizes and may set some weights exactly to zero. L2 penalizes squared sizes, making a very large coefficient disproportionately expensive; it generally shrinks coefficients without automatically eliminating features.
  • The penalty strength is tuned rather than learned as an ordinary weight. Its practical meaning depends on feature scaling, loss normalization and implementation conventions, so copying a coefficient from another task is not a complete justification.

Common wrong answers and the exact correction
  • L2 is not guaranteed feature elimination
  • Dropout and batch normalization work differently from explicit weight penalties.

Apply the distinction

Data, components and application

  • Penalty too weak → increase gradually → reduce excessive flexibility
  • Penalty too strong → reduce it → avoid underfitting
  • Features have incomparable scales → standardize → make penalties comparable

How to evaluate it

Look for lower validation error and a narrower generalization gap, not the smallest raw training loss.

Build the answer in this order

  1. Diagnose overfitting
  2. Choose penalty and explain its effect
  3. Tune strength without test reuse
  4. Compare the resulting validation performance

An answer you could write

  • “The gap suggests excessive flexibility, so I add a weight penalty and tune its strength on validation data.”
  • “A slightly worse training fit is acceptable when unseen-case performance improves.”

Proposed answer points

  • The original tail is Flatten9408 → Dense256 → Dense128 → Dense918. Its Dense parameter counts are 2,408,704, 32,896 and 118,422; with 18,960 convolution parameters the total is 2,578,982. The first Dense alone accounts for about 93.4%, so the actual bottleneck is the flattened-to-dense connection.
  • A defensible replacement is Flatten9408→Dense64→Dense918. Unchanged convolutions:18,960; Dense64:602,176; output:59,670; total:680,806. Reduction:1,898,176≈73.6%.

Avoid: 5,000 unevenly spread images raise overfitting and class-imbalance concerns; those are related but different problems. The combined 918-way output is one design, not the only possible factorized output architecture.

Dropout

Dropout randomly sets a fraction of activations to zero during training. The network cannot rely on the same particular hidden units always being available, reducing co-adaptation.

What information this representation preserves

  • Dropout randomly suppresses eligible activations during training. Changing the omitted subset means downstream units cannot depend on the same precise feature combination always being present, discouraging fragile co-adaptation.
  • In inverted dropout, surviving activations are divided by the probability of being kept. This preserves their expected scale over random masks; ordinary inference then uses the full representation without additional random masking.
  • Dropout does not remove stored weight matrices or automatically reduce model size. Its default training/inference distinction must be respected; deliberately stochastic test-time dropout is a special uncertainty procedure, not the normal evaluation described here.
Implementation steps and their purpose
  1. Identify a training/validation overfitting gap
  2. Add dropout to suitable hidden representations
  3. Choose a dropout fraction
  4. Train with fresh random masks
  5. Evaluate in inference mode with dropout disabled and the framework scaling convention applied

Prepare the data and validate the representation

Data, components and application

  • Excessive dropout harms learning → lower rate → retain enough signal
  • Dropout enabled at normal evaluation → switch to inference mode → obtain the intended deterministic prediction
  • Small data remains unrepresentative → improve coverage → regularization cannot invent missing cases

How to evaluate it

Compare validation loss and task metrics; accept dropout only if it improves generalization under the same split.

Build the answer in this order

  1. Identify overfitting evidence
  2. Explain temporary random omission
  3. Specify training versus inference behavior
  4. Justify rate using validation

Use as a regularization option when a network overfits; choose placement and strength based on validation rather than habit.

C125

Transfer learning and fine tuning

Transfer learning reuses a model trained on another dataset. A frozen feature extractor learns only a new task head; fine tuning also updates selected pretrained layers on the new data.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Choose from the scenario

Useful when the new labeled dataset is small and the earlier task provides relevant representations.

Scenario cueSuitable choiceWhy it fits
Small image dataset with a related source representationCompare a frozen encoder plus new head before extensive tuningIt limits learned degrees of freedom while testing whether earlier features support the target.

Separate frozen-head training from fine tuning

Worked study example: Illustrative pretrained encoder has 1,000,000 parameters and produces 128 features. A new five-class head uses 128×5+5 = 645 parameters.

All steps shown
StageTrainable parametersPurpose
Freeze encoder; train new head645Adapt output to five target labels

Update all encoder layers1,000,645Most flexibility and greatest small-data risk
Stored model sizeStill includes frozen encoder parametersFreezing reduces updates, not storage

What this tells us: The frozen encoder remains part of prediction. Training fewer values does not mean those frozen weights disappear from the deployed model.

The distinction that changes the answer

  • Transfer learning reuses features learned on another dataset. Freezing the base means its weights do not change while the new head learns; fine tuning means updating selected base weights as well.
  • The earlier representation helps only if it retains information useful for the new task. Similar image structures may transfer, but major changes in sensors, objects or conditions can make an apparently powerful pretrained model unsuitable.
  • First adapt the output head to the actual labels, then consider limited fine tuning with a small learning rate. Input normalization must match the selected model. Source-task accuracy does not establish performance on the new target distribution.

Apply the distinction

Data, components and application

  • Source domain differs → validate carefully → reused features may not transfer
  • Too much fine tuning with little data → freeze more layers → reduce overfitting
  • Excessive learning rate → lower it → preserve useful features

How to evaluate it

C034

Market basket analysis

Market basket analysis finds items that occur together and expresses associations as IF-condition THEN-consequent rules. The basket definition determines what association means.

Sample Q3(b): consultation-history basket

Worked study example: Reasoned study answer. Original database has 5,000 consultations; later trial additions are unquantified. Assume recorded diagnosis date is the treatment-date proxy because no separate actual treatment date is supplied.

What this tells us: This preserves the history→current outcome flow. A treatment-duration item would answer a different question from time elapsed since an earlier treatment.

What information this representation preserves

  • Basket construction is the central modelling choice. One basket per consultation asks which prior facts are associated with the current consultation’s diagnosis. One basket per patient instead aggregates across visits and answers a different question. The unit determines both contents and transaction count.
  • Ordinary baskets are unordered sets, so past/current roles and elapsed time must be encoded into item names or categories. Patient ID links visits and dates order them; neither belongs as a usual association item. Each treatment’s time gap must remain linked to that treatment, particularly when several historical treatments exist.
  • Mining generates combinations, not automatically diagnostic knowledge. After finding frequent itemsets and rules, keep consequents that predict current diagnosis and antecedents available beforehand. Support/confidence screen statistical evidence; domain review and held-out checks address usefulness. Associations do not establish causation or justify treatment on their own.
Implementation steps and their purpose
  1. Define the transaction unit and count.
  2. Join/clean records and encode facts as items.
  3. Bin numerical/time values where appropriate.
  4. Mine frequent itemsets and generate rules.
  5. Filter by support, confidence and application relevance.

Prepare the data and validate the representation

Data, components and application

  • Temporal leakage → use only pre-consultation history → future facts are unavailable at prediction.
  • Wrong consequent → keep current-diagnosis RHS for diagnostic rules → co-occurrence mining does not know the application target.

How to evaluate it

Check threshold counts, useful consequent, held-out performance and expert relevance. Association is neither causation nor treatment justification.

Build the answer in this order

  1. Unit → contents → encoding → count.
  2. Mine rules.
  3. Filter target/time roles.
  4. Validate useful associations.

Choose the representation from the task

Useful for cross-selling or discovering history-to-outcome patterns when data can be represented as transactions.

An answer you could write

  • “I create one basket per consultation, linking prior records by patient ID/date and encoding earlier diagnoses, treatments, linked time gaps and the current diagnosis.”
  • “I retain rules with current-diagnosis RHS and available-history LHS, sufficient support/confidence and validated domain relevance.”

C035

Association-rule support

Support is the proportion of all baskets containing every item in the whole rule: both the condition and the consequent. It measures how common that combination is.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Rule support

support = count(both condition and consequent) / count(all baskets)
condition
home
consequent
news
basket
one browsing session
  1. Sessions1,4,6,7 contain both home and news.
  2. All seven sessions are eligible baskets.
  3. Divide4 by7.

Interpret the result: 4/7≈57.1%; reverse direction has the same support.

Additional illustrative practice: Illustrative support counts with sample-style thresholds

Illustrative support counts with sample-style thresholds

Worked study example: There are 100 consultation baskets. A=an encoded prior-history condition; B=current diagnosis. This is invented arithmetic matching the sample discussion, not an actual clinical dataset statistic.

All steps shown
Basket categoryCountContributes to support(A→B)?
Contains both A and B12Yes
Contains A without B8No
Contains B without A28No
Contains neither52No
All eligible baskets100Denominator
Joint support12/100=12%Passes minimum 10%; fails 15%

What this tells us: The condition occurs 20 times, but 12/20 is confidence, not support. The reverse rule B→A still has 12% support because exactly the same 12 baskets contain both.

Why the calculation works

  • Support answers how widely the entire rule combination occurs, not how reliable the rule is when triggered. Its denominator is all eligible transactions under the chosen basket definition. Therefore changing from consultation baskets to patient baskets changes support even when some item labels remain the same.
  • Both sides must appear together in a supporting basket. A rule with a frequent condition but an uncommon joint outcome can have low support. Reversing the rule does not change this joint count, so support is symmetric even though confidence is usually directional.
  • Minimum support reduces search and removes fragile rare combinations, but high support is not a universal quality criterion. An important rare event may be excluded, while common uninformative combinations survive. The threshold should follow supplied exam requirements or be chosen/validated for the task, not declared as a standard percentage for every domain.
Implementation steps and their purpose
  1. Count all eligible baskets.
  2. Count baskets containing the complete condition and consequent.
  3. Divide complete-rule count by total basket count.
  4. Compare with the supplied support threshold.
  5. Keep basket unit/count consistent across calculations.

Use the result and check it

Data, components and application

  • Rare but important rule → justify threshold/domain review → a high threshold may discard useful rare cases.
  • Duplicated transactions → deduplicate at the defined unit → inflated counts distort evidence.

How to evaluate it

Recalculate counts and check denominator. Report percentage or count exactly as requested; minimum count 3 is different from 3%.

Build the answer in this order

  1. Define basket unit.
  2. Identify whole itemset.
  3. Count and divide by all baskets.
  4. Apply threshold and explain coverage.

Use to reject extremely rare associations or calculate whether a rule meets the supplied minimum support.

  • “Twelve of 100 baskets contain both sides, so support is 12%; it passes the stated 10% minimum.”
  • “Reversing the rule leaves support unchanged, although confidence will change because its condition count changes.”

C036

Association-rule confidence and lift

Confidence asks how often the consequent occurs when the condition occurs. Lift compares that confidence with how common the consequent already is.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Conditional confidence

confidence(A → B) = count(A and B) / count(A)
A
antecedent/condition items
B
consequent/output items
  1. home appears in sessions1,3,4,5,6,7:6 triggers.
  2. news appears in1,2,4,6,7:5 triggers.
  3. Both occur in1,4,6,7:4 joint baskets.

Interpret the result: home→news=4/6; news→home=4/5. Confidence depends on direction.

Additional illustrative practice: Illustrative directional confidence and lift

Illustrative directional confidence and lift

Worked study example: Use 100 baskets: A appears 20 times, B 40 times, both 12 times. Lift is study elaboration; support/confidence are explicitly taught in inspected slides.

All steps shown
QuantityCalculationInterpretation
Confidence A→B12/20=60%B among A baskets
Confidence B→A12/40=30%A among B baskets
Baseline B frequency40/100=40%B without requiring A
Lift A→B0.60/0.40=1.5B occurs 1.5× baseline among A
Minimum confidence 70%60% failsDo not claim rule passes

What this tells us: A 60% confidence is meaningful only alongside its baseline, support and application role. In another dataset where B occurs in 80% of all baskets, 60% confidence would be worse than that baseline.

Why the calculation works

  • Confidence measures the conditional success rate among baskets where the antecedent occurs. It is directional: the same joint count divided by different condition counts yields different confidence for A→B and B→A. This is why frequent-itemset discovery alone does not determine the best rule direction.
  • A popular consequent can make confidence look strong without any useful association. Lift compares conditional frequency with the consequent’s overall frequency. Above one means positive association relative to that baseline; one means no improvement in this comparison. It still does not establish a cause or a safe clinical action.
  • Filtering must also respect the intended prediction flow. Even a high-support, high-confidence rule that predicts another treatment instead of current diagnosis does not answer the sample diagnostic question. Item-role labels make this filtering explicit; a mining algorithm cannot infer past/current roles from an unordered basket.
Implementation steps and their purpose
  1. Count baskets with the condition.
  2. Count baskets with both sides.
  3. Confidence = both count / condition count.
  4. For lift, divide confidence by overall consequent frequency.
  5. Apply supplied thresholds and domain constraints.

Use the result and check it

Data, components and application

  • Popular consequent → compare baseline/lift → high confidence can be uninformative.
  • Small condition count → require support and validate → confidence from a few examples is unstable.

How to evaluate it

Check rule direction, counts and holdout behaviour. Lift above one suggests positive association, not causality or clinical validity.

Build the answer in this order

  1. Calculate support/confidence.
  2. Check baseline prevalence.
  3. Apply thresholds.
  4. Explain relevance and limitations.

An answer you could write

  • “For A→B, confidence is 12/20=60%; B occurs in 40% overall, giving lift 1.5 under this illustrative extension.”
  • “I also require a current-diagnosis RHS, pre-diagnosis LHS, adequate support and validation; no universal cutoff is assumed.”

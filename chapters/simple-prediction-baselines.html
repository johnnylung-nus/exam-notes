C142

Linear / logistic regression

Linear regression predicts a numeric value from a weighted combination of features. Logistic regression predicts class probability by applying a logistic transformation to a weighted combination.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Choose from target type: sales amount is numeric regression, purchase yes/no is classification.

Scenario cueSuitable choiceWhy it fits
Target is purchase/no purchaseUse logistic classification as a simple baselineIt supplies a bounded probability and a transparent decision boundary for comparison with more complex models.

2. How it works — what happens and why

  • Linear regression predicts a numeric quantity as a weighted combination of inputs and fits squared-error loss in the basic lecture form. Logistic regression instead maps a weighted total to a class probability; its name does not make a purchase label a numeric regression target.
  • For logistic prediction, the learned score and decision threshold are separate. A probability of0.7 means an estimated class probability, not a guaranteed purchase, and it may need calibration checking.
  • Coefficients are interpreted conditional on other included inputs and preprocessing. Correlation, omitted information and target leakage can all undermine a simple story about why a coefficient is large; regression coefficients do not automatically establish causation.
Implementation steps and their purpose
  1. Define target and prediction-time features
  2. Prepare categories, missing values and numeric scales
  3. Fit linear regression with squared error for numeric targets or logistic regression with classification loss
  4. For classification choose a probability threshold using costs
  5. Check held-out predictions and errors

4. Design the solution and check the result

Data, components and application

  • Linear relationship inadequate → add justified features or compare nonlinear models → capture missing structure
  • Correlated predictors → consider regularization or PCA → stabilize the fitted model
  • Target leakage → remove outcome-derived features → preserve deployment validity

How to evaluate it

Use MAE/RMSE and residual analysis for numeric targets; use loss, precision, recall and confusion matrix for purchase classification.

  1. Identify target type
  2. Choose model and loss
  3. Explain output interpretation
  4. Evaluate against a baseline

6. Turn understanding into an exam answer

  • “For purchase yes/no I use logistic regression with a binary classification loss, not ordinary numeric least squares.”
  • “If I use PCA scores, I construct them from predictor inputs only and evaluate on unseen visitors.”

C143

K-nearest neighbours

K-nearest neighbors predicts using the labels of nearby training examples. Here K means the number of neighbors consulted, not the number of clusters or principal components.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Useful when similar feature profiles are likely to have similar targets and a meaningful distance can be defined.

Scenario cueSuitable choiceWhy it fits
Similar feature profiles plausibly share the targetTry scaled KNN as a baselineIts local vote gives a simple comparison without assuming one global linear boundary.

2. How it works — what happens and why

  • K-nearest neighbors stores labeled training examples and predicts from the local neighborhood of a query. Here K is the number of consulted neighbors, unlike K-means cluster count or PCA retained dimension.
  • Feature scale and distance define what local means. A large-unit attribute can dominate raw Euclidean distance; irrelevant dimensions can dilute useful similarity. Fit scaling using training data and select meaningful inputs.
  • Small K follows very local detail and noise; larger K smooths decisions but may blend distinct populations or favor a majority class. Tune that trade-off using held-out task metrics, not a fixed rule that more neighbors is always safer.
Implementation steps and their purpose
  1. Fit preprocessing on training data
  2. Scale numeric features and choose a distance
  3. Calculate the new case’s distances to training observations
  4. Select the K nearest
  5. Vote for classification or average numeric targets
  6. Tune K using validation

4. Design the solution and check the result

Data, components and application

  • Small K follows noise → increase K → smooth the boundary
  • Very large K ignores local groups → decrease K → retain local distinctions
  • Different feature units → standardize → make distance meaningful
  • High dimension → select useful features → avoid weak distance discrimination

How to evaluate it

Use held-out target metrics and prediction latency; compare neighbor behavior for sparse regions and minority classes.

Build the answer in this order

  1. Define similarity
  2. Explain the role of K
  3. Show the vote
  4. Discuss scale, noise and dimension

  • Neighbor count is selected using validation, not a fixed universal rule.

6. Turn understanding into an exam answer

  • “With K3 the nearest labels are Y,Y,N, so the query is classified as a purchaser.”
  • “I tune K and the preparation pipeline using purchaser recall and false-positive costs on held-out cases.”

ISY5001 Q3(a)(i) — Model choice against a ranked-output requirement

What the question requires

  1. Underline “least suitable”.
  2. Identify the required ranked list of diagnoses.
  3. Compare the proposed methods under stated assumptions.

Proposed answer points

  • Under a basic hard-label single-tree interpretation, a single tree is the intended weak choice because the required output is a ranked differential list.
  • A single tree can in fact rank classes by leaf class proportions; explain the assumed implementation rather than asserting an inherent impossibility.

Avoid: Choosing a suitable model does not answer which is least suitable. There is no official key confirming a unique implementation assumption.

ISY5001 Q3(a)(ii) — Inputs, derived variables and ranked diagnoses

What the question requires

  1. Use only listed or explicitly derived fields.
  2. Derive age at consultation; encode/scale appropriately.
  3. Separate doctor diagnosis as the label.
  4. Explain how each remaining method generates a ranking.

Proposed answer points

  • Inputs: listed symptoms, signs, medication-use flags, gender, occupation, and age derived from consultation date minus birth date.
  • Trees: aggregate class counts/probabilities across trees and rank. KNN: find nearby historical feature vectors, count their attached diagnosis labels, then rank up to ten.

Avoid: Medication-use flags are not measured blood-pressure/glucose. A label is not an input coordinate; neighbour support is not automatically a calibrated probability.

C079

LLM reasoning and chain of thought

A fluent sequence of reasoning-looking steps can still be wrong. The lecture distinguishes language generation from valid problem solving.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when assessing an LLM answer, proposed plan or chain of thought in a constrained scenario.

Scenario cueSuitable choiceWhy it fits
Answer gives a multi-step planTrace every state transitionChecks whether the procedure actually works.
Answer resembles memorized exampleRecheck exact question detailsChanged capacities or goals may invalidate familiar steps.

2. How it works — what happens and why

  • Language generation selects plausible text; legal problem solving additionally requires explicit states, permitted operations and a verified goal condition.
  • A long explanation can hide an illegal transfer, an unstated measurement capability or a changed question. Check operations rather than rhetorical confidence.
  • Intermediate state verification is essential: a final number can be right by coincidence while the proposed procedure cannot produce it.
  • The lecture’s water-jug example shows why a solution should be executable in the stated world, not only resemble a familiar puzzle answer.
Implementation steps and their purpose
  1. Write down the actual state, goal and allowed operations.
  2. Translate the proposed answer into explicit steps.
  3. Check each step against constraints.
  4. Recalculate intermediate results.
  5. Check the final goal independently.
  6. Reject an invalid step even if the explanation sounds confident.

3. Check a jug plan by actual volumes

Worked study example: Lecture capacities and goal; state order is (5L mug,3L mug). No graduation marks are available.

All steps shown
StepOperationStateLegality check

1Fill 3L mug(0,3)Tap fills to known capacity
2Pour 3L into empty 5L(3,0)All 3L fits

What this tells us: “Pour exactly 1L” would be illegal without a way to measure it. The demonstrated route obtains 1L through capacity constraints rather than inventing a measuring action.

4. Design the solution and check the result

Data, components and application

  • Memorized familiar puzzle answer → recheck the exact wording → changed details can invalidate it.
  • Persuasive explanation → verify state transitions → language confidence is not proof.
  • Correct-looking final answer → inspect legal operations → a lucky result can hide invalid reasoning.

How to evaluate it

Evaluate constraint satisfaction, correctness of intermediate states and actual attainment of the goal.

Build the answer in this order

  1. Formalize the exact problem.
  2. Verify each operation.
  3. Identify invalid assumption/step.
  4. Check the goal.

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Confident but impossible stepAssumed graduations or arbitrary measurementRestrict operators to permitted actionsA plan must be executable.
Goal reached in prose onlyNo state traceWrite quantities after each operationMakes contradictions visible.
Common wrong answers and the exact correction
  • More explanation does not guarantee better reasoning.
  • Do not treat generated text as a verified calculation.

6. Turn understanding into an exam answer

  • Represent the jug state as amounts in the 5L and 3L mugs and allow only fill, pour and empty operations.
  • The sequence (0,0)→(0,3)→(3,0)→(3,3)→(5,1) leaves one litre in the 3L mug.
  • Reject a step that assumes arbitrary measured quantities because the mugs have no graduations.

C080

Validity, soundness, and reasoning failure

Validity asks whether a conclusion follows from the premises. Soundness also requires true premises; a valid-looking argument based on a wrong case assumption is insufficient.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Use when critiquing a reasoning system, proposed formula or confident explanation.

Scenario cueSuitable choiceWhy it fits
Unsigned discrepancy requiredUse magnitude of whole differenceEither ordering should yield the same discrepancy.
Relative percentage explicitly definedUse the specified denominatorA percentage-point difference is a different quantity.

2. How it works — what happens and why

  • Validity concerns whether the conclusion follows from the premises; soundness additionally needs true premises. Unsupported case assumptions undermine the answer even if the arithmetic is consistent.
  • A counterexample is often faster than a long critique: reverse input order, test zero difference or test the boundary at the threshold.
  • Units and scales are part of the reasoning. Fractions and percentages can describe the same quantity but require consistent thresholds.
  • The sample’s percentage wording is ambiguous; an exam answer should state the adopted interpretation rather than claim a universally correct clinical equation.
Implementation steps and their purpose
  1. List the premises actually supplied by the case.
  2. Separate assumptions from evidence.
  3. Check the inference or calculation.
  4. Test edge cases and reversed inputs.
  5. Check whether the conclusion answers the requested question.

3. Test scale, sign and equality separately

Worked study example: Sample Q2(g) interpretation: 30 percentage points between normalized mean ratios. This is a study calculation only.

All steps shown

Left=.20; right=.60−.40.40Yes

What this tells us: Using abs(left)−abs(right) leaves the first case negative. The absolute value must enclose the whole difference. If a relative percentage is intended, a reference denominator must be defined instead.

4. Design the solution and check the result

Data, components and application

  • Unstated assumption → label it explicitly → readers can assess its effect.
  • Wrong scale → keep fractions and percentages consistent → avoids a 100-fold threshold error.
  • Wrong problem solved → reread the exact requested quantity → a correct calculation can be irrelevant.

How to evaluate it

Verify premises, logical steps, units, signs, boundary conditions and final requirements.

Build the answer in this order

  1. Case facts versus assumptions.
  2. Reasoning rule.
  3. Counterexample or boundary test.
  4. Supported conclusion.

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
30 used with fractional ratiosScale mismatchUse .30 or convert both sides to percentPrevents a hundredfold threshold error.
Boundary result incorrectGreater-than replaced with greater-or-equalMatch exact requested comparisonEquality can change the decision.
Common wrong answers and the exact correction
  • Plausible is not the same as valid.
  • The sample’s “30%” interpretation needs a stated reference.

6. Turn understanding into an exam answer

  • Assuming the threshold means 30 percentage points between normalized means, compare abs(left−right) with .30.
  • Taking absolute values separately does not fix a negative difference; reversing left/right should not change an unsigned discrepancy.
  • Use strict greater-than when required and state that a relative-percentage interpretation needs a defined denominator.

7. Where this is tested in the sample papers

ISY5001 Q2(i) — Patient self-service: benefits, risks and role boundaries

What the question requires

  1. State a position on removing the primary doctor.
  2. Acknowledge the convenience benefit.
  3. Explain a case-specific risk and a safer scope.

Proposed answer points

  • A patient-facing information/capture function could improve convenience, but removing the doctor is not justified by the presented diagnostic/triage support case.
  • Capture errors, incomplete context and delayed escalation are possible risks; retain clinician assessment for the clinical decision.

Avoid: Do not claim all cognitive systems always require a doctor; argue from this system’s intended users and risks.

C081

Soar architecture

Soar’s lecture example separates long-term action knowledge from the current state and constructed search states in working memory.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when explaining how a cognitive architecture represents a problem and selects actions toward a goal.

Scenario cueSuitable choiceWhy it fits
Need represent reusable proceduresLong-term knowledgeOperators persist across current cases.
Need evaluate this current configurationWorking memory/state spaceThe solution depends on current state and goal.

2. How it works — what happens and why

  • The Soar example stores reusable operators and relations in long-term memory; working memory contains the current problem and constructed states.
  • Operators describe legal transformations, while state values describe current quantities. Confusing them makes it impossible to verify a search path.
  • Search chooses a sequence, not just the locally closest-looking state. Some legal solutions temporarily move farther from the final quantity.
  • Loop restrictions and path-length preferences can guide search, but a particular heuristic is not by itself proof of a globally shortest solution.
Implementation steps and their purpose
  1. Represent current state and goal in working memory.
  2. Keep reusable objects, relations and operators in long-term memory.
  3. Apply only legal operators to generate next states.
  4. Search the resulting state space.
  5. Select a path that reaches the goal and meets the stated cost preference.

3. Show what belongs in each memory

Worked study example: Lecture jug example; current state is (amount in 5L,amount in 3L).

All steps shown
Memory/itemConcrete contentUsed for
Long-term operatorFill from tap to 3LReusable possible action
Long-term operatorPour 3L mug into 5L until source empty/destination fullDefines legal transition
Working memoryCurrent state (3,3)Describes this search node

Search resultPath to (5,1)Executable solution from this initial state

What this tells us: A state such as (3,3) is not permanent action knowledge. The same operator can be applied to multiple states with different resulting amounts.

4. Design the solution and check the result

Data, components and application

  • State confused with operator → separate water amounts from fill/pour/empty actions → clarifies search.
  • Immediate error reduction required at every step → allow necessary temporary increases → a legal goal-reaching path need not improve monotonically.
  • Loops → track/restrict unhelpful reversals → avoids repeated states.

How to evaluate it

Check operator legality, capacity constraints, goal attainment and path length where required.

Build the answer in this order

  1. State/goal.
  2. Memory contents.
  3. Operators and transitions.
  4. Search result and cost.

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Search loops repeatedlyUnhelpful reversals not trackedRecord visited/restricted transitionsAvoids revisiting the same configurations endlessly.
Greedy step blocks solutionOnly immediate distance decrease allowedSearch legal alternatives with suitable path controlTemporary increases can be necessary.
Common wrong answers and the exact correction
  • Working memory is not the entire permanent knowledge base.
  • A goal-distance heuristic does not alone prove optimality.

6. Turn understanding into an exam answer

  • Store reusable fill/pour/empty operators in long-term knowledge and the current amounts/goal in working memory.
  • Apply legal operators to construct successor states and search for a path ending with one litre in the 3L mug.
  • Track unhelpful reversals and do not claim that an immediate-distance heuristic alone proves shortest-path optimality.

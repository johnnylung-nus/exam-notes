C115

Multi-input / multi-output architectures

Multiple inputs let a network combine different information sources. Multiple outputs let it learn several related targets, with a suitable output head and loss for each target.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Use when the scenario includes images plus text or metadata, or requires several predictions about the same object.

Scenario cueSuitable choiceWhy it fits
Several labels can independently apply to an objectUse separately labeled sigmoid headsA softmax would force competition even when two attributes should both be present.

2. How it works — what happens and why

  • Process each modality according to its structure: tokens as sequences, images as spatial arrays and numeric metadata as prepared measurements. Combining raw values blindly can erase the relationships the branch should exploit.
  • A merge joins representations belonging to the same case. Every source must exist at prediction time; metadata recorded after an outcome is leakage even if it enters through a separate branch.
  • Separate outputs need separate labels, activations and losses. Loss weights control their influence on shared layers, so the numerically larger loss must not automatically determine what all shared features learn.
Implementation steps and their purpose
  1. List each input modality and its shape
  2. Give each modality a suitable processing branch
  3. Combine branch representations
  4. Attach task-specific output heads
  5. Define each target and corresponding loss
  6. Balance losses and validate every output

3. Design two inputs and two outputs

Worked study example: Illustrative task predicts exclusive product type among three classes and continuous estimated weight from one product image plus four metadata features.

All steps shown
StageExample shapePurpose

Metadata branch4 numbers → Dense8Learn numeric evidence
Merge32+8 = 40 featuresCombine evidence for one product
Type output40 → 3 softmaxCategorical cross-entropy

What this tells us: Report type errors and weight error separately. A favorable combined loss can conceal deterioration in the business-critical output.

4. Design the solution and check the result

Data, components and application

  • One modality has a different scale or missing values → prepare it separately → avoid corrupting fusion
  • One task dominates training → adjust loss weighting → preserve the other task

How to evaluate it

Measure each output separately and check whether using multiple inputs improves over single-input baselines.

Build the answer in this order

  1. Identify information sources
  2. Draw branches and merge point
  3. Label each output
  4. Explain activation, loss and evaluation per head

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Deployment lacks a metadata inputTraining used a source recorded after the decisionRemove that source and retrainA model cannot operationally depend on information unavailable when it must act.
Common wrong answers and the exact correction
  • Concatenating unrelated raw inputs is not automatically a good design
  • Multiple exclusive classes differ from multiple separate outputs.

6. Turn understanding into an exam answer

  • “I use modality-specific branches, then merge representations for the same observation.”
  • “Each output has its own target, activation, loss and evaluation; I justify how the losses are balanced.”

7. Where this is tested in the sample papers

ISY5002 Q1(d) — Sequence model, input construction and combination

What the question requires

  1. Choose LSTM for ordered session events.
  2. Represent each session as an ordered sequence with a purchase label.
  3. Encode page/source, scale duration, pad/mask and split without future leakage.
  4. Combine outputs with earlier models without training-score leakage.

Proposed answer points

  • Clickstream sequence → LSTM → Dense sigmoid → purchase score; use binary cross-entropy for the binary label.
  • For stacking, generate LSTM training scores out of sample, add them to the earlier model’s inputs, and compare against that model on validation data.

Avoid: Do not use post-purchase/future events when predicting an earlier intervention. In-sample base-model scores can leak into a stacked learner.

C116

Shared layers / encoder architectures

Shared layers apply the same learned feature extractor to different inputs. An encoder turns an input into a compact representation; shared encoding makes two observations comparable in the same learned feature space.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Useful for comparing paired images or recognizing the same person across cameras.

Scenario cueSuitable choiceWhy it fits
Compare an entrance image with a stored employee imageUse a shared encoder followed by a comparison headThe lecture’s reidentification task needs both inputs represented consistently despite different appearance conditions.

2. How it works — what happens and why

  • Shared layers mean the same parameter values are applied twice, not merely two networks with identical layer layouts. Both inputs undergo one learned transformation and become directly comparable representations.
  • The comparison stage operates on encoded features rather than raw pixels. Pair training must include matching and nonmatching examples across camera, pose and lighting variation; otherwise background can become a shortcut.
  • Evaluation depends on the claim. New images of enrolled employees and entirely unseen people require different splits. Identity-disjoint testing is necessary when claiming generalization to unseen identities, not just random image separation.
Implementation steps and their purpose
  1. Prepare both inputs consistently
  2. Pass each through the same encoder weights
  3. Compare or combine encoded representations
  4. Predict whether the pair matches
  5. Train on labeled matching and nonmatching pairs

3. Compare pairs in one learned feature space

Worked study example: Illustrative shared encoder outputs two coordinates. Squared distance adds the squared coordinate differences; lower values suggest a match after a threshold has been validated.

All steps shown
PairEncoded vectorsSquared distance
Same person, new view[0.8,0.2] and [0.7,0.3]0.1²+(−0.1)² = 0.02
Different people[0.8,0.2] and [0.1,0.9]0.7²+(−0.7)² = 0.98
Illustrative ruleMatch when distance <0.1First matches; second does not

What this tells us: The threshold is illustrative, not a universal setting. Choose it from held-out false-match and missed-match costs under realistic camera conditions.

4. Design the solution and check the result

Data, components and application

  • Different camera conditions → collect varied positive pairs → learn stable identity evidence
  • Separate encoders drift apart → share weights where justified → use a common feature transformation
  • Identity leakage → split by person when testing unseen-person generalization → make the evaluation realistic

How to evaluate it

Evaluate false matches and missed matches on held-out pairs under realistic angle, lighting and occlusion conditions.

Build the answer in this order

  1. Explain the comparison task
  2. Show two branches with shared weights
  3. Label the comparison stage
  4. State realistic validation cases

5. Diagnose the proposed model — change and justify

What you observeWhy it happensWhat to changeWhy that helps
Matching works only on the original cameraEncoder learned background or lighting shortcutsCollect cross-camera positive and negative pairsSharing weights cannot create invariance unless the training examples expose the desired identity-preserving changes.
Common wrong answers and the exact correction
  • Shared weights mean one parameter set, not merely two identical-looking architectures
  • An encoder is not itself a final class label.

6. Turn understanding into an exam answer

  • “Both branches share weights, placing the inputs in one learned feature space.”
  • “I validate false matches and missed matches using the intended camera conditions and identity split.”

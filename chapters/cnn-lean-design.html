C112

CNN convolution, padding, stride

Convolution learns local filters and reuses each filter across an image. Padding controls border handling; stride is how far the filter moves between positions. Different filters produce different output channels.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

A convolution response

response = Σ(patch value × kernel value) + bias
Σ
sum across the spatial patch and input channels
bias
one learned offset per output filter
  1. Multiply corresponding3×3 entries.
  2. Add1+6+6+0+3+0+4+1+2=23 before bias.
  3. For8×8 input,3×3 kernel,stride1,no padding: output side=8−3+1=6.
  4. Four filters produce6×6×4 output; one cell padding per side gives8×8×4.

Interpret the result: Kernel size determines local coverage; filter count determines output channels.

What this tells us: Changing stride or padding changes positions and computation, but not the count of filter weights in this example.

Why the calculation works

  • A standard convolution filter covers a small spatial patch across all input channels. It multiplies corresponding values, adds them, and produces one response; reuse across positions makes the same learned detector available throughout the image.
  • The number of filters determines the output channels, while kernel size determines each local receptive patch. Moving by stride two skips more positions and reduces output size; padding inserts border values so filters can still cover edge locations.
  • State the padding convention before calculating. If padding means one added cell on each side, total added size is two. The lecture shape formula uses total padding, so silently inserting the per-side value would give the wrong result.
Try a moving 2×2 filter — additional illustrative example
Implementation steps and their purpose
  1. Write input height, width and channels
  2. Choose filter size and number of filters
  3. Choose padding and stride
  4. Slide filters across all input channels
  5. Add one bias per filter and apply activation

Use the result and check it

Data, components and application

  • Shrinking maps lose border detail → add padding → retain coverage
  • Excessive stride loses small features → reduce stride → preserve spatial detail
  • Too many filters → reduce channel counts → control capacity and cost

How to evaluate it

Check output dimensions and compare held-out recognition quality against computation and memory requirements.

C113

Pooling

Pooling summarizes a local patch without learning convolution weights. Max pooling keeps the largest activation; it reduces spatial dimensions and downstream computation while discarding some location detail.

What this tells us: If there are eight input channels, each is pooled separately: 4×4×8 becomes 2×2×8, so a subsequent flatten has 32 values instead of 128.

Calculate pooling output size

output side = floor((input side − window)/stride) + 1
floor
round down after division
window
pooling window side
stride
distance between window positions
  1. For4×4,window2,stride2: floor((4−2)/2)+1=2.
  2. Each2×2 patch yields6,8,3 or4.
  3. Lecture larger example: input61,window4,stride2 gives floor(57/2)+1=29.

Interpret the result: Pooling reduces spatial size, not channel count.

What information this representation preserves

  • Max pooling retains the strongest activation within each window independently for each channel. It does not compare channels or learn a new filter; the input feature detector already learned what a strong activation means.
  • Reducing spatial resolution lowers work in later layers and makes an exact small translation less influential. The cost is loss of location and fine-detail evidence, so pooling needs to match the smallest important object or defect.
  • Window and stride jointly determine the output. A two-by-two window with stride one overlaps; the same window with stride two does not. “Pooling halves the image” is only true for suitable settings and dimensions.
Implementation steps and their purpose
  1. Select pooling window and stride
  2. Move the window over each channel independently
  3. Keep the maximum for max pooling
  4. Calculate reduced height and width
  5. Preserve the number of channels

Prepare the data and validate the representation

Data, components and application

  • Fine detail disappears → use less pooling or smaller stride → retain small-object evidence
  • Large flattened tail persists → inspect final feature-map dimensions → pooling may not be sufficient alone

How to evaluate it

Compare validation quality and resource cost; inspect whether the smallest relevant object survives repeated downsampling.

Build the answer in this order

  1. Explain what information is retained
  2. Compute spatial output
  3. State channels unchanged
  4. Justify whether that detail loss is acceptable

C114

CNN dimensions and parameter counts

CNN shape calculations show how data moves between layers. Parameter counts show which layers dominate storage and fitting capacity; a large flattened Dense layer can outweigh all convolution layers.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Audit original versus revised Dense tail

Dense parameters = inputs × outputs + outputs
inputs
number of values entering the layer
outputs
number of output units; each has a bias
  1. Original:9408×256+256=2,408,704.
  2. Intermediate:256×128+128=32,896.
  3. Original output:128×918+918=118,422.
  4. Add convolution18,960: total2,578,982.
  5. Revised Dense64→Dense918 total=602,176+59,670+18,960=680,806.
  6. Reduction=(2,578,982−680,806)/2,578,982≈73.6%.

Interpret the result: The first Dense layer is about93.4% of the original parameters.

Find the expensive tail and redesign it

What this tells us: The first Dense layer contains about 93.4% of the original parameters. Reducing its width addresses the actual bottleneck while preserving early spatial feature extraction.

Why the calculation works

  • Calculate the data shape after every operation before counting parameters. Flatten multiplies height, width and channels; it rearranges values without learning weights, but can feed an expensive Dense layer.
  • A Dense layer connects every input to every output. A convolution learns one small shared parameter set per filter; spatial positions increase computation but do not multiply that filter’s stored weights.
  • Parameter count indicates storage and fitting capacity, not complete speed. Operations, feature-map sizes and hardware also matter. A lean redesign must preserve task quality, including rare classes, rather than merely produce a smaller number.
Implementation steps and their purpose
  1. Track height, width and channels after every layer
  2. For convolution use floor((input + twice padding − filter)/stride)+1 per spatial axis
  3. Count convolution weights as filter height × width × input channels × output channels, plus output-channel biases
  4. Flatten by multiplying final dimensions
  5. Count Dense weights as input units × output units, plus output biases

Use the result and check it

Data, components and application

  • Dense tail dominates → reduce hidden width → cut cost and capacity
  • Shape mismatch → recalculate each stage → ensure a valid architecture

How to evaluate it

Compare total parameters, inference cost and validation performance; parameter reduction alone does not prove better accuracy.

Build the answer in this order

  1. Locate the expensive layer
  2. Show the arithmetic
  3. Propose a smaller valid replacement
  4. Explain expected benefit and validation

C163

CNN application design

CNN design connects the image task, learned spatial features and a correctly sized output. The classifier should be no larger than justified by the data and operational constraints.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

What must the system deliver?

Use when a scenario asks for image-model architecture, activation, loss, data preparation and a lean redesign.

Scenario cueSuitable choiceWhy it fits
Owner wants a lean model with limited uneven training imagesReduce the expensive tail and use class-aware validationThis targets resource cost and capacity while separately exposing minority-class failures.

What each component receives and produces

  • A CNN architecture answer needs an input shape, a spatial feature extractor, a classifier and a label-compatible output. Choosing ReLU or softmax without explaining which stage and target it serves is incomplete.
  • Separate excessive fitting capacity from class imbalance. A smaller Dense tail can reduce overfitting risk and resource cost; class weighting, sampling and appropriate metrics address unequal label counts. Neither alone repairs missing representative classes.
  • Keep the original task clear. The sample requires918 exclusive brand–type–value combinations, so replacing the head with918 softmax outputs preserves it. A multi-head decomposition is another possible design only if labels and combination constraints are justified.
Implementation steps and their purpose
  1. Define image dimensions and required classes
  2. Resize and normalize consistently and split original images first
  3. Stack a small number of convolution/activation/pooling stages
  4. Track shapes and identify the expensive tail
  5. Choose a compact classifier with target-matched output
  6. Train with augmentation, regularization and validation monitoring

Specify a lean classifier without changing the task

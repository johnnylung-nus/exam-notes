Genetic algorithm representation and fitness

A genetic algorithm searches a population of encoded candidate solutions. Fitness expresses how good each decoded solution is for the actual objective and constraints.

What this tells us: The fitness transformation makes minimisation compatible with higher-is-better selection. The invalid chromosome illustrates why constraint handling precedes celebration of a small numeric cost.

Why the calculation works

  • A chromosome must encode one complete candidate solution. For a route, a city permutation represents visit order; for a binary selection, bits represent chosen items. This choice determines which crossover/mutation operations preserve valid candidates. A convenient string format is not enough if decoding creates impossible plans.
  • Fitness should reward the desired objective while handling constraints. If the problem minimises cost but roulette favours larger fitness, the raw distance cannot be used unchanged. Feasibility can be enforced by representation, repair or an explicit justified penalty; an invalid short route must not beat a valid complete tour.
  • Population search explores several candidates and recombines useful parts, but it does not guarantee improvement every generation or a global optimum. Track the best feasible solution separately, use a budget/stopping rule and compare repeated runs. Diversity is a resource: too little can trap the population, while too much random variation slows refinement.
Implementation steps and their purpose
  1. Define what one full solution contains.
  2. Choose chromosome encoding: bits, real values, integers or a permutation.
  3. Define objective, constraints and fitness direction.
  4. Initialise a diverse population and evaluate it.
  5. Select, recombine, mutate and replace repeatedly until a stopping rule.

Use the result and check it

Data, components and application

  • Fitness ignores constraint → enforce validity/penalty/repair → a high score may otherwise be unusable.
  • Poor encoding → choose meaningful representation → search operates on encoded solutions, not business intent.

How to evaluate it

Track best feasible objective, runtime and variability across runs; compare a simple baseline. No automatic global-optimum guarantee.

Build the answer in this order

  1. Define solution and encoding.
  2. Specify fitness/constraints.
  3. Explain generation loop.
  4. Set stop and evaluate.

GA selection operators

GA selection favours fitter candidates for reproduction while retaining some diversity. It decides who contributes genetic material, not how genes are changed.

What this tells us: Across these three draws each candidate was selected once, although probabilities differ. Expected tendency over many draws is not a guaranteed per-generation quota.

Why the calculation works

  • Roulette selection turns suitable fitness values into a probability distribution. A candidate gets an interval proportional to its fitness, and a random draw selects the interval it falls inside. A fitter individual has more chance, but a weaker one can still be chosen and a strong one can be sampled repeatedly.
  • Tournament selection instead samples participants and chooses the best among them; rank selection uses ordering rather than raw score gaps. These choices change selection pressure. Large score disparities under roulette can rapidly duplicate one candidate, while excessive pressure reduces diversity before better combinations have been explored.
  • Selection is not crossover or replacement. It chooses who contributes genetic material. After generating offspring, a separate replacement policy determines which old population members remain. Confusing these steps makes a trace impossible to check and can accidentally discard the best feasible solution.
Implementation steps and their purpose
  1. Evaluate every candidate’s fitness.
  2. Choose a method: roulette, tournament or rank selection.
  3. Roulette: divide suitable nonnegative fitness by total and form cumulative intervals.
  4. Draw/select parents according to the method.
  5. Then apply crossover, mutation and replacement.

Use the result and check it

Data, components and application

  • One candidate dominates → rank/tournament pressure tuning → diversity can collapse early.
  • Raw negative costs → transform or use a compatible selection method → roulette probabilities must be valid.

How to evaluate it

Check probabilities sum to one and random values map to the correct interval. Compare diversity, convergence and final feasible quality.

Build the answer in this order

  1. State fitness direction.
  2. Calculate selection weights.
  3. Show selected parents.
  4. Discuss pressure and diversity.

C057

GA crossover and mutation

Crossover recombines existing parent material; mutation randomly changes components to introduce/restore diversity. Both depend on the chromosome representation.

What this tells us: Crossover can create new combinations without creating a new allele; mutation directly changes a gene. Neither guarantees higher fitness, and an invalid child cannot be judged merely by its apparent score.

Interpret the result: Offspring01101011 and11100010; validity/fitness must be checked after changes.

What information this representation preserves

  • Crossover rearranges material already present in parents; mutation can introduce a value absent from the current population. Their roles differ even when both change the chromosome. Selection exploits existing fitness, crossover recombines useful patterns, and mutation counters loss of diversity.
  • Operators must match encoding. Splicing binary strings is straightforward, but splicing two route permutations can repeat a city and omit another. A permutation-aware operator or repair rule is therefore a necessary part of the design, not an optional cosmetic cleanup. The repaired result must be evaluated again.
  • Rates specify expected tendencies, not exact counts in a random generation. A per-bit mutation rate multiplies population size and chromosome length for expected bit changes; a per-chromosome rate means something else. Increasing mutation can restore diversity but eventually turns structured search toward randomness; high crossover can also disrupt useful combinations.
Implementation steps and their purpose
  1. Select parents first.
  2. Apply crossover if its probability test passes.
  3. Use single-point, multi-point or uniform crossover as specified.
  4. Apply mutation at the stated gene/chromosome level.
  5. Check validity, repair if required, evaluate and replace.

Prepare the data and validate the representation

Data, components and application

  • Permutation duplicates → permutation-safe crossover/repair → ordinary string splicing can invalidate routes.
  • Mutation too high → reduce rate → useful structure is lost; too low can lose diversity.

How to evaluate it

Check offspring validity, diversity and best feasible fitness over multiple runs. Improvement in one generation is not guaranteed.

Build the answer in this order

  1. Show parent encoding.
  2. Apply exact crossover/mutation.
  3. Check constraints.
  4. Explain parameter trade-off.

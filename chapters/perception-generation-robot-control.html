C160

Recognition, detection, and segmentation applications

Image classification says what is present; detection adds object locations, usually boxes; segmentation assigns pixel-level regions. Select the output resolution needed by the downstream action.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Choose from the scenario

Use for product sorting, surveillance or inspection where a single whole-image label may be insufficient.

Scenario cueSuitable choiceWhy it fits
Robot must grasp a particular object among severalProvide detection/segmentation plus relevant pose/location informationKnowing the object identity alone cannot determine where the gripper should move.

Judge localization rather than only the class label

Worked study example: Illustrative target mask contains100 pixels. Predicted mask contains120 pixels, with80 pixels overlapping the true target. Intersection-over-union measures overlap quality.

What this tells us: The overlap measure is an illustrative evaluation extension. A robot additionally needs coordinate mapping, obstacle information and motion/safety checks.

The distinction that changes the answer

  • Classification answers which category is present; detection adds where objects are; segmentation assigns individual pixels to regions. The required downstream action determines whether a label, bounding box or detailed mask is needed.
  • A whole-image class can be confused by several objects and cannot directly supply a grasp location. Detection separates targets spatially; segmentation can provide shape boundaries when a box includes too much background or overlapping material.
  • Training labels and evaluation must match the output. Pixel masks require different annotation from image labels, and a good image classifier does not establish tracking, localization or safe robotic success.

What would make the choice wrong?

Common wrong answers and the exact correction
  • A class probability does not provide a grasp location
  • Detection and segmentation require different labels.

Apply the distinction

Data, components and application

  • Background objects confuse a classifier → localize targets → separate their evidence
  • Occlusion or new lighting → collect representative cases → improve robustness
  • Detection errors propagate to control → evaluate end-to-end success → component accuracy can hide task failure

How to evaluate it

Use class errors for recognition, localization quality for boxes/masks, and real task success; account for latency.

Build the answer in this order

  1. State required output detail
  2. Explain why a label alone is insufficient
  3. Draw perception-to-action flow
  4. Evaluate errors at the right level

An answer you could write

  • “I use localization as well as recognition because the robot needs the target position, not just its class.”
  • “I measure localization quality and final correct-sort, safety and timing performance.”

C161

Generative models / GAN applications

A GAN learns a generator that creates samples and a discriminator that distinguishes generated from real samples. Their competing training can produce realistic synthetic data.

DiagramHow it worksWorked exampleChoose & designProblems & fixes

What must the system deliver?

Use for generation or augmentation when realistic sample variation is useful; generated appearance is not proof of label correctness or full data coverage.

Scenario cueSuitable choiceWhy it fits
Need additional plausible image variationConsider generative augmentation only with real-data validationUseful generated samples must preserve target identity and relevant operating variation.

What each component receives and produces

  • The discriminator learns to distinguish real and generated examples; the generator learns to make outputs the discriminator treats as real. Their objectives interact, so training is not simply minimizing ordinary supervised class error for one fixed target.
  • Realistic appearance and useful diversity are separate. A generator that repeats a few convincing examples can look successful while failing to cover the minority class’s important variation, especially when the real examples are extremely limited.
  • Synthetic augmentation needs label and physical validity checks. It is a training resource, not an independent real-world test population. A downstream model may exploit generator artifacts unless tested on untouched real cases.
Implementation steps and their purpose
  1. Define what should be generated and under which conditions
  2. Train a discriminator using real and generated examples
  3. Train the generator to make its outputs harder to distinguish
  4. Alternate updates
  5. Inspect realism and diversity
  6. Validate any downstream model using untouched real data

Detect synthetic quantity without coverage

Worked study example: Illustrative augmentation generator produces100 fault images, but80 are near-copies of one pattern and20 of a second. A classifier is evaluated on100 independent real faults.

All steps shown

Synthetic rows100Large row count alone

What this tells us: This illustrates why two original faults cannot justify claims that a generator has supplied broad fault coverage. Better synthetic appearance does not prove diagnostic validity.

Data, implementation and validation

Data, components and application

  • Mode collapse repeats similar examples → inspect diversity → sample count can exaggerate coverage
  • Synthetic artifacts become class shortcuts → test on real held-out data → avoid learning generator clues
  • Only two anomalies → collect real faults → generation cannot establish all missing fault types

How to evaluate it

Assess realism, diversity and actual task performance separately; never use synthetic-only testing as proof of real-world benefit.

Build the answer in this order

  1. Explain generator/discriminator roles
  2. State why generation is needed
  3. Identify artifact/coverage risks
  4. Propose real-data evaluation

Common wrong answers and the exact correction
  • GAN training differs from ordinary supervised class prediction
  • More synthetic samples do not guarantee more independent information.

An answer you could write

  • “The GAN’s generator and discriminator are trained competitively, but I separately inspect diversity and label validity.”
  • “I accept augmentation only if an untouched real test set improves, not because synthetic evaluation looks strong.”

C162

Deep-learning decision / control applications

A control system repeatedly observes the environment, chooses an action, receives feedback and acts again. Deep reinforcement learning uses a neural model to learn action choices from reward.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

What must the system deliver?

Use when actions change future states, such as moving, grasping and sorting objects under safety constraints.

Scenario cueSuitable choiceWhy it fits
Learn movement and grasp choices on a conveyorUse observe–policy–safety check–act–feedback architectureSequential actions alter the next state and require both learned choices and enforceable motion constraints.

What each component receives and produces

  • State summarizes information needed to choose an action: recognized object attributes, target/obstacle positions and motion, plus robot/gripper condition. A category label alone is insufficient for motion control.
  • Reward connects behavior to the true objective. Correct placement, collision avoidance and completion time must be considered together; otherwise a policy can earn a good numeric score through a shortcut the owner does not want.
  • Simulation permits exploratory failures without physical harm, but transfer must be tested under real sensing and dynamics. A separate motion/safety controller checks limits and collision risk rather than assuming the learned policy is intrinsically safe.
Implementation steps and their purpose
  1. Define state from perception and robot sensors
  2. Define available movement/grasp actions
  3. Define reward for correct completion, safety and efficiency
  4. Train primarily in simulation where appropriate
  5. Add motion/safety checks before execution
  6. Test transfer in a controlled physical setting

Make a reward trade-off explicit

Worked study example: Illustrative reward per completed attempt: +100 correct bin,−200 any collision,−1 per second. These weights demonstrate design reasoning; the sample does not prescribe exact numeric coefficients.

All steps shown
AttemptReward calculationResult
Safe correct placement in10s100−1090
Correct placement in5s with collision100−200−5−105
Wrong bin in8s without collision0−8−8
Safe correct placement in15s100−1585

What this tells us: The collision penalty prevents the faster but unsafe action from winning. A production design would also explicitly address unsafe termination, wrong placement and other reward loopholes.

Data, implementation and validation

Data, components and application

  • Reward favors speed at any cost → penalize collisions and wrong bins → align with all objectives
  • Dangerous exploration → simulation then controlled tests → reduce physical risk
  • Simulation mismatch → validate progressively → confirm learned behavior transfers

How to evaluate it

Measure correct-sort rate, collisions, completion time and performance under varied conditions; reward alone can hide an exploited shortcut.

Build the answer in this order

  1. Define state/action/reward
  2. Draw observe–decide–check–act–feedback
  3. Justify safety training
  4. Specify task-level evaluation

Where this is tested in the sample papers

ISY5002 Q2(b) — Deep-RL sorting architecture, reward and safe learning

What the question requires

  1. Define observations/state, actions and task success.
  2. Choose reward terms for correct sorting, safety and time.
  3. Draw hardware, perception, decision and control loops.
  4. Explain simulation-first training and controlled transfer.

Proposed answer points

  • RGB-D + robot sensors → identification/tracking → state → deep-RL policy → safety/motion checks → arm/gripper action → new observations and reward. Include target objects, obstacles, other robots and people in the environment.
  • Reward correct placement; penalize collisions and unnecessary time. Enforce joint/gripper constraints in control rather than hoping a learned reward guarantees safety.
  • Train in a physics-based simulator, then validate in controlled low-risk real tests with safety constraints active.

Avoid: A reward penalty is not a hard safety guarantee. Classification of the object and control of the robot are separate responsibilities.

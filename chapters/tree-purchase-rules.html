C146

Decision-tree splitting and information gain

A decision tree repeatedly chooses a feature test that makes child groups more class-pure. Information gain is parent uncertainty minus the size-weighted uncertainty remaining after a split.

How it worksWorked exampleChoose & designProblems & fixesExam answer

1. What problem does it solve?

Use for interpretable classification rules and for explaining why a particular feature is tested near the root.

Scenario cueSuitable choiceWhy it fits
Asked what customer characteristics favor purchaseTranslate the given root-to-leaf conditions into a joint ruleThe path describes the model’s conditional segment, not an isolated feature effect.

2. How it works — what happens and why

  • Entropy measures class uncertainty in a node. A balanced binary node has one bit; a pure node has zero. A useful split reduces the remaining weighted uncertainty, not simply the largest single child’s uncertainty.
  • Information gain compares parent entropy with the size-weighted sum of child entropies. Weighting matters because a tiny pure leaf should not outweigh a large mixed group merely by being perfectly pure.
  • A tree repeats local split choices to form rules. A root feature is important for that fitted tree’s partition, but other useful features can appear lower down or in an ensemble; tree position is not a causal claim.
Implementation steps and their purpose
  1. Start with all training cases at the root
  2. Calculate parent entropy from class proportions
  3. Consider categorical tests or numeric thresholds
  4. Calculate the size-weighted child entropies
  5. Select the largest information gain
  6. Repeat with stopping or pruning rules

4. Design the solution and check the result

Data, components and application

  • Many-value identifiers create pure tiny leaves → reject identifiers or use gain ratio/pruning → avoid memorization
  • Continuous features need thresholds → test candidate midpoints → choose a defensible split
  • Small leaves unstable → require minimum samples → improve generalization

How to evaluate it

Evaluate held-out class metrics and the usefulness of extracted rules, not only training purity.

7. Where this is tested in the sample papers

ISY5002 Q1(a) — Interpret a tree and connect it to business value

What the question requires

  1. Read the supplied branches for likely purchasers.
  2. Explain the action supported by that prediction.
  3. Identify a specific model/data weakness and proposed improvement.
  4. Test whether the change improves business outcome, not just training fit.

Proposed answer points

  • Test whether adding product-page engagement improves held-out prediction. Check feature availability at the intervention time, then assess incremental sales/profit with an appropriate controlled comparison.

Avoid: Do not assume every browser with high page activity will buy, or infer causal sales gains from offline accuracy alone.

C147

Gain ratio / Gini

Gain ratio adjusts information gain for the number and balance of branches. Gini impurity measures how mixed the class proportions are; a good split minimizes size-weighted child impurity.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when comparing tree split criteria or explaining why raw information gain can overvalue a many-valued feature.

Scenario cueSuitable choiceWhy it fits
A candidate feature has a unique value per customerDo not accept high information gain as proof of predictive valueIts apparent purity can be a lookup table that cannot route a previously unseen identity meaningfully.

2. How it works — what happens and why

  • Raw information gain can favor many-valued attributes because splitting into many tiny groups often produces pure training leaves. A unique ID can therefore look optimal while containing no reusable rule.
  • Gain ratio divides information gain by the entropy of the branch-size distribution, accounting for how the attribute partitions the observations. It reduces this branching bias but still needs sensible candidate restrictions and pruning.
  • Gini impurity is one minus the sum of squared class proportions. It uses no logarithm, but its split comparison still needs size-weighted children. Greater gain is good; lower remaining Gini is good, so do not reverse the selection direction.
Implementation steps and their purpose
  1. Calculate information gain for candidate attributes
  2. For gain ratio divide by the entropy of branch sizes
  3. For Gini calculate one minus the sum of squared class proportions
  4. Weight child impurities by sample counts
  5. Choose the best valid split under the chosen criterion

4. Design the solution and check the result

Data, components and application

  • Unique ID gets high information gain → remove ID or penalize branching → prevent a lookup table
  • A small unbalanced split looks attractive → enforce minimum leaf size → avoid unstable decisions

How to evaluate it

Compare pruned trees on held-out metrics; split purity alone is only a local training criterion.

Build the answer in this order

  1. Identify bias in the proposed criterion
  2. Explain the alternative in words
  3. Show impurity calculation if asked

  • Gain ratio does not eliminate every overfitting risk.

C148

Tree pruning

Pruning reduces a tree’s complexity so it captures repeatable structure rather than tiny training-specific exceptions. Pre-pruning stops growth; postpruning removes branches after a larger tree is grown.

How it worksWorked exampleChoose & designProblems & fixes

1. What problem does it solve?

Use when training performance is high but validation quality drops, or the tree contains many poorly supported leaves.

Scenario cueSuitable choiceWhy it fits
Many small leaves and a widening train–validation gapCompare minimum-leaf/depth limits or postpruned candidatesThese directly reduce unsupported decision exceptions rather than changing the target objective.

2. How it works — what happens and why

  • Growing a tree repeatedly partitions training data until leaves can represent tiny exceptions. These exceptions may be real noise rather than stable structure; training purity therefore keeps improving after validation quality has peaked.
  • Pre-pruning prevents weak or poorly supported splits using depth, leaf-size or improvement constraints. Postpruning starts with a larger fitted tree and removes branches, selecting among candidates on validation evidence.
  • Pruning can alter both missed positives and false alarms. A smaller tree is preferable only when its error trade-off and simplicity suit the task; aggressive pruning can erase a real minority pattern.
Implementation steps and their purpose
  1. Inspect training and validation errors
  2. Limit depth, require minimum leaf samples or demand useful split improvement
  3. Alternatively grow a tree then form simpler pruned candidates
  4. Compare candidates using validation data
  5. Keep the simplest tree with adequate task performance

3. Choose a pruned tree using error costs

Worked study example: Illustrative purchase validation set and costs: missed purchaser10 units, false coupon1 unit. Compare three fitted tree candidates with the same held-out cases.

What this tells us: Moderate pruning removes unstable distinctions without losing too much purchase signal. Heavy pruning reduces false alarms but misses too many valuable purchasers.

4. Design the solution and check the result

Data, components and application

  • Tree too complex → increase leaf size or prune → reduce variance
  • Tree too shallow misses clear patterns → relax limits cautiously → reduce underfitting
  • Choose pruning from test data → use validation instead → keep the final estimate independent

How to evaluate it

Compare recall, precision and business value before and after pruning; report the trade-off rather than assuming every smaller tree is better.

Build the answer in this order

  1. Identify overfitting evidence
  2. Distinguish pre- and postpruning
  3. State the selection data
  4. Explain the resulting business consequences

5. Diagnose the proposed model — change and justify

  • Pruning may change both missed positives and false alarms
  • Perfect training classification is not the objective.

6. Turn understanding into an exam answer

  • “Moderate pruning has expected validation cost210, below280 for the full tree and340 for heavy pruning.”
  • “I choose the validated trade-off, not the smallest tree or the perfect training fit.”

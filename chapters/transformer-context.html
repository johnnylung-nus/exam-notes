Transformer / positional encoding

A transformer represents tokens using attention rather than recurrence. Positional encoding adds information about token order, because content-only self-attention does not by itself specify sequence positions.

Worked study example: Illustrative target sequence is “I like tea”. Train next-token prediction using shifted targets, and apply a causal visibility mask.

What this tells us: The current target token must not be offered as its own answer. Position information and causal masking solve different problems: order representation versus future leakage.

What information this representation preserves

  • Self-attention compares token content, but without added position information it does not intrinsically know which token came first. Positional encoding attaches order information to token representations before attention combines their context.
  • An encoder can attend over the available input sequence. A causal decoder must prevent each prediction position from attending to future target tokens; otherwise training receives information unavailable during generation.
  • A translation-style decoder can additionally attend to encoder outputs through cross-attention. That does not mean every transformer has both an encoder and a decoder: choose the structure required by the task rather than copying every block.
Implementation steps and their purpose
  1. Convert tokens to vectors
  2. Add position information
  3. Apply attention and feedforward blocks
  4. Choose an encoder, decoder or combined structure for the task
  5. Mask future positions for causal prediction
  6. Attach a suitable output and train

Prepare the data and validate the representation

Data, components and application

  • Future tokens visible during next-token training → apply causal mask → prevent cheating
  • Missing positions → add positional encoding → preserve order-sensitive meaning
  • Long inputs cost memory → control sequence length → attention comparisons grow rapidly

How to evaluate it

Evaluate on held-out task data with the same masking and prediction-time information constraints.

Self-attention and multi-head attention

Self-attention lets each token combine information from other tokens in the same sequence. Multiple heads learn separate comparisons, allowing several relationship patterns to be represented together.

Turn attention scores into contextual evidence

Worked study example: Illustrative query scores for two allowed tokens are 0 and ln(3), after any scaling. Their scalar values are 2 and 10. Natural exponentiation is used in softmax.

Read the relationships and follow the choices

  • Queries represent what a token seeks; keys represent how other tokens can be matched; values contain the information to combine. These are learned projections of token representations, not independent raw measurements.
  • Comparing a query with available keys creates scores. Scaling controls score magnitude, masking removes forbidden positions, and softmax turns scores into nonnegative weights that sum to one. The resulting output is a weighted sum of values.
  • Several heads use different learned projections, enabling different relationships to be represented at once. A head is not assigned a guaranteed human meaning; useful context relationships emerge only if training supports them.
Implementation steps and their purpose
  1. Create query, key and value representations from token vectors
  2. Compare each query with available keys
  3. Scale scores and turn them into normalized weights
  4. Form a weighted combination of value vectors
  5. Repeat with different learned projections in several heads
  6. Combine head outputs

Choose the method from the problem

Useful when the meaning of one token depends on context elsewhere in the input, including distant context.

Scenario cueSuitable choiceWhy it fits

Common wrong answers and the exact correction

Implement it and test the outcome

Data, components and application

  • Unwanted future information → apply a mask before normalization → respect prediction order
  • One relation insufficient → multiple heads → learn different comparisons
  • Expensive long sequences → constrain length → manage memory

How to evaluate it

Judge downstream prediction quality, cost and generalization; attention pictures alone do not prove causal explanations.

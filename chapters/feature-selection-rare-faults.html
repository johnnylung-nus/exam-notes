C149

Curse of dimensionality

As feature count grows, data becomes sparse in the expanded space. More observations are needed to cover it, and distances can become less discriminative, hurting generalization and neighbor-based methods.

What information this representation preserves

  • Adding dimensions expands the space the observations must cover. With a fixed sample, neighborhoods contain less local evidence, and irrelevant features can make distances reflect noise rather than target-relevant similarity.
  • A feature count that is manageable for thousands of normal cases can still be unsupported for two abnormal cases. The rare class’s independent coverage matters; aggregate sample size conceals this asymmetry.
  • Feature selection retains original variables; PCA combines correlated variables; a smaller model restricts fitting capacity. Each targets a different source of difficulty, and none creates examples of fault mechanisms not observed in training.
Implementation steps and their purpose
  1. Compare useful sample count with feature count and model capacity
  2. Inspect irrelevant, repeated or noisy features
  3. Select a smaller meaningful feature subset
  4. Consider PCA when correlated numeric features can be compressed
  5. Validate the complete reduction-plus-model pipeline

Prepare the data and validate the representation

Data, components and application

  • Many weak dimensions → remove or combine features → improve sample efficiency
  • Two anomalies reused repeatedly → collect varied anomalies → do not mistake duplication for coverage
  • Distance dominated by noise → scale and select relevant features → restore useful similarity

How to evaluate it

Compare held-out rare-case recall, false-alarm rate and model stability across splits; acknowledge large uncertainty with few faults.

Build the answer in this order

  1. Explain why available cases do not cover the space
  2. Identify an appropriate reduction
  3. Preserve prediction-relevant information
  4. Evaluate without leakage

C150

Filter / wrapper / embedded feature selection

Feature selection keeps some original variables. Filters use statistics, wrappers test feature subsets with a model, and embedded methods obtain selection or importance from the model fitting process.

DiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Choose from the scenario

Use to remove irrelevant or redundant inputs, reduce cost and improve generalization while retaining original-feature meaning.

Scenario cueSuitable choiceWhy it fits
Question gives changed importance between a tree and AdaBoostPropose removing weak candidates then retrainingThe exam needs a testable improvement flow, not an assumption that ranking automatically supplies the best subset.

What this tells us: Reduced false positives alone cannot justify the top-two model if it misses many more purchasers. Select using the stated objective and input collection cost.

The distinction that changes the answer

  • Filter selection uses a statistical property such as variance, correlation or target association without fitting every candidate model subset. It is fast but can miss a feature useful only through interaction.
  • Wrappers repeatedly train and validate the chosen model on candidate subsets. They account for that model’s behavior but can be expensive and can overfit the validation search if unchecked.
  • Embedded/model-based approaches obtain coefficients or importance during fitting. A low-importance feature is a candidate for removal, not proof it is useless; correlated substitutes and changing model regions can alter rankings. Keep the selection process inside training folds.

What would make the choice wrong?

What you observeWhy it happensWhat to changeWhy that helps
Selection performs well only when using the whole datasetValidation labels influenced the feature choicesRun selection inside each training foldOtherwise the model-building process has already seen the validation outcome through the selected inputs.
Common wrong answers and the exact correction
  • PCA creates new combined features, so it is feature extraction
  • L2 shrinkage does not inherently set coefficients to zero.

Apply the distinction

Data, components and application

  • Univariate filter misses feature combinations → validate model-based subsets → interactions may matter
  • Wrapper search expensive → restrict candidates → control runtime
  • Importance biased or unstable → check held-out removal impact → avoid treating rankings as truth

How to evaluate it

Accept reduction when the relevant metric is preserved or improved and operational complexity falls.

Build the answer in this order

  1. Identify redundant or costly features
  2. Name a selection family
  3. Explain its criterion
  4. Retrain and compare fairly

An answer you could write

  • “I remove four low-importance inputs using training evidence, retrain AdaBoost and compare on the same validation cases.”
  • “I retain the reduction only if purchaser recall and business value are maintained or improved.”

C151

Forward / backward / recursive feature selection

Forward selection adds features; backward selection removes features by testing the resulting subset performance; recursive feature elimination repeatedly removes the least important features according to a fitted estimator.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixes

Trace forward selection rather than list feature names

Worked study example: Illustrative candidate purchase inputs are duration D,product count P and bounce rate B. Scores below are cross-validated recall from models trained on each stated subset.

What this tells us: The best single feature is not necessarily the complete best subset. Refitting after changes allows the model to adapt its weights or splits to what remains.

What information this representation preserves

  • Forward selection asks which single addition best improves the current subset; it does not choose the next feature from an unchanging initial ranking. Two weak standalone features can still interact, which a greedy start may miss.
  • Backward selection tests candidate removals from the current full subset. RFE instead ranks features using the fitted estimator and removes low-ranked ones, refitting afterward because importance can change.
  • Subset size is a development choice. A tiny improvement may not justify more inputs, acquisition cost or instability. Use cross-validated task performance and avoid reporting the searched-on validation score as an unbiased final estimate.
Implementation steps and their purpose
  1. Define a cross-validated task metric
  2. For forward selection start empty and test each possible addition
  3. For backward selection start full and test each possible removal
  4. For RFE fit the estimator and remove lowest-ranked features
  5. Refit after each change
  6. Stop at a validated subset size

Prepare the data and validate the representation

Data, components and application

  • Greedy decisions miss the best combination → acknowledge search limits → do not claim a global optimum
  • Selection uses all data → place it inside folds → prevent optimistic results
  • Correlated features swap importance → inspect stability → avoid overinterpreting one retained variable

How to evaluate it

Compare selected subsets using the same metric and splitting rules, and measure reduced data-collection or inference cost.

Build the answer in this order

  1. Choose addition/removal direction
  2. State how each candidate is scored
  3. Explain stopping
  4. Validate the final pipeline

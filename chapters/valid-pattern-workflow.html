C134

Pattern recognition workflow

Pattern recognition turns observed data into a useful decision through acquisition, preparation, features, modeling and evaluation. Start from the decision required, not a fashionable algorithm.

DiagramHow it worksWorked exampleChoose & designProblems & fixes

Trace a purchase-prediction case through the pipeline

Worked study example: Illustrative goal is to issue a coupon after the first three browsing events, before any checkout. One completed session later ends in a purchase.

All steps shown
StageConcrete choiceCheck
Decision pointAfter events 1–3Events 4 onward unavailable
Valid featuresProduct page count and duration from first three eventsNo final-session total
TargetPurchased after that point: yes/noOutcome becomes label, not input
BaselineSmall tree on prefix aggregatesInterpretable purchase rules
AlternativeLSTM on the same prefix eventsTests useful order information
EvaluationHeld-out users and expected coupon valueFair inputs and business costs

What this tells us: Both candidate models must receive the same prediction-time information. Otherwise apparent model improvement may be a data-access advantage or leakage.

What information this representation preserves

  • Start with a decision and its time: recommending a coupon before checkout is different from explaining completed purchases afterward. This determines which labels and input events are legitimate.
  • Data acquisition, cleaning, feature construction, model fitting and evaluation form one pipeline. A good classifier cannot repair a target leaked during feature construction, and an impressive metric can still miss the business objective.
  • Every proposed improvement needs a mechanism: identify the observed problem, change the relevant stage, explain why that change targets the problem, then compare under the same realistic evaluation. Merely naming a more advanced model is not an explanation.
Implementation steps and their purpose
  1. Define the decision, target and prediction time
  2. Collect representative inputs and reliable labels
  3. Clean, encode and scale data as needed
  4. Select or extract relevant features
  5. Fit a suitable baseline and model
  6. Evaluate unseen cases and operational usefulness

Prepare the data and validate the representation

Data, components and application

  • Target or future information enters inputs → exclude it before preparation → prevent leakage
  • Training data misses operating conditions → collect representative cases → enable realistic generalization
  • Unclear business objective → define error costs → select the right metric

How to evaluate it

Evaluate technical metrics and business consequences together; improvements must help the actual decision.

Build the answer in this order

  1. State objective and available data
  2. Propose the complete input-to-output flow
  3. Identify the main failure risk
  4. Justify remedies and validation

Use as the overall flow for any scenario involving purchase, fault, image or sequence prediction.

C135

Supervised / unsupervised / reinforcement learning

Supervised learning uses input–target examples; unsupervised learning discovers structure without target labels; reinforcement learning learns actions from rewards received through interaction.

DiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Choose from the scenario

Select the learning setup from the available feedback and required output.

Scenario cueSuitable choiceWhy it fits
A robot must learn actions with delayed outcomesSpecify state, action and reward rather than only class labelsThe action changes the next state, so a sequence of decisions determines success.

Choose from what is observed and required

Worked study example: Illustrative tasks use superficially similar sensor/customer data but different feedback. Do not choose the setup solely from the data format.

All steps shown
TaskAvailable feedbackAppropriate learning goal
Purchase from browsing historyEach session has later purchase/no-purchase labelSupervised sequence classification
Discover customer segmentsBehavior features but no known segment labelsUnsupervised clustering
Robot grasp and sortingActions alter state; reward follows success/safety/timeReinforcement learning
Rare fault screening3000 normal and only 2 abnormal sequencesConsider normal-pattern anomaly screening plus fault collection

What this tells us: The last choice addresses missing anomaly coverage; it does not turn two known faults into reliable evidence about all abnormal situations.

The distinction that changes the answer

  • The type of feedback determines the learning setup. Supervised cases have target labels; unsupervised cases supply inputs but no correct category; reinforcement learning supplies consequences of actions taken through time.
  • Sequence inputs do not automatically imply reinforcement learning. Purchase prediction from a labeled browsing sequence is supervised; robot actions that change subsequent observations and reward create a control problem.
  • Scarce fault labels can make a two-class model poorly supported even with abundant normal data. A normal-pattern anomaly model asks whether an observation differs from learned normal behavior; it does not automatically identify every fault cause.

What would make the choice wrong?

What you observeWhy it happensWhat to changeWhy that helps
Clustering results are reported as established fault labelsUnlabeled similarity groups were treated as supervised classesProfile and validate groups or obtain fault labelsSimilar observations may share an operating condition without sharing a diagnosis.
Common wrong answers and the exact correction
  • Reward is not the same as a correct class label
  • Unsupervised learning does not provide known class meanings automatically.

Apply the distinction

Data, components and application

  • Only two abnormal examples → supervised fault coverage is unreliable → consider normal-pattern anomaly modeling while collecting more anomalies
  • A sequence exists but actions do not change outcomes → supervised sequence prediction may suffice → sequence data alone does not imply reinforcement learning

How to evaluate it

Use held-out prediction error for supervised learning, meaningful stable groups for clustering, and cumulative reward plus safety/task success for control.

Build the answer in this order

  1. State what feedback exists
  2. Classify the learning type
  3. Match model to output
  4. Explain how success is measured

An answer you could write

  • “Purchase prediction is supervised because every session has an outcome label, even though its inputs form a sequence.”
  • “Robot control is reinforcement learning because actions change future states and are judged by cumulative task, safety and time consequences.”

Where this is tested in the sample papers

ISY5002 Q2(b) — Deep-RL sorting architecture, reward and safe learning

What the question requires

  1. Define observations/state, actions and task success.
  2. Choose reward terms for correct sorting, safety and time.
  3. Draw hardware, perception, decision and control loops.
  4. Explain simulation-first training and controlled transfer.

Proposed answer points

  • RGB-D + robot sensors → identification/tracking → state → deep-RL policy → safety/motion checks → arm/gripper action → new observations and reward. Include target objects, obstacles, other robots and people in the environment.
  • Reward correct placement; penalize collisions and unnecessary time. Enforce joint/gripper constraints in control rather than hoping a learned reward guarantees safety.
  • Train in a physics-based simulator, then validate in controlled low-risk real tests with safety constraints active.

Avoid: A reward penalty is not a hard safety guarantee. Classification of the object and control of the robot are separate responsibilities.

C136

Normalization and preprocessing

Preprocessing makes data usable without changing what the prediction means. Cleaning handles missing, noisy or inconsistent values; encoding represents categories; scaling makes numeric magnitudes comparable.

CalculationDiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Worked study example: Illustrative training duration values have mean 20 and standard deviation 5. A wavelet energy feature has mean 100 and standard deviation 20. Use those fitted statistics for a new sequence.

New unseen categoryNot present in training vocabularyUse defined unknown handling, not an arbitrary ordered code

What this tells us: Before scaling, energy’s raw magnitude is much larger; afterward these values reflect deviations relative to each feature’s training variation.

  1. Duration30s,training mean20s,SD5s givesz=2.
  2. Energy120,training mean100,SD20 givesz=1.
  3. Missing duration is not the same as a true zero;fit an explicit missing-value rule.

Interpret the result: Comparable numeric scale does not guarantee useful diagnostic content.

What information this representation preserves

  • Preparation must preserve meaning: missing duration is not a real zero-duration visit, and an extreme vibration value may be the fault to detect rather than removable noise. Cleaning requires the task context.
  • Fit transformation parameters only on training records. Imputation values, category vocabularies, scaling means and PCA directions all carry information from the data used to fit them, even without using labels explicitly.
  • For concatenated features, different scales can dominate distances or gradient updates. Histogram counts and wavelet statistics may need different preparation before concatenation; scaling does not make unsuitable features informative.
Implementation steps and their purpose
  1. Split data before fitting preparation steps
  2. Inspect missing values, outliers and invalid records
  3. Fit imputation and category encoding on training data
  4. Fit min–max scaling or standardization where useful
  5. Apply the same fitted transformations to validation, test and future data

Prepare the data and validate the representation

Data, components and application

  • Missing value is coded zero → distinguish missingness from a real zero → avoid false evidence
  • Huge scale differences → standardize → prevent domination of distances
  • Outliers may be real faults → investigate before removal → do not delete the target phenomenon

How to evaluate it

Check prepared ranges, missingness by class and held-out model quality; preprocessing should improve validity, not merely make training easier.

Build the answer in this order

  1. Identify the data defect
  2. Specify the transformation
  3. Explain the training-only fitting rule
  4. Show why it helps the chosen model

Choose the representation from the task

Especially important for distance models, neural networks and PCA, or when multiple sources have incompatible units.

An answer you could write

  • “I fit missing-value and scaling rules on training sequences, then apply them unchanged to validation and test.”
  • “I retain genuine abnormal sensor values and distinguish missing measurements from zero readings.”

C137

Data splits and cross-validation

Training data fits model parameters; validation data guides choices; test data estimates final generalization. Cross-validation rotates the validation fold to obtain a less split-dependent development estimate.

DiagramHow it worksWorked exampleChoose & designProblems & fixes

Construct a leakage-safe sequence comparison

Worked study example: Illustrative five users A–E each have many sessions. We want performance on entirely new users, so keep each user’s sessions together.

All steps shown
StageData roleAllowed operations
Training foldUsers A,B,CFit scaler, feature selector and candidate model
Validation foldUser DTransform with training rules; compare settings
Final testUser EAssess selected pipeline after development
Invalid alternativeSome A sessions in training and other A sessions in validationMay reward user memorization
LSTM stacking featureOut-of-fold scores on training usersGenerating model must not have trained on scored cases

What this tells us: If the operational target is future sessions of existing users, a time-based design may be more appropriate; state the intended claim explicitly.

What information this representation preserves

  • A split should represent what new means: new users, future time periods or new physical units. Randomly splitting correlated fragments from the same case can make validation look independent when the model has effectively seen that case.
  • All fitted preparation and selection must occur inside each fold. Scaling, feature removal or PCA performed before cross-validation lets the validation partition influence the model-building process.
  • Cross-validation gives repeated development comparisons; the final untouched test estimates the selected pipeline. Repeatedly choosing the best method from test results converts that test into another development set.
Implementation steps and their purpose
  1. Choose a split matching the deployment unit and time order
  2. Keep a final test set untouched
  3. Fit preprocessing on each training partition
  4. Train and score each validation fold
  5. Choose settings using validation results
  6. Refit the selected pipeline and assess the final test once

Prepare the data and validate the representation

Data, components and application

  • Duplicates or related sessions cross partitions → group split → avoid memorization leakage
  • Future data predicts past → chronological split → match deployment
  • Feature selection uses all labels → move selection inside folds → keep validation honest

How to evaluate it

Report mean and spread across folds plus final test metrics, especially rare-class performance.

Build the answer in this order

  1. Define unseen-case meaning
  2. State split method
  3. Explain what is fit on training only
  4. Describe fair model comparison

Choose the representation from the task

Use whenever comparing models, selecting features or tuning settings without contaminating the final assessment.

Scenario cueSuitable choiceWhy it fits
Two abnormal sequences are the only fault evidenceReport uncertainty and prioritize more fault dataNo clever split creates a reliable estimate of broad abnormal performance from only two independent cases.

Information loss, noise and failure cases

What you observeWhy it happensWhat to changeWhy that helps
Validation is excellent but new-user performance collapsesRelated sessions crossed the splitGroup by user before any fittingThe evaluation then measures transfer to unseen users rather than recall of familiar behavior.
Common wrong answers and the exact correction
  • Repeatedly choosing from test scores turns the test into validation
  • Random splits are inappropriate for some temporal tasks.

An answer you could write

  • “I group sessions by user before fitting any preprocessing because the target is new-user generalization.”
  • “I tune using validation users and retain the final test users for the selected pipeline only.”

C141

Hyperparameter tuning and generalization

Hyperparameters are choices made outside ordinary weight fitting, such as tree depth, neighbor count, learning rate or dropout rate. Generalization is success on new cases, not fitting training examples perfectly.

Interpret the result: A perfect training fit can be a worse exam-scenario model.

Read the relationships and follow the choices

  • Hyperparameters set model-building behavior rather than being ordinary fitted coefficients: tree depth, neighbor count, learning rate and dropout rate are examples. Their quality is measured by validation of the complete fitted pipeline.
  • Compare training and validation together. Both poor suggests underfitting or weak features; training excellent and validation poor suggests overfitting or split mismatch. The observed pattern should determine the remedy.
  • An extensive search can overfit validation by repeatedly choosing lucky scores. Restrict the search to plausible settings, compare variation across folds and keep a final untouched assessment rather than indefinitely chasing tiny gains.
Implementation steps and their purpose
  1. Set a simple baseline and relevant validation metric
  2. Choose a small justified search space
  3. Fit complete pipelines inside each training fold
  4. Compare validation results using grid or random search
  5. Prefer a simpler model when performance is comparable
  6. Evaluate the selected pipeline on the final test

Choose the method from the problem

Use to choose complexity and training settings while controlling overfitting.

Scenario cueSuitable choiceWhy it fits
Both training and validation recall are lowInvestigate missing signal or insufficient model capacityMore regularization would likely restrict the model further rather than fix the lack of learned structure.

Common wrong answers and the exact correction
  • Learned weights differ from hyperparameters
  • Lower training loss is not the selection rule.

Implement it and test the outcome

Data, components and application

  • Too many searches overfit validation → reduce speculative searching or use nested validation → get a more honest estimate
  • Both training and validation poor → improve features or capacity → address underfitting
  • Large train–validation gap → regularize or simplify → address overfitting

How to evaluate it

Track validation mean/spread, final target metrics and runtime; keep the final test out of selection.

Build the answer in this order

  1. Diagnose underfit versus overfit
  2. Name the actual adjustable setting
  3. Explain the validation procedure
  4. State the expected trade-off

An answer you could write

  • “Depth4 gives the best validation recall at0.82, whereas unlimited depth overfits despite perfect training recall.”
  • “I select settings through validation and use the final test only after selection.”

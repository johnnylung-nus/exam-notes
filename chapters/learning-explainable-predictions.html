C027

Inductive learning and generalization

Generalisation means learned patterns also work on unseen cases. Matching every training observation can simply mean memorisation.

What this tells us: The perfect training score is not the success criterion. The larger train–validation gap indicates the deep model has learned details that fail to transfer under this evaluation setting.

Read the relationships and follow the choices

  • Generalisation is about the prediction setting, not simply a random percentage split. If the future task concerns new patients, repeated consultations from the same patient can make a row-random split optimistic. If the task predicts later behaviour, training must not use events that happened after the prediction point.
  • Preprocessing is part of the fitted system. Imputation, scaling, feature selection and vocabulary learning must be fitted on permitted training data, then applied unchanged to validation/test examples. Otherwise the model has indirectly seen information from the data used to judge it.
  • Validation is used to choose settings; test data estimate performance after these choices. Reusing the test set to repeatedly select depth, factors or features turns it into another validation set. Metrics also depend on error costs: a higher overall accuracy can hide unacceptable misses in an important class.
Implementation steps and their purpose
  1. Define the real future cases and desired target.
  2. Split data before fitting preprocessing or selecting models.
  3. Fit only training examples.
  4. Tune complexity with validation or cross-validation.
  5. Use a final untouched test set and inspect relevant errors.

Choose the method from the problem

Use when evaluating a proposed learned model, comparing complexity or explaining why training accuracy alone is insufficient.

Common wrong answers and the exact correction

  • Good average results can hide failures in important groups.

Implement it and test the outcome

Data, components and application

  • Patient/time leakage → group patients or respect time where required → repeated/future information inflates results.
  • Unrepresentative data → assess relevant subgroups and shifts → random splits do not fix missing populations.

How to evaluate it

Compare training and validation performance, then final test results. Choose metrics by the cost of mistakes, not accuracy alone.

Build the answer in this order

  1. Define unseen setting.
  2. Check split/leakage.
  3. Compare fit and generalisation.
  4. Justify complexity and metric.

An answer you could write

  • The moderate tree’s validation accuracy86% exceeds the deep tree’s75%, despite the deep tree fitting training data perfectly.
  • I choose using validation, fit preprocessing on training only and reserve the final test; patient-group or time splits must reflect the real prediction setting.

C028

Decision-tree reasoning

A decision tree learns feature tests from labelled data. Prediction follows one branch per test to a leaf containing a class or numeric output.

DiagramHow it worksWorked exampleChoose & designProblems & fixesExam answer

Illustrative tree training versus prediction

Worked study example: Toy classification tree predicts delivery delay. Historical labels are known only during training; thresholds below are invented.

All steps shown
CaseFeature valuesPathOutput
New parcel ADistance=8; backlog=highDistance>5, then backlog highDelay
New parcel BDistance=8; backlog=lowDistance>5, then backlog lowOn time
New parcel CDistance=2Distance≤5On time
Historical training rowSame features plus actual outcomeUsed to select splitsOutcome is label, not input

What this tells us: The explanation for A names its two tested conditions. If the system had used the actual future delivery outcome as a feature, the apparent training success would be leakage, not useful learning.

What information this representation preserves

  • A decision tree converts feature tests into a path to an output. During training, splits are selected from labelled examples; during prediction, the learned thresholds/categories are fixed and a new case follows one branch at each node. Training and traversal are different computations.
  • A root-to-leaf path can be explained as an AND of its branch conditions. This is why a tree can act like learned rules, but the conditions were induced statistically rather than necessarily supplied by experts. A leaf’s label distribution is empirical support, not automatically a calibrated clinical probability.
  • A deep tree can isolate individual training records and noise. Restricting depth, requiring larger leaves or pruning removes fragile distinctions. A forest trains multiple trees and aggregates their outputs: a node split is not a separate tree, and adding new database records does not itself retrain existing trees.
Implementation steps and their purpose
  1. Specify input features and training labels.
  2. Clean/encode features without leaking the label.
  3. Learn splits separating useful outcomes.
  4. Limit depth/prune or tune minimum leaf size.
  5. For a new case, follow tests and explain its path.

Prepare the data and validate the representation

Data, components and application

  • Very deep tree → pruning/validation → small leaves may memorise noise.
  • Missing/unavailable input → define handling or ask for information → prediction cannot rely on future outcomes.

How to evaluate it

Use held-out classification/regression checks appropriate to the target; inspect errors and tree complexity. For an ensemble, combine tree outputs explicitly.

Build the answer in this order

  1. Define example, inputs and label.
  2. Explain learning splits.
  3. Trace inference.
  4. Describe validation and overfitting control.

Choose the representation from the task

Useful when prediction needs interpretable conditions; different from a KG, which represents entity relationships.

An answer you could write

  • Parcel A follows distance>5 and high backlog to the delay leaf, while parcel B follows the same first branch but low backlog to on-time.
  • Historical outcome is the label used to learn these tests, not a prediction-time feature; I prune or limit depth and evaluate unseen parcels.

Where this is tested in the sample papers

ISY5001 Q3(a)(i) — Model choice against a ranked-output requirement

What the question requires

  1. Underline “least suitable”.
  2. Identify the required ranked list of diagnoses.
  3. Compare the proposed methods under stated assumptions.

Proposed answer points

  • Under a basic hard-label single-tree interpretation, a single tree is the intended weak choice because the required output is a ranked differential list.
  • A single tree can in fact rank classes by leaf class proportions; explain the assumed implementation rather than asserting an inherent impossibility.

Avoid: Choosing a suitable model does not answer which is least suitable. There is no official key confirming a unique implementation assumption.

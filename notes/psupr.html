C134

Pattern recognition workflow

Pattern recognition turns observed data into a useful decision through acquisition, preparation, features, modeling and evaluation. Start from the decision required, not a fashionable algorithm.

Problem it solves: Use as the overall flow for any scenario involving purchase, fault, image or sequence prediction.

How to use it

  1. Define the decision, target and prediction time
  2. Collect representative inputs and reliable labels
  3. Clean, encode and scale data as needed
  4. Select or extract relevant features
  5. Fit a suitable baseline and model
  6. Evaluate unseen cases and operational usefulness
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: predict purchase before checkout using only earlier session activity. Page counts may suit a tree; ordered page events may justify LSTM.

What can go wrong → what to change → why

  • Target or future information enters inputs → exclude it before preparation → prevent leakage
  • Training data misses operating conditions → collect representative cases → enable realistic generalization
  • Unclear business objective → define error costs → select the right metric

How to evaluate

Evaluate technical metrics and business consequences together; improvements must help the actual decision.

Answer flow

  1. State objective and available data
  2. Propose the complete input-to-output flow
  3. Identify the main failure risk
  4. Justify remedies and validation

Exam traps

  • A complex model cannot repair an invalid prediction-time definition
  • Data preparation is part of the fitted pipeline.

C135

Supervised / unsupervised / reinforcement learning

Supervised learning uses input–target examples; unsupervised learning discovers structure without target labels; reinforcement learning learns actions from rewards received through interaction.

Problem it solves: Select the learning setup from the available feedback and required output.

How to use it

  1. Identify whether labels, unlabeled observations or action rewards are available
  2. Decide whether the goal is prediction, grouping or sequential action
  3. Define the training case and feedback
  4. Choose a compatible model
  5. Design evaluation around the real objective
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: labeled purchase/no-purchase sessions are supervised; customer groups without labels are unsupervised; robot picking actions rewarded for correct sorting are reinforcement learning.

What can go wrong → what to change → why

  • Only two abnormal examples → supervised fault coverage is unreliable → consider normal-pattern anomaly modeling while collecting more anomalies
  • A sequence exists but actions do not change outcomes → supervised sequence prediction may suffice → sequence data alone does not imply reinforcement learning

How to evaluate

Use held-out prediction error for supervised learning, meaningful stable groups for clustering, and cumulative reward plus safety/task success for control.

Answer flow

  1. State what feedback exists
  2. Classify the learning type
  3. Match model to output
  4. Explain how success is measured

Exam traps

  • Reward is not the same as a correct class label
  • Unsupervised learning does not provide known class meanings automatically.

C136

Normalization and preprocessing

Preprocessing makes data usable without changing what the prediction means. Cleaning handles missing, noisy or inconsistent values; encoding represents categories; scaling makes numeric magnitudes comparable.

Problem it solves: Especially important for distance models, neural networks and PCA, or when multiple sources have incompatible units.

How to use it

  1. Split data before fitting preparation steps
  2. Inspect missing values, outliers and invalid records
  3. Fit imputation and category encoding on training data
  4. Fit min–max scaling or standardization where useful
  5. Apply the same fitted transformations to validation, test and future data
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: training mean duration 20 seconds and standard deviation 5 turn 30 seconds into (30−20)/5 = 2. Reuse those training statistics for a new visitor.

What can go wrong → what to change → why

  • Missing value is coded zero → distinguish missingness from a real zero → avoid false evidence
  • Huge scale differences → standardize → prevent domination of distances
  • Outliers may be real faults → investigate before removal → do not delete the target phenomenon

How to evaluate

Check prepared ranges, missingness by class and held-out model quality; preprocessing should improve validity, not merely make training easier.

Answer flow

  1. Identify the data defect
  2. Specify the transformation
  3. Explain the training-only fitting rule
  4. Show why it helps the chosen model

Exam traps

  • Never fit a scaler or PCA on the test set
  • Raw neighboring image pixels are often correlated, not automatically independent features.

C137

Data splits and cross-validation

Training data fits model parameters; validation data guides choices; test data estimates final generalization. Cross-validation rotates the validation fold to obtain a less split-dependent development estimate.

Problem it solves: Use whenever comparing models, selecting features or tuning settings without contaminating the final assessment.

How to use it

  1. Choose a split matching the deployment unit and time order
  2. Keep a final test set untouched
  3. Fit preprocessing on each training partition
  4. Train and score each validation fold
  5. Choose settings using validation results
  6. Refit the selected pipeline and assess the final test once
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: five-fold validation trains on four parts and validates on the fifth, repeated five times. A customer must not appear in both partitions when testing new-customer performance.

What can go wrong → what to change → why

  • Duplicates or related sessions cross partitions → group split → avoid memorization leakage
  • Future data predicts past → chronological split → match deployment
  • Feature selection uses all labels → move selection inside folds → keep validation honest

How to evaluate

Report mean and spread across folds plus final test metrics, especially rare-class performance.

Answer flow

  1. Define unseen-case meaning
  2. State split method
  3. Explain what is fit on training only
  4. Describe fair model comparison

Exam traps

  • Repeatedly choosing from test scores turns the test into validation
  • Random splits are inappropriate for some temporal tasks.

C138

Imbalanced data and augmentation

Class imbalance means some target classes have far fewer examples. A model can achieve high overall accuracy while failing the rare class that matters most.

Problem it solves: Use when faults, fraud or some product classes are scarce; limited minority diversity is separate from simple count imbalance.

How to use it

  1. Count examples and inspect coverage per class
  2. Split original cases before augmentation
  3. Apply training-only class weights or resampling
  4. Use label-preserving augmentation where appropriate
  5. Tune decision thresholds using validation costs
  6. Report minority-class metrics
Example · data issues · evaluation · exam flow

Worked idea

Sample Q2(c): 3000 normal and 2 abnormal sequences give about 99.93% accuracy by predicting everything normal, yet abnormal recall is zero.

What can go wrong → what to change → why

  • Few abnormal cases → collect diverse faults or model normal behavior → two cases cannot represent all faults
  • Oversampling duplicates → validate carefully → repetition does not create new anomaly types
  • Invalid image transformation → restrict augmentation → preserve label meaning

How to evaluate

Inspect confusion matrix, minority recall/precision and per-class F1; include false-alarm burden and uncertainty from tiny samples.

Answer flow

  1. Show why accuracy misleads
  2. Identify count and diversity problems
  3. Propose justified training remedies
  4. Specify rare-case evaluation

Exam traps

  • Do not augment test data as new independent evidence
  • Class weighting cannot compensate for completely absent fault types.

C139

Confusion matrix and classification metrics

A confusion matrix separates correct positives, missed positives, false alarms and correct negatives. Choose metrics from the consequence of each error, not whichever number is largest.

Problem it solves: Use when comparing classifiers against a business objective or diagnosing minority-class failures.

How to use it

  1. Define the positive class explicitly
  2. Count true positives, false negatives, false positives and true negatives
  3. Calculate recall as found positives divided by all actual positives
  4. Calculate precision as correct positives divided by all predicted positives
  5. Compare error costs and choose a threshold

Source check: The parent sample analysis flags inconsistent original-table class counts versus the stated 15.5% purchaser prevalence; preserve the given table and state the label caveat.

Example · data issues · evaluation · exam flow

Worked idea

Illustrative: 80 true positives, 20 missed positives and 40 false positives give recall 80/100 = 0.80, precision 80/120 ≈ 0.667 and F1 ≈ 0.727.

What can go wrong → what to change → why

  • Accuracy hides missed purchasers → inspect recall → measure how many opportunities are missed
  • Too many coupon false alarms → inspect precision and coupon cost → judge operational burden
  • Class labels unclear → confirm matrix orientation → prevent reversed conclusions

How to evaluate

Sample discussion favors SVM recall 0.9771 over NN 0.9616 when missing purchasers costs more than unused coupons; this is a cost-based choice.

Answer flow

  1. State positive class
  2. Compare missed positives and false alarms
  3. Relate differences to business cost
  4. Justify the chosen model

Exam traps

  • Precision and recall have different denominators
  • Original sample counts and stated prevalence require checking rather than silently reversing labels.

C140

ROC and gain/lift charts

ROC compares true-positive rate against false-positive rate as the threshold changes. Gain and lift ask whether targeting the highest-scored cases finds more positives than random targeting.

Problem it solves: Useful for choosing operating thresholds or prioritizing a limited marketing capacity.

How to use it

  1. Produce scores on held-out observations
  2. Vary the classification threshold for an ROC curve
  3. Compare area under the curve as ranking discrimination
  4. Sort customers by score for gain
  5. Compare selected-group positive rate with the overall baseline for lift
  6. Choose a usable operating point
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: if the top 20% of customers contains 50% of purchasers, gain is 50% at 20% coverage and lift is 50/20 = 2.5 over random selection.

What can go wrong → what to change → why

  • Good overall ROC but excessive false alarms → inspect the actual threshold and precision → business workload matters
  • Evaluate training scores → use held-out scores → avoid optimistic ranking
  • Population changes → recheck base rate and lift → targeting value can shift

How to evaluate

Compare AUC, gain at the available budget, precision/recall and expected profit together.

Answer flow

  1. State ranking versus fixed decision
  2. Explain axes or targeted fraction
  3. Interpret the business consequence
  4. Select an operating threshold

Exam traps

  • AUC is not accuracy
  • A high AUC does not determine the best coupon threshold.

C141

Hyperparameter tuning and generalization

Hyperparameters are choices made outside ordinary weight fitting, such as tree depth, neighbor count, learning rate or dropout rate. Generalization is success on new cases, not fitting training examples perfectly.

Problem it solves: Use to choose complexity and training settings while controlling overfitting.

How to use it

  1. Set a simple baseline and relevant validation metric
  2. Choose a small justified search space
  3. Fit complete pipelines inside each training fold
  4. Compare validation results using grid or random search
  5. Prefer a simpler model when performance is comparable
  6. Evaluate the selected pipeline on the final test
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a deeper tree improves training recall but reduces validation recall; select the shallower tree rather than assuming the larger model learned more useful structure.

What can go wrong → what to change → why

  • Too many searches overfit validation → reduce speculative searching or use nested validation → get a more honest estimate
  • Both training and validation poor → improve features or capacity → address underfitting
  • Large train–validation gap → regularize or simplify → address overfitting

How to evaluate

Track validation mean/spread, final target metrics and runtime; keep the final test out of selection.

Answer flow

  1. Diagnose underfit versus overfit
  2. Name the actual adjustable setting
  3. Explain the validation procedure
  4. State the expected trade-off

Exam traps

  • Learned weights differ from hyperparameters
  • Lower training loss is not the selection rule.

C142

Linear / logistic regression

Linear regression predicts a numeric value from a weighted combination of features. Logistic regression predicts class probability by applying a logistic transformation to a weighted combination.

Problem it solves: Choose from target type: sales amount is numeric regression, purchase yes/no is classification.

How to use it

  1. Define target and prediction-time features
  2. Prepare categories, missing values and numeric scales
  3. Fit linear regression with squared error for numeric targets or logistic regression with classification loss
  4. For classification choose a probability threshold using costs
  5. Check held-out predictions and errors
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a linear model predicting amount 12 when actual amount is 10 has squared error 4. A logistic purchase probability of 0.7 predicts purchase at threshold 0.5, but that threshold is a decision choice.

What can go wrong → what to change → why

  • Linear relationship inadequate → add justified features or compare nonlinear models → capture missing structure
  • Correlated predictors → consider regularization or PCA → stabilize the fitted model
  • Target leakage → remove outcome-derived features → preserve deployment validity

How to evaluate

Use MAE/RMSE and residual analysis for numeric targets; use loss, precision, recall and confusion matrix for purchase classification.

Answer flow

  1. Identify target type
  2. Choose model and loss
  3. Explain output interpretation
  4. Evaluate against a baseline

Exam traps

  • Despite its name logistic regression is used for classification
  • A probability is not a guaranteed outcome.

C143

K-nearest neighbours

K-nearest neighbors predicts using the labels of nearby training examples. Here K means the number of neighbors consulted, not the number of clusters or principal components.

Problem it solves: Useful when similar feature profiles are likely to have similar targets and a meaningful distance can be defined.

How to use it

  1. Fit preprocessing on training data
  2. Scale numeric features and choose a distance
  3. Calculate the new case’s distances to training observations
  4. Select the K nearest
  5. Vote for classification or average numeric targets
  6. Tune K using validation
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: among five nearest customers, four purchased and one did not, so majority-vote classification predicts purchase.

What can go wrong → what to change → why

  • Small K follows noise → increase K → smooth the boundary
  • Very large K ignores local groups → decrease K → retain local distinctions
  • Different feature units → standardize → make distance meaningful
  • High dimension → select useful features → avoid weak distance discrimination

How to evaluate

Use held-out target metrics and prediction latency; compare neighbor behavior for sparse regions and minority classes.

Answer flow

  1. Define similarity
  2. Explain the role of K
  3. Show the vote
  4. Discuss scale, noise and dimension

Exam traps

  • Do not include the query’s own label as a neighbor in evaluation
  • Neighbor count is selected using validation, not a fixed universal rule.

C144

Naive Bayes and conditional independence

Naive Bayes scores each class using its prior probability and the likelihood of the observed feature values. It assumes features are conditionally independent given the class, not independent in the whole dataset.

Problem it solves: Useful as a simple probabilistic classifier and for short count-based exam calculations.

How to use it

  1. Count each class to obtain priors
  2. Estimate feature likelihoods within each class
  3. Multiply prior by the relevant likelihoods
  4. Compare class scores
  5. Normalize by the sum of scores if actual posterior probabilities are requested
Example · data issues · evaluation · exam flow

Worked idea

Sample calculation: Carryback score = (5/9)×(1/5)×(3/5) = 1/15; Mistracking score = (4/9)×(2/4)×(2/4) = 1/9. Normalized probabilities are 37.5% and 62.5%, so choose Mistracking.

What can go wrong → what to change → why

  • Zero count kills a product → apply consistent Laplace smoothing → permit unseen values
  • Strongly dependent measurements → inspect performance or compare alternatives → avoid double-counting evidence
  • Different class frequencies → retain priors → do not compare likelihoods alone

How to evaluate

Check class errors and probability quality on held-out data; assumptions need not be perfectly true for useful classification.

Answer flow

  1. State conditional independence
  2. Calculate priors and likelihoods
  3. Show both scores
  4. Normalize and decide if asked

Exam traps

  • The common evidence denominator cancels only for class ranking
  • Likelihood and posterior have opposite conditioning directions.
Sample paper: 5002 Q2(d)

C145

Laplace correction

Laplace correction prevents an unseen categorical feature value from making an entire Naive Bayes class score zero. Add one to every possible category count and adjust the denominator consistently.

Problem it solves: Use when limited training data leaves a category unobserved within a class.

How to use it

  1. List all possible categories for the feature
  2. Count each category within the class
  3. Add one to every category count
  4. Add the number of possible categories to that class-feature total
  5. Use the smoothed likelihoods in the class-score product
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a three-category feature has counts 0,2,3 within a class. Add-one smoothing gives probabilities 1/8, 3/8 and 4/8, which sum to one.

What can go wrong → what to change → why

  • Only zero numerator changed → correct all counts and denominator → retain a valid probability distribution
  • Many categories with tiny data → consider grouping or more data → avoid estimates dominated by smoothing
  • Unseen category at deployment → define category handling during preparation → keep the model usable

How to evaluate

Compare held-out log loss or classification metrics, especially cases containing uncommon categories.

Answer flow

  1. Identify the zero-product problem
  2. State category count
  3. Show corrected numerator and denominator
  4. Continue the class comparison

Exam traps

  • Adding one only to the zero count without denominator correction is not standard Laplace smoothing
  • This fixes estimation, not feature dependence.
Sample paper: 5002 Q2(d)

C146

Decision-tree splitting and information gain

A decision tree repeatedly chooses a feature test that makes child groups more class-pure. Information gain is parent uncertainty minus the size-weighted uncertainty remaining after a split.

Problem it solves: Use for interpretable classification rules and for explaining why a particular feature is tested near the root.

How to use it

  1. Start with all training cases at the root
  2. Calculate parent entropy from class proportions
  3. Consider categorical tests or numeric thresholds
  4. Calculate the size-weighted child entropies
  5. Select the largest information gain
  6. Repeat with stopping or pruning rules
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a balanced two-class node has entropy 1 bit. A split producing two pure child groups has weighted child entropy 0, so information gain is 1 bit.

What can go wrong → what to change → why

  • Many-value identifiers create pure tiny leaves → reject identifiers or use gain ratio/pruning → avoid memorization
  • Continuous features need thresholds → test candidate midpoints → choose a defensible split
  • Small leaves unstable → require minimum samples → improve generalization

How to evaluate

Evaluate held-out class metrics and the usefulness of extracted rules, not only training purity.

Answer flow

  1. Interpret the given tree path
  2. Explain the selected split
  3. Identify a model weakness
  4. Propose a change and fair evaluation

Exam traps

  • Root position indicates importance within that tree, not causation
  • Weight child uncertainty by group size.
Sample paper: 5002 Q1(a)

C147

Gain ratio / Gini

Gain ratio adjusts information gain for the number and balance of branches. Gini impurity measures how mixed the class proportions are; a good split minimizes size-weighted child impurity.

Problem it solves: Use when comparing tree split criteria or explaining why raw information gain can overvalue a many-valued feature.

How to use it

  1. Calculate information gain for candidate attributes
  2. For gain ratio divide by the entropy of branch sizes
  3. For Gini calculate one minus the sum of squared class proportions
  4. Weight child impurities by sample counts
  5. Choose the best valid split under the chosen criterion
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a balanced binary node has Gini 1−0.5²−0.5² = 0.5; a pure node has Gini 0. Splitting into pure groups gives weighted child Gini 0.

What can go wrong → what to change → why

  • Unique ID gets high information gain → remove ID or penalize branching → prevent a lookup table
  • A small unbalanced split looks attractive → enforce minimum leaf size → avoid unstable decisions

How to evaluate

Compare pruned trees on held-out metrics; split purity alone is only a local training criterion.

Answer flow

  1. Identify bias in the proposed criterion
  2. Explain the alternative in words
  3. Show impurity calculation if asked
  4. Retain validation and pruning

Exam traps

  • Higher gain/gain ratio is preferred, but lower weighted Gini is preferred
  • Gain ratio does not eliminate every overfitting risk.

C148

Tree pruning

Pruning reduces a tree’s complexity so it captures repeatable structure rather than tiny training-specific exceptions. Pre-pruning stops growth; postpruning removes branches after a larger tree is grown.

Problem it solves: Use when training performance is high but validation quality drops, or the tree contains many poorly supported leaves.

How to use it

  1. Inspect training and validation errors
  2. Limit depth, require minimum leaf samples or demand useful split improvement
  3. Alternatively grow a tree then form simpler pruned candidates
  4. Compare candidates using validation data
  5. Keep the simplest tree with adequate task performance
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a branch identifies one exceptional purchaser correctly in training but repeatedly produces false positives in validation; removing it may improve generalization.

What can go wrong → what to change → why

  • Tree too complex → increase leaf size or prune → reduce variance
  • Tree too shallow misses clear patterns → relax limits cautiously → reduce underfitting
  • Choose pruning from test data → use validation instead → keep the final estimate independent

How to evaluate

Compare recall, precision and business value before and after pruning; report the trade-off rather than assuming every smaller tree is better.

Answer flow

  1. Identify overfitting evidence
  2. Distinguish pre- and postpruning
  3. State the selection data
  4. Explain the resulting business consequences

Exam traps

  • Pruning may change both missed positives and false alarms
  • Perfect training classification is not the objective.

C149

Curse of dimensionality

As feature count grows, data becomes sparse in the expanded space. More observations are needed to cover it, and distances can become less discriminative, hurting generalization and neighbor-based methods.

Problem it solves: Important when many features are built from a small dataset, especially rare-fault examples.

How to use it

  1. Compare useful sample count with feature count and model capacity
  2. Inspect irrelevant, repeated or noisy features
  3. Select a smaller meaningful feature subset
  4. Consider PCA when correlated numeric features can be compressed
  5. Validate the complete reduction-plus-model pipeline
Example · data issues · evaluation · exam flow

Worked idea

Sample Q2(c): 30 extracted features may be reasonable for 3000 normal sequences, but two abnormal sequences still provide extremely weak evidence about the abnormal class.

What can go wrong → what to change → why

  • Many weak dimensions → remove or combine features → improve sample efficiency
  • Two anomalies reused repeatedly → collect varied anomalies → do not mistake duplication for coverage
  • Distance dominated by noise → scale and select relevant features → restore useful similarity

How to evaluate

Compare held-out rare-case recall, false-alarm rate and model stability across splits; acknowledge large uncertainty with few faults.

Answer flow

  1. Explain why available cases do not cover the space
  2. Identify an appropriate reduction
  3. Preserve prediction-relevant information
  4. Evaluate without leakage

Exam traps

  • High dimension is not automatically fatal with abundant relevant data
  • Dimensionality reduction cannot manufacture missing anomaly diversity.
Sample paper: 5002 Q2(c)

C150

Filter / wrapper / embedded feature selection

Feature selection keeps some original variables. Filters use statistics, wrappers test feature subsets with a model, and embedded methods obtain selection or importance from the model fitting process.

Problem it solves: Use to remove irrelevant or redundant inputs, reduce cost and improve generalization while retaining original-feature meaning.

How to use it

  1. Fit all selection inside training partitions
  2. Use filters for fast initial screening
  3. Use wrappers when subset interactions justify repeated model fitting
  4. Use embedded coefficients or tree importances where appropriate
  5. Retrain the reduced pipeline
  6. Compare validation performance and cost
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: remove constant columns using a filter, then compare an AdaBoost model with and without low-importance inputs on the same validation cases.

What can go wrong → what to change → why

  • Univariate filter misses feature combinations → validate model-based subsets → interactions may matter
  • Wrapper search expensive → restrict candidates → control runtime
  • Importance biased or unstable → check held-out removal impact → avoid treating rankings as truth

How to evaluate

Accept reduction when the relevant metric is preserved or improved and operational complexity falls.

Answer flow

  1. Identify redundant or costly features
  2. Name a selection family
  3. Explain its criterion
  4. Retrain and compare fairly

Exam traps

  • PCA creates new combined features, so it is feature extraction
  • L2 shrinkage does not inherently set coefficients to zero.

C151

Forward / backward / recursive feature selection

Forward selection adds features; backward selection removes features by testing the resulting subset performance; recursive feature elimination repeatedly removes the least important features according to a fitted estimator.

Problem it solves: Use when a manageable original-feature subset is required and the selection procedure can be validated.

How to use it

  1. Define a cross-validated task metric
  2. For forward selection start empty and test each possible addition
  3. For backward selection start full and test each possible removal
  4. For RFE fit the estimator and remove lowest-ranked features
  5. Refit after each change
  6. Stop at a validated subset size
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: forward selection chooses duration first, then adds page count only if the pair improves validation recall. RFE instead starts with the full set and uses fitted importance to remove weak inputs.

What can go wrong → what to change → why

  • Greedy decisions miss the best combination → acknowledge search limits → do not claim a global optimum
  • Selection uses all data → place it inside folds → prevent optimistic results
  • Correlated features swap importance → inspect stability → avoid overinterpreting one retained variable

How to evaluate

Compare selected subsets using the same metric and splitting rules, and measure reduced data-collection or inference cost.

Answer flow

  1. Choose addition/removal direction
  2. State how each candidate is scored
  3. Explain stopping
  4. Validate the final pipeline

Exam traps

  • Backward selection and RFE use different removal criteria
  • RFE requires an estimator capable of ranking features.

C152

PCA, variance, and principal directions

PCA replaces correlated numeric features with new uncorrelated directions, ordered by how much data variation they capture. It solves representation and dimensionality reduction, not collaborative recommendation.

Problem it solves: Useful for compressing related features or reducing multicollinearity, while accepting some loss of original-feature interpretability.

How to use it

  1. Exclude the prediction target and future information
  2. Split before fitting PCA
  3. Center training features and standardize when units require it
  4. Fit principal directions using training inputs
  5. Choose component count using variance and validation
  6. Transform validation/test inputs using the fitted preparation and directions

Source check: Lecture p32 overstates independence and p62 implies all scores have standard deviation one. Notes correct both while preserving lecture terminology.

Example · data issues · evaluation · exam flow

Worked idea

Illustrative: eigenvalues 6,3,1 sum to 10; retaining two components keeps (6+3)/10 = 90% of variance. Sample Q1(e): 10 components meet a stated 90% criterion because nine retain 86.8% and ten retain 92.2%.

What can go wrong → what to change → why

  • Revenue included in PCA for Revenue prediction → remove and refit → prevent leakage
  • High variance is irrelevant to target → compare prediction quality → variance retention is not accuracy

How to evaluate

Inspect cumulative explained variance, loadings, retained information and held-out downstream metrics.

Answer flow

  1. Explain why reduction helps
  2. State a retention rule
  3. Interpret large absolute loadings
  4. Use valid component scores as predictors

Exam traps

  • Uncorrelated does not generally mean independent
  • Default PC scores need not have unit variance.

C153

Eigenvalues / eigenvectors and SVD

For PCA, eigenvectors specify principal directions and eigenvalues tell how much variance each direction captures. SVD is another way to obtain those directions from the centered data matrix.

Problem it solves: Use to connect the geometric PCA explanation with variance-retention calculations without treating symbols as a separate formula table.

How to use it

  1. Prepare and center the feature matrix
  2. Obtain directions from covariance eigenvectors or from SVD of centered inputs
  3. Sort directions by eigenvalue or singular value
  4. Select component count using cumulative explained variance
  5. Project prepared observations onto the retained directions

Source check: The supplied extracted core lecture text supports PCA eigenvectors/eigenvalues but has no explicit SVD derivation. SVD equivalence is a marked explanatory extension to confirm against the SVD conversation, not attributed to these slides.

Example · data issues · evaluation · exam flow

Worked idea

Illustrative: singular values 3 and 1 have squared values 9 and 1; the first direction accounts for 9/(9+1) = 90% of variance, not 3/(3+1) = 75%.

What can go wrong → what to change → why

  • Sum raw singular values for variance → square them first → variance depends on squared singular values
  • Forget centering → center using training means → obtain PCA directions around the mean
  • Interpret loadings as observations → distinguish directions from scores → avoid category mistakes

How to evaluate

Check retained variance, reconstruction usefulness and downstream held-out performance; retain more components only when justified.

Answer flow

  1. Explain direction versus amount
  2. Show retention arithmetic
  3. Distinguish eigenvectors/loadings from scores
  4. Apply the same fitted transform to new cases

Exam traps

  • Singular values are not themselves covariance eigenvalues
  • PCA dimensionality reduction is distinct from recommendation MF.

C154

Clustering vs classification

Classification learns known target categories from labeled cases. Clustering discovers groups from similarity without known category labels; the groups need interpretation after fitting.

Problem it solves: Choose classification when purchase, fault or class labels are available; choose clustering when exploring unknown customer or operating groups.

How to use it

  1. State whether target labels exist
  2. Define the input observations and similarity
  3. For classification train against known labels
  4. For clustering fit a grouping method without pretending to know classes
  5. Profile discovered groups and connect them to an action
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: predicting purchase/no purchase is classification. Grouping customers by behavior without purchase labels is clustering; a group only becomes a useful segment after its profile is examined.

What can go wrong → what to change → why

  • A cluster is assumed to mean abnormal → inspect and validate → similarity does not establish a fault label
  • Labels too scarce → consider anomaly detection with normal data → do not invent a fully supervised dataset
  • Arbitrary scaling → prepare features → prevent unit-driven groups

How to evaluate

Classification uses held-out target errors; clustering uses compactness/separation, stability and meaningful profiles.

Answer flow

  1. Identify available supervision
  2. Choose prediction or discovery
  3. Explain output meaning
  4. State the right evaluation

Exam traps

  • Cluster numbers are arbitrary labels, not a ranked severity scale
  • Clusters need not match real class boundaries.

Distances and standardization for clustering

A clustering distance expresses what similar means. Numeric Euclidean distance is sensitive to feature scale; ordinal and nominal categories require a representation that respects their meaning.

Problem it solves: Use before K-means or hierarchical clustering, because the distance determines which cases form groups.

  2. Choose features relevant to the grouping goal
  3. Standardize numeric features when unequal units should not dominate

  5. Inspect nearest and farthest examples for plausibility

C156

K-means and centroid updates

K-means forms K groups by repeatedly assigning each point to its nearest centroid and recomputing each centroid as the mean of its assigned points. Here K is the number of clusters.

Problem it solves: Useful for numeric data when compact groups around representative means make sense.

How to use it

  1. Prepare numeric features and choose K
  2. Initialize K centroids
  3. Assign each point to its nearest centroid
  4. Replace each centroid with the mean of its assigned points
  5. Repeat until assignments or centroids stabilize
  6. Compare multiple initializations
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: points 2 and 4 assigned to one one-dimensional cluster produce centroid (2+4)/2 = 3. Each reassignment/recompute cycle seeks a lower within-cluster squared-distance total.

What can go wrong → what to change → why

  • Bad initial centers → use multiple starts or K-means++ → reduce poor local solutions
  • Different scales → standardize → prevent one feature dominating
  • Outliers or noncompact shapes → inspect or choose a better grouping method → means may misrepresent the data

How to evaluate

Compare within-cluster squared error, silhouette, stability and business profiles over plausible K values.

Answer flow

  1. State what K means
  2. Show assignment and mean update
  3. Explain convergence and initialization
  4. Justify evaluation and interpretation

Exam traps

  • K-means does not require known class labels
  • It reaches a local solution, not a guaranteed global optimum.

C157

K-means++ initialization

K-means++ selects initial centroids that tend to be spread out, then runs ordinary K-means. It reduces the risk that several starting centers occupy the same small region.

Problem it solves: Use when standard random initialization produces unstable or poor cluster solutions.

How to use it

  1. Prepare feature scales and choose K
  2. Select the first center randomly
  3. Find each point’s squared distance to its nearest chosen center
  4. Sample another center with probability proportional to that squared distance
  5. Repeat until K centers exist
  6. Run normal assignment-and-mean-update iterations
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: candidate squared distances 1 and 9 produce selection probabilities 10% and 90%. The more distant candidate is more likely, but not guaranteed, to become the next center.

What can go wrong → what to change → why

  • Outlier far from all centers → investigate unusual points → K-means++ may choose it
  • Different starting runs vary → use several starts → retain a strong solution
  • Clusters are elongated → change method if appropriate → initialization cannot repair the model geometry

How to evaluate

Compare final squared error and stability across starts, along with silhouette and meaningful profiles.

Answer flow

  1. Identify the initialization problem
  2. Explain distance-weighted seeding
  3. State ordinary K-means follows
  4. Discuss remaining limitations

Exam traps

  • It does not choose K automatically
  • It is probabilistic, not simply always choosing the farthest point.

C158

Hierarchical clustering and linkage

Hierarchical clustering creates nested groups displayed in a dendrogram. Agglomerative clustering starts with one cluster per observation and repeatedly merges the closest pair. Linkage defines distance between clusters.

Problem it solves: Useful for exploring grouping at several levels without selecting the final number of groups before constructing the hierarchy.

How to use it

  1. Prepare features and choose observation distance
  2. Start with individual clusters
  3. Calculate inter-cluster distances under the chosen linkage
  4. Merge the closest pair
  5. Repeat and record merge heights
  6. Cut the dendrogram at a justified level and profile groups
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: for two groups, single linkage uses their nearest pair, complete linkage their farthest pair, and average linkage the average cross-group distance. Ward favors merges with a small increase in within-group squared variation.

What can go wrong → what to change → why

  • Single-link chains connect distinct groups → compare complete/average linkage → alter the grouping criterion
  • Outliers dominate merges → investigate → avoid interpreting noise as a segment
  • Many observations → consider cost → pairwise calculations can be expensive

How to evaluate

Inspect dendrogram stability, separation and substantive group profiles; compare plausible linkage choices.

Answer flow

  1. Explain merge sequence
  2. State linkage meaning
  3. Choose a defensible cut
  4. Interpret groups and limitations

Exam traps

  • Dendrogram height depends on distance/linkage
  • Hierarchical merging usually cannot undo a bad earlier merge.

C159

Cluster evaluation and number of clusters

Cluster evaluation checks compactness, separation, stability and usefulness. Choosing K is a modeling decision; lower within-cluster error alone cannot determine the best count because that error normally falls as K grows.

Problem it solves: Use when asked how many groups to keep or whether discovered segments are valid.

How to use it

  1. Fit a plausible range of cluster counts
  2. Plot within-cluster squared error and inspect diminishing returns
  3. Compare silhouette and other validity indices
  4. Check stability across starts or samples
  5. Profile each group using original features
  6. Choose a useful interpretable solution
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: error falls 100→55→40→37→35 for K=1…5; K=3 is a plausible elbow because later gains are small, but profiles and stability must support that choice.

What can go wrong → what to change → why

  • Choose largest K because error is smallest → use elbow plus validation → avoid trivial tiny groups
  • Nice statistics but no usable segments → inspect profiles → clusters must support the objective
  • Small unstable cluster → inspect rare real pattern versus noise → avoid automatic deletion

How to evaluate

Higher silhouette/Calinski–Harabasz and lower Davies–Bouldin are favorable; no single score proves the true grouping.

Answer flow

  1. State evaluation criteria
  2. Compare several K choices
  3. Explain technical and business evidence
  4. Defend a practical count

Exam traps

  • K here is clusters, unlike K-nearest neighbors
  • Silhouette near zero indicates overlapping/boundary cases, not perfect grouping.

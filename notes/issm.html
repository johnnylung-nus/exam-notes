C083

Signals, sensors, and sensing pipeline

A sensor captures a physical quantity; a signal records its variation. Sense making turns the measurements into useful findings and actions.

Problem it solves: Use to design an intelligent sensing solution from a concrete user problem.

How to use it

  1. State the event or condition the user needs to know.
  2. Choose a sensor that observes relevant evidence.
  3. Specify placement, signal and acquisition rate.
  4. Process/extract useful features.
  5. Map features to a finding.
  6. Define the resulting alert, recommendation or action.
Example · data issues · evaluation · exam flow

Worked idea

Lecture example: pressure sensors monitor a water system; deviations from a normal range can indicate a condition requiring investigation. The value comes from the interpreted finding and action.

What can go wrong → what to change → why

  • Wrong measurement chosen → link sensor to required finding → prevents collecting irrelevant data.
  • Poor deployment → choose suitable placement/range → signal quality begins at capture.
  • Numbers without action → define decision and user response → connects sensing to value.

How to evaluate

Check measurement quality, finding correctness, useful action, latency and error consequences.

Answer flow

  1. User need.
  2. Sensor → acquired signal.
  3. Processing → finding.
  4. Action and evaluation.

Exam traps

  • A sensor reading is not automatically knowledge.
  • IoT transfer/storage alone does not create intelligent sense making.

C084

Sampling and aliasing

Sampling converts a continuous-time signal into readings at intervals. Undersampling can make different original signals appear identical: aliasing.

Problem it solves: Use when fast changes are lost or a sampled recording shows a misleading pattern.

How to use it

  1. Identify the highest frequency that must be preserved.
  2. Choose a sampling rate meeting the lecture’s twice-highest-frequency rule.
  3. Avoid unwanted above-range components before sampling.
  4. Record consistently and retain timing.
  5. Check that the digitized signal preserves task-relevant behaviour.

Source check: Checklist originally points at a sound-anomaly example; sampling principle is in the introduction lecture.

Example · data issues · evaluation · exam flow

Worked idea

Lecture question: maximum voice frequency 4,000 Hz → minimum sampling rate 8,000 samples/second under the stated ideal assumption. The backwards-looking movie wheel illustrates undersampling.

What can go wrong → what to change → why

  • Rate too low → acquire faster → prevents irreversible loss of frequency identity.
  • Rate chosen from bandwidth alone → check frequency-range assumptions → highest frequency and bandwidth are not always equal.
  • Already aliased recording → reacquire appropriately → later interpolation cannot uniquely recover lost evidence.

How to evaluate

Check represented frequencies, timing consistency and final task performance; test fast events explicitly.

Answer flow

  1. Fastest relevant variation.
  2. Required acquisition rate.
  3. Aliasing consequence and remedy.
  4. Verify preserved information.

Exam traps

  • Twice the bandwidth only applies under the relevant signal assumptions.
  • More samples do not repair a poor sensor position.

C085

Periodic / even / odd signals

Periodic signals repeat after a fixed interval. Even signals mirror around time zero; odd signals reverse sign as time is reversed.

Problem it solves: Use when identifying signal structure or choosing a representation suited to repetition and symmetry.

How to use it

  1. Check whether the full pattern repeats after one fixed interval.
  2. Distinguish repetition from a single similar-looking segment.
  3. Compare values at equal positive and negative times.
  4. Same values indicate even symmetry; opposite values indicate odd symmetry.
  5. Use the identified property to explain the signal, not just name it.
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: cos(t) is periodic and even; sin(t) is periodic and odd. A one-off sensor spike is not periodic merely because its shape resembles another spike.

What can go wrong → what to change → why

  • Noise hides repetition → inspect enough cycles → one short window can mislead.
  • Symmetry judged visually → compare paired times/values → confirms the definition.
  • Periodic assumed forever → state the observed range → finite data supports limited claims.

How to evaluate

Check candidate periods and paired-time values using the whole available signal range.

Answer flow

  1. Observed pattern.
  2. Test repetition.
  3. Test symmetry.
  4. Explain relevance to representation.

Exam traps

  • Periodic and even/odd describe different properties.
  • Even does not mean positive and odd does not mean negative.

C086

Superposition and signal decomposition

Superposition builds a signal by scaling and adding simpler components. Decomposition works in the other direction to make complex behaviour easier to analyze.

Problem it solves: Use when a sensor signal combines multiple patterns and a simpler component representation is useful.

How to use it

  1. State the observed signal and relevant component types.
  2. Choose a suitable basis or component representation.
  3. Find component weights.
  4. Study useful components separately.
  5. Add weighted components to reconstruct or approximate the signal.
  6. Check what information the approximation loses.
Example · data issues · evaluation · exam flow

Worked idea

Lecture link: a sound signal can be represented with sinusoidal basis functions. A strong low-frequency component and a faster component explain different parts of its variation.

What can go wrong → what to change → why

  • Wrong basis → choose components matched to the signal/task → improves interpretability.
  • Too few components → retain additional useful ones → reduces reconstruction loss.
  • Assuming linearity without checking → state the linear-system condition → superposition is not universal.

How to evaluate

Compare reconstructed with original signal and check whether retained components preserve the task-relevant event.

Answer flow

  1. Complex signal problem.
  2. Decomposition choice.
  3. Component interpretation or reconstruction.
  4. Information retained versus lost.

Exam traps

  • Linear superposition uses scaling and addition, not multiplication of signals.
  • Small reconstruction error alone does not prove useful classification.

C087

Time and frequency representation

Time representation shows how readings change; frequency representation shows which rates of variation contribute. Choose according to the question.

Problem it solves: Use when a repeated pattern is hard to see in raw readings or when the timing of a change matters.

How to use it

  1. Identify whether the task needs event timing, frequency content or both.
  2. Inspect the time signal.
  3. Use Fourier analysis for overall frequency components.
  4. If timing matters, use a localized representation such as the lecture’s wavelet approach.
  5. Extract relevant coefficients/statistics and evaluate the task.
Example · data issues · evaluation · exam flow

Worked idea

Lecture comparison: 5 Hz followed by 25 Hz and 25 Hz followed by 5 Hz have different time order. An overall frequency view does not clearly say when each component occurred.

What can go wrong → what to change → why

  • Time information lost → use localized analysis → preserves event timing.
  • Raw waveform too complex → transform to relevant frequency features → exposes repeated structure.
  • Transform chosen for appearance → test target task → a clear plot is not proof of useful evidence.

How to evaluate

Check retained frequency/time information and downstream recognition on unseen sequences.

Answer flow

  1. Question needs what information?
  2. Choose representation.
  3. Explain information gained/lost.
  4. Evaluate downstream usefulness.

Exam traps

  • Frequency is not amplitude.
  • A whole-recording Fourier view is not a time-frequency map.

C088

Fourier transformation

Fourier transformation expresses a signal using sinusoidal components. Coefficients tell how much each frequency contributes; the inverse reconstructs it.

Problem it solves: Use to identify frequency content and create features for sensor classification or analysis.

How to use it

  1. Prepare the sampled signal and its sampling rate.
  2. Calculate the Fourier coefficients.
  3. Inspect useful frequency components.
  4. Use coefficients or derived features for the task.
  5. Apply the inverse if reconstruction is needed.
  6. Check whether time localization is required.
Example · data issues · evaluation · exam flow

Worked idea

Lecture four-value signal [2,3,4,4] gives coefficients [13,−2+i,−1,−2−i], where i is the imaginary unit. The zero-frequency coefficient 13 is the sum of values, not their mean.

What can go wrong → what to change → why

  • Timing of change hidden → use wavelet/windowed analysis → overall frequencies do not locate events.
  • Frequency bins misread → retain sampling-rate information → bin number alone is not frequency in hertz.
  • Unnecessary complex arithmetic → explain representation first → supports scenario reasoning.

How to evaluate

Verify inverse reconstruction and whether chosen frequency features distinguish the required classes/events.

Answer flow

  1. Why frequency analysis?
  2. Transform signal.
  3. Interpret useful components.
  4. State localization limit and evaluate.

Exam traps

  • FFT is an efficient way to compute the discrete transform.
  • Do not discard phase and expect exact reconstruction.

C089

Filtering and convolution

Filtering emphasizes or removes selected signal components. Convolution applies a local filter across the signal; low-pass filtering smooths while high-pass filtering emphasizes changes.

Problem it solves: Use for noise reduction, feature extraction and the lecture’s wavelet decomposition/reconstruction.

How to use it

  1. Identify the unwanted variation and useful event detail.
  2. Choose a suitable low-pass/high-pass filter.
  3. Apply the filter consistently across the signal.
  4. For wavelets, split approximation/detail and downsample.
  5. Retain or modify useful coefficients.
  6. Reconstruct when a cleaned signal is required.
Example · data issues · evaluation · exam flow

Worked idea

Lecture wavelet flow: low-pass produces approximation; high-pass produces detail; repeated decomposition separates scales. Thresholding selected wavelet coefficients and reconstructing can denoise a signal.

What can go wrong → what to change → why

  • Useful fast event smoothed away → choose filtering strength using the task → noise removal must preserve evidence.
  • Boundary artifacts → state extension method → edge values depend on it.
  • Denoising judged only visually → check downstream accuracy → smooth does not always mean correct.

How to evaluate

Compare original/cleaned signals, retained event details and task performance; check edge and transient behaviour.

Answer flow

  1. Noise versus useful component.
  2. Filter/decomposition choice.
  3. Retained detail and reconstruction.
  4. Evaluate task impact.

Exam traps

  • High-frequency content is not always noise.
  • Hand-crafted filters and learned convolution kernels have different parameter origins.

C090

Signal distributions and statistics

A distribution describes likely readings; statistics summarize observed data. A class-specific distribution can support probabilistic sensor classification.

Problem it solves: Use when deciding which class best explains measured features, such as vibration and acoustic categories.

How to use it

  1. Prepare relevant features and reliable class labels.
  2. Estimate class priors from training counts.
  3. Estimate each feature’s likelihood within each class.
  4. For Naive Bayes, state conditional independence given class.
  5. Multiply prior by feature likelihoods.
  6. Normalize scores if probabilities are requested and choose the larger.
Example · data issues · evaluation · exam flow

Worked idea

5002 study answer: Carryback score=5/9×1/5×3/5=1/15; Mistracking=4/9×2/4×2/4=1/9. Normalize to 0.375 and 0.625; predict Mistracking.

What can go wrong → what to change → why

  • Class imbalance → include priors → avoids treating unequal class frequencies as equal.
  • Correlated features → question the independence assumption → duplicated evidence can distort scores.
  • Poor distribution fit → inspect data and choose suitable model → one Gaussian may not fit multiple groups.

How to evaluate

Check held-out predictions, class-specific errors and whether probabilities reflect actual outcomes.

Answer flow

  1. Given readings and classes.
  2. Prior and likelihood counts.
  3. Score/normalize.
  4. Prediction, assumption and validation.

Exam traps

  • Likelihood P(reading given class) is not posterior P(class given reading).
  • Use the same denominator for score normalization.
Sample paper: 5001 Q1(d)

C091

Gaussian mixtures / expectation maximization

A Gaussian mixture models several overlapping groups. Expectation maximization (EM) alternates estimating hidden group membership and updating model parameters.

Problem it solves: Use when one distribution is too simple and the data’s component labels are unknown.

How to use it

  1. Choose component count and initialize parameters/mixture proportions.
  2. E-step: estimate each observation’s probability of belonging to each component.
  3. M-step: update component parameters using those weighted memberships.
  4. Update mixture proportions.
  5. Repeat until the stopping condition.
  6. Check sensitivity to initialization and fit.

Source check: Lecture p45 contains inconsistent Blue denominators/copied counts. Use correct weighted totals (10.69) and the EM principle, not the erroneous printed arithmetic.

Example · data issues · evaluation · exam flow

Worked idea

Lecture dice example: equal initial die-selection probabilities; a six has likelihood 0.4 under Yellow and 0.1 under Blue. Weighted scores 0.20 and 0.05 normalize to membership 0.8 and 0.2.

What can go wrong → what to change → why

  • Unknown labels → soft memberships → each observation can contribute to both components.
  • Poor initialization → compare plausible starts → one run may give a poor solution.
  • Too simple model → assess component count → multiple peaks may need multiple components.

How to evaluate

Inspect fit, convergence and stability; evaluate downstream classification if that is the goal.

Answer flow

  1. Mixed data without labels.
  2. Initialize.
  3. Estimate memberships ↔ update distributions.
  4. Check fit and limitations.

Exam traps

  • E-step estimates memberships; M-step updates parameters.
  • Soft membership is not a known true label.

C092

Basis vectors and energy compaction

A basis defines how a signal is represented. Energy compaction seeks a few components that preserve much of the signal with low reconstruction error.

Problem it solves: Use when raw sensor vectors are large or redundant and a compact representation is needed.

How to use it

  1. Prepare comparable signal vectors.
  2. Choose or learn basis directions.
  3. Project each signal to obtain component weights.
  4. Retain the useful components.
  5. Reconstruct using their weighted sum.
  6. Compare reconstruction loss and downstream usefulness.
Example · data issues · evaluation · exam flow

Worked idea

Lecture change of basis: signal (1,2) projected onto unit directions (1,1)/√2 and (−1,1)/√2 has weights 3/√2 and 1/√2. Both reconstruct (1,2); fewer components make an approximation.

What can go wrong → what to change → why

  • Too few directions → keep more components → preserves important variation.
  • Unrepresentative training signals → learn on representative data → basis may otherwise fit the wrong patterns.
  • Low-variance but important event lost → evaluate the target task → energy retained is not identical to task relevance.

How to evaluate

Check reconstruction squared error, size/computation savings and classification or detection quality.

Answer flow

  1. Need compact representation.
  2. Basis and projection.
  3. Retain components and reconstruct.
  4. Measure information loss and task value.

Exam traps

  • A component weight is not the basis vector.
  • Energy compaction is not the recommendation problem solved by MF.

C093

Supervised representation learning

Supervised representation learning uses labelled task examples to learn features useful for prediction. Transfer can freeze an encoder or fine-tune it.

Problem it solves: Use when sensor labels exist or a pretrained model can help with a smaller target dataset.

How to use it

  1. Define the target labels and prepare representative data.
  2. Start from an appropriate representation model.
  3. For linear adaptation, freeze the encoder and train the new output mapping.
  4. For fine-tuning, continue training the representation on target data.
  5. Compare both approaches on held-out target cases.
Example · data issues · evaluation · exam flow

Worked idea

Lecture distinction: a fixed feature extractor plus new linear classifier changes the output mapping; fine-tuning changes the pretrained feature extractor itself.

What can go wrong → what to change → why

  • Few target examples → start with frozen features → fewer trainable parameters can reduce fitting risk.
  • Domain mismatch → consider fine-tuning → adapts features to new signals.
  • Validation degradation → reduce capacity/training or retain frozen features → target labels may not support extensive updates.

How to evaluate

Check target-task errors, class coverage, resource cost and training/validation gap.

Answer flow

  1. Labels and deployment task.
  2. Frozen versus adapted representation.
  3. Explain data/capacity trade-off.
  4. Compare on unseen target cases.

Exam traps

  • Pretraining and target-task training are different stages.
  • Fine-tuning is not just attaching a new output layer.

C094

Self-supervised representation learning

Self-supervised learning creates a training target from the data itself. A pretext task learns features that are later assessed on a real downstream task.

Problem it solves: Use when unlabelled sensor recordings are plentiful but human annotation is expensive or scarce.

How to use it

  1. Collect representative unlabelled inputs.
  2. Choose a data-derived pretext task.
  3. Train an encoder with that objective.
  4. Use the learned representation for the target task.
  5. Add target labels where needed.
  6. Evaluate on independent target cases.
Example · data issues · evaluation · exam flow

Worked idea

Lecture options: reconstruct an input through an autoencoder, or learn similarity from positive/negative pairs. Both learn features without a human label for every pretraining example.

What can go wrong → what to change → why

  • Pretext solved using irrelevant cues → choose task/augmentation carefully → learned features may miss the target concept.
  • No target evaluation → test with downstream labels → low pretraining loss does not establish usefulness.
  • Different deployment domain → adapt and re-evaluate → transfer is not guaranteed.

How to evaluate

Compare downstream performance with a baseline using the same target-label budget, and check representation robustness.

Answer flow

  1. Available unlabelled data.
  2. Pretext objective.
  3. Reuse for downstream task.
  4. Evaluate target benefit.

Exam traps

  • Self-supervised has a learning signal; it is not “no target”.
  • Target tasks may still need human labels.

C095

Autoencoders and reconstruction

An autoencoder has an encoder that creates a representation and a decoder that reconstructs the input. Training minimizes reconstruction error.

Problem it solves: Use for learning sensor features or a compact code when no class label is needed for the pretraining task.

How to use it

  1. Prepare representative inputs.
  2. Choose encoder, code size and decoder.
  3. Use the original input as the reconstruction target.
  4. Train by reducing input–output differences.
  5. Extract the code for downstream use.
  6. Check reconstruction and feature usefulness on unseen data.
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a 100-value sensor window is encoded into 10 values and decoded back into 100. The loss measures differences between original and reconstructed readings, not whether a class prediction is correct.

What can go wrong → what to change → why

  • Code too small → increase capacity if useful details vanish → compression trades detail for size.
  • Model copies everything → constrain representation appropriately → copying alone need not learn useful abstraction.
  • Good reconstruction but poor classifier → evaluate downstream features → reconstruction and class separation differ.

How to evaluate

Use held-out reconstruction error plus downstream classification/retrieval where applicable; compare raw-input baseline.

Answer flow

  1. Why learn a representation?
  2. Encoder → code → decoder.
  3. Reconstruction target/loss.
  4. Check compression and downstream value.

Exam traps

  • Under-complete has fewer code dimensions; over-complete need not compress.
  • An autoencoder is not automatically PCA.

C096

Denoising autoencoders

A denoising autoencoder receives a corrupted input but is trained to reconstruct the original clean input.

Problem it solves: Use when sensor noise should be removed while retaining the underlying useful structure.

How to use it

  1. Start with representative clean training signals.
  2. Add realistic corruption to create model inputs.
  3. Keep the clean originals as targets.
  4. Train encoder and decoder to reduce clean-target reconstruction error.
  5. Test on unseen noisy signals.
  6. Check whether important event details survive.
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: add mild jitter to a clean vibration window; input is the noisy window, target is the original. Reconstructing the noisy target would teach noise copying instead.

What can go wrong → what to change → why

  • Training noise unrealistic → use corruption resembling deployment → improves relevance.
  • Over-smoothing → inspect important transients → a smoother signal may erase faults.
  • Noisy target used by mistake → preserve clean target → the learning objective must reward denoising.

How to evaluate

Compare reconstruction against available clean references and evaluate the final sensing task under realistic noise.

Answer flow

  1. Noise problem.
  2. Corrupted input and clean target.
  3. Reconstruction objective.
  4. Check detail preservation and task benefit.

Exam traps

  • Ordinary reconstruction and denoising use different input-target pairs.
  • Denoising does not guarantee correct anomaly classification.

C097

Contrastive learning

Contrastive learning shapes the representation: positive pairs should be similar, while negative pairs should be less similar.

Problem it solves: Use when the desired invariance can be specified through paired views instead of a class label for every input.

How to use it

  1. Define what should count as the same underlying event/object.
  2. Create positive pairs with valid augmentation or context.
  3. Select appropriate negative pairs.
  4. Train the encoder to bring positives together and separate negatives.
  5. Test learned features on the target task.
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: two mildly noise-corrupted views of the same activity window are positives if the activity remains unchanged. Different windows are not automatically valid negatives if they show the same activity.

What can go wrong → what to change → why

  • Augmentation changes the class → constrain transformations → positives must retain target meaning.
  • False negatives → inspect pair construction → semantically similar inputs should not be forced apart unnecessarily.
  • Good pair loss but weak task result → evaluate downstream labels → pretext success alone is insufficient.

How to evaluate

Assess retrieval/neighbour quality, downstream prediction and robustness to the intended transformations.

Answer flow

  1. What must remain similar?
  2. Positive/negative construction.
  3. Representation objective.
  4. Downstream benefit and pair errors.

Exam traps

  • Contrastive learning does not reconstruct every input by definition.
  • Choose invariance for the actual sensing task.

C098

Anomaly detection

Anomaly detection identifies observations that differ from expected behaviour. It may return a normal/anomaly label or a score needing a threshold.

Problem it solves: Use for unusual sensor behaviour when the exact fault type may be unknown or rare.

How to use it

  1. Define normal behaviour and relevant context.
  2. Prepare representative normal and available abnormal examples.
  3. Choose cluster-distance, distribution-based or supervised classification approach according to available data.
  4. Produce a score or label.
  5. Select a threshold according to false-alarm/missed-event consequences.
  6. Investigate flagged cases and monitor drift.
Example · data issues · evaluation · exam flow

Worked idea

Lecture example: machine sound is recorded for time-series anomaly detection. A score can rank suspicious windows; a chosen threshold turns the score into an alert.

What can go wrong → what to change → why

  • Rare faults → evaluate missed events as well as false alarms → overall accuracy can be misleading.
  • Normal operation changes → include context/update baseline → drift can trigger spurious alarms.
  • Single reading normal but sequence unusual → analyze windows → collective anomalies need temporal context.

How to evaluate

Check false alarms, missed anomalies, detection delay and usefulness of alerts on unseen operation periods.

Answer flow

  1. What is normal?
  2. Point/contextual/collective deviation.
  3. Score and threshold.
  4. Consequences and evaluation.

Exam traps

  • An anomaly is not automatically a diagnosed fault.
  • A score is not yet an operational decision.

C099

Single-modality sensing

Single-modality sensing uses one type of evidence, such as inertial measurements, audio or vision. Choose the modality according to what must be recognized.

Problem it solves: Use when a simple sufficient sensor solution is preferable to combining multiple data types.

How to use it

  1. Define the target event and operating conditions.
  2. Choose a modality that observes the needed evidence.
  3. Capture and buffer an appropriate window.
  4. Extract features or learn a representation.
  5. Recognize the activity/object/event.
  6. Connect the result to the specified action.
Example · data issues · evaluation · exam flow

Worked idea

Lecture inertial example: accelerometer measurements along three axes support orientation and gesture recognition. Lecture audio examples distinguish speaker identity, keywords and limited commands.

What can go wrong → what to change → why

  • Chosen modality cannot observe required fact → add/change evidence → no algorithm can reliably infer every hidden detail.
  • Environment noise or occlusion → improve capture or consider complementary input → modality has specific weaknesses.
  • Single reading too weak → use a sequence/window → motion and speech depend on change.

How to evaluate

Check target recognition, robustness in intended conditions, latency and whether the sensor is sufficient for the required output.

Answer flow

  1. Required fact.
  2. Why this modality?
  3. Window/features/model.
  4. Failures and action quality.

Exam traps

  • Three accelerometer axes remain one modality.
  • Speaker recognition is not speech transcription.

C100

Data augmentation for sensors

Sensor augmentation creates plausible variations of training windows while preserving the target meaning. The lecture covers scaling, magnitude filtering, jittering and time-warping.

Problem it solves: Use when training data lacks realistic variation or the model overfits to exact recorded conditions.

How to use it

  1. Identify harmless variation expected in deployment.
  2. Choose transformations that preserve the target label.
  3. Apply augmentation to training data only.
  4. Keep clean validation/test data separate.
  5. Train and compare with the same baseline.
  6. Inspect class-specific changes and robustness.
Example · data issues · evaluation · exam flow

Worked idea

Lecture distinction: scaling multiplies the whole window by a scalar; jittering adds noise; time-warping smoothly changes temporal positions. Their suitability depends on what defines the activity/fault.

What can go wrong → what to change → why

  • Transformation changes event meaning → restrict range/type → prevents wrong training labels.
  • Augmented copies across splits → split originals first → prevents leakage.
  • Only augmented test performance improves → use realistic independent recordings → synthetic robustness is not enough.

How to evaluate

Compare unseen real-data errors and resistance to relevant noise, while checking that important magnitude/timing cues remain usable.

Answer flow

  1. Missing variation.
  2. Label-preserving transform.
  3. Training-only use.
  4. Real-data comparison.

Exam traps

  • Augmentation does not create independent real participants/machines.
  • A technique useful for one sensor task may destroy another task’s label.

C101

Multimodal representation and fusion

Fusion combines evidence from sensor streams. The lecture distinguishes tightly coupled early/intermediate fusion, loosely coupled restricted fusion and uncoupled late fusion.

Problem it solves: Use when sensors provide complementary information or one stream can guide interpretation of another.

How to use it

  1. State the information and quality of each stream.
  2. Align observations from the same situation.
  3. Early/intermediate: combine inputs/features before recognition.
  4. Restricted: use one recognition result to constrain the other search.
  5. Late: combine separate recognition decisions.
  6. Compare the chosen design with a single-stream baseline.
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: sound and vibration can support a machine-fault decision. Late fusion keeps each recognizer separate; feature-level fusion combines their representations before a shared recognizer.

What can go wrong → what to change → why

  • Mismatched times/entities → align streams → prevents combining unrelated events.
  • Noisy modality dominates → account for input quality → more inputs can worsen results.
  • Existing pipelines costly to rebuild → consider late fusion → reuses separate recognizers.

How to evaluate

Compare task errors, missing/noisy-stream robustness, latency and added implementation cost.

Answer flow

  1. Why multiple streams?
  2. Choose fusion point.
  3. Handle alignment/quality.
  4. Compare actual benefit.

Exam traps

  • Fusion is not automatically more accurate.
  • Label the fusion point; “combine data” alone is vague.

C102

Spatial / temporal / feature alignment

Alignment makes streams refer to comparable positions, times or features. Fusion is unreliable if the inputs describe different events.

Problem it solves: Use before combining sensors with different clocks, viewpoints, sampling rates or representation spaces.

How to use it

  1. Spatial: transform locations into a common coordinate frame.
  2. Temporal: place observations on a common time axis.
  3. When similar sequences run at different speeds, consider dynamic time warping.
  4. Feature alignment: map matching modalities to comparable learned representations.
  5. Verify correspondence before using combined evidence.
Example · data issues · evaluation · exam flow

Worked idea

Lecture dynamic-time-warping example matches similar time-series shapes even when their timing differs; matching the same index alone cannot handle different speeds.

What can go wrong → what to change → why

  • Clock offset → synchronize timestamps → avoids false cross-sensor relationships.
  • Different coordinate frames → calibrate transformations → same position otherwise has different values.
  • Unrelated sequences forced together → validate event identity → numerical alignment does not prove semantic correspondence.

How to evaluate

Check known corresponding points/events, alignment error and downstream task improvement.

Answer flow

  1. What differs between streams?
  2. Spatial/time/feature correction.
  3. Validate correspondence.
  4. Evaluate fused task.

Exam traps

  • Temporal alignment and spatial alignment solve different mismatches.
  • CLIP-style feature alignment is not a clock-synchronization method.

C103

End-to-end sense-making design

End-to-end sense making connects raw sensor data to recognized entities, relationships, context, knowledge and an action.

Problem it solves: Use for scenario questions asking for a complete architecture rather than only a model name.

How to use it

  1. Define the user goal and required decision.
  2. Specify sensors, signals and data preparation.
  3. Choose features/representation and recognition task.
  4. Combine entity relationships with context/domain knowledge.
  5. Show planning and the action/output.
  6. Return observations/feedback where the task is a continuing loop.
Example · data issues · evaluation · exam flow

Worked idea

Lecture ADAS example: cameras and motion sensors → recognize lane position and drift → decide warning → audible alert. The diagram should label the data passed between these functions.

What can go wrong → what to change → why

  • Model output unrelated to user need → connect each stage to the required action → exposes missing functions.
  • Sensors disagree → align and assess quality → avoids unsupported combined conclusions.
  • Good classifier but unusable system → evaluate timing and error consequences → complete-system usefulness matters.

How to evaluate

Check sensing, recognition and decision errors separately, then task success, latency, robustness and action consequences.

Answer flow

  1. Scenario goal.
  2. Inputs → processing → knowledge.
  3. Decision → action/feedback.
  4. Evaluate complete loop.

Exam traps

  • An architecture needs responsibilities and labelled arrows, not just input → AI → output.
  • Learning/training need not happen in every runtime loop.

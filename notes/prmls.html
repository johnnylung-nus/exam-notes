C104

Artificial neuron, weights, bias, activation

A neuron combines inputs using learned weights, adds a bias, then applies an activation. Weights control input influence; bias shifts the point at which the neuron responds.

Problem it solves: Use neurons as building blocks when the relationship between inputs and target must be learned from examples.

How to use it

  1. Encode each input numerically
  2. Multiply inputs by their weights and add the bias
  3. Apply the chosen activation
  4. Compare output with the training target and update weights
Example · data issues · evaluation · exam flow

Worked idea

Lecture example: inputs 1 and 0, weights 2 and 6, bias −3 give total −1; the stated step activation outputs 0.

What can go wrong → what to change → why

  • Different input scales distort learning → scale using training statistics → inputs become comparable
  • Only linear layers → add nonlinear hidden activations → stacked layers can represent nonlinear patterns

How to evaluate

Choose classification metrics or regression error to match the target; training output alone does not establish generalization.

Answer flow

  1. Identify the input values
  2. Explain weight and bias roles
  3. Calculate total then activation
  4. Match final activation to the required output

Exam traps

  • A bias is learned, not an additional measured customer attribute
  • Activation is not the loss function.

C105

Perceptron and linear separability

A single perceptron makes a binary decision using one straight separating boundary. It can learn a solution only when the training classes are linearly separable.

Problem it solves: Useful as a simple binary baseline; unsuitable when the classes require curved or disconnected decision regions.

How to use it

  1. Initialize weights and bias
  2. Calculate weighted input and hard-threshold output
  3. Find target minus predicted output
  4. Adjust each weight by learning rate × error × its input
  5. Repeat over examples
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: learning rate 0.1, target 1, predicted 0, input 2 gives a weight increase of 0.2. XOR needs more than one linear boundary.

What can go wrong → what to change → why

  • Nonseparable classes → use nonlinear hidden layers → combine several boundaries
  • Large learning steps oscillate → reduce learning rate → updates become controlled

How to evaluate

Check errors on unseen cases and whether a linear decision boundary is plausible; failure to converge may reflect the model limitation.

Answer flow

  1. Inspect the class arrangement
  2. Decide whether a straight boundary suffices
  3. Show one update if asked
  4. Justify an MLP when it does not

Exam traps

  • Training longer cannot make one perceptron solve XOR
  • A threshold output is not a calibrated probability.

C106

ADALINE and delta rule

ADALINE learns from the continuous weighted sum before thresholding. The delta rule changes weights to reduce squared prediction error, rather than using only the final class decision.

Problem it solves: Use to explain gradient-based learning and contrast ADALINE with the perceptron.

How to use it

  1. Calculate the continuous weighted sum
  2. Subtract it from the target
  3. Multiply error by input and learning rate to obtain the weight adjustment
  4. Update weights and repeat
  5. Apply a threshold if a final binary class is required
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: target 1, linear output 0.4, input 2 and learning rate 0.1 give adjustment 0.1 × 0.6 × 2 = 0.12.

What can go wrong → what to change → why

  • Unscaled inputs cause unstable updates → standardize → gradients are better balanced
  • Nonlinear target → add nonlinear hidden structure → a single linear unit cannot express it

How to evaluate

Track mean squared error on training and validation data, and classification performance if a threshold is applied.

Answer flow

  1. State which output supplies the error
  2. Calculate the error
  3. Show the update
  4. Explain the limitation of one linear unit

Exam traps

  • Do not compute ADALINE learning error from the thresholded class
  • ADALINE is not automatically a multilayer nonlinear model.

C107

MLP and backpropagation

An MLP passes inputs through hidden layers to predict a target. Backpropagation calculates how each weight contributed to the loss, allowing a gradient-based optimizer to update it.

Problem it solves: Use for supervised nonlinear relationships, especially prepared tabular features; choose architecture complexity to fit available data.

How to use it

  1. Prepare inputs and training labels
  2. Run a forward pass through hidden and output layers
  3. Calculate task-appropriate loss
  4. Propagate loss gradients backward using the chain rule
  5. Update weights and monitor validation performance
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: purchase prediction uses prepared visitor features → small ReLU hidden layers → one sigmoid output; binary cross-entropy measures mismatch with purchase labels.

What can go wrong → what to change → why

  • Training improves while validation worsens → simplify, regularize or stop early → reduce fitting of training-specific noise
  • Poor gradients → inspect activation and initialization → restore useful learning signals

How to evaluate

Assess held-out precision, recall and loss for classification, or regression error for numeric targets.

Answer flow

  1. Specify input and output
  2. Draw hidden structure
  3. Justify output activation and loss
  4. Explain training and validation checks

Exam traps

  • Backpropagation computes gradients
  • the optimizer performs updates
  • More layers are not automatically better.
Sample paper: 5002 Q1(b)

C108

Activation-function choices

Hidden activations provide nonlinearity. Output activation expresses the required prediction: sigmoid for one binary probability, softmax for mutually exclusive classes, and linear output for unrestricted numeric regression.

Problem it solves: Choose activations from the target meaning and gradient behavior, rather than using the same function everywhere.

How to use it

  1. Identify binary, multiclass, multilabel or numeric output
  2. Use ReLU as a practical hidden-layer choice
  3. Choose output activation consistent with the labels
  4. Pair it with an appropriate loss
  5. Inspect gradient and validation behavior
Example · data issues · evaluation · exam flow

Worked idea

Sample application: one of 918 exclusive product combinations needs 918 softmax outputs and categorical cross-entropy. A purchase yes/no model needs one sigmoid output and binary cross-entropy.

What can go wrong → what to change → why

  • Sigmoid hidden units saturate → consider ReLU and suitable initialization → reduce vanishing gradients
  • Mutually nonexclusive labels → use separate sigmoid outputs → several labels may be true

How to evaluate

Check probabilities, loss and per-class errors on held-out data; matching activation to task is necessary but does not guarantee accuracy.

Answer flow

  1. State target type
  2. Choose hidden activation
  3. Choose output activation
  4. Explain why the loss matches the output

Exam traps

  • Softmax classes compete and sum to one
  • ReLU is not a probability output.
Sample paper: 5002 Q2(a)

C109

RBF networks

An RBF network describes an input by its closeness to hidden-unit centers. Nearby inputs activate a Gaussian basis function strongly; the output combines these responses.

Problem it solves: Useful for nonlinear mapping when local regions in feature space provide a meaningful representation.

How to use it

  1. Scale inputs before calculating distances
  2. Choose hidden centers, often using clustering
  3. Set a width for each center
  4. Calculate radial responses for each training input
  5. Learn supervised output weights
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a sensor observation near the normal-operation center activates that unit strongly; one far away receives a weak response. Width determines how broad that neighborhood is.

What can go wrong → what to change → why

  • Widths too narrow → validate wider widths → avoid memorizing isolated training cases
  • Widths too broad → reduce widths or add centers → distinguish meaningful regions
  • Many centers → reduce them with clustering → control model size

How to evaluate

Tune center count and widths using validation classification or regression error; compare against a simple baseline.

Answer flow

  1. Explain why distance is meaningful
  2. Specify centers and widths
  3. Describe the two-stage training
  4. Connect model output to the target

Exam traps

  • An RBF hidden unit measures distance, not a perceptron-style global boundary
  • Scaling changes those distances.

C110

General regression neural networks

GRNN predicts a numeric value by combining stored training targets, giving greater influence to examples closer to the new input. Its output divides a similarity-weighted target sum by the similarity sum.

Problem it solves: Use for nonlinear regression where local similarity predicts the target and storing representative examples is feasible.

How to use it

  1. Scale and clean numeric inputs
  2. Store representative training inputs and targets in pattern units
  3. Calculate Gaussian similarity to the new input
  4. Sum similarity-weighted targets
  5. Divide by the sum of similarities
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: targets 10 and 20 receive similarities 0.8 and 0.2; prediction is (0.8×10 + 0.2×20)/(0.8+0.2) = 12.

What can go wrong → what to change → why

  • Small smoothing width → increase after validation → reduce sensitivity to noise
  • Large training memory → reduce representative patterns → improve inference cost
  • Distant query → flag weak support → local averaging may be unreliable

How to evaluate

Tune smoothing width using held-out MAE or RMSE; inspect errors in sparsely sampled regions.

Answer flow

  1. Identify numeric target
  2. Explain similarity weighting
  3. Show numerator and denominator
  4. Justify smoothing and validation

Exam traps

  • The denominator normalizes weights
  • GRNN is not the same architecture as a generic backpropagation MLP.

C111

Self-organizing maps

A self-organizing map maps high-dimensional inputs onto a small organized grid. The winning unit and its neighbors move toward each input, so similar observations tend to occupy nearby map positions.

Problem it solves: Use for unsupervised grouping and visualization when labels are absent and a neighborhood structure is useful.

How to use it

  1. Scale features and choose grid size
  2. Initialize unit prototype vectors
  3. Find the prototype closest to the input
  4. Move the winner and its grid neighbors toward that input
  5. Gradually reduce learning rate and neighborhood size
  6. Inspect and profile the resulting map
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: customers with similar spending profiles collect near one another on a two-dimensional grid; labels such as high spending are assigned only after inspecting profiles.

What can go wrong → what to change → why

  • One large-scale feature dominates → standardize → balance distances
  • Oversized grid with little data → validate a smaller grid → avoid many unsupported map units

How to evaluate

Check representation error, neighborhood preservation and whether the discovered profiles are meaningful for the task.

Answer flow

  1. State that training is unsupervised
  2. Explain winner selection
  3. Explain neighborhood updates
  4. Interpret the map without inventing known labels

Exam traps

  • SOM grid positions are not the original feature values
  • Unlike plain winner-only competition, neighbors also learn.

C112

CNN convolution, padding, stride

Convolution learns local filters and reuses each filter across an image. Padding controls border handling; stride is how far the filter moves between positions. Different filters produce different output channels.

Problem it solves: Use when local spatial patterns such as edges or shapes matter; weight sharing avoids a separate weight for every image position.

How to use it

  1. Write input height, width and channels
  2. Choose filter size and number of filters
  3. Choose padding and stride
  4. Slide filters across all input channels
  5. Add one bias per filter and apply activation
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: a 32×32 input with a 3×3 filter, no padding and stride 1 produces 30×30 positions. Padding 1 on each edge preserves 32×32 at stride 1.

What can go wrong → what to change → why

  • Shrinking maps lose border detail → add padding → retain coverage
  • Excessive stride loses small features → reduce stride → preserve spatial detail
  • Too many filters → reduce channel counts → control capacity and cost

How to evaluate

Check output dimensions and compare held-out recognition quality against computation and memory requirements.

Answer flow

  1. State the required visual patterns
  2. Specify filters, padding and stride
  3. Calculate output shape
  4. Justify the trade-off

Exam traps

  • Filter size and number of filters are different choices
  • A standard filter spans all input channels.
Sample paper: 5002 Q2(a)

C113

Pooling

Pooling summarizes a local patch without learning convolution weights. Max pooling keeps the largest activation; it reduces spatial dimensions and downstream computation while discarding some location detail.

Problem it solves: Useful after convolution when exact feature position is less important than whether a feature is present.

How to use it

  1. Select pooling window and stride
  2. Move the window over each channel independently
  3. Keep the maximum for max pooling
  4. Calculate reduced height and width
  5. Preserve the number of channels
Example · data issues · evaluation · exam flow

Worked idea

Lecture example: max pooling a 4×4 map with 2×2 nonoverlapping windows gives [[6,8],[3,4]]. A 61×61 map with window 4 and stride 2 gives floor((61−4)/2)+1 = 29 positions per side.

What can go wrong → what to change → why

  • Fine detail disappears → use less pooling or smaller stride → retain small-object evidence
  • Large flattened tail persists → inspect final feature-map dimensions → pooling may not be sufficient alone

How to evaluate

Compare validation quality and resource cost; inspect whether the smallest relevant object survives repeated downsampling.

Answer flow

  1. Explain what information is retained
  2. Compute spatial output
  3. State channels unchanged
  4. Justify whether that detail loss is acceptable

Exam traps

  • Ordinary max pooling has no learned weights
  • Pooling does not necessarily halve dimensions unless the settings do so.

C114

CNN dimensions and parameter counts

CNN shape calculations show how data moves between layers. Parameter counts show which layers dominate storage and fitting capacity; a large flattened Dense layer can outweigh all convolution layers.

Problem it solves: Use when asked whether a model is lean, feasible, or too complex for the available images.

How to use it

  1. Track height, width and channels after every layer
  2. For convolution use floor((input + twice padding − filter)/stride)+1 per spatial axis
  3. Count convolution weights as filter height × width × input channels × output channels, plus output-channel biases
  4. Flatten by multiplying final dimensions
  5. Count Dense weights as input units × output units, plus output biases
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: 3×3 convolution, 3 input channels and 16 filters has (3×3×3+1)×16 = 448 parameters. Sample Dense layer: 9408×256+256 = 2,408,704.

What can go wrong → what to change → why

  • Dense tail dominates → reduce hidden width → cut cost and capacity
  • Shape mismatch → recalculate each stage → ensure a valid architecture

How to evaluate

Compare total parameters, inference cost and validation performance; parameter reduction alone does not prove better accuracy.

Answer flow

  1. Locate the expensive layer
  2. Show the arithmetic
  3. Propose a smaller valid replacement
  4. Explain expected benefit and validation

Exam traps

  • Include biases
  • Reusing convolution weights means spatial positions do not multiply its parameter count.
Sample paper: 5002 Q2(a)

C115

Multi-input / multi-output architectures

Multiple inputs let a network combine different information sources. Multiple outputs let it learn several related targets, with a suitable output head and loss for each target.

Problem it solves: Use when the scenario includes images plus text or metadata, or requires several predictions about the same object.

How to use it

  1. List each input modality and its shape
  2. Give each modality a suitable processing branch
  3. Combine branch representations
  4. Attach task-specific output heads
  5. Define each target and corresponding loss
  6. Balance losses and validate every output
Example · data issues · evaluation · exam flow

Worked idea

Lecture application: video question answering combines a video with a question. The same video may require a person identity answer or an action answer depending on that question.

What can go wrong → what to change → why

  • One modality has a different scale or missing values → prepare it separately → avoid corrupting fusion
  • One task dominates training → adjust loss weighting → preserve the other task

How to evaluate

Measure each output separately and check whether using multiple inputs improves over single-input baselines.

Answer flow

  1. Identify information sources
  2. Draw branches and merge point
  3. Label each output
  4. Explain activation, loss and evaluation per head

Exam traps

  • Concatenating unrelated raw inputs is not automatically a good design
  • Multiple exclusive classes differ from multiple separate outputs.
Sample paper: 5002 Q1(d)

C116

Shared layers / encoder architectures

Shared layers apply the same learned feature extractor to different inputs. An encoder turns an input into a compact representation; shared encoding makes two observations comparable in the same learned feature space.

Problem it solves: Useful for comparing paired images or recognizing the same person across cameras.

How to use it

  1. Prepare both inputs consistently
  2. Pass each through the same encoder weights
  3. Compare or combine encoded representations
  4. Predict whether the pair matches
  5. Train on labeled matching and nonmatching pairs
Example · data issues · evaluation · exam flow

Worked idea

Lecture example: compare an entrance-camera photograph with an employee reference image; shared convolution layers encode both before the comparison stage.

What can go wrong → what to change → why

  • Different camera conditions → collect varied positive pairs → learn stable identity evidence
  • Separate encoders drift apart → share weights where justified → use a common feature transformation
  • Identity leakage → split by person when testing unseen-person generalization → make the evaluation realistic

How to evaluate

Evaluate false matches and missed matches on held-out pairs under realistic angle, lighting and occlusion conditions.

Answer flow

  1. Explain the comparison task
  2. Show two branches with shared weights
  3. Label the comparison stage
  4. State realistic validation cases

Exam traps

  • Shared weights mean one parameter set, not merely two identical-looking architectures
  • An encoder is not itself a final class label.

C117

RNN sequence representation

An RNN processes an ordered sequence while carrying a hidden state from one step to the next. The same recurrent weights are reused, so the current representation depends on earlier observations.

Problem it solves: Use when order matters, such as browsing events, speech, text or a sensor time series.

How to use it

  1. Define what one sequence and one time step mean
  2. Sort events in time
  3. Encode step features and scale numeric measurements
  4. Pad and mask unequal lengths when batching
  5. Feed the sequence to recurrent units
  6. Choose sequence-level or per-step output
Example · data issues · evaluation · exam flow

Worked idea

Sample application: each visitor session is a sequence of visited page IDs and durations; the final output predicts purchase probability.

What can go wrong → what to change → why

  • Randomly shuffled steps → restore temporal order → preserve the pattern
  • Future events in inputs → restrict to prediction-time information → prevent leakage
  • Long dependencies → consider LSTM → improve memory handling

How to evaluate

Split by session/user or time as required; assess held-out task metrics rather than isolated time-step accuracy alone.

Answer flow

  1. Define sequence
  2. Describe preprocessing
  3. Explain hidden-state memory
  4. Match output and loss to target

Exam traps

  • A list of aggregate counts does not preserve event order
  • CNN and RNN suitability depends on the information structure, not a universal power ranking.
Sample paper: 5002 Q1(d)

C118

LSTM and stacked recurrent networks

LSTM is a recurrent model with a memory cell and gates controlling what is kept, added and exposed. This helps learn longer dependencies than a plain RNN. Stacked recurrent layers learn successive sequence representations.

Problem it solves: Use for ordered data when earlier events can influence a later decision, such as a purchase at the end of browsing.

How to use it

  1. Build one correctly ordered sequence per case
  2. Encode categories, scale numeric features and pad/mask
  3. Use LSTM units to summarize relevant history
  4. Pass sequence outputs onward when stacking recurrent layers
  5. Attach a target-appropriate final head
  6. Train with validation monitoring
Example · data issues · evaluation · exam flow

Worked idea

Sample application: LSTM → Dense sigmoid predicts purchase/no purchase. To combine with AdaBoost, use out-of-fold LSTM scores as an extra training feature.

What can go wrong → what to change → why

  • Too many recurrent units → reduce width and stop early → control overfitting
  • Long irrelevant histories → choose a prediction window → reduce noise
  • Leakage in stacking → generate scores from held-out folds → avoid training on memorized predictions

How to evaluate

Compare against a simple aggregate-feature baseline using recall, precision and business costs.

Answer flow

  1. Justify why order matters
  2. Specify sequence preprocessing
  3. Draw LSTM and output
  4. Explain valid combination and evaluation

Exam traps

  • LSTM does not eliminate every gradient or data problem
  • The slide gate description contains a wording inconsistency: input gates add information, forget gates control retained memory.
Sample paper: 5002 Q1(d)

C119

Vanishing / exploding gradients

Backpropagation repeatedly multiplies local derivatives. Very small products make early-layer gradients vanish; very large products make them explode, causing unstable updates.

Problem it solves: Diagnose deep networks or long recurrent chains that learn very slowly, stop improving, or produce unstable losses.

How to use it

  1. Inspect training loss and gradient magnitudes
  2. Check saturation, depth and initialization
  3. Choose activation-compatible initialization
  4. Use residual connections for deep feedforward networks or LSTM for long sequences
  5. Reduce excessive learning rates and clip exploding gradients when needed
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: multiplying a derivative of 0.1 ten times produces 0.0000000001; an early layer receives a tiny learning signal.

What can go wrong → what to change → why

  • Saturated sigmoid → use suitable hidden activations → avoid repeated tiny derivatives
  • Exploding gradients → clip gradient norm → cap extreme updates
  • Poor initialization → Xavier or He as appropriate → improve scale propagation

How to evaluate

Look for stable learning and improved validation loss; a lower training loss alone does not establish better generalization.

Answer flow

  1. Identify the observed failure
  2. Explain small or large derivative products
  3. Match remedy to cause
  4. Check learning and validation again

Exam traps

  • Vanishing gradients and overfitting are different failures
  • Dropout is not the primary fix for exploding gradients.

C120

Xavier / He initialization

Initialization sets starting weights before learning. Random weights break symmetry; their scale should avoid making activations or gradients disappear or grow excessively through the network.

Problem it solves: Use when designing or debugging a deep network, especially if training fails from the beginning.

How to use it

  1. Identify hidden activation type
  2. Choose Xavier-style initialization for sigmoid/tanh networks
  3. Choose He initialization for ReLU networks
  4. Start biases at zero when appropriate
  5. Train and inspect activation, gradient and loss behavior
Example · data issues · evaluation · exam flow

Worked idea

Lecture He rule: with 100 inputs per neuron, weight variance is 2/100 = 0.02, so standard deviation is about 0.141. These are starting statistics, not fixed learned weights.

What can go wrong → what to change → why

  • All weights identical → randomize → neurons can learn different features
  • Huge initial weights saturate sigmoid → reduce scale → maintain useful derivatives
  • Tiny initial weights → choose suitable variance → preserve signals across depth

How to evaluate

Check stable convergence and validation performance across reasonable random seeds; initialization is one part of the training setup.

Answer flow

  1. Name the activation
  2. Choose a compatible initializer
  3. Explain symmetry and scale
  4. Distinguish initialization from regularization

Exam traps

  • Xavier formulas have multiple conventions
  • use the lecture or stated implementation convention in a calculation
  • Biases can be zero even though all connecting weights should not be identical.

C121

L1 / L2 regularization

L1 and L2 add weight penalties to prediction loss. L1 encourages some weights to become exactly zero; L2 discourages large weights and usually spreads influence across smaller nonzero weights.

Problem it solves: Use when training fits too closely to limited or noisy data; L1 can also support feature selection in suitable models.

How to use it

  1. Train a baseline and inspect training/validation gap
  2. Add a nonnegative penalty strength
  3. Choose L1 for sparse coefficients or L2 for shrinkage
  4. Tune strength using validation data
  5. Refit and assess on untouched test data
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: weights 3 and 4 have absolute-value total 7 for L1 and squared total 25 for L2, before multiplying by the chosen penalty coefficient.

What can go wrong → what to change → why

  • Penalty too weak → increase gradually → reduce excessive flexibility
  • Penalty too strong → reduce it → avoid underfitting
  • Features have incomparable scales → standardize → make penalties comparable

How to evaluate

Look for lower validation error and a narrower generalization gap, not the smallest raw training loss.

Answer flow

  1. Diagnose overfitting
  2. Choose penalty and explain its effect
  3. Tune strength without test reuse
  4. Compare the resulting validation performance

Exam traps

  • L2 is not guaranteed feature elimination
  • Dropout and batch normalization work differently from explicit weight penalties.
Sample paper: 5002 Q2(a)

C122

Dropout

Dropout randomly sets a fraction of activations to zero during training. The network cannot rely on the same particular hidden units always being available, reducing co-adaptation.

Problem it solves: Use as a regularization option when a network overfits; choose placement and strength based on validation rather than habit.

How to use it

  1. Identify a training/validation overfitting gap
  2. Add dropout to suitable hidden representations
  3. Choose a dropout fraction
  4. Train with fresh random masks
  5. Evaluate in inference mode with dropout disabled and the framework scaling convention applied
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: dropout rate 0.3 means roughly 30% of the targeted activations are removed on a training pass; it does not permanently delete 30% of model parameters.

What can go wrong → what to change → why

  • Excessive dropout harms learning → lower rate → retain enough signal
  • Dropout enabled at normal evaluation → switch to inference mode → obtain the intended deterministic prediction
  • Small data remains unrepresentative → improve coverage → regularization cannot invent missing cases

How to evaluate

Compare validation loss and task metrics; accept dropout only if it improves generalization under the same split.

Answer flow

  1. Identify overfitting evidence
  2. Explain temporary random omission
  3. Specify training versus inference behavior
  4. Justify rate using validation

Exam traps

  • Dropout does not directly add an L1/L2 penalty
  • It does not automatically reduce stored parameter count.

C123

Batch normalization

Batch normalization standardizes intermediate activations using batch statistics during training, then learns scale and shift. It often makes optimization more stable; any regularization effect is secondary.

Problem it solves: Use to improve training behavior in a suitable deep architecture, not as a synonym for input preprocessing or dropout.

How to use it

  1. Insert batch normalization at an appropriate layer position
  2. Estimate batch mean and variance during training
  3. Normalize activations and apply learned scale and shift
  4. Maintain running statistics
  5. Use stored statistics in inference mode
Example · data issues · evaluation · exam flow

Worked idea

Lecture values have mean 0.54 and standard deviation 0.69; a value 1.6 becomes approximately (1.6−0.54)/0.69 = 1.54 before learned scale and shift.

What can go wrong → what to change → why

  • Very small batches produce noisy estimates → reconsider batch size or normalization choice → stabilize statistics
  • Training/evaluation mode mismatch → use inference mode for testing → avoid batch-dependent errors

How to evaluate

Compare convergence speed, stable loss and held-out quality; do not claim it guarantees absence of overfitting.

Answer flow

  1. Identify optimization difficulty
  2. Explain normalization and learned rescaling
  3. State training/inference distinction
  4. Compare with weight penalties and dropout

Exam traps

  • Batch normalization does not remove neurons
  • It is different from fitting a scaler once on the original training features.

C124

Residual connections

A residual connection adds a block’s input to its learned transformation. The block can learn a correction to the input rather than having to rebuild the entire desired mapping.

Problem it solves: Use to train deeper networks more effectively when adding layers makes optimization difficult.

How to use it

  1. Group layers into a residual block
  2. Compute the block transformation
  3. Pass the original input through a shortcut
  4. Add shortcut and block output
  5. Match shapes with a projection when necessary
  6. Train and compare against a plain network
Example · data issues · evaluation · exam flow

Worked idea

Self-attention lets each token combine information from other tokens in the same sequence. Multiple heads learn separate comparisons, allowing several relationship patterns to be represented together.

Problem it solves: Useful when the meaning of one token depends on context elsewhere in the input, including distant context.

How to use it

  2. Compare each query with available keys
  3. Scale scores and turn them into normalized weights
  4. Form a weighted combination of value vectors
  5. Repeat with different learned projections in several heads
  6. Combine head outputs

An ensemble combines several model predictions. It helps most when the individual models are useful and make different errors, so their mistakes can partly cancel.

Problem it solves: Use when a single model is unstable or several complementary sources of predictive evidence are available.

How to use it

  2. Encourage diversity through data, features or model choices
  3. Generate predictions on valid held-out cases
  4. Combine using majority vote, averaged probabilities or justified weights

C129

Bagging and bootstrap sampling

Bagging trains models on bootstrap samples and aggregates their predictions. A bootstrap sample is drawn with replacement, so some observations repeat and some are left out.

Problem it solves: Useful for reducing variance of unstable learners such as deep decision trees.

How to use it

  1. Draw a same-size sample with replacement from training data
  2. Train one base model
  3. Repeat independently for many models
  4. Vote for classification or average numeric predictions
  5. Use out-of-bag predictions or validation data to estimate quality
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: sampling five times from records A–E might produce A,A,C,E,C; B and D are out of that sample. Standard same-size bootstraps contain about 63% unique observations on average.

What can go wrong → what to change → why

  • Base models repeat identical errors → increase meaningful diversity → averaging cannot cancel shared bias
  • Correlated observations leak across evaluation → split by entity first → preserve independence
  • Too few models → add models until validation stabilizes → reduce sampling variability

How to evaluate

Use out-of-bag estimates for development and a final untouched test set when available; match metrics to the application.

Answer flow

  1. Explain replacement
  2. Describe independent training
  3. State aggregation
  4. Explain why variance falls

  • The lecture two-thirds description is an approximation, not the definition of bootstrap sample size.

Boosting adds learners sequentially to improve the current ensemble. AdaBoost increases emphasis on training observations that previous learners classified incorrectly, then combines learners using performance-based weights.

Problem it solves: Useful when several weak but informative learners can form a stronger classifier.

How to use it

  1. Start with equal observation weights
  2. Fit a weak classifier
  3. Calculate its weighted error
  4. Increase relative weight of misclassified observations
  5. Fit the next learner on the revised weighting
  6. Combine learner votes with learned weights
Example · data issues · evaluation · exam flow

Worked idea

What can go wrong → what to change → why

  • Too many rounds → validate early stopping/learning rate → control overfitting

Gradient boosting builds an additive model sequentially. Each new learner addresses the current loss errors; with squared-error regression this corresponds to learning the remaining residuals.

Problem it solves: Useful for strong nonlinear tabular prediction where shallow trees can gradually correct systematic errors.

How to use it

  1. Choose a task-appropriate differentiable loss
  2. Start with a simple constant prediction
  3. Calculate what changes would reduce current loss
  4. Fit a small learner to those correction targets
  5. Add a scaled correction using a learning rate
  6. Monitor validation performance across rounds
Example · data issues · evaluation · exam flow

Worked idea

Illustrative: actual sales are 10 and current prediction is 7; the residual is 3. A learner predicting correction 2 with learning rate 0.1 changes the prediction to 7.2.

  • Large updates → lower learning rate → make gradual corrections

C008

Simulated annealing（模擬退火）

Simulated annealing is an optimisation search that sometimes accepts a worse move, helping escape a local minimum. The chance of accepting worse moves decreases as temperature（溫度） cools.

Recognise（辨識；從資料找出物件或模式） this in a question: Local optimum（局部最優解）, stuck, no need for full path, improve a candidate

What this tells us: B was worse than A but enabled C. Greedy（貪婪式） local improvement would reject B and remain at 10 in this neighbourhood. Annealing makes escape possible, not certain, and the final returned best must still satisfy hard constraints（硬性約束）.

How can accepting a worse move escape a local trap?

  • Annealing changes the local-search acceptance rule. An improving neighbour is accepted, but a worse neighbour may also be accepted with probability governed by how much worse it is and the current temperature. Early exploration（探索新選擇） can therefore leave a basin that traps always-improve search.
  • As temperature decreases, worse moves become less likely, shifting effort from exploration toward refinement. Cooling too quickly removes that opportunity before the search has explored useful alternatives. Never cooling enough keeps discarding useful improvements in favour of random wandering.
  • The best solution encountered should be tracked separately from the current solution: accepting a worse current candidate need not erase a better earlier result. The supplied lecture briefly lists annealing as a local-minimum escape technique; this procedural explanation is study elaboration rather than a detailed taught numerical schedule.
Implementation steps and their purpose
  1. Define candidate solutions, allowed neighbours and objective.
  2. Start from a solution and a temperature schedule.
  3. Propose a random neighbour.
  4. Accept improvements; sometimes accept a worse move according to temperature and deterioration.
  5. Cool gradually, repeat and retain the best solution found.

Choose the method from the problem

Useful when the search/error landscape has local traps and always-improve local search（局部搜尋） can get stuck.

Common wrong answers and the exact correction
  • Temperature is an algorithm control, not model prediction（預測） confidence（信賴度；前件出現時後件也出現的比例）.
  • This is an optional optimiser（最佳化器；按梯度更新參數）, not a guaranteed cure for every training（訓練） issue.

Implement it and test the outcome

Data, components and application

  • Cooling too quickly → slow cooling or restart → search may freeze in a poor basin.
  • Always accepting worse moves → reduce temperature → otherwise search resembles random wandering.

How to evaluate it

Compare best feasible objective across repeated runs and time budgets. A single successful run is not a general optimality（最優性） guarantee.

Build the answer in this order

  1. Identify the local-trap problem.
  2. Define neighbours and objective.
  3. Explain controlled worse-move acceptance.
  4. Justify（給出理由；用情境與證據支持選擇） stopping and compare repeated results.

An answer you could write

  • I may accept penalty12 temporarily from penalty10 at high temperature because it permits reaching the penalty4 region that greedy improvement cannot enter here.
  • I retain best feasible penalty4 separately, cool exploration gradually and compare repeated runs; annealing makes escape possible without a global-optimum guarantee.

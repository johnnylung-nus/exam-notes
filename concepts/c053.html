Sequence-based recommendation（推薦）

Sequence-based recommenders use the order of a user’s interactions to predict the next useful item or rank（秩；矩陣獨立資訊的維度數） candidates for current intent（意圖）.

Recognise（辨識；從資料找出物件或模式） this in a question: Next item, session（工作階段；一次連續造訪的記錄） history, connected users/items, nonlinear（非線性；不能只用線性關係表示） preferences

Illustrative session intent and leakage

Worked study example: User browses shirts, briefly clicks trousers, then returns to a shirt. These invented events mirror the lecture accidental-side-excursion issue.

What this tells us: A model that blindly follows the latest click may rank trousers. A validated sequence-aware model can use broader shirt context, but the improvement must be measured rather than assumed from its architecture（架構） name.

How does the order of past interactions change the next recommendation?

  • A session sequence（序列；有先後順序的資料） represents a changing intent through ordered events. A bag of viewed items loses which event happened recently and which preceded it. A next-item model learns from prefixes to a later target, while a candidate-ranking model uses the sequence to judge each supplied candidate; these are distinct outputs.
  • Different lecture models use sequence evidence differently. Prod2Vec learns item relationships from session context using a word-embedding analogy（類比；由相似案例推想）; GRU4Rec processes ordered events through recurrent state; attention/Transformer（注意力轉換模型） methods can weight relevant past events rather than letting the latest accidental click dominate.
  • Training examples must stop at the prediction time. A label（標籤；作比較的正確答案） such as the next purchase or click belongs after the prefix and cannot appear among its input features（特徵；描述樣本的屬性）. Session boundaries, repeated events and timestamps need consistent（一致性） handling. Recent evidence can be useful without proving that a user’s temporary browsing goal represents permanent taste.
Implementation steps and their purpose
  1. Group and time-order events into user/session sequences.
  2. Encode items and available context.
  3. Train next-item prediction or candidate ranking（排序） using only earlier events.
  4. Use RNN（Recurrent Neural Network；循環神經網路）/GRU or attention/Transformer according to the lecture design.
  5. Serve candidates/rankings and update session context.

Prepare the data and validate the representation（表徵；資料的表示方式）

Data, components and application

  • Accidental recent click → attention to relevant history → latest event alone may distort intent.
  • Future leakage → chronological construction/split（切分；按條件分開資料） → prediction cannot use later clicks.

How to evaluate it

Evaluate next-item/ranking success on later events plus latency. Check anonymous sessions and short histories.

Build the answer in this order

  1. Identify sequence/target.
  2. Define event order and features.
  3. Explain model’s sequence use.
  4. Validate future predictions.

Choose the representation from the task

Useful when recent session behaviour matters, such as a shopper’s changing goal or news interests.

Common wrong answers and the exact correction
  • A session is not automatically a lifelong user profile.
  • A ranking model need not be the catalogue retrieval（檢索） model.

An answer you could write

  • “I build ordered prefixes from events before prediction, using the next interaction only as the target.”
  • “The shirt-history example motivates testing relevant-history attention against a recency-only model; I evaluate later-event ranking without future leakage.”

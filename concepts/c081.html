C081

Soar architecture（架構）

Soar’s lecture example separates long-term action knowledge from the current state and constructed search states in working memory（工作記憶；當前處理的資訊）.

What must the system deliver?

Use when explaining how a cognitive architecture represents a problem and selects actions（動作） toward a goal.

Scenario cueSuitable choiceWhy it fits
Need represent reusable proceduresLong-term knowledgeOperators persist across current cases.
Need evaluate this current configurationWorking memory/state space（狀態空間）The solution depends on current state and goal.

How do working memory, operators and productions interact in Soar?

  • The Soar example stores reusable operators and relations（關係；對象間的連結） in long-term memory（長期記憶）; working memory contains the current problem and constructed states.
  • Operators describe legal transformations（變換；把資料轉成另一表示）, while state values describe current quantities. Confusing them makes it impossible to verify a search path.
  • Search chooses a sequence（序列；有先後順序的資料）, not just the locally closest-looking state. Some legal solutions temporarily move farther from the final quantity.
  • Loop restrictions and path-length preferences can guide search, but a particular heuristic（啟發式；引導搜尋的估計） is not by itself proof of a globally shortest solution.
Implementation steps and their purpose
  1. Represent current state and goal in working memory.
  2. Keep reusable objects, relations and operators in long-term memory.
  3. Apply only legal operators to generate next states.
  4. Search the resulting state space.
  5. Select a path that reaches the goal and meets the stated cost preference.

What this tells us: A state such as (3,3) is not permanent action knowledge. The same operator can be applied to multiple states with different resulting amounts.

Data, implementation and validation

Data, components and application

  • State confused with operator → separate water amounts from fill/pour/empty actions → clarifies search.
  • Immediate error reduction required at every step → allow necessary temporary increases → a legal goal-reaching path need not improve monotonically.
  • Loops → track/restrict unhelpful reversals → avoids repeated states.

How to evaluate it

Check operator legality, capacity constraints（約束條件）, goal attainment and path length where required.

Build the answer in this order

  1. State/goal.
  2. Memory contents.
  3. Operators and transitions（狀態轉移）.
  4. Search result and cost.

Diagnose: Search loops repeatedly

Common wrong answers and the exact correction
  • Working memory is not the entire permanent knowledge base（知識庫；供推理查用的知識）.
  • A goal-distance heuristic does not alone prove optimality（最優性）.

An answer you could write

  • Store reusable fill/pour/empty operators in long-term knowledge and the current amounts/goal in working memory.
  • Apply legal operators to construct successor（後繼狀態；一次動作可到達的狀態） states and search for a path ending with one litre in the 3L mug.
  • Track unhelpful reversals and do not claim that an immediate-distance heuristic alone proves shortest-path optimality.

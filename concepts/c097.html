Contrastive learning（對比學習）

Contrastive learning shapes the representation（表徵；資料的表示方式）: positive pairs should be similar, while negative pairs should be less similar.

What this tells us: The model cannot infer（推論；由依據得出結論） the correct notion of sameness from arbitrary pair labels. Specify whether the goal is activity, person identity or fault type before making pairs.

Which pairs should a contrastive representation pull together?

  • Contrastive learning teaches what should be close in feature space（特徵空間；以特徵作座標的空間） by constructing positive pairs and what should be separated using negative pairs.
  • The pair rule encodes the intended invariance（不變性；指定變化下結果不變）. Two views of one window may be positive only if the transformation（變換；把資料轉成另一表示） preserves the activity/fault meaning.
  • Incorrect negative construction can push together-class examples apart; incorrect positives can merge different classes（類別；分類目標）. Pair quality is part of the learning problem.
  • The contrastive objective is not reconstruction（重建）. A representation can ignore irrelevant variation while preserving task-relevant differences without reproducing every input value.
Implementation steps and their purpose
  1. Define what should count as the same underlying event/object（客體；三元組終點）.
  2. Create positive pairs with valid augmentation（增強；產生保留所需意義的資料變體） or context.
  3. Select appropriate negative pairs.
  4. Train the encoder（編碼器） to bring positives together and separate negatives.
  5. Test learned features on the target task.

Prepare the data and validate the representation

Data, components and application

  • Augmentation changes the class → constrain transformations → positives must retain target meaning.
  • False negatives → inspect pair construction → semantically similar inputs should not be forced apart unnecessarily.
  • Good pair loss but weak task result → evaluate downstream（後續階段；使用前一步結果的模型或流程） labels → pretext success alone is insufficient.

How to evaluate it

Assess retrieval（檢索）/neighbour quality, downstream prediction（預測） and robustness to the intended transformations.

Build the answer in this order

  1. What must remain similar?
  2. Positive/negative construction.
  3. Representation objective.
  4. Downstream benefit and pair errors.

Choose the representation from the task

Use when the desired invariance can be specified through paired views instead of a class label for every input.

Common wrong answers and the exact correction
  • Contrastive learning does not reconstruct every input by definition.
  • Choose invariance for the actual sensing task.

An answer you could write

  • I define positive pairs as views preserving the target activity and negatives as justified different examples.
  • I avoid transformations that alter class-defining magnitude or timing.
  • I evaluate downstream classification and robustness, not contrastive loss alone.

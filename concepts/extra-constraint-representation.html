Constraint-Based Representation

Represent a problem using variables, their allowed domains and constraints. The representation states what is allowed; backtracking is one procedure for finding a compatible assignment.

What to draw / write: Constraint-based representation

Variables: A, B, C
Domains: state the allowed values for A, B, C
Constraints:
  A ≠ B
  B ≠ C
  A + C = 10
Variable
An unknown decision to assign.
Domain
Allowed values for each variable; derive them from the question.
Constraint
A relation that permitted assignments must satisfy.
  • Exam answer: Write Variables / Domains / Constraints explicitly.
  • The three constraints are on the lecture slide; domains are not supplied there, so do not invent them as lecture facts.
  • Use the question’s values and separate hard rules from soft preferences.

Used Cases:

The use-case names come from the lecture. The short scenarios below explain how to recognize them in an exam; they are teaching examples, not quoted exam questions.

Lecture use caseWhat it meansExample / clue in a question
Scheduling（排程）Assign tasks/resources while obeying restrictions.Assign jobs to workers and time slots; no worker can perform two overlapping jobs.
Timetabling（時間表安排）Assign events to times/rooms without conflicts.Place exams in rooms and periods; avoid student clashes and respect room capacity.
Configuration problems（配置問題）Choose compatible parts/options subject to rules.Select computer parts whose socket, memory and power requirements are compatible; state variables, domains and constraints.

Choose by the required job: explain what knowledge is stored and how this representation helps with the scenario. A use-case name alone is not a sufficient reason.

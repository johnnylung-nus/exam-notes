Hyperparameter tuning（超參數調整） and generalization（泛化能力）

Hyperparameters（超參數） are choices made outside ordinary weight fitting, such as tree depth, neighbor count, learning rate（學習率） or dropout（隨機停用神經元） rate. Generalization is success on new cases, not fitting training（訓練） examples perfectly.

Recognise（辨識；從資料找出物件或模式） this in a question: Training improves, validation worsens, memorisation, limited labelled data · Preprocessing（前處理）, leakage, small dataset, validation, tune hyperparameters

Which validation evidence（證據；已觀察到的資訊） justifies a hyperparameter choice?

  • Hyperparameters set model-building behavior rather than being ordinary fitted coefficients: tree depth, neighbor count, learning rate and dropout rate are examples. Their quality is measured by validation of the complete fitted pipeline（處理流程）.
  • Compare training and validation together. Both poor suggests underfitting（擬合不足） or weak features（特徵；描述樣本的屬性）; training excellent and validation poor suggests overfitting（過度擬合） or split（切分；按條件分開資料） mismatch. The observed pattern should determine the remedy.
  • An extensive search can overfit validation by repeatedly choosing lucky scores. Restrict the search to plausible settings, compare variation across folds and keep a final untouched assessment rather than indefinitely chasing tiny gains.
Implementation steps and their purpose
  1. Set a simple baseline（基準；供比較的簡單方法） and relevant（相關性；是否切合問題） validation metric
  2. Choose a small justified search space
  3. Fit complete pipelines inside each training fold
  4. Compare validation results using grid or random search
  5. Prefer a simpler model when performance is comparable
  6. Evaluate the selected pipeline on the final test

Common wrong answers and the exact correction
  • Learned weights（權重） differ from hyperparameters
  • Lower training loss（損失函數；衡量預測錯誤） is not the selection rule.

Implement it and test the outcome

Data, components and application

  • Too many searches overfit validation → reduce speculative searching or use nested validation → get a more honest estimate
  • Both training and validation poor → improve features or capacity → address underfitting
  • Large train–validation gap → regularize or simplify → address overfitting

How to evaluate it

Track validation mean（均值；平均數）/spread, final target metrics and runtime; keep the final test out of selection.

Build the answer in this order

  1. Diagnose underfit versus overfit
  2. Name the actual adjustable setting
  3. Explain the validation procedure
  4. State the expected trade-off（取捨；改善一項可能犧牲另一項）

An answer you could write

  • “Depth4 gives the best validation recall at0.82, whereas unlimited depth overfits despite perfect training recall.”
  • “I select settings through validation and use the final test only after selection.”

Where this is tested in the sample papers

ISY5002 Q1(a) — Interpret a tree and connect it to business value

What the question requires

  1. Read the supplied branches for likely purchasers.
  2. Explain the action supported by that prediction（預測）.
  3. Identify a specific model/data weakness and proposed improvement.
  4. Test whether the change improves business outcome, not just training fit.

Proposed answer points

  • High PageValue（頁面價值；題目定義的頁面平均經濟價值） and low BounceRate（跳出率；進站後未觸發其他請求便離開的比例） characterize purchase-likely branches in the displayed model. This can guide targeted offers.
  • Test whether adding product-page engagement improves held-out（留出資料；未參與該階段訓練） prediction. Check feature availability at the intervention time, then assess incremental sales/profit with an appropriate controlled comparison.

Avoid: Do not assume every browser with high page activity will buy, or infer（推論；由依據得出結論） causal（因果；一者造成另一者變化） sales gains from offline accuracy（準確率） alone.

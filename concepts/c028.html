C028

Decision-tree（決策樹；逐條條件作判斷） reasoning（推理）

A decision tree learns feature（特徵；描述樣本的屬性） tests from labelled data. Prediction（預測） follows one branch per test to a leaf（葉節點；決策樹的最終輸出） containing a class（類別；分類目標） or numeric（數值型；以數量表示） output.

Recognise（辨識；從資料找出物件或模式） this in a question: Explain purchase rules, feature split（切分；按條件分開資料）, entropy（熵）, information gain（資訊增益）, many tiny leaves

How does a decision tree turn evidence（證據；已觀察到的資訊） into a conclusion（結論）?

  • A decision tree converts feature tests into a path to an output. During training, splits are selected from labelled examples; during prediction, the learned thresholds/categories are fixed and a new case follows one branch at each node. Training and traversal（遍歷） are different computations.
  • A root-to-leaf path can be explained as an AND of its branch conditions. This is why a tree can act like learned rules, but the conditions were induced statistically rather than necessarily supplied by experts. A leaf’s label distribution（分布） is empirical support（支持度；同時出現的交易比例）, not automatically a calibrated（校準；令量測或機率對應實際意義） clinical probability（機率）.
  • A deep tree can isolate individual training records and noise（雜訊；干擾有效訊息的成分）. Restricting depth, requiring larger leaves or pruning（剪枝） removes fragile distinctions. A forest trains multiple trees and aggregates their outputs: a node split is not a separate tree, and adding new database records does not itself retrain existing trees.
Implementation steps and their purpose
  1. Specify input features and training labels.
  2. Clean/encode features without leaking the label.
  3. Learn splits separating useful outcomes.
  4. Limit depth/prune or tune minimum leaf size.
  5. For a new case, follow tests and explain its path.

Prepare the data and validate the representation（表徵；資料的表示方式）

Data, components and application

  • Very deep tree → pruning/validation → small leaves may memorise noise.
  • Missing/unavailable input → define handling or ask for information → prediction cannot rely on future outcomes.

How to evaluate it

Use held-out（留出資料；未參與該階段訓練） classification/regression（迴歸；預測連續數值） checks appropriate to the target; inspect errors and tree complexity. For an ensemble（集成學習）, combine tree outputs explicitly（明確；直接提供的資訊）.

Build the answer in this order

  1. Define example, inputs and label.
  2. Explain learning splits.
  3. Trace inference.
  4. Describe validation and overfitting（過度擬合） control.

Common wrong answers and the exact correction
  • A tree is an algorithm/model, not a database cylinder.
  • Each node split is not a separate trained tree.

An answer you could write

  • Parcel A follows distance>5 and high backlog to the delay leaf, while parcel B follows the same first branch but low backlog to on-time.
  • Historical outcome is the label used to learn these tests, not a prediction-time feature; I prune or limit depth and evaluate unseen parcels.

Where this is tested in the sample papers

ISY5001 Q3(a)(i) — Model choice against a ranked-output requirement

What the question requires

  1. Underline “least suitable”.
  2. Identify the required ranked list of diagnoses.
  3. Compare the proposed methods under stated assumptions（假設；答案依賴但題目未明說的條件）.

Proposed answer points

  • Under a basic hard-label single-tree interpretation, a single tree is the intended weak choice because the required output is a ranked differential list.
  • A single tree can in fact（事實；推理中已知的資訊） rank classes by leaf class proportions; explain the assumed implementation rather than asserting an inherent impossibility.

Avoid: Choosing a suitable model does not answer which is least suitable. There is no official key confirming a unique implementation assumption.

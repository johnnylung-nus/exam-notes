Data splits and cross-validation（交叉驗證）

Training（訓練） data fits model parameters（參數）; validation data guides choices; test data estimates final generalization（泛化能力）. Cross-validation rotates the validation fold to obtain a less split-dependent development estimate.

What this tells us: If the operational target is future sessions of existing users, a time-based design may be more appropriate; state the intended claim explicitly（明確；直接提供的資訊）.

What information must stay out of model fitting and tuning?

  • A split（切分；按條件分開資料） should represent what new means: new users, future time periods or new physical units. Randomly splitting correlated（相關；數值一同變化的程度） fragments from the same case can make validation look independent when the model has effectively seen that case.
  • All fitted preparation and selection must occur inside each fold. Scaling, feature removal or PCA（Principal Component Analysis；主成分分析） performed before cross-validation lets the validation partition influence the model-building process.
  • Cross-validation gives repeated development comparisons; the final untouched test estimates the selected pipeline. Repeatedly choosing the best method from test results converts that test into another development set.
Implementation steps and their purpose
  1. Choose a split matching the deployment unit and time order
  2. Keep a final test set（測試集） untouched
  3. Fit preprocessing on each training partition
  4. Train and score each validation fold
  5. Choose settings using validation results
  6. Refit the selected pipeline and assess the final test once

Prepare the data and validate the representation（表徵；資料的表示方式）

Data, components and application

  • Duplicates or related sessions cross partitions → group split → avoid memorization leakage
  • Future data predicts past → chronological split → match deployment
  • Feature selection（特徵選擇） uses all labels（標籤；作比較的正確答案） → move selection inside folds → keep validation honest

How to evaluate it

Report mean（均值；平均數） and spread across folds plus final test metrics, especially rare-class performance.

Build the answer in this order

  1. Define unseen-case meaning
  2. State split method
  3. Explain what is fit on training only
  4. Describe fair model comparison

Choose the representation from the task

Use whenever comparing models, selecting features or tuning settings without contaminating the final assessment.

Diagnose: Validation is excellent but new-user performance collapses

What you observeWhy it happensWhat to changeWhy that helps
Validation is excellent but new-user performance collapsesRelated sessions crossed the splitGroup by user before any fittingThe evaluation（評估） then measures transfer to unseen users rather than recall（召回率） of familiar behavior.
Common wrong answers and the exact correction
  • Repeatedly choosing from test scores turns the test into validation
  • Random splits are inappropriate for some temporal（時間的） tasks.

An answer you could write

  • “I group sessions by user before fitting any preprocessing because the target is new-user generalization.”
  • “I tune using validation users and retain the final test users for the selected pipeline only.”

C062

TF-IDF（Term Frequency–Inverse Document Frequency；詞頻與逆文件頻率） and cosine similarity（餘弦相似度）

TF-IDF gives more weight to distinctive words. Cosine similarity compares vector directions to rank（秩；矩陣獨立資訊的維度數） related texts.

How does a query become a comparable vector?

  • TF-IDF is a representation（表徵；資料的表示方式） step: distinctive terms receive greater weight than words common across the collection. It does not itself retrieve an answer.
  • Cosine similarity compares vector directions. Ranking（排序） chooses the closest stored question, then its identifier retrieves the linked approved answer.
  • Stored questions and new queries must use the same fitted vocabulary/weights（權重） or embedding model. Vectors from incompatible spaces cannot be meaningfully compared.
  • A threshold checks match adequacy; it is an application-tuned decision, not a universal number or probability（機率） of medical correctness.
  • Tiny cosine calculation, using supplied weights in the same two word dimensions: query [1,1] and stored question A [1,1] have matching-position products 1×1 + 1×1 = 2. Each vector has length √2, so similarity is 2/(√2×√2) = 1.
  • For stored question B [1,0], the matching-position products sum to 1 and its length is 1, giving 1/(√2×1) ≈ 0.707. Dividing by both lengths compares direction rather than rewarding a question simply for having larger weights. These supplied vectors illustrate the calculation, not the FAQ scores below.
Implementation steps and their purpose
  1. Prepare stored questions using consistent（一致性） tokenization.
  2. Fit the vocabulary and word weights on the stored/training（訓練） collection.
  3. Transform stored questions and new query in the same vector space.
  4. Compare query against candidate vectors using cosine similarity.
  5. Return the linked answer only when the match is adequate.

Use the result and check it

Data, components and application

  • Synonyms share few words → use semantic（語義；所表達的意思） embeddings → better captures paraphrases.
  • Weak nearest match → clarify/fallback（備援處理） → the closest available answer can still be wrong.

How to evaluate it

Test known paraphrases and unrelated questions; measure whether the retrieved approved answer is relevant（相關性；是否切合問題）.

Build the answer in this order

  1. Existing FAQ → stored question-answer links.
  2. Same representation for query and collection.
  3. Similarity rank → answer lookup.
  4. Check relevance and fallback.

Common wrong answers and the exact correction
  • A vector store is not automatically a knowledge graph（知識圖譜）.
  • Cosine similarity is not a calibrated（校準；令量測或機率對應實際意義） probability.

When would this calculation be useful?

Use for a simple text-classification or FAQ-retrieval baseline（基準；供比較的簡單方法）; embeddings are more suitable when different words express similar meaning.

Scenario cueSuitable choiceWhy it fits
Similar wording and simple baseline neededTF-IDF plus cosineEasy to inspect term contributions and evaluate retrieval.
Different wording with same meaningSentence embeddings plus cosineCan match semantic paraphrases with little shared vocabulary.

An answer you could write

  • Store the specialist’s FAQ question–answer pairs with stable IDs and represent stored questions and the new query using the same embedding model.
  • Rank stored question vectors by cosine similarity; when the best match is adequate, return its linked approved answer.
  • If no adequate match exists, ask for clarification or report that no approved match is available; a generative model or knowledge graph is unnecessary for this direct lookup.

Where this is tested in the sample papers

ISY5001 Q1(b) — FAQ retrieval without unnecessary architecture（架構）

What the question requires

  1. Store approved question–answer pairs.
  2. Represent stored questions and the new query consistently.
  3. Retrieve the closest question and its linked approved answer.
  4. Clarify or fall back when no reliable match exists.

Proposed answer points

  • New query → embedding/similarity search → matched FAQ ID → linked answer.
  • A generative LLM（Large Language Model；大型語言模型） or knowledge graph is not required. Retrieval plus generation would be a different, justified extension.

Avoid: Similarity is not proof the retrieved answer is correct; keep a fallback.

C005

A* search（A星搜尋）

A* compares the estimated whole journey: cost already paid plus estimated cost remaining. It keeps competing frontier（待探索節點集） paths, not only the current node’s children.

Candidate search node.
g(n)
Actual accumulated cost from the start to n.

Estimated remaining cost from n to the goal.
f(n)

Why is the first generated goal not necessarily optimal?

  • A* estimates the complete route through a waiting node: g is everything already paid from the start, h estimates the remaining journey, and f=g+h. The comparison is across all retained frontier entries. Moving into one branch does not erase promising alternatives from previous expansions.
  • An admissible（可採納性；不高估成本） h is a lower bound（下界；真值不會比它更小） on the true remaining cost. A frontier f therefore bounds how cheaply a solution through that node could turn out. If a generated goal costs 450 but another waiting node has f=417, the unfinished route could still beat the goal and must be considered.
  • Graph duplicate handling matters as well as admissibility. If a cheaper route reaches an already expanded state, reopen it unless the implementation can rely on a consistent（一致性） heuristic. A* is not simply “choose the child nearest the destination”; that would ignore g and potentially ignore the global frontier.
Implementation steps and their purpose
  1. Set cost so far g(start)=0; h is estimated remaining cost.
  2. Calculate f=g+h for every frontier entry.
  3. Expand（展開；產生節點的後續候選） the globally lowest f; keep unexpanded alternatives.
  4. For each child, add the edge to the parent g and update cheaper paths.
  5. Stop when the goal is selected as the lowest-f frontier entry.

Use the result and check it

Data, components and application

  • Stopping on goal generation（生成式；學習資料生成或分布） → continue frontier comparison → another route may be cheaper.
  • Inconsistent heuristic → reopen improved states or require consistency → closed-state shortcuts can lose optimality（最優性）.

How to evaluate it

Check cumulative g, correct h and all frontier f values. Optimality needs admissibility plus correct repeated-state handling.

Build the answer in this order

  1. Define g, h and f in words.
  2. Maintain frontier across branches.
  3. Update cheaper duplicate paths.
  4. Explain stopping and optimality conditions.

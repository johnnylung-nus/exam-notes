Graph-based recommendation（推薦）

Graph-based recommendation models users, items and other entities（實體；被描述的對象） as nodes, with interactions/relationships as edges. Recommendation can become missing-link prediction（預測）.

Recognise（辨識；從資料找出物件或模式） this in a question: Next item, session（工作階段；一次連續造訪的記錄） history, connected users/items, nonlinear（非線性；不能只用線性關係表示） preferences

What this tells us: The candidate has several interpretable supporting paths. This is stronger explanation than saying “GNN（Graph Neural Network；圖神經網路） predicts B”, but still needs held-out usefulness checks and source-quality control.

How do graph neighbours transmit recommendation evidence?

  • A recommendation graph can combine user–item interactions with categories, creators or social links. That structure may connect entities with little direct rating overlap, but each edge type must retain its meaning: friendship, purchase and membership（隸屬度） are not interchangeable levels of preference.
  • Graph representations（表徵；資料的表示方式） can be learned through sampled walks or neighbour aggregation（鄰居聚合；整合相鄰節點資訊）. Node2Vec turns walks into contexts for embedding（嵌入；用向量表示內容） learning; GraphSAGE samples and aggregates neighbour features. A link scorer then predicts whether a user–item connection is plausible. Explain this chain instead of calling the graph itself a recommender（推薦系統）.
  • The graph must respect the prediction boundary. Removing the held-out edge from the loss（損失函數；衡量預測錯誤） is insufficient if that same edge remains available during embedding construction or neighbour messages. New-node behaviour also depends on available features and graph connections, not on the mere existence of a graph-neural label.
Implementation steps and their purpose
  1. Define node and edge types.
  2. Construct a graph using training-time information only.
  3. Learn representations through random walks or neighbour aggregation.
  4. Score possible user–item links or retrieve（檢索；找出相關資料） nearby item embeddings.
  5. Filter seen/ineligible items and rank（秩；矩陣獨立資訊的維度數）.

Common wrong answers and the exact correction
  • A possible link is not an established fact（事實；推理中已知的資訊）.
  • Random walks and graph neural aggregation are different training mechanisms.

Implement it and test the outcome

Data, components and application

  • Future/test edges included → remove them before training/features → topology can leak the answer.
  • Sparse/new nodes → use features/fallback → graph structure alone may provide little evidence.

How to evaluate it

Evaluate held-out link/recommendation rankings, cold-node behaviour, scalability and source quality.

Build the answer in this order

  1. Draw typed graph.
  2. Explain embedding/scoring.
  3. Prevent edge leakage.
  4. Justify（給出理由；用情境與證據支持選擇） extra relationship value.

An answer you could write

  • “I represent users, items and sports with typed edges, learn representations from training-only links, then score possible user–item connections.”
  • “For B, shared sport and friend history are supporting signals, not verified preference; I remove target edges before embedding and evaluate held-out rankings.”

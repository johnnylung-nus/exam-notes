C038

User-based（以使用者為基礎） collaborative filtering（協同過濾）

User-based CF recommends what similar users like. Similarity（相似度） comes from shared rating/interaction patterns; it is a neighbourhood-based form of CF.

Recognise this in a question: Ratings, similar users/items, collaborative filtering, sparse（稀疏性） voluntary feedback

What this tells us: The calculation is easy only after neighbour reliability is established. A high similarity computed from one shared rating is not as persuasive as comparable agreement across many relevant items.

How do similar users predict a missing preference?

  • User-based CF asks which other users show a similar pattern of preferences, then borrows their opinions on items the target has not rated. Shared-item overlap is essential evidence: two people cannot be reliably called similar merely because both have many ratings somewhere in the catalogue.
  • Prediction weights each usable neighbour by similarity. For a candidate item, only neighbours who rated that item contribute. If user rating habits differ, Pearson/mean-centering compares relative liking rather than treating a generous 5 and a strict 4 as different tastes by default.
  • The sample treatment scenario requires reasoning（推理） through the mechanism: sparse voluntary feedback means few commonly rated treatments, which makes patient similarity unreliable, which weakens recommendations. Saying “not enough data” omits this causal chain. Also, the case rates treatment sets per consultation, so individual-treatment matrix cells cannot be counted without an explicit assumption.
Implementation steps and their purpose
  1. Build user–item ratings with blanks retained as unknown.
  2. Compare the target user with others on valid shared items.
  3. Select similar users who rated each candidate item.
  4. Compute a similarity-weighted rating or preference score.
  5. Rank eligible unseen items and test held-out results.

Prepare the data and validate the representation

Data, components and application

  • Sparse overlap → collect history or use content/hybrid（混合式） fallback（備援處理） → similarity based on few common items is unreliable.
  • Different rating habits → mean-centering/Pearson → generous and strict users can share tastes.

How to evaluate it

Use rating MAE（平均絕對誤差）/RMSE（均方根誤差） when predicting scores; use top-list relevance for recommendations. Check coverage（涵蓋率） and low-history users.

Common wrong answers and the exact correction
  • Missing is not dislike.
  • The sample’s treatment-set feedback is not automatically separate ratings for every treatment.

An answer you could write

Where this is tested in the sample papers

ISY5001 Q3(c) — User-based CF suitability with sparse voluntary ratings

What the question requires

  1. Identify patients as users and treatments as candidate items.
  2. Use the stated limited voluntary feedback.
  3. Connect sparsity to little common rating history.
  4. Explain why unreliable similarities weaken recommendations.

Proposed answer points

  • A concise negative answer: with 2,000 patients, 300 treatments and only about 40% providing feedback, shared rating history is likely sparse, weakening patient similarity.
  • The recorded feedback concerns a set of treatments per consultation, not necessarily a separate rating for every treatment.

Avoid: Do not claim an exact density from an assumed three treatments per patient. The 0.4% illustration requires unverified individual-treatment ratings.

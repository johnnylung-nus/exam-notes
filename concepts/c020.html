Ontologies（本體；概念與關係的規範）

An ontology formally specifies a domain’s concepts, relationships, hierarchies and constraints（約束條件）. It provides shared meaning and supports classification（分類；預測類別）/consistency（一致性） checks.

Recognise（辨識；從資料找出物件或模式） this in a question: Shared vocabulary, type constraints, relationship queries, multi-hop（多跳） facts（事實；推理中已知的資訊）

What this tells us: The useful result is not merely a prettier graph. Shared definitions support（支持度；同時出現的交易比例） inference, validation and integration while retaining the distinction between rules/schema（知識結構） and instance facts.

What does an ontology add beyond a list of entities（實體；被描述的對象）?

  • An ontology specifies what kinds of things exist in the model and what relationships are meaningful between them. It gives different datasets a shared vocabulary, so “provider”, “doctor” and “clinician” are reconciled only when the domain definitions justify（給出理由；用情境與證據支持選擇） equivalence（等價；兩者互相成立） rather than because their words look similar.
  • Class hierarchy enables consequences such as Professor being an Academic. Property constraints and definitions allow consistency checking: a relation can be flagged if its endpoints do not match the intended types. The ontology defines the semantics; the KG（Knowledge Graph；知識圖譜） contains particular people, courses and their asserted relations.
  • A formal model still depends on correct domain choices and source facts. An apparently inconsistent record may expose a source-data error, a mapping error or an overly restrictive ontology. The appropriate response is to investigate, not to silently delete a difficult fact merely to make the reasoner report consistency.
Implementation steps and their purpose
  1. Define important classes and instance types.
  2. Specify properties and permitted relations.
  3. Add class hierarchy and constraints.
  4. Map source terms to the shared definitions.
  5. Check consistency and state valid inferred memberships.

Prepare the data and validate the representation（表徵；資料的表示方式）

Data, components and application

  • Conflicting source meanings → map and reconcile concepts → identical labels（標籤；作比較的正確答案） can mean（均值；平均數） different things.
  • Excessive complexity → model required distinctions only → maintenance cost can exceed value.

How to evaluate it

Check class consistency, illegal relation types and whether relevant（相關性；是否切合問題） queries can be expressed. Have domain experts review definitions.

Build the answer in this order

  1. Identify shared concepts.
  2. Define hierarchy and constraints.
  3. Map entities/facts.
  4. Demonstrate one inference and validation.

Choose the representation from the task

Useful when several data sources must describe the same domain consistently or when valid relations and class membership matter.

Common wrong answers and the exact correction
  • Ontology defines the schema/meaning; a KG stores concrete facts.
  • More formality does not make incorrect source facts true.

An answer you could write

  • Because Professor is a subclass of Academic and Academic of Person, Alice being a Professor implies Alice is Academic and Person.
  • The ontology defines classes and permitted relationships; the KG stores Alice and AI101 facts, whose mappings and constraints I validate.

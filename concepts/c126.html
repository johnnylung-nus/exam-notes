Transformer / positional encoding

A transformer represents tokens using attention rather than recurrence. Positional encoding adds information about token order, because content-only self-attention does not by itself specify sequence positions.

What this tells us: The current target token must not be offered as its own answer. Position information and causal masking solve different problems: order representation versus future leakage.

Why does attention still need information about token order?

  • Self-attention compares token content, but without added position information it does not intrinsically know which token came first. Positional encoding attaches order information to token representations before attention combines their context.
  • An encoder can attend over the available input sequence. A causal decoder must prevent each prediction position from attending to future target tokens; otherwise training receives information unavailable during generation.
  • A translation-style decoder can additionally attend to encoder outputs through cross-attention. That does not mean every transformer has both an encoder and a decoder: choose the structure required by the task rather than copying every block.
Implementation steps and their purpose
  1. Convert tokens to vectors
  2. Add position information
  3. Apply attention and feedforward blocks
  4. Choose an encoder, decoder or combined structure for the task
  5. Mask future positions for causal prediction
  6. Attach a suitable output and train

Prepare the data and validate the representation

Data, components and application

  • Future tokens visible during next-token training → apply causal mask → prevent cheating
  • Missing positions → add positional encoding → preserve order-sensitive meaning
  • Long inputs cost memory → control sequence length → attention comparisons grow rapidly

How to evaluate it

Evaluate on held-out task data with the same masking and prediction-time information constraints.

Common wrong answers and the exact correction
  • Not every transformer needs encoder–decoder cross-attention
  • A decoder-only model can use masked self-attention.

An answer you could write

  • “For next-token generation I use positions plus masked self-attention so only the available prefix informs each output.”
  • “Cross-attention is added only when a separate source representation, such as a sentence to translate, is required.”

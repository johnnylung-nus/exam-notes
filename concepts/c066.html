C066

Vision cognition（認知；理解與思考） pipeline（處理流程）

Vision cognition goes beyond naming objects: pixels become features（特徵；描述樣本的屬性）, objects, relations（關係；對象間的連結）, context and a useful decision.

Recognise（辨識；從資料找出物件或模式） this in a question: Image label（標籤；作比較的正確答案）, object（客體；三元組終點） location, bounding boxes（邊界框；框出物件位置）, pixel area, segmentation（分割）

What this tells us: Adding a language label to “mask detected” does not create the missing coverage evidence. The chosen visual output must match the rule’s actual requirements.

How do pixels become evidence for a decision?

  • The camera observes pixels, not compliance. A pipeline must extract the relevant objects and relationships before applying the rule that defines correct behaviour.
  • Perception can detect a mask yet miss whether it covers the nose. The judgement therefore needs more detailed location/coverage information.
  • Domain rules supply the meaning of the observation: which equipment is required, where it belongs and what missing evidence prevents a conclusion（結論）.
  • Uncertainty（不確定性） should identify its source, such as an occluded region, rather than merely attach a confident-sounding label to an incomplete view.

Common wrong answers and the exact correction
  • “Mask detected” does not prove “mask worn correctly”.
  • Do not invent hidden details from one image.

Apply the distinction

Data, components and application

  • Poor lighting/occlusion → improve capture or request another view → missing evidence cannot support（支持度；同時出現的交易比例） a confident judgement.
  • Object detected but placement wrong → inspect regions/relations → presence alone does not prove compliance.
  • Unsupported inference（推論；由依據得出結論） → separate visible evidence from interpretation → exposes uncertainty.

How to evaluate it

Check perception, interpretation, judgement, usability and consequences of errors separately.

Build the answer in this order

  1. Required decision.
  2. Perception output needed.
  3. Rules/context → decision.
  4. Check failure and response.

An answer you could write

  • The camera supplies pixels; recognition extracts PPE items and placement relationships needed by the checklist.
  • Detecting a mask is insufficient to prove correct wearing because nose/mouth coverage must also be checked.
  • If a required region is occluded, request another view or review instead of asserting that the item is absent.

ISY5001 Q2(b) — Functions, inputs and outputs

What the question requires

  1. Separate App and Web responsibilities.
  2. Name each input and processing function.
  3. Name distinct outputs and give a case example.

Proposed answer points

  • App: images of the eyes under illumination → measure/compare pupil（瞳孔；眼睛中央讓光進入的開口） response → RAPD（Relative Afferent Pupillary Defect；相對傳入性瞳孔缺損；本題比較雙眼對光反應） indication.
  • Web: patient profile, symptoms（症狀；患者感受到的不適） and signs (including RAPD) → diagnostic/triage（分流；判斷處理或轉介的急切程度） reasoning → diagnosis（診斷；判斷可能的疾病或故障原因） or differential list, urgency and action guidance.

Avoid: A diagnosis, referral urgency（轉介急切程度） and action are different outputs. This is a case-study architecture, not clinical advice.

ISY5001 Q2(i) — Patient self-service: benefits, risks and role boundaries

What the question requires

  1. State a position on removing the primary doctor.
  2. Acknowledge the convenience benefit.
  3. Explain a case-specific risk and a safer scope.

Proposed answer points

  • A patient-facing information/capture function could improve convenience, but removing the doctor is not justified by the presented diagnostic/triage support case.
  • Capture errors, incomplete context and delayed escalation are possible risks; retain clinician assessment for the clinical decision.

Avoid: Do not claim all cognitive systems always require a doctor; argue from this system’s intended users and risks.

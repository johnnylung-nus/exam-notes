Neural knowledge graph（知識圖譜） embeddings（向量表示）

Neural KG models learn richer interactions between entities（實體） and relations（關係）. Graph neural approaches also aggregate information from neighbours. The architecture（架構） determines what new entities it can handle.

What this tells us: The transfer comes from reusing a learned aggregation function, not from every neural network automatically understanding new nodes. The lecture’s broad claim needs this qualification.

What can a neural graph model learn from entity information?

  • A neural KG model must specify where information comes from. ConvE processes learned head/relation embeddings through convolution（卷積） and nonlinear features before matching candidate tails. Graph neural models instead use graph neighbourhoods, sometimes with relation-specific aggregation; these mechanisms are not interchangeable descriptions of “deep learning”.
  • Neighbour aggregation lets information from connected nodes influence a representation. Repeating layers reaches progressively farther neighbours, but only through the allowed training（訓練） graph. If held-out target edges are left in that graph, the supposed prediction（預測） can leak its own answer through message passing.
  • Unseen-node handling is architecture-dependent. An ID-only embedding table has no learned entry for a new identifier. An inductive feature aggregator such as GraphSAGE can compute a new representation from available features and neighbours using shared parameters（參數）. It still needs useful inputs; a completely isolated featureless new node remains difficult.
Implementation steps and their purpose
  1. Define link prediction or node/graph classification（分類） target.
  2. Choose inputs: IDs, relation types, node features or text.
  3. Use the appropriate architecture, such as ConvE or relation-aware aggregation.
  4. Train on permitted graph information.
  5. Validate on the required setting, including genuinely unseen nodes if relevant.

Common wrong answers and the exact correction
  • Not every neural embedding model handles unseen entities without retraining.
  • A predicted link remains a hypothesis.

Implement it and test the outcome

Data, components and application

  • Overfitting（過度擬合） → dropout（隨機停用神經元）, regularisation and validation → added capacity can memorise links.
  • Unseen IDs → use an inductive feature/aggregation design where appropriate → ordinary ID embeddings do not automatically generalise.

How to evaluate it

Check held-out prediction, leakage through graph edges, relation-specific errors and runtime.

Build the answer in this order

  1. State target and graph inputs.
  2. Explain one chosen architecture.
  3. Specify training split.
  4. Assess accuracy（準確率）, unseen-node support and cost.

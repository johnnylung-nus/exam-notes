Inductive learning（歸納學習） and generalization（泛化能力）

Generalisation means learned patterns also work on unseen cases. Matching every training（訓練） observation can simply mean（均值；平均數） memorisation.

What makes a learned rule generalise to new cases?

  • Generalisation is about the prediction（預測） setting, not simply a random percentage split（切分；按條件分開資料）. If the future task concerns new patients, repeated consultations from the same patient can make a row-random split optimistic. If the task predicts later behaviour, training must not use events that happened after the prediction point.
  • Preprocessing is part of the fitted system. Imputation, scaling, feature selection（特徵選擇） and vocabulary learning must be fitted on permitted training data, then applied unchanged to validation/test examples. Otherwise the model has indirectly seen information from the data used to judge it.
  • Validation is used to choose settings; test data estimate performance after these choices. Reusing the test set（測試集） to repeatedly select depth, factors or features（特徵；描述樣本的屬性） turns it into another validation set（驗證集）. Metrics also depend on error costs: a higher overall accuracy can hide unacceptable misses in an important class（類別；分類目標）.
Implementation steps and their purpose
  1. Define the real future cases and desired target.
  2. Split data before fitting preprocessing or selecting models.
  3. Fit only training examples.
  4. Tune complexity with validation or cross-validation（交叉驗證）.
  5. Use a final untouched test set and inspect relevant（相關性；是否切合問題） errors.

Common wrong answers and the exact correction
  • Validation selects settings; test estimates final performance.
  • Good average results can hide failures in important groups.

Implement it and test the outcome

Data, components and application

  • Patient/time leakage → group patients or respect time where required → repeated/future information inflates results.
  • Unrepresentative data → assess relevant subgroups and shifts → random splits do not fix missing populations.

How to evaluate it

Compare training and validation performance, then final test results. Choose metrics by the cost of mistakes, not accuracy alone.

Build the answer in this order

  1. Define unseen setting.
  2. Check split/leakage.
  3. Compare fit and generalisation.
  4. Justify（給出理由；用情境與證據支持選擇） complexity and metric.

An answer you could write

  • The moderate tree’s validation accuracy86% exceeds the deep tree’s75%, despite the deep tree fitting training data perfectly.
  • I choose using validation, fit preprocessing on training only and reserve the final test; patient-group or time splits must reflect the real prediction setting.

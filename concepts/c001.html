Search problem（搜尋問題） formulation

Search means exploring possible states and actions（動作） to reach a goal. The representation（表徵；資料的表示方式） determines what solutions the algorithm can find.

Recognise（辨識；從資料找出物件或模式） this in a question: State space（狀態空間）, actions, goal, route, reasoning engine（推理引擎；套用知識得結論）

Illustrative route state: location is not enough

Worked study example: A courier starts at A, must visit B and C, and return to A. We compare two partial routes arriving at B. These are invented values used to explain state design.

All steps shown
Partial routeCorrect state informationCan go straight home?
A→BAt B; visited A,B; C unservedNo: C remains required
A→C→BAt B; visited A,B,CYes, if return edge allowed
A→B→ABack at A; C unservedNot a goal despite returning
A→C→B→ABack at A; all servedFeasible（可行；符合所有硬性條件）; compare total cost

What this tells us: A visited-set is necessary because the same current location does not imply the same remaining task. After feasibility is established, compare complete-route costs. A heuristic（啟發式；引導搜尋的估計） cannot repair a representation that forgot a required customer.

What belongs in a search state?

  • A search state must retain everything that changes future legal actions. For a visit-each-city route, “current city” alone is insufficient: two arrivals at the same city can have different unvisited destinations. They are different planning states even though they share a location.
  • The goal test（目標檢驗） answers whether a candidate is acceptable; the objective compares acceptable candidates. “Every customer served” is a goal/constraint（約束條件）, while minimum distance ranks feasible routes. Mixing them lets an apparently cheap solution win by skipping required work.
  • An action changes the state and has a cost. Costs must represent the exam objective: distance, time and fare are different quantities. State updates must also update resources, visited locations or deadlines, because later action feasibility depends on these values.
Implementation steps and their purpose
  1. Define what one state contains.
  2. Specify the initial state（初始狀態） and valid actions.
  3. State the goal test and hard constraints（硬性約束）.
  4. Assign action costs and the objective.
  5. Choose a search method that matches costs, memory and heuristic availability.

Prepare the data and validate the representation

Data, components and application

  • Missing state information → include visited cities/resources → legality depends on history.
  • Conflicting objectives → state priority or weights（權重） → cheapest and fastest need not coincide.

How to evaluate it

Check that the final path reaches the goal, obeys constraints and has correctly summed cost. Compare search effort and solution quality.

Build the answer in this order

  1. Identify state and goal.
  2. Define actions, constraints and costs.
  3. Justify（給出理由；用情境與證據支持選擇） algorithm.
  4. Trace and check result.

Choose the representation from the task

Use when the question asks for a route, arrangement or sequence（序列；有先後順序的資料） satisfying requirements.

Common wrong answers and the exact correction
  • A node is a state, not necessarily just a location.
  • A feasible solution need not be optimal（最優）.

An answer you could write

  • I represent the courier state as current city plus the visited-city set, because reaching B before versus after visiting C leaves（葉節點；決策樹的最終輸出） different legal next actions.
  • The route must visit B and C and return to A; among routes meeting those hard requirements I minimise total travel cost.

Breadth-first search（廣度優先搜尋）

Breadth-first search explores all states at one depth before going deeper. It uses a queue: add new children at the end.

Recognise（辨識；從資料找出物件或模式） this in a question: State space（狀態空間）, actions（動作）, goal, route, reasoning engine（推理引擎；套用知識得結論）

Illustrative BFS queue trace

Worked study example: A has children B,C; B has D,E; C has goal G. Expand（展開；產生節點的後續候選） children left to right. Every edge costs one unit.

All steps shown
RemovedQueue after adding childrenReason
AB,CFirst level waits
BC,D,EC was discovered before D,E
CD,E,GAll children append to end
D then EGEarlier depth-two nodes go first
GEmptyParent chain gives A→C→G

What this tells us: The solution costs two steps even though the expansion trace inspected five other nodes. With unequal fares, this guarantee applies only to edge count; a two-edge route could cost more than a three-edge route.

Why does a queue find the shallowest solution?

  • BFS keeps earlier discoveries ahead of later discoveries. Appending children to the queue means every depth-one node is removed before depth-two nodes. This is why it finds a minimum-number-of-actions route when all action costs are equal, rather than because it estimates distance to the goal.
  • The frontier（待探索節點集） is the waiting list, not the route already travelled. Parent pointers reconstruct the actual solution after a goal is found; the expansion order may include nodes belonging to several different branches and is usually not itself a valid route.
  • In a graph, repeated-state handling prevents cycles（循環；路徑返回已到過的狀態） from recreating the same work. With a proper state definition and unit-cost edges, recording a discovered state prevents later longer routes to that same state from entering the queue. Memory can still grow rapidly because an entire wide level waits together.
Implementation steps and their purpose
  1. Put the start in the frontier queue.
  2. Remove the oldest queued node and check the goal.
  3. Append its valid unvisited children.
  4. Record parents to reconstruct the path.
  5. Repeat until success or the queue is empty.

Choose the method from the problem

Useful for fewest-step solutions when each action has the same cost, or finding all nodes within a limited number of hops.

Common wrong answers and the exact correction
  • Fewest edges does not mean（均值；平均數） cheapest weighted path.
  • State tie/child order rather than inventing a unique trace.

Implement it and test the outcome

Data, components and application

  • Cycles → keep visited states → prevent repeated expansion.
  • Large branching → frontier grows rapidly → consider cost/heuristic search when suitable.

How to evaluate it

Verify the queue and expansion order. On equal-cost edges, the first reached goal has minimum steps; weighted edges require another criterion.

Build the answer in this order

  1. Check equal step costs.
  2. Write frontier after each expansion.
  3. Apply stated child order.
  4. Return path, not just visiting order.

An answer you could write

  • All edges in this example cost one, so BFS finds a minimum-step route by removing the oldest frontier node and appending new children.
  • The expansion order is A,B,C,D,E,G, but the returned parent path is A→C→G, costing two steps.

C023

TransE embeddings（嵌入；用向量表示內容）

TransE learns vectors so that moving from a head entity（頭實體；關係起點） by a relation（關係；對象間的連結） vector lands near the tail entity（尾實體；關係終點）. Nearer means a more plausible triple（三元組；主體、關係、客體）.

Recognise（辨識；從資料找出物件或模式） this in a question: Predict a missing relation, entity（實體；被描述的對象） embedding, relation-specific（關係專屬；依關係使用不同設定） projection（投影；轉到選定方向的座標）

TransE score interpretation

d(h,r,t)=‖h+r−t‖
h, r, t
Head-entity, relation and tail-entity vectors.
‖ ‖
The specified vector norm; commonly L1 or L2.
d
Mismatch/distance score; smaller is a better match under this convention.
  1. Add the relation vector to the head.
  2. Measure distance from that position to each candidate tail.
  3. Lower mismatch means a better model fit; a negative-distance score reverses the numeric（數值型；以數量表示） direction.

Interpret the result: Rank（秩；矩陣獨立資訊的維度數） plausible tails, then validate proposed links.

How does a relation translate one entity toward another?

  • TransE tries to make a head vector plus a relation vector land near a tail vector. The remaining distance is a mismatch measure: smaller distance means the triple fits the learned geometry better. Some implementations report the negative distance, in which case larger scores mean（均值；平均數） better; state the direction rather than confusing score with distance.
  • Training（訓練） compares observed triples against corrupted（擾動；輸入被加雜訊或遮蔽） alternatives, such as replacing the tail. This creates pressure to preserve known relationships while separating unlikely ones. Because KG（Knowledge Graph；知識圖譜） data are incomplete, a corrupted triple can accidentally be true; the negative labels（標籤；作比較的正確答案） are not equivalent to verified false facts.
  • The geometric simplification provides compact scoring but limits relation patterns. If one head with one relation has many distinct tails, forcing all of them near the same translated location can collapse distinctions. A more expressive model is justified by the relation structure and held-out（留出資料；未參與該階段訓練） results, not simply by having a longer name.
Implementation steps and their purpose
  1. Collect known head–relation–tail triples.
  2. Learn entity and relation vectors.
  3. Train known triples to score better than corrupted alternatives.
  4. For a query, apply the relation to the head vector.
  5. Rank candidate tails by closeness and validate predicted links.

Choose the method from the problem

Use for compact KG representations（表徵；資料的表示方式） and candidate missing-link prediction when a simple translation model suits the relations.

Common wrong answers and the exact correction
  • Vectors are learned features（特徵；描述樣本的屬性）, not literal coordinates in the real world.
  • A high score does not establish causation（因果；一者造成另一者變化）.

Implement it and test the outcome

Data, components and application

  • One-to-many relations → consider relation-specific models → one translation struggles to represent many distinct tails.
  • False negatives in corrupted triples → sample/check carefully → missing links may actually be true.

How to evaluate it

Hide known links and check candidate ranking; inspect relation types where performance is poor. Compare cost and quality with alternatives.

Build the answer in this order

  1. Identify link-prediction task.
  2. Explain translation in words.
  3. Describe training and ranking.
  4. State expressiveness limits.

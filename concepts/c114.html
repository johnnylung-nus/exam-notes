CNN（卷積神經網路） dimensions and parameter counts（參數數量）

CNN shape calculations show how data moves between layers. Parameter counts show which layers dominate storage and fitting capacity; a large flattened Dense layer can outweigh all convolution（卷積） layers.

Recognise this in a question: Image CNN, padding（填充）/stride（步幅）, feature（特徵；描述樣本的屬性） maps, pooling（池化）, huge dense layer

Audit original versus revised Dense tail

Dense parameters（參數） = inputs × outputs + outputs
inputs
number of values entering the layer
outputs
number of output units; each has a bias（偏置／偏差；須看語境）
  1. Original:9408×256+256=2,408,704.
  2. Intermediate:256×128+128=32,896.
  3. Original output:128×918+918=118,422.
  4. Add convolution18,960: total2,578,982.
  5. Revised Dense64→Dense918 total=602,176+59,670+18,960=680,806.
  6. Reduction=(2,578,982−680,806)/2,578,982≈73.6%.

Interpret the result: The first Dense layer is about93.4% of the original parameters.

What this tells us: The first Dense layer contains about 93.4% of the original parameters. Reducing its width addresses the actual bottleneck while preserving early spatial（空間的） feature extraction.

Which layer dominates the CNN's parameter count?

  • Calculate the data shape after every operation before counting parameters. Flatten multiplies height, width and channels; it rearranges values without learning weights（權重）, but can feed an expensive Dense layer.
  • A Dense layer connects every input to every output. A convolution learns one small shared parameter set per filter; spatial positions increase computation but do not multiply that filter’s stored weights.
  • Parameter count indicates storage and fitting capacity, not complete speed. Operations, feature-map sizes and hardware also matter. A lean redesign must preserve task quality, including rare classes, rather than merely produce a smaller number.
Implementation steps and their purpose
  1. Track height, width and channels after every layer
  2. For convolution use floor((input + twice padding − filter)/stride)+1 per spatial axis（軸；運算指定的維度）
  3. Count convolution weights as filter height × width × input channels × output channels, plus output-channel biases
  4. Flatten by multiplying final dimensions
  5. Count Dense weights as input units × output units, plus output biases

Use the result and check it

Data, components and application

  • Dense tail dominates → reduce hidden width → cut cost and capacity
  • Shape mismatch → recalculate each stage → ensure a valid architecture

How to evaluate it

Compare total parameters, inference（推論；由依據得出結論） cost and validation performance; parameter reduction alone does not prove better accuracy（準確率）.

Build the answer in this order

  1. Locate the expensive layer
  2. Show the arithmetic
  3. Propose a smaller valid replacement
  4. Explain expected benefit and validation

Diagnose: A convolution count is implausibly large

A convolution count is implausibly largeWeights were counted again at every spatial positionCount each shared kernel（核函數） once plus its output biasThe same detector is reused across locations, unlike unique Dense input-output connections.
Common wrong answers and the exact correction
  • Include biases
  • Reusing convolution weights means spatial positions do not multiply its parameter count.

Where this is tested in the sample papers

ISY5002 Q2(a) — Lean CNN redesign, parameter arithmetic, activations and loss（損失函數；衡量預測錯誤）

What the question requires

  1. Locate the parameter bottleneck.
  2. Propose a smaller classifier tail while preserving required outputs.
  3. Recalculate weights plus biases and total reduction.
  4. Choose activations/loss consistent（一致性） with the classification（分類；預測類別） task.
  5. Validate accuracy, imbalance and lean deployment constraints（約束條件）.

Proposed answer points

  • The original tail is Flatten9408 → Dense256 → Dense128 → Dense918. Its Dense parameter counts are 2,408,704, 32,896 and 118,422; with 18,960 convolution parameters the total is 2,578,982. The first Dense alone accounts for about 93.4%, so the actual bottleneck is the flattened-to-dense connection.
  • A defensible replacement is Flatten9408→Dense64→Dense918. Unchanged convolutions:18,960; Dense64:602,176; output:59,670; total:680,806. Reduction:1,898,176≈73.6%.
  • Use ReLU（修正線性；負數歸零） in the hidden layers（隱藏層；中間處理層）, softmax（機率正規化函數） over the 918 mutually exclusive combined classes, and categorical cross-entropy（類別交叉熵；多類分類損失）. Smaller is not automatically better: check held-out quality.

Avoid: 5,000 unevenly spread images raise overfitting（過度擬合） and class-imbalance concerns; those are related but different problems. The combined 918-way output is one design, not the only possible factorized output architecture.

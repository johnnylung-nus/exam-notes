C003

Depth-first search（深度優先搜尋）

Depth-first search follows one branch deeply before returning to alternatives. New children go at the front of the frontier（待探索節點集）, giving stack-like behaviour.

Illustrative DFS with a failed branch

Worked study example: A has B,C; B has D,E; C has goal G. Visit the left child first. D and E are dead ends.

All steps shown
ActionActive routeUnexplored alternative
Descend A→B→DA,B,DE and C
D fails; backtrackA,BE and C
Try E; E failsA,B,EC
Return to A; try CA,CG below C
Reach GA,C,GSolution found

What this tells us: The route A→C→G has two edges, but DFS explored a complete wrong branch first. A different tree could give DFS a much longer first solution; reaching a goal provides no shortest-path proof.

What does depth-first exploration（探索新選擇） keep and discard?

  • DFS places the current branch’s children ahead of older alternatives, so it follows one branch before visiting siblings. Backtracking means returning to the most recent decision with an unexplored alternative; it does not mean（均值；平均數） randomly restarting from the root.
  • DFS can keep a relatively narrow active path, but a deep wrong branch delays an easy shallow goal. In an infinite tree it may never return. Graph cycle（循環；路徑返回已到過的狀態） checks avoid repeated states, while a depth limit addresses unbounded depth; these solve different failure causes.
  • The stack order must match the question’s stated neighbour order. Pushing B then C onto an ordinary stack causes C to pop first, so implementations often push children in reverse order to obtain a left-to-right trace. An exam trace should state its convention rather than claim one universal sequence（序列；有先後順序的資料）.
Implementation steps and their purpose
  1. Start with the initial node.
  2. Take the most recently added node.
  3. Check goal and generate children in the stated order.
  4. Explore deeper before siblings.
  5. Backtrack when a branch ends; track visited states or path cycles.

Choose the method from the problem

Useful for exploring a branch, enumerating paths or situations where keeping a broad frontier is expensive.

Common wrong answers and the exact correction
  • Do not describe DFS as level-by-level.
  • Deepest-first does not mean choosing the most promising heuristic（啟發式；引導搜尋的估計）.

Implement it and test the outcome

Data, components and application

  • Infinite branch → depth limit or suitable cycle control → ensure other branches can be considered.
  • Poor first branch → excessive search → use information or another strategy.

How to evaluate it

Check expansion/backtracking order and memory. DFS does not generally guarantee the shortest or cheapest solution.

Build the answer in this order

  1. Identify branching and goal.
  2. Apply stack order consistently.
  3. Show backtracking.
  4. Discuss completeness（完備性） and cost limitations for this space.

An answer you could write

  • With left-first DFS, I explore A→B→D, backtrack to try E, then return to A and explore C→G.
  • The solution is A→C→G; the earlier visited D and E belong to failed branches, and DFS provides no general shortest-path guarantee.

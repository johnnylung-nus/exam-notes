C115

Multi-input / multi-output architectures

Multiple inputs let a network combine different information sources. Multiple outputs let it learn several related targets, with a suitable output head and loss for each target.

Recognise this in a question: Multiple sensors, camera + sound, conflicting measurements, alignment · History matters, sequential purchases, time steps, long dependencies

What must the system deliver?

Use when the scenario includes images plus text or metadata, or requires several predictions about the same object.

Scenario cueSuitable choiceWhy it fits
Several labels can independently apply to an objectUse separately labeled sigmoid headsA softmax would force competition even when two attributes should both be present.

How are several inputs or outputs connected in one model?

  • Process each modality according to its structure: tokens as sequences, images as spatial arrays and numeric metadata as prepared measurements. Combining raw values blindly can erase the relationships the branch should exploit.
  • A merge joins representations belonging to the same case. Every source must exist at prediction time; metadata recorded after an outcome is leakage even if it enters through a separate branch.
  • Separate outputs need separate labels, activations and losses. Loss weights control their influence on shared layers, so the numerically larger loss must not automatically determine what all shared features learn.
Implementation steps and their purpose
  1. List each input modality and its shape
  2. Give each modality a suitable processing branch
  3. Combine branch representations
  4. Attach task-specific output heads
  5. Define each target and corresponding loss
  6. Balance losses and validate every output

Design two inputs and two outputs

Worked study example: Illustrative task predicts exclusive product type among three classes and continuous estimated weight from one product image plus four metadata features.

What this tells us: Report type errors and weight error separately. A favorable combined loss can conceal deterioration in the business-critical output.

Data, implementation and validation

Data, components and application

  • One modality has a different scale or missing values → prepare it separately → avoid corrupting fusion
  • One task dominates training → adjust loss weighting → preserve the other task

How to evaluate it

Measure each output separately and check whether using multiple inputs improves over single-input baselines.

Build the answer in this order

  1. Identify information sources
  2. Draw branches and merge point
  3. Label each output
  4. Explain activation, loss and evaluation per head

Diagnose: Deployment lacks a metadata input

What you observeWhy it happensWhat to changeWhy that helps
Deployment lacks a metadata inputTraining used a source recorded after the decisionRemove that source and retrainA model cannot operationally depend on information unavailable when it must act.
Common wrong answers and the exact correction
  • Concatenating unrelated raw inputs is not automatically a good design
  • Multiple exclusive classes differ from multiple separate outputs.

An answer you could write

  • “I use modality-specific branches, then merge representations for the same observation.”
  • “Each output has its own target, activation, loss and evaluation; I justify how the losses are balanced.”

Where this is tested in the sample papers

ISY5002 Q1(d) — Sequence model, input construction and combination

What the question requires

  1. Choose LSTM for ordered session events.
  2. Represent each session as an ordered sequence with a purchase label.
  3. Encode page/source, scale duration, pad/mask and split without future leakage.
  4. Combine outputs with earlier models without training-score leakage.

Proposed answer points

  • Clickstream sequence → LSTM → Dense sigmoid → purchase score; use binary cross-entropy for the binary label.
  • For stacking, generate LSTM training scores out of sample, add them to the earlier model’s inputs, and compare against that model on validation data.

Avoid: Do not use post-purchase/future events when predicting an earlier intervention. In-sample base-model scores can leak into a stacked learner.

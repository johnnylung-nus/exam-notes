C052

Deep collaborative filtering（協同過濾）

Deep collaborative filtering learns nonlinear（非線性；不能只用線性關係表示） user–item interactions. In neural CF（Collaborative Filtering）, user and item embeddings（嵌入；用向量表示內容） feed an MLP（Multilayer Perceptron；多層感知器；多層前饋神經網路） instead of relying only on a dot product（內積；逐項相乘後相加）.

Recognise（辨識；從資料找出物件或模式） this in a question: Next item, session（工作階段；一次連續造訪的記錄） history, connected users/items, nonlinear preferences

What must the system deliver?

Consider when sufficient interaction data and features（特徵；描述樣本的屬性） justify（給出理由；用情境與證據支持選擇） more capacity than simple MF（Matrix Factorization；矩陣分解）.

Scenario cueSuitable choiceWhy it fits
Dot-product model underfits supported interactionsCompare MLP/NeuMFNonlinear combinations may capture additional structure
Very sparse（稀疏性） data and no side featuresKeep regularised MF baseline（基準；供比較的簡單方法）Deep capacity may memorise rather than generalise

What nonlinear interaction does a deep recommender（推薦系統） add?

  • Neural CF replaces or extends the simple dot-product interaction between user and item embeddings. An MLP can learn nonlinear combinations, but the diagram must show what enters the embeddings and what the output predicts. User/item identifiers select learned vectors; their raw numeric（數值型；以數量表示） size is not a meaningful feature.
  • Deep architecture（架構） does not change the need to define labels（標籤；作比較的正確答案）. Explicit ratings suggest a regression（迴歸；預測連續數值） loss; sampled implicit positives/negatives suggest a classification（分類；預測類別） or ranking（排序） objective. An autoencoder（自編碼器） is a different design: it compresses a rating/interactions vector and reconstructs outputs, so missing-value treatment must be specified rather than silently trained as dislike.
  • Additional capacity can learn useful feature interactions when enough evidence（證據；已觀察到的資訊） exists, but can also memorise sparse IDs. Side information can help with content and new entities（實體；被描述的對象） only if the architecture actually consumes it. A deep ID-only model does not know a new item’s description merely because such descriptions exist elsewhere in the system.
Implementation steps and their purpose
  1. Define user/item inputs and explicit or implicit target.
  2. Map IDs or features to embeddings.
  3. Combine embeddings with the chosen neural layers.
  4. Train with a loss matched to rating or binary/ranking target.
  5. Tune capacity/regularisation and compare against MF.

What this tells us: The neural network（神經網路） can express a different interaction, but must learn it from representative targets. More flexible scoring is only useful if it improves held-out（留出資料；未參與該階段訓練） recommendations under serving constraints（約束條件）.

Data, implementation and validation

Data, components and application

  • Sparse IDs/cold start → add side information or fallback（備援處理） → ID-only embeddings still need history.
  • Overfitting（過度擬合）/cost → regularise and baseline-test → nonlinear capacity is not automatically useful.

How to evaluate it

Check held-out recommendation（推薦） quality, coverage（涵蓋率；能服務的使用者或項目範圍）, latency and model size. Separate candidate retrieval（檢索） from expensive ranking if catalogue is large.

Build the answer in this order

  1. Define target.
  2. Explain chosen architecture.
  3. Specify data/loss.
  4. Justify benefit over simple baseline.

Common wrong answers and the exact correction
  • Do not confuse user/item IDs with meaningful numerical magnitudes.
  • Deep models do not automatically solve missing feedback.

An answer you could write

  • “User/item IDs select embeddings, which are combined by an MLP and trained against the defined rating or implicit target.”
  • “I compare the neural scorer with regularised MF using held-out recommendation quality and latency; extra capacity is justified only by measured benefit.”

C014

Conflict resolution in rule systems

Conflict resolution chooses which rule fires when several rules match in the same cycle. The choice can affect processing order and possibly outputs.

What this tells us: The conclusion follows the declared business exception, not a claim that higher priority is a probability. Without override semantics, firing R1 later could reintroduce the forbidden action.

Which rule should fire when several rules match?

  • Matching rules and selecting a rule are separate steps. Several rules may be eligible because their conditions all hold. The conflict set is this collection of activations; it does not necessarily mean the rules logically contradict one another. Selection controls processing when only one is fired per cycle.
  • The lecture offers priority, specificity and recency policies. Priority expresses domain precedence, specificity prefers a rule with more particular matching conditions, and recency uses newer supporting facts. These are policies, not mathematical evidence that the selected conclusion is truer than the others.
  • When conclusions really conflict, a firing-order rule may be insufficient unless the KB defines override/retraction behaviour. An audit trail should show matching rules, the selected policy and its consequence. In a high-impact scenario, unresolved contradictions should be flagged rather than hidden by whichever record happened to be stored first.

Common wrong answers and the exact correction
  • A conflict set need not imply all rules are logically inconsistent.
  • Choosing one rule does not prove the others false.

Apply the distinction

Data, components and application

  • Hidden priorities → record explicit rule priority → make behaviour reproducible.
  • Conflicting conclusions → detect and escalate or apply defined precedence → arbitrary order can produce unsafe decisions.

How to evaluate it

Create test cases where multiple rules match. Check deterministic selection, explanation and that important exceptions are not bypassed.

Build the answer in this order

  1. Identify matching rules.
  2. Show the conflict.
  3. Name and apply selection policy.
  4. Explain resulting conclusion.

An answer you could write

  • Both the loyalty rule and restricted-item rule match; the documented priority10 exclusion overrides priority1 discount.
  • I record that precedence and check the final action so later firing of the general rule cannot silently restore the prohibited discount.

Where this is tested in the sample papers

ISY5001 Q2(d) — Knowledge-based internal architecture and data structures

What the question requires

  1. Validate inputs; distinguish present, absent and unknown.
  2. Store patient facts in working memory.
  3. Represent specialist knowledge as disease frames and diagnostic/triage/action rules.
  4. Match/fire rules; display conclusions and explanations.

Proposed answer points

  • Patient facts → inference engine ← knowledge base → diagnosis candidates + urgency + action.
  • Show structures: patient fact fields; disease frame IDs; rules with conditions, conclusions, priority and explanation. One engine can apply several rule types.
  • If evidence is missing/conflicting, request information or flag for doctor review. Clinical contents require specialist validation.

Avoid: A box labelled “AI” is insufficient. A KB stores knowledge; an inference engine names the procedure using it. Softmax scores do not automatically encode urgency.

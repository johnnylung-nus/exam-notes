C064

Dialogue management（對話管理） and generation（生成式；學習資料生成或分布）

Dialogue management decides what happens next; natural language generation (NLG（Natural Language Generation；自然語言生成）) expresses the result in readable language.

What must the system deliver?

What must the bot remember between turns?

  • Dialogue state（對話狀態） records a pending action, filled slots and relevant（相關性；是否切合問題） prior（先驗機率；看證據之前） objects. It is operational memory, not the specialist’s FAQ knowledge base（知識庫；供推理查用的知識）.
  • Dialogue management chooses among waiting, asking for information and acting. The choice depends on whether the action template is complete.
  • Natural language generation turns an actual result into a reply. A template may be sufficient for reliable confirmations; a generative model is optional.
  • State must distinguish pending, completed and failed actions（動作） so a later “change it” modifies the intended object rather than creates a duplicate.
Implementation steps and their purpose
  1. Receive intent and slots from NLU（Natural Language Understanding；自然語言理解）.
  2. Check whether required details are complete.
  3. Wait for more input or actively ask for missing details.
  4. Call the relevant API（Application Programming Interface；應用程式介面） or database once complete.
  5. Generate a response from the returned facts（事實；推理中已知的資訊）.
  6. Retain useful context for the next turn.

Data, implementation and validation

Data, components and application

  • Fluent reply without executed action → separate action result from response generation → prevents false confirmations.
  • Lost context → retain relevant recent messages/entities（實體；被描述的對象） → supports follow-up questions.
  • Invented facts → use templates or grounded generation → keeps responses faithful.

How to evaluate it

Check task completion, retries, correction rate, response time and whether output matches the actual execution result.

Build the answer in this order

  1. Input state → missing fields.
  2. Next dialogue action.
  3. Execute supported operation.
  4. Return grounded response and evaluate completion.

Common wrong answers and the exact correction
  • NLU understands; dialogue management chooses the next step; NLG phrases the answer.

An answer you could write

  • Dialogue management retains the pending reminder and filled slots while collecting missing information.
  • Once complete, it calls the scheduling service and generates confirmation from the returned result.
  • Store the reminder ID so “make it 30 minutes” updates the existing reminder rather than creating a duplicate.

Where this is tested in the sample papers

ISY5001 Q1(a) — Intent and slots

What the question requires

  1. List the supported user goals.
  2. For each goal, identify the fields needed to fulfil it.
  3. Give an appropriate value example; separate user context from intent.

Proposed answer points

  • Intent = what the user wants; slot = a required detail; slot value = the actual detail.
  • Case-supported goals include ergonomic（人體工學；讓工作環境配合人體需要） advice, habit reminders and exercise guidance. A reminder needs type/interval; an exercise request needs exercise type.

Avoid: Do not use a job role or every symptom（症狀；患者感受到的不適） as a separate intent.

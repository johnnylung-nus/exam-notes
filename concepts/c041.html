C041

Recommendation（推薦） evaluation（評估）

Evaluation must match the goal: rating error checks score prediction（預測）; top-list metrics check recommendation usefulness. A low rating error does not ensure a useful ranked list.

What this tells us: No single number replaces the others. The correct choice follows whether the question asks accurate ratings, a useful top list, or preferential ordering within that list.

Are we evaluating ratings or the top of a ranked list?

  • Rating prediction and recommendation ranking（排序） are related but different objectives. MAE/RMSE（均方根誤差） compare numeric estimates with known held-out ratings. Precision/recall at K assess which relevant items appear in a displayed list. A model can predict middling ratings accurately yet miss the few useful items that should reach the top.
  • The evaluation candidate set and unknown labels（標籤） must be explicit. If only known test ratings are evaluated, the result measures performance on that restricted set; it does not reveal whether every unseen catalogue item is irrelevant. The lecture workshop also allows fewer than K qualifying recommendations, so record the actual denominator used.
  • Precision@K（前K項精確率） ignores positions within the selected set. If order is important, a rank-sensitive measure is needed in addition. Beyond accuracy（準確率）, coverage（涵蓋率）, diversity（多樣性）, new-user performance and serving cost determine whether a recommender（推薦系統） solves the real scenario. Select settings on validation and reserve final test data.
Implementation steps and their purpose
  1. Define relevant items and what the user actually sees.
  2. Hold out known interactions/ratings without leaking them into training（訓練）.
  3. Tune on validation data and reserve a final test.
  4. Calculate MAE/RMSE for rating predictions, precision/recall at K for relevant lists.
  5. Also assess coverage, diversity and operational cost.

Use the result and check it

Data, components and application

  • Unknown relevance → state evaluation coverage/candidate policy（策略） → unrated does not prove irrelevant.
  • Ranking ignored → use a rank-sensitive check when required → precision@K treats positions within K alike.

How to evaluate it

Use identical splits and eligibility rules for fair comparisons. Record threshold and denominator; lecture workshop variants sometimes return fewer than K recommendations.

Build the answer in this order

  1. Goal → split → metric.
  2. State relevance threshold.
  3. Compute and interpret.
  4. Discuss coverage and deployment.

ISY5001 Q3(c) — User-based（以使用者為基礎） CF（協同過濾） suitability with sparse（稀疏） voluntary ratings

What the question requires

  1. Identify patients as users and treatments as candidate items.
  2. Use the stated limited voluntary feedback.
  3. Connect sparsity to little common rating history.
  4. Explain why unreliable similarities weaken recommendations.

Proposed answer points

  • A concise negative answer: with 2,000 patients, 300 treatments and only about 40% providing feedback, shared rating history is likely sparse, weakening patient similarity（相似度）.
  • The recorded feedback concerns a set of treatments per consultation, not necessarily a separate rating for every treatment.

Avoid: Do not claim an exact density from an assumed three treatments per patient. The 0.4% illustration requires unverified individual-treatment ratings.

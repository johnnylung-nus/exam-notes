Random forests and feature importance

A random forest combines bootstrapped decision trees and randomly limits candidate features at each split. This creates tree diversity beyond ordinary bagging.

How does a random forest reduce tree correlation?

  • Random forest adds feature randomization to bootstrap sampling. At each split, a tree considers only a random candidate subset, reducing the chance that one strong feature makes every tree follow the same early decisions.
  • A final prediction aggregates trees, not their importance scores. Impurity importance totals a feature’s contribution to training-node purification; permutation importance instead measures validation deterioration when its information is disrupted.
  • Importance is model-dependent and can be redistributed across correlated inputs. A feature unused by one tree may still help other trees correct errors in different data regions, so removing it requires a retrained comparison.
Implementation steps and their purpose
  1. Prepare training features and labels
  2. Draw a bootstrap sample for each tree
  3. At each split consider a random subset of features
  4. Grow the tree
  5. Vote across trees or average regression outputs
  6. Estimate quality and examine feature importance

Prepare the data and validate the representation

Data, components and application

  • Highly correlated trees → reduce candidate features per split → encourage diversity
  • Importance suggests a removable feature → retrain and validate removal → ranking alone does not prove redundancy
  • Too much complexity → tune leaf size/depth → control generalization

How to evaluate it

Compare held-out recall, precision and business cost; inspect importance stability and out-of-bag estimates during development.

Build the answer in this order

  1. State both randomness sources
  2. Explain prediction aggregation
  3. Interpret importance cautiously
  4. Validate any feature-removal proposal

Choose the representation from the task

Useful for nonlinear tabular classification or regression with interactions; a strong baseline when interpretability of one small tree is not essential.

Common wrong answers and the exact correction
  • Importance is not causation
  • Random forests can overfit and do not guarantee unbiased importance rankings.

An answer you could write

  • “Random forests vary both training cases and candidate features at each split.”
  • “I test the reduced feature set on held-out cases rather than removing variables solely from one importance ranking.”

ISY5001 Q3(a)(i) — Model choice against a ranked-output requirement

What the question requires

  1. Underline “least suitable”.
  2. Identify the required ranked list of diagnoses.
  3. Compare the proposed methods under stated assumptions.

Proposed answer points

  • Under a basic hard-label single-tree interpretation, a single tree is the intended weak choice because the required output is a ranked differential list.
  • A single tree can in fact rank classes by leaf class proportions; explain the assumed implementation rather than asserting an inherent impossibility.

Avoid: Choosing a suitable model does not answer which is least suitable. There is no official key confirming a unique implementation assumption.

ISY5001 Q3(a)(ii) — Inputs, derived variables and ranked diagnoses

What the question requires

  1. Use only listed or explicitly derived fields.
  2. Derive age at consultation; encode/scale appropriately.
  3. Separate doctor diagnosis as the label.
  4. Explain how each remaining method generates a ranking.

Proposed answer points

  • Inputs: listed symptoms, signs, medication-use flags, gender, occupation, and age derived from consultation date minus birth date.
  • Trees: aggregate class counts/probabilities across trees and rank. KNN: find nearby historical feature vectors, count their attached diagnosis labels, then rank up to ten.

Avoid: Medication-use flags are not measured blood-pressure/glucose. A label is not an input coordinate; neighbour support is not automatically a calibrated probability.

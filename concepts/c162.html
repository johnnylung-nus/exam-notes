C162

Deep-learning decision / control applications

A control system repeatedly observes the environment, chooses an action, receives feedback and acts again. Deep reinforcement learning（強化學習） uses a neural model to learn action choices from reward（獎勵）.

Recognise（辨識；從資料找出物件或模式） this in a question: Robot sorting, actions（動作） change environment, reward, safe learning

What must the system deliver?

Use when actions change future states, such as moving, grasping and sorting objects under safety constraints（約束條件）.

Scenario cueSuitable choiceWhy it fits
Learn movement and grasp choices on a conveyorUse observe–policy（策略）–safety check–act–feedback architecture（架構）Sequential actions alter the next state and require both learned choices and enforceable motion constraints.

How do state, action and reward define the control problem?

  • State summarizes information needed to choose an action: recognized object（客體；三元組終點） attributes（屬性；對象的描述欄位）, target/obstacle positions and motion, plus robot/gripper（夾爪；機器人抓取物件的部件） condition. A category label（標籤；作比較的正確答案） alone is insufficient for motion control.
  • Reward connects behavior to the true objective. Correct placement, collision avoidance and completion time must be considered together; otherwise a policy can earn a good numeric score through a shortcut the owner does not want.
  • Simulation（模擬；先在虛擬環境測試或學習） permits exploratory failures without physical harm, but transfer must be tested under real sensing and dynamics. A separate motion/safety controller checks limits and collision risk rather than assuming the learned policy is intrinsically safe.
Implementation steps and their purpose
  1. Define state from perception（感知；由輸入理解環境） and robot sensors（感測器）
  2. Define available movement/grasp actions
  3. Define reward for correct completion, safety and efficiency
  4. Train primarily in simulation where appropriate
  5. Add motion/safety checks before execution
  6. Test transfer in a controlled physical setting

Make a reward trade-off（取捨；改善一項可能犧牲另一項） explicit

Worked study example: Illustrative reward per completed attempt: +100 correct bin（分箱；直方圖的數值區間，本題也可指分類收集箱）,−200 any collision,−1 per second. These weights（權重） demonstrate design reasoning（推理）; the sample does not prescribe exact numeric coefficients.

Data, implementation and validation

Data, components and application

  • Reward favors speed at any cost → penalize collisions and wrong bins → align with all objectives
  • Dangerous exploration（探索新選擇） → simulation then controlled tests → reduce physical risk
  • Simulation mismatch → validate progressively → confirm learned behavior transfers

How to evaluate it

Measure correct-sort rate, collisions, completion time and performance under varied conditions; reward alone can hide an exploited shortcut.

Where this is tested in the sample papers

ISY5002 Q2(b) — Deep-RL sorting architecture, reward and safe learning

What the question requires

  1. Define observations（觀測值）/state, actions and task success.
  2. Choose reward terms for correct sorting, safety and time.
  3. Draw hardware, perception, decision and control loops.
  4. Explain simulation-first training and controlled transfer.

Proposed answer points

  • RGB-D（Red, Green, Blue–Depth；彩色加深度影像） + robot sensors → identification/tracking → state → deep-RL policy → safety/motion checks → arm/gripper action → new observations and reward. Include target objects, obstacles, other robots and people in the environment.
  • Reward correct placement; penalize collisions and unnecessary time. Enforce joint/gripper constraints in control rather than hoping a learned reward guarantees safety.
  • Train in a physics-based（基於物理；模擬運動、接觸等物理規律） simulator, then validate in controlled low-risk real tests with safety constraints active.

Avoid: A reward penalty is not a hard safety guarantee. Classification（分類；預測類別） of the object and control of the robot are separate responsibilities.

Natural language understanding（自然語言理解）

Natural language understanding (NLU) converts a request into an intent（意圖） plus the details needed to act.

What this tells us: The second sentence is not a new unrelated intent. Its interpretation depends on the pending action and the slot currently being requested.

What must NLU extract before the system can act?

  • An utterance expresses a goal and details. NLU maps it to an actionable representation; it does not simply search for any matching word.
  • The goal determines which slots matter: a reminder needs a reminder type and interval, whereas exercise guidance needs the chosen exercise.
  • References such as “that reminder” require earlier conversation state. Re-reading the latest sentence alone can lose the object（客體；三元組終點） being changed.
  • NLU output can be incomplete. Dialogue management（對話管理） must collect missing values（缺失值） before an action is executed or confirmed.
Implementation steps and their purpose
  1. List only functions supported by the case.
  2. Tokenize or otherwise prepare the input.
  3. Identify the requested intent.
  4. Extract the required slot values.
  5. Resolve references using previous turns.
  6. Pass a completed action template to dialogue management.

Prepare the data and validate the representation

Data, components and application

  • Ambiguous request → clarify the intent → avoids an incorrect action.
  • Missing detail → ask for that slot → completes the request.
  • “It” or “his” unresolved → use conversation context → links the right entity（實體；被描述的對象）.

How to evaluate it

Test paraphrases, ambiguous requests and multi-turn references; check whether the final action matches the request.

Build the answer in this order

  1. List case functions.
  2. Map request → intent + slots.
  3. Explain missing-context handling.
  4. Test complete tasks.

Common wrong answers and the exact correction
  • User role is not automatically an intent.
  • Intent, slot name and actual value are different.

An answer you could write

  • EyeCoach supports ergonomic advice, visual-habit reminders and eye-exercise guidance as high-level user goals.
  • A reminder request needs its reminder type and interval; if the interval is missing, retain the type and ask only for that interval.
  • The follow-up “every 20 minutes” fills the pending interval rather than creating a new unrelated request.

Where this is tested in the sample papers

ISY5001 Q1(a) — Intent and slots

What the question requires

  1. List the supported user goals.
  2. For each goal, identify the fields needed to fulfil it.
  3. Give an appropriate value example; separate user context from intent.

Proposed answer points

  • Intent = what the user wants; slot = a required detail; slot value = the actual detail.
  • Case-supported goals include ergonomic advice, habit reminders and exercise guidance. A reminder needs type/interval; an exercise request needs exercise type.

Avoid: Do not use a job role or every symptom as a separate intent.

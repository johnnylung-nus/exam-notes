C161

Generative models（生成模型） / GAN（Generative Adversarial Network；生成對抗網路） applications

A GAN learns a generator（生成器；產生仿真樣本） that creates samples and a discriminator（判別器；辨別真實與生成樣本） that distinguishes generated from real samples. Their competing training（訓練） can produce realistic synthetic data.

What must the system deliver?

Use for generation（生成式；學習資料生成或分布） or augmentation when realistic sample variation is useful; generated appearance is not proof of label（標籤；作比較的正確答案） correctness or full data coverage（涵蓋率；能服務的使用者或項目範圍）.

Scenario cueSuitable choiceWhy it fits
Need additional plausible image variationConsider generative augmentation only with real-data validationUseful generated samples must preserve target identity and relevant（相關性；是否切合問題） operating variation.

What do generator and discriminator learn from each other?

  • The discriminator learns to distinguish real and generated examples; the generator learns to make outputs the discriminator treats as real. Their objectives interact, so training is not simply minimizing ordinary supervised class（類別；分類目標） error for one fixed target.
  • Realistic appearance and useful diversity（多樣性） are separate. A generator that repeats a few convincing examples can look successful while failing to cover the minority class’s important variation, especially when the real examples are extremely limited.
  • Synthetic augmentation needs label and physical validity（推論有效性） checks. It is a training resource, not an independent（獨立；知道一者不改變另一者機率） real-world test population（族群）. A downstream model may exploit generator artifacts unless tested on untouched real cases.
Implementation steps and their purpose
  1. Define what should be generated and under which conditions
  2. Train a discriminator using real and generated examples
  3. Train the generator to make its outputs harder to distinguish
  4. Alternate updates
  5. Inspect realism and diversity
  6. Validate any downstream model using untouched real data

Detect synthetic quantity without coverage

Worked study example: Illustrative augmentation generator produces100 fault images, but80 are near-copies of one pattern and20 of a second. A classifier is evaluated on100 independent real faults.

Data, implementation and validation

Data, components and application

  • Mode collapse repeats similar examples → inspect diversity → sample count can exaggerate coverage
  • Synthetic artifacts become class shortcuts → test on real held-out data → avoid learning generator clues
  • Only two anomalies → collect real faults → generation cannot establish all missing fault types

How to evaluate it

Assess realism, diversity and actual task performance separately; never use synthetic-only testing as proof of real-world benefit.

Build the answer in this order

  1. Explain generator/discriminator roles
  2. State why generation is needed
  3. Identify artifact/coverage risks
  4. Propose real-data evaluation（評估）

Diagnose: Generated outputs repeat similar examples

What you observeWhy it happensWhat to changeWhy that helps
Generated outputs repeat similar examplesMode collapse or insufficient source variationInspect sample diversity and gather more real patternsRepeated realistic images add little evidence（證據；已觀察到的資訊） about unobserved fault conditions.
Common wrong answers and the exact correction
  • GAN training differs from ordinary supervised class prediction（預測）
  • More synthetic samples do not guarantee more independent information.

An answer you could write

  • “The GAN’s generator and discriminator are trained competitively, but I separately inspect diversity and label validity.”
  • “I accept augmentation only if an untouched real test set（測試集） improves, not because synthetic evaluation looks strong.”

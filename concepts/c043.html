C043

Matrix factorization（矩陣分解）

MF（Matrix Factorization） is a model-based CF（Collaborative Filtering；協同過濾） method: it learns a short hidden-factor vector for each user and item from interaction ratings. Their dot product（內積；逐項相乘後相加） predicts a rating.

Recognise（辨識；從資料找出物件或模式） this in a question: Missing ratings, latent factors（潛在因子）, large sparse（稀疏性） rating matrix

What this tells us: The factors already encode learned preferences; no neighbour search or genre labels（標籤；作比較的正確答案） are needed to compute these scores. Known ratings（已知評分；實際有記錄的評分） need not be reproduced exactly because a compact regularised approximation may generalise better.

How do learned user and item factors predict a rating?

  • MF is a model-based method within collaborative filtering. It learns compact user and item vectors from ratings rather than explicitly（明確；直接提供的資訊） searching similar users at every request. A coordinate is a learned latent factor; assigning it a genre name is optional interpretation, not something the algorithm knows from ratings alone.
  • The dot product is the prediction（預測） mechanism: multiply corresponding user and item entries and add them. Training（訓練） adjusts these entries so known ratings are approximated while regularisation limits unnecessary magnitude. There are usually far fewer factors than catalogue items, allowing shared patterns to connect sparse observations（觀測值）.
  • For explicit ratings, blank cells remain unknown rather than becoming target zeroes. The training objective is assessed on observed training ratings, and held-out（留出資料；未參與該階段訓練） ratings must not influence fitting. Ordinary SVD（Singular Value Decomposition；奇異值分解） of a completed numeric（數值型；以數量表示） matrix is not automatically the same procedure; keep the separate SVD/PCA（Principal Component Analysis；主成分分析） teaching problem distinct.
Implementation steps and their purpose
  1. Prepare observed user, item, rating records and split（切分；按條件分開資料） them.
  2. Choose latent-factor count and initialise vectors.
  3. Fit known training ratings with a regularisation penalty.
  4. Tune factor count/penalty on validation data.
  5. Score unseen items by user–item dot product and rank eligible ones.

Use the result and check it

Data, components and application

  • Treat blanks as zero → fit observed ratings appropriately → missing is not dislike.
  • Too many factors → regularise/reduce dimension → sparse data can be memorised.

How to evaluate it

Compare validation rating error and recommendation relevance（相關性；是否切合問題）. Check cold-start coverage（涵蓋率；能服務的使用者或項目範圍） separately.

When would this calculation be useful?

Use to share patterns across many sparse ratings without calculating a neighbourhood for every prediction.

C034

Market basket analysis

Market basket analysis finds items that occur together and expresses associations as IF-condition THEN-consequent rules. The basket definition determines what association means.

What counts as one transaction before mining associations?

  • Basket construction is the central modelling choice. One basket per consultation asks which prior facts are associated with the current consultation’s diagnosis. One basket per patient instead aggregates across visits and answers a different question. The unit determines both contents and transaction count.
  • Ordinary baskets are unordered sets, so past/current roles and elapsed time must be encoded into item names or categories. Patient ID links visits and dates order them; neither belongs as a usual association item. Each treatment’s time gap must remain linked to that treatment, particularly when several historical treatments exist.
  • Mining generates combinations, not automatically diagnostic knowledge. After finding frequent itemsets and rules, keep consequents that predict current diagnosis and antecedents available beforehand. Support/confidence screen statistical evidence; domain review and held-out checks address usefulness. Associations do not establish causation or justify treatment on their own.
Implementation steps and their purpose
  1. Define the transaction unit and count.
  2. Join/clean records and encode facts as items.
  3. Bin numerical/time values where appropriate.
  4. Mine frequent itemsets and generate rules.
  5. Filter by support, confidence and application relevance.

Prepare the data and validate the representation

Data, components and application

  • Temporal leakage → use only pre-consultation history → future facts are unavailable at prediction.
  • Wrong consequent → keep current-diagnosis RHS for diagnostic rules → co-occurrence mining does not know the application target.

How to evaluate it

Check threshold counts, useful consequent, held-out performance and expert relevance. Association is neither causation nor treatment justification.

Build the answer in this order

  1. Unit → contents → encoding → count.
  2. Mine rules.
  3. Filter target/time roles.
  4. Validate useful associations.

Common wrong answers and the exact correction
  • Elapsed time since treatment differs from treatment duration.
  • Similar words do not prove identical clinical meanings.

An answer you could write

  • “I create one basket per consultation, linking prior records by patient ID/date and encoding earlier diagnoses, treatments, linked time gaps and the current diagnosis.”
  • “I retain rules with current-diagnosis RHS and available-history LHS, sufficient support/confidence and validated domain relevance.”

ISY5001 Q3(b)(i) — Temporal association baskets and preprocessing

What the question requires

  1. Choose the basket unit.
  2. Join patient records and order by date.
  3. Encode earlier diagnosis/treatment, time gap and current diagnosis with distinct roles.
  4. State basket count and assumptions.

Proposed answer points

  • One consultation per basket: prior diagnoses + prior treatments + time since each treatment + current doctor diagnosis.
  • Assuming the original 5,000 consultation records and visit date as a treatment-date proxy, create about 5,000 baskets. New trial consultations are not quantified.

Avoid: Patient count does not determine consultation-basket count. Time since treatment differs from duration of treatment. IDs join records; they are not normally mined items.

ISY5001 Q3(b)(ii) — Filter mined rules for the diagnostic task

What the question requires

  1. Keep a current-diagnosis consequent.
  2. Use antecedents available before diagnosis.
  3. Apply justified support/confidence thresholds.
  4. Check temporal meaning and clinical plausibility.

Proposed answer points

  • Role-labelled items let a filter reject treatment-only consequents from a diagnosis ruleset.
  • Case-derived illustration: prior lens replacement + elapsed time at least six months → current PCO diagnosis association. This is not a clinical rule to apply without validation.
  • With 100 baskets, 20 containing the antecedent and 12 containing both: support=12%; confidence=60%. Pass/fail depends on chosen minima.

Avoid: Ordinary baskets have no time order: encode roles/time. Association does not prove causation or safe treatment.

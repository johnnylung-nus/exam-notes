Content-based（以內容為基礎） recommendation（推薦）

Content-based recommendation matches item attributes（屬性；對象的描述欄位） to a user’s preferences or previously liked items. It does not require other users to have rated the same item.

Recognise（辨識；從資料找出物件或模式） this in a question: Recommend with item attributes, new item, user profile

How do item features become personalised recommendations?

  • Content-based recommendation uses item descriptions as evidence（證據；已觀察到的資訊）. A movie can be represented by genre, director or a text vector, and the user can be represented in that same feature space（特徵空間；以特徵作座標的空間） through preferences or liked items. Unlike CF（Collaborative Filtering；協同過濾）, similarity is not derived from other users rating the same products.
  • Averaging liked items creates a prototype, but a single average can erase several different interests. Someone who likes technical textbooks and comedy novels need not want an item halfway between them. Comparing candidates with several liked items or separate profiles can preserve these modes.
  • Content features help new items before ratings arrive, provided their descriptions are available. They do not solve a new-user profile with no preferences or history. Recommending only close matches also narrows variety, so the lecture suggests controlled randomness or excluding items that are too similar when serendipity matters.
Implementation steps and their purpose
  1. Extract structured item features or text vectors.
  2. Build a user profile from declared preferences or liked items.
  3. Use the same feature representation（表徵；資料的表示方式） for both.
  4. Compute similarity and rank（秩；矩陣獨立資訊的維度數） unseen eligible items.
  5. Add controlled variety and evaluate relevance（相關性；是否切合問題）.

Prepare the data and validate the representation

Data, components and application

  • Overspecialisation → bounded exploration（探索新選擇）/diversity（多樣性） → repeatedly similar items reduce discovery.
  • Poor metadata → improve extraction/semantic（語義；所表達的意思） representation → missing useful attributes weakens matching.

How to evaluate it

Measure relevant recommendations and diversity, not rating error if no rating is predicted. Check new-user profile availability.

Build the answer in this order

  1. Identify features.
  2. Build profile.
  3. Match/rank.
  4. Discuss metadata, cold start（冷啟動） and variety.

Common wrong answers and the exact correction
  • Item-based（以項目為基礎） CF uses interaction patterns; content-based filtering（濾波） uses item attributes.
  • New-item support（支持度；同時出現的交易比例） still needs useful content.

An answer you could write

  • “I encode film attributes and the user’s liked-film profile in the same space, rank unseen candidates by cosine similarity（餘弦相似度） and explain the matching attributes.”
  • “For a new item this works from metadata; for a new user I first need preferences or a fallback, and I assess diversity as well as relevance.”

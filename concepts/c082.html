C082

RAG（Retrieval-Augmented Generation；檢索增強生成；先找資料再作答） and knowledge-graph cognition（認知；理解與思考）

RAG retrieves relevant（相關性；是否切合問題） source material before an LLM（Large Language Model；大型語言模型） writes an answer. A knowledge graph（知識圖譜） represents explicit（明確；直接提供的資訊） entities（實體；被描述的對象） and relationships for linked knowledge use.

Recognise（辨識；從資料找出物件或模式） this in a question: Answer from documents, grounded（依據來源；使輸出有可核對支持） response, current facts（事實；推理中已知的資訊）, connected evidence（證據；已觀察到的資訊）

How do retrieved passages and graph relationships support cognition?

  • FAQ retrieval returns an existing answer linked to a matched question. RAG adds generation from retrieved evidence; these are different architectures and different sources of risk.
  • RAG needs loading（負荷量；原特徵對主成分的係數）, splitting（切分；按條件分開資料）, indexing and retrieval before an LLM can use source chunks. The retrieved text must actually contain evidence for the requested answer.
  • A knowledge graph explicitly represents entities and relationships; a vector index ranks similar text. Choosing one depends on the needed query, not a preference for complexity.
  • Grounding reduces unsupported output but does not guarantee it disappears. Check retrieval relevance and generated claims as separate stages.

Common wrong answers and the exact correction
  • Retrieval alone is not RAG.
  • A vector database（向量資料庫；按向量相似度找資料） and a knowledge graph are different representations.
Apply the distinction

Apply the distinction

Data, components and application

  • Wrong chunk retrieved → improve retrieval and inspect relevance → generation cannot fix missing evidence reliably.
  • Unsupported answer → require citations（引用；資料來源標註）/fallback（備援處理） → limits overreach.
  • Unnecessary graph complexity → use a simple linked FAQ store → matches the actual task.

How to evaluate it

Check retrieval relevance, answer faithfulness, coverage（涵蓋率；能服務的使用者或項目範圍）, uncertainty（不確定性） and end-to-end（端到端） task success.

Build the answer in this order

  1. Knowledge needed.
  2. Choose retrieval/store representation.
  3. Retrieved evidence → answer.
  4. Check faithfulness and missing evidence.
An answer you could write

An answer you could write

  • For the supplied FAQ collection, semantic retrieval plus approved-answer lookup directly addresses Q1(b).
  • RAG is appropriate when retrieved passages must be synthesized; it adds a generation step that must be checked for evidence faithfulness.
  • A knowledge graph is justified by explicit relationship queries, not merely by the existence of a knowledge base（知識庫；供推理查用的知識）.

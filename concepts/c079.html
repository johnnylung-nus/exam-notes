LLM（Large Language Model；大型語言模型） reasoning（推理） and chain of thought（思維鏈）

A fluent sequence（序列；有先後順序的資料） of reasoning-looking steps can still be wrong. The lecture distinguishes language generation（生成式；學習資料生成或分布） from valid problem solving.

Recognise（辨識；從資料找出物件或模式） this in a question: Call tools, execute a workflow, choose actions（動作）, multi-step planning

Check a jug plan by actual volumes

Worked study example: Lecture capacities and goal; state order is (5L mug,3L mug). No graduation marks are available.

All steps shown
StepOperationStateLegality check
0Start empty(0,0)Within capacities
1Fill 3L mug(0,3)Tap fills to known capacity
2Pour 3L into empty 5L(3,0)All 3L fits
3Refill 3L(3,3)Both within capacity
4Pour until 5L full(5,1)Only 2L transfers; 1L remains

What this tells us: “Pour exactly 1L” would be illegal without a way to measure it. The demonstrated route obtains 1L through capacity constraints（約束條件） rather than inventing a measuring action.

Why is a fluent reasoning trace insufficient evidence（證據；已觀察到的資訊） of correctness?

  • Language generation selects plausible text; legal problem solving additionally requires explicit（明確；直接提供的資訊） states, permitted operations and a verified goal condition.
  • A long explanation can hide an illegal transfer, an unstated measurement capability or a changed question. Check operations rather than rhetorical confidence（信賴度；前件出現時後件也出現的比例）.
  • Intermediate state verification is essential: a final number can be right by coincidence while the proposed procedure cannot produce it.
  • The lecture’s water-jug example shows why a solution should be executable in the stated world, not only resemble a familiar puzzle answer.
Implementation steps and their purpose
  1. Write down the actual state, goal and allowed operations.
  2. Translate the proposed answer into explicit steps.
  3. Check each step against constraints.
  4. Recalculate intermediate results.
  5. Check the final goal independently.
  6. Reject an invalid step even if the explanation sounds confident.

Prepare the data and validate the representation（表徵；資料的表示方式）

Data, components and application

  • Memorized familiar puzzle answer → recheck the exact wording → changed details can invalidate it.
  • Persuasive explanation → verify state transitions（狀態轉移） → language confidence is not proof.
  • Correct-looking final answer → inspect legal operations → a lucky result can hide invalid reasoning.

How to evaluate it

Evaluate constraint satisfaction, correctness of intermediate states and actual attainment of the goal.

Build the answer in this order

  1. Formalize the exact problem.
  2. Verify each operation.
  3. Identify invalid assumption（假設；答案依賴但題目未明說的條件）/step.
  4. Check the goal.

Common wrong answers and the exact correction
  • More explanation does not guarantee better reasoning.
  • Do not treat generated text as a verified calculation.

An answer you could write

  • Represent the jug state as amounts in the 5L and 3L mugs and allow only fill, pour and empty operations.
  • The sequence (0,0)→(0,3)→(3,0)→(3,3)→(5,1) leaves one litre in the 3L mug.
  • Reject a step that assumes arbitrary measured quantities because the mugs have no graduations.

C059

Cognitive-system architecture（認知系統架構）

A cognitive system（認知系統） turns observations（觀測值） into useful actions（動作） using perception（感知；由輸入理解環境）, memory and reasoning（推理）. Learning is a separate function; applying a fixed rule is not learning.

How do perception, memory, reasoning and action connect?

  • Perception transforms measurements into usable facts（事實；推理中已知的資訊）; reasoning needs those facts plus stored knowledge, rather than guessing directly from a raw image.
  • A runtime case record holds the present observations. A knowledge base holds reusable definitions, relationships and rules applied to many cases.
  • Reasoning selects a conclusion（結論）; planning identifies what to do; action delivers or executes it. The boxes should not all be labelled “AI（Artificial Intelligence；人工智慧）”.
  • Learning changes a model or knowledge from experience. Applying an unchanged formula to another image changes the case result, not the formula.
Implementation steps and their purpose
  1. State the user problem and required output.
  2. Name the inputs and perception process.
  3. Show what information enters memory or the knowledge base.
  4. Connect reasoning to a decision and action.
  5. Show feedback or learning only where the case supports it.

Data, implementation and validation

Data, components and application

  • Vague AI box → label（標籤；作比較的正確答案） inputs, outputs and responsibility → makes the design assessable.
  • Invented training（訓練） → distinguish building a model from using a fixed rule → preserves case evidence（證據；已觀察到的資訊）.

How to evaluate it

Check each required output, component errors, response time and the consequences of a wrong action.

Build the answer in this order

  1. User need → required functions.
  2. Data → perception output.
  3. Knowledge → reasoning/action.
  4. Test the whole flow.

Common wrong answers and the exact correction
  • A function is a verb/process; raw data（原始資料；未轉成有意義描述的輸入） and information are outputs.
  • Not every deployed cognitive system learns during operation.

An answer you could write

  • The App recognizes pupil/iris regions, counts their pixels and calculates relative pupil sizes before applying the supplied rule.
  • The current case record holds measurements; the knowledge base holds reusable definitions and comparison rules.
  • Applying a fixed rule is reasoning/inference, not learning a new rule during the consultation.

Where this is tested in the sample papers

ISY5001 Q2(a) — Stakeholder（持份者；受系統影響或參與的人） pain points（痛點；使用者目前面對的困難）

What the question requires

  1. Name the stakeholder.
  2. State a difficulty supported by the case.
  3. Connect it to the system’s intended benefit.

Proposed answer points

  • Primary doctors may lack specialist eye knowledge when choosing diagnosis（診斷；判斷可能的疾病或故障原因）/referral urgency（轉介急切程度）.
  • Patients may face extra referral steps or delayed specialist assessment.

Avoid: Avoid invented numerical（數值型；以數量表示） shortages or generic “AI is faster” claims.

ISY5001 Q2(h) — Eleven cognitive-model entities（實體；被描述的對象）/functions

What the question requires

  1. Follow the supplied diagram, not a generic training pipeline（處理流程）.
  2. For each row give a case-specific function or output.
  3. Keep processes (verbs) distinct from data/results (nouns).
  4. Respect the greyed learning/new-knowledge branch.

Proposed answer points

  • Operational sequence（序列；有先後順序的資料）: stimulus（環境刺激；系統感測到的外界變化） → capture → raw pixels → recognize/segment → measurements → apply known rule → result/plan → display/action → effect.
  • The supplied figure greys out Learn and new knowledge. Do not invent online learning as an active App function.

Avoid: SystemReady is a status, not perception. Raw pixels are not yet labelled pupil/iris information.

ISY5001 Q2(i) — Patient self-service: benefits, risks and role boundaries

What the question requires

  1. State a position on removing the primary doctor.
  2. Acknowledge the convenience benefit.
  3. Explain a case-specific risk and a safer scope.

Proposed answer points

  • A patient-facing information/capture function could improve convenience, but removing the doctor is not justified by the presented diagnostic/triage（分流；判斷處理或轉介的急切程度） support（支持度；同時出現的交易比例） case.
  • Capture errors, incomplete context and delayed escalation are possible risks; retain clinician assessment for the clinical decision.

Avoid: Do not claim all cognitive systems always require a doctor; argue from this system’s intended users and risks.

Quick distinction: capture and recognize are functions; pixels and measurements are their different outputs. Applying an existing rule is inference. It does not create new knowledge.

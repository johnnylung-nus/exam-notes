C063

Slot detection（槽位辨識） and information extraction（資訊擷取）

Slots（資訊欄位） are named details required by an intent（意圖）. Information extraction finds the values and links them to the correct entities（實體；被描述的對象）.

What this tells us: The slot name is “interval”, its value is “20 minutes”, and the intent is “set reminder”. Writing all three as the same concept makes the schema（知識結構） unusable.

Which required details have been supplied, and which are missing?

  • Slot extraction answers which details accompany the goal. The same entity value can serve different roles, so its slot name must follow the selected action.
  • Standard dates, locations and names can use NER（Named Entity Recognition；命名實體辨識）; custom terms such as reminder type may need domain rules or annotated examples.
  • Validation checks whether a value is usable, not merely present. “Regularly” does not specify a numeric（數值型；以數量表示） interval if the scheduling service requires one.
  • Conversation state supplies omitted details only when the reference is clear; otherwise clarification is safer than filling a field with a guess.
Implementation steps and their purpose
  1. Define required slot names for each intent.
  2. Extract standard entities such as dates or locations using NER.
  3. Use domain rules or annotated examples for custom fields.
  4. Resolve references to previous entities.
  5. Validate completeness（完備性） and ask only for missing information.

Prepare the data and validate the representation

Data, components and application

  • Wrong entity type → validate against the slot schema → avoids putting a person into a location field.
  • Custom wording missed → add domain rules or labelled examples → covers case vocabulary.
  • Unclear reference → clarify → avoids filling a slot with a guess.

How to evaluate it

Check extracted values, their field names, reference resolution and downstream（後續階段；使用前一步結果的模型或流程） action correctness.

Build the answer in this order

  1. Required action → required fields.
  2. Choose entity extraction method.
  3. Handle missing/ambiguous values.
  4. Verify action template.

Choose the representation from the task

Use when the system knows the requested action but still needs who, where, when or another domain-specific field.

Common wrong answers and the exact correction
  • A slot is the field; its value is the supplied detail.
  • Detecting an entity alone does not resolve its role.

An answer you could write

  • For set-reminder intent, use reminder_type and interval slots; “blink every 20 minutes” supplies their values.
  • Normalize equivalent wording such as “half an hour” to the scheduling service’s interval representation.
  • Resolve “that reminder” using dialogue state（對話狀態） and ask for clarification if the reference or a required value is missing.

Where this is tested in the sample papers

ISY5001 Q1(a) — Intent and slots

What the question requires

  1. List the supported user goals.
  2. For each goal, identify the fields needed to fulfil it.
  3. Give an appropriate value example; separate user context from intent.

Proposed answer points

  • Intent = what the user wants; slot = a required detail; slot value = the actual detail.
  • Case-supported goals include ergonomic（人體工學；讓工作環境配合人體需要） advice, habit reminders and exercise guidance. A reminder needs type/interval; an exercise request needs exercise type.

Avoid: Do not use a job role or every symptom（症狀；患者感受到的不適） as a separate intent.

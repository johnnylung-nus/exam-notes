C061

Intent classification（意圖分類）

Intent classification predicts the user’s requested goal from their utterance（語句片段；一次說話單位）. It is a classification（分類；預測類別） task, not the extraction of every detail.

What this tells us: “Software engineer” is a role feature in the work-pattern problem, not a user intent. A high-level intent must describe what the bot is being asked to do.

What goal is the user expressing?

  • Training examples connect many utterance forms to a small set of supported goals. The class label describes the operation, not the employee’s occupation.
  • A classifier learns a boundary between intents from labelled text features. A similarity approach instead compares the query with representative known utterances.
  • Both methods need coverage（涵蓋率；能服務的使用者或項目範圍） of confusing requests; ordinary word overlap can confuse “show reminder settings” with “set a reminder”.
  • Confidence（信賴度；前件出現時後件也出現的比例） handling is part of the design. The highest-ranked supported class can still be wrong when the request is unsupported or ambiguous.

Common wrong answers and the exact correction
  • Classification chooses a goal; NER（Named Entity Recognition；命名實體辨識） extracts a detail.
  • Similar wording need not mean（均值；平均數） identical intent.

Apply the distinction

Data, components and application

  • Similar classes confused → improve representative training examples and boundaries → makes routing clearer.
  • Unsupported request forced into a class → provide fallback → avoids pretending the system can fulfil it.
  • Few labelled examples → test a similarity baseline → reduces initial training needs.

How to evaluate it

Inspect intent mistakes by class and paraphrase; also check whether the system completes the intended task.

Build the answer in this order

  1. Identify supported goals.
  2. Choose text representation（表徵；資料的表示方式） and classifier.
  3. Specify uncertain-input handling.
  4. Evaluate routing and task success.

An answer you could write

  • Define intents by the requested operation: ergonomic advice, reminder setting and exercise guidance, not software engineer or sales executive.
  • Train an intent classifier on labelled paraphrases using consistent（一致性） text features or compare with representative utterance embeddings（嵌入；用向量表示內容）.
  • Check confusion between related requests and provide clarification for unsupported or uncertain intent predictions.

Where this is tested in the sample papers

ISY5001 Q1(a) — Intent and slots

What the question requires

  1. List the supported user goals.
  2. For each goal, identify the fields needed to fulfil it.
  3. Give an appropriate value example; separate user context from intent.

Proposed answer points

  • Intent = what the user wants; slot = a required detail; slot value = the actual detail.
  • Case-supported goals include ergonomic advice, habit reminders and exercise guidance. A reminder needs type/interval; an exercise request needs exercise type.

Avoid: Do not use a job role or every symptom（症狀；患者感受到的不適） as a separate intent.

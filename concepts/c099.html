Single-modality（單一模態） sensing

Single-modality sensing uses one type of evidence（證據；已觀察到的資訊）, such as inertial measurements, audio or vision. Choose the modality（模態；資料形式如語音或影像） according to what must be recognized.

Recognise（辨識；從資料找出物件或模式） this in a question: Multiple sensors（感測器）, camera + sound, conflicting measurements, alignment（對齊）

What this tells us: One strong result does not transfer automatically across tasks. A model identifying the speaker has not thereby recognized the command or checked whether it is safe to execute.

What can one sensing modality observe reliably?

  • A single modality can have multiple axes or channels. Three accelerometer axes remain inertial evidence, not three different modalities.
  • The useful unit often is a time window: one isolated acceleration reading can occur during several activities, while a changing pattern is more distinctive.
  • Task definitions matter within a modality. Audio classification, speaker recognition and speech recognition have different outputs despite using microphone data.
  • Start with the simplest evidence sufficient for the goal; add a modality when it resolves a specific observable weakness rather than for sophistication.
Implementation steps and their purpose
  1. Define the target event and operating conditions.
  2. Choose a modality that observes the needed evidence.
  3. Capture and buffer an appropriate window.
  4. Extract features（特徵；描述樣本的屬性） or learn a representation（表徵；資料的表示方式）.
  5. Recognize the activity/object（客體；三元組終點）/event.
  6. Connect the result to the specified action.

Prepare the data and validate the representation

Data, components and application

  • Chosen modality cannot observe required fact（事實；推理中已知的資訊） → add/change evidence → no algorithm can reliably infer（推論；由依據得出結論） every hidden detail.
  • Environment noise（雜訊；干擾有效訊息的成分） or occlusion → improve capture or consider complementary input → modality has specific weaknesses.
  • Single reading too weak → use a sequence（序列；有先後順序的資料）/window → motion and speech depend on change.

How to evaluate it

Check target recognition, robustness in intended conditions, latency and whether the sensor is sufficient for the required output.

Build the answer in this order

  1. Required fact.
  2. Why this modality?
  3. Window/features/model.
  4. Failures and action quality.

Common wrong answers and the exact correction
  • Three accelerometer axes remain one modality.
  • Speaker recognition is not speech transcription.

An answer you could write

  • I choose one modality because it directly observes the required motion/sound/appearance evidence.
  • I define one window and its target output before selecting the recognizer.
  • I add another modality only if it supplies a clearly missing piece of evidence.

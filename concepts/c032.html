Retrieval-augmented generation（檢索增強生成；先找資料再作答）

Retrieval-augmented generation retrieves relevant（相關性；是否切合問題） external material and supplies it to an LLM（Large Language Model；大型語言模型） before it generates an answer. It can improve grounding（依據來源；使輸出有可核對支持） and freshness.

Recognise（辨識；從資料找出物件或模式） this in a question: Answer from documents, grounded response, current facts（事實；推理中已知的資訊）, connected evidence（證據；已觀察到的資訊）

What this tells us: A useful system can explain whether failure came from retrieval coverage（涵蓋率；能服務的使用者或項目範圍） or generation faithfulness. Retrieval reduces hallucination（幻覺；生成無依據內容） risk but does not guarantee correctness.

Where does retrieved evidence enter a generated answer?

  • RAG has two accuracy（準確率） problems: finding the right evidence and generating an answer that stays faithful to it. A generator can be perfectly faithful to an irrelevant passage and still answer the user incorrectly. Evaluating only fluent final wording hides the retrieval failure.
  • The document index should preserve source identity and enough context to interpret exceptions. A chunk containing “remote work permitted” may be misleading if the adjacent condition requires country approval. Chunking（分塊；切成可處理的小段） and retrieval must retain the rule and its applicable scope, rather than merely maximise keyword matches.
  • In sample Q1(b), returning the approved answer linked to the closest stored question is semantic FAQ retrieval. It becomes retrieval-augmented generation only if an LLM synthesises a response from retrieved evidence. Do not add that generation step merely to sound sophisticated when exact approved answers already meet the task.
Implementation steps and their purpose
  1. Prepare approved documents with source identifiers.
  2. Split（切分；按條件分開資料）/index searchable content using suitable text or embeddings（嵌入；用向量表示內容）.
  3. Retrieve relevant passages for the user query.
  4. Provide passages and the question to the LLM.
  5. Return an evidence-grounded answer or clarify when retrieval is insufficient.

Prepare the data and validate the representation（表徵；資料的表示方式）

Data, components and application

  • Wrong passage → improve retrieval/chunking → generation cannot compensate for absent evidence.
  • Unsupported additions → constrain answer to evidence and verify → RAG reduces but does not eliminate hallucination.

How to evaluate it

Check retrieval relevance/coverage and answer faithfulness separately. Test unanswered questions and stale/conflicting policies.

Build the answer in this order

  1. Identify knowledge source.
  2. Describe retrieval.
  3. Describe grounded generation.
  4. Add verification/fallback（備援處理）.

Common wrong answers and the exact correction
  • Semantic FAQ retrieval returning a stored answer is not automatically RAG.
  • Retrieval does not retrain the LLM.

An answer you could write

  • “I index approved policy passages with source IDs, retrieve the relevant rule plus exceptions, and generate only claims supported by those passages.”
  • “When retrieval is insufficient, I clarify or report the gap; the FAQ task may instead return its stored approved answer directly.”

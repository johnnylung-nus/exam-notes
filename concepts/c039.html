C039

Item-based（以項目為基礎） collaborative filtering（協同過濾）

Item-based CF（Collaborative Filtering） compares items using how users rated them, then recommends items related to those the target user liked. It remains collaborative filtering.

Recognise（辨識；從資料找出物件或模式） this in a question: Ratings, similar users/items, collaborative filtering, sparse（稀疏性） voluntary feedback

What this tells us: One shared similarity table supports personalised predictions through each user’s own ratings. The method does not compare a user profile directly with product-description features.

How do similar items support（支持度；同時出現的交易比例） a recommendation（推薦）?

  • Item-based CF represents each item by its pattern of user interactions, then compares items across users. It is not content matching: two films with different descriptions can be similar because the same users rate them similarly. Transposing the rating matrix changes the comparison perspective, not the source of evidence.
  • For a target user and candidate X, find items that user has rated and that are similar to X. Their ratings, weighted by item similarity, determine the candidate score. Different users therefore receive different predictions even though the item-similarity table is shared.
  • Precomputation can reduce serving work because item relationships often change less frequently than individual interests. The advantage depends on user/item counts and catalogue change, not an absolute law that item-based is always faster. New or rarely interacted items still lack collaborative evidence and may need content or popularity（熱門程度） fallback.
Implementation steps and their purpose
  1. Transpose（轉置） the interaction perspective: each item is described by user ratings.
  2. Compute item similarities using suitable overlap/normalisation.
  3. Precompute a neighbour list for each item.
  4. Use the target user’s ratings of similar items to score candidates.
  5. Exclude seen/ineligible items and rank（秩；矩陣獨立資訊的維度數）.

Prepare the data and validate the representation（表徵；資料的表示方式）

Data, components and application

  • Sparse item histories → content/hybrid（混合式） fallback → item similarities also need evidence.
  • Changing catalogue → refresh similarities → old precomputed neighbours can become stale.

How to evaluate it

Compare rating/top-list accuracy（準確率）, coverage（涵蓋率；能服務的使用者或項目範圍） and serving cost. The usual item-based speed benefit depends on item/user counts and update frequency（頻率）.

Build the answer in this order

  1. Identify item representation.
  2. Explain offline similarity.
  3. Show user-specific scoring.
  4. Discuss stability and sparse-item limits.

Choose the representation from the task

Useful when item similarities can be precomputed and remain more stable than user similarities.

Common wrong answers and the exact correction
  • Similarity here comes from users, not product descriptions.
  • Precomputation does not remove all cold-start problems.

An answer you could write

  • “I precompute similarity between item rating columns, then score X using this user’s ratings of its similar items: (0.9×5+0.1×2)=4.7.”
  • “The speed benefit comes from reuse of stable item similarities, but sparse/new items still require evidence or fallback.”

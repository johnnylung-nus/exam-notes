Ensemble（集成學習） diversity（多樣性） and voting（投票）

An ensemble combines several model predictions. It helps most when the individual models are useful and make different errors, so their mistakes can partly cancel.

Recognise（辨識；從資料找出物件或模式） this in a question: Unstable single tree, feature importance（變數重要性；模型使用該特徵的相對程度）, bootstrap（自助抽樣；從原資料有放回抽樣）, vote

Choose from the scenario

Use when a single model is unstable or several complementary sources of predictive evidence（證據；已觀察到的資訊） are available.

Why can diverse mistakes make an ensemble more reliable?

  • Combining models helps when their errors differ on relevant（相關性；是否切合問題） cases. Three copies of the same decision function offer no new evidence; diversity must coexist with reasonable individual predictive ability.
  • Majority voting combines hard decisions, while probability（機率） averaging retains confidence（信賴度；前件出現時後件也出現的比例） information. A learned stacker uses base-model outputs as features（特徵；描述樣本的屬性） and therefore needs out-of-fold training（訓練） predictions to avoid learning from memorized scores.
  • The strongest component is the practical baseline（基準；供比較的簡單方法）. Ensemble accuracy alone does not settle value if extra inference（推論；由依據得出結論） cost, difficult maintenance or increased false alarms outweigh the improvement.

Diagnose: Ensemble adds cost but no validation improvement

What you observeWhy it happensWhat to changeWhy that helps
Ensemble adds cost but no validation improvementBase models make highly correlated（相關；數值一同變化的程度） errorsInspect disagreement and remove redundant（冗餘；資訊重複） componentsExtra copies of the same mistakes cannot cancel those mistakes.
Common wrong answers and the exact correction
  • Diversity alone is insufficient if all models are poor
  • Stacking needs a learned combiner, unlike fixed voting.

Apply the distinction

Data, components and application

  • Highly correlated errors → diversify models or training samples → gain complementary evidence
  • One weak model hurts → remove or reweight after validation → avoid blind averaging
  • Stacking leakage → use out-of-fold base predictions → keep combiner training honest

How to evaluate it

Compare target metrics and resource cost; a tiny accuracy gain may not justify（給出理由；用情境與證據支持選擇） much higher latency.

Build the answer in this order

  1. Identify the single-model weakness
  2. Explain useful diversity
  3. Specify combination
  4. Validate benefit and business cost

An answer you could write

  • “The models are useful individually and their validation errors differ, so aggregation may reduce mistakes.”
  • “I compare against the best component and include recall（召回率）, false-alarm cost and latency in the choice.”

Where this is tested in the sample papers

ISY5002 Q1(d) — Sequence（序列；有先後順序的資料） model, input construction and combination

What the question requires

  1. Choose LSTM（Long Short-Term Memory；長短期記憶網路） for ordered session（工作階段；一次連續造訪的記錄） events.
  2. Represent each session as an ordered sequence with a purchase label.
  3. Encode page/source, scale duration, pad（補齊；把不同長度輸入補至所需長度）/mask（遮罩；標示哪些位置應使用或忽略） and split（切分；按條件分開資料） without future leakage.
  4. Combine outputs with earlier models without training-score leakage.

Proposed answer points

  • Clickstream（點擊軌跡；依次瀏覽與操作的記錄） sequence → LSTM → Dense sigmoid（S形函數） → purchase score; use binary cross-entropy（二元交叉熵；二分類損失） for the binary label.
  • For stacking, generate LSTM training scores out of sample, add them to the earlier model’s inputs, and compare against that model on validation data.

Avoid: Do not use post-purchase/future events when predicting an earlier intervention. In-sample base-model scores can leak into a stacked learner.

Anomaly detection（異常偵測）

Anomaly detection identifies observations（觀測值） that differ from expected behaviour. It may return a normal/anomaly label（標籤；作比較的正確答案） or a score needing a threshold（門檻值）.

Recognise this in a question: Very few faults, only two anomalies, rare abnormal event · Rare class（類別；分類目標）, imbalance, augmentation, synthetic samples

When is deviation from normal behaviour more useful than fault classification（分類；預測類別）?

  • Anomaly scores measure deviation from an assumed normal reference, not a verified cause. A high score indicates investigation need unless a separate diagnostic model is validated.
  • Geometric methods use distance from normal clusters; statistical methods use low-probability regions; supervised methods require normal and abnormal labels.
  • A threshold converts scores into operational alerts and changes false alarms versus missed events. It should reflect scenario costs and available validation.
  • Context and sequences matter: an individually ordinary reading may be abnormal for the operating mode or as part of an unusual pattern.
Implementation steps and their purpose
  1. Define normal behaviour and relevant context.
  2. Prepare representative normal and available abnormal examples.
  3. Choose cluster-distance, distribution-based or supervised classification approach according to available data.
  4. Produce a score or label.
  5. Select a threshold according to false-alarm/missed-event consequences.
  6. Investigate flagged cases and monitor drift.

Implement it and test the outcome

Data, components and application

  • Rare faults → evaluate missed events as well as false alarms → overall accuracy can be misleading.
  • Normal operation changes → include context/update baseline → drift can trigger spurious alarms.
  • Single reading normal but sequence unusual → analyze windows → collective anomalies need temporal（時間的） context.

How to evaluate it

Check false alarms, missed anomalies, detection delay and usefulness of alerts on unseen operation periods.

Build the answer in this order

  1. What is normal?
  2. Point/contextual/collective deviation.
  3. Score and threshold.
  4. Consequences and evaluation（評估）.

An answer you could write

  • I define normal behaviour for the relevant operating mode and produce an anomaly score.
  • I choose a threshold using missed-event and false-alert consequences on held-out operation.
  • A flagged anomaly is not automatically a diagnosed Mistracking or Carryback cause.

ISY5002 Q2(c) — Critique anomaly classification with only two anomalies

What the question requires

  1. Read the imbalance and representation constraints（約束條件）.
  2. Identify two distinct challenges in the proposed classifier.
  3. Propose a remedy for each and tie it to the supplied features（特徵；描述樣本的屬性）/data.
  4. Explain how anomaly detection would be assessed.

Proposed answer points

  • Challenge 1:3,000 normal sequences versus two anomalies cannot support reliable supervised anomaly generalization（泛化能力）; an all-normal model already scores 3000/3002≈99.93% accuracy. Consider learning normal behaviour with a one-class or reconstruction-based detector and collect more diverse verified anomalies.
  • Challenge 2:30 concatenated features can be redundant/on different scales; the plotted histogram may be less discriminative than frequency（頻率） features. Inspect the supplied figure, compare representations on held-out data, scale training-derived features and reduce redundant dimensions if justified.
  • Each sequence has 4×50=200 samples; this is separate from the engineered 10+20=30 feature dimensions. Evaluate false alarms and anomaly recall（召回率）; two anomalies make estimates highly uncertain.

Avoid: Do not manufacture many reliable abnormal examples by copying two rows. A temporal histogram also discards order. The missing QA answer is newly analysed study guidance, not a past reviewed answer.

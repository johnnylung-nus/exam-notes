Batch normalization（批次正規化）

Batch normalization standardizes intermediate activations using batch statistics during training（訓練）, then learns scale and shift. It often makes optimization more stable; any regularization（正則化） effect is secondary.

Recognise（辨識；從資料找出物件或模式） this in a question: Loss（損失函數；衡量預測錯誤） spikes, gradients vanish/explode, deep model not learning

Normalize and rescale one feature（特徵；描述樣本的屬性）

z=(x−μ)/√(v+ε); output=γz+β
μ
training-batch mean（均值；平均數）
v
training-batch variance（變異數）
ε
small stability constant
γ,β
learned scale and shift
  1. Batch[1,3] has mean2,variance1.
  2. Ignoring ε for arithmetic,normalized values are[−1,1].
  3. Scaleγ=2,shiftβ=0.5 gives[−1.5,2.5].
  4. At inference（推論；由依據得出結論）,use stored statistics rather than the current test batch.

Interpret the result: Batch normalization differs from input scaling, dropout（隨機停用神經元） and weight penalties.

Normalize and then learn a useful scale

Worked study example: Illustrative batch for one feature is [1,3], mean 2 and variance 1. Ignore the tiny stability constant for arithmetic. Learned scale is 2 and learned shift is 0.5.

What this tells us: The transformed training pair has mean 0.5, demonstrating why learned shift breaks the simplistic permanent-zero-mean interpretation.

Which statistics does batch normalization use at training and inference?

  • Batch normalization normalizes intermediate features with batch mean and variance during training, then applies learned scale and shift. Those learned terms can restore a useful distribution; normalized does not mean permanently mean zero and variance one.
  • Running statistics accumulated during training are used at inference. This avoids making one deployed prediction（預測） depend on whatever unrelated observations（觀測值） happen to share its test batch.
  • It often improves optimization and introduces batch-related noise（雜訊；干擾有效訊息的成分）, but does not explicitly（明確；直接提供的資訊） shrink weights（權重） like L2（L2懲罰；以權重平方作限制） or randomly drop units like dropout. Input scaling fitted once on training features is also different from normalization of intermediate activations.
Implementation steps and their purpose
  1. Insert batch normalization at an appropriate layer position
  2. Estimate batch mean and variance during training
  3. Normalize activations and apply learned scale and shift
  4. Maintain running statistics
  5. Use stored statistics in inference mode

Use the result and check it

Data, components and application

  • Very small batches produce noisy estimates → reconsider batch size（批次大小；每次更新用的樣本數） or normalization choice → stabilize statistics
  • Training/evaluation（評估） mode mismatch → use inference mode for testing → avoid batch-dependent errors

How to evaluate it

Compare convergence（收斂；結果逐步趨於穩定） speed, stable loss and held-out（留出資料；未參與該階段訓練） quality; do not claim it guarantees absence of overfitting（過度擬合）.

Build the answer in this order

  1. Identify optimization difficulty
  2. Explain normalization and learned rescaling
  3. State training/inference distinction
  4. Compare with weight penalties and dropout

Common wrong answers and the exact correction
  • Batch normalization does not remove neurons
  • It is different from fitting a scaler once on the original training features.

When would this calculation be useful?

Use to improve training behavior in a suitable deep architecture（架構）, not as a synonym for input preprocessing（前處理） or dropout.

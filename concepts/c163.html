C163

CNN（Convolutional Neural Network；卷積神經網路） application design

CNN design connects the image task, learned spatial（空間的） features（特徵；描述樣本的屬性） and a correctly sized output. The classifier should be no larger than justified by the data and operational constraints（約束條件）.

Recognise（辨識；從資料找出物件或模式） this in a question: Image CNN, padding（填充）/stride（步幅）, feature maps（特徵圖；某層輸出的空間表示）, pooling（池化）, huge dense layer（全連接層；各輸入連至各輸出）

What must the system deliver?

Use when a scenario asks for image-model architecture, activation（激活函數；轉換神經元輸出）, loss（損失函數；衡量預測錯誤）, data preparation and a lean redesign.

Scenario cueSuitable choiceWhy it fits
Owner wants a lean model（精簡模型；控制參數、儲存與運算量） with limited uneven training（訓練） imagesReduce the expensive tail（尾實體；關係終點） and use class-aware validationThis targets resource cost and capacity while separately exposing minority-class failures.

How do image constraints determine the CNN application design?

  • A CNN architecture answer needs an input shape, a spatial feature extractor, a classifier and a label-compatible output. Choosing ReLU（Rectified Linear Unit；修正線性；負數歸零） or softmax（機率正規化；轉成總和為1的權重） without explaining which stage and target it serves is incomplete.
  • Separate excessive fitting capacity from class（類別；分類目標） imbalance. A smaller Dense tail can reduce overfitting（過度擬合） risk and resource cost; class weighting, sampling（取樣） and appropriate metrics address unequal label（標籤；作比較的正確答案） counts. Neither alone repairs missing representative classes.
  • Keep the original task clear. The sample requires918 exclusive brand–type–value combinations, so replacing the head（頭實體；關係起點） with918 softmax outputs preserves it. A multi-head decomposition is another possible design only if labels and combination constraints are justified.
Implementation steps and their purpose
  1. Define image dimensions and required classes
  2. Resize and normalize consistently and split（切分；按條件分開資料） original images first
  3. Stack a small number of convolution（卷積）/activation/pooling stages
  4. Track shapes and identify the expensive tail
  5. Choose a compact classifier with target-matched output
  6. Train with augmentation（增強；產生保留所需意義的資料變體）, regularization（正則化） and validation monitoring

Specify a lean classifier without changing the task

Worked study example: Sample original tail is Flatten9408 → Dense256 → Dense128 → Dense918. Retain convolution layers totaling18,960 parameters（參數）; replace the whole old Dense tail with Dense64 → Dense918.

Data, implementation and validation

Data, components and application

  • Few uneven images → class-aware metrics plus suitable augmentation → address coverage（涵蓋率；能服務的使用者或項目範圍）/imbalance
  • Huge Dense tail → reduce width → cut cost and fitting capacity
  • New labels needed → verify output mapping → maintain the intended class task

How to evaluate it

Compare per-class recall（召回率）, overall quality, parameter count and inference（推論；由依據得出結論） cost against the original model.

Build the answer in this order

  1. Identify the design flaw
  2. Draw a valid replacement
  3. Calculate its size
  4. Justify（給出理由；用情境與證據支持選擇） activation/loss and validation

Diagnose: Training loss falls but validation loss rises

What you observeWhy it happensWhat to changeWhy that helps
Training loss falls but validation loss risesClassifier overfits limited dataUse early stopping（提前停止）, suitable augmentation and validated regularizationThese reduce training-specific fit while retaining useful visual patterns.
Common wrong answers and the exact correction
  • Uneven classes and overfitting are distinct issues
  • A leaner architecture must still meet the prediction（預測） objective.

An answer you could write

  • “I retain the convolution blocks and replace Dense256→Dense128 with Dense64, followed by918-way softmax.”
  • “The new total is680,806; I train categorical cross-entropy and compare per-class recall, validation loss, size and inference cost.”

Where this is tested in the sample papers

ISY5002 Q2(a) — Lean CNN redesign, parameter arithmetic, activations and loss

What the question requires

  1. Locate the parameter bottleneck.
  2. Propose a smaller classifier tail while preserving required outputs.
  3. Recalculate weights（權重） plus biases and total reduction.
  4. Choose activations/loss consistent with the classification（分類；預測類別） task.
  5. Validate accuracy, imbalance and lean deployment constraints.

Proposed answer points

  • The original tail is Flatten9408 → Dense256 → Dense128 → Dense918. Its Dense parameter counts（參數數量） are 2,408,704, 32,896 and 118,422; with 18,960 convolution parameters the total is 2,578,982. The first Dense alone accounts for about 93.4%, so the actual bottleneck is the flattened-to-dense connection.
  • A defensible replacement is Flatten9408→Dense64→Dense918. Unchanged convolutions:18,960; Dense64:602,176; output:59,670; total:680,806. Reduction:1,898,176≈73.6%.
  • Use ReLU in the hidden layers, softmax over the 918 mutually exclusive combined classes, and categorical cross-entropy. Smaller is not automatically better: check held-out quality.

Avoid: 5,000 unevenly spread images raise overfitting and class-imbalance concerns; those are related but different problems. The combined 918-way output is one design, not the only possible factorized output architecture.

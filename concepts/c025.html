C025

Bilinear（雙線性） / DistMult embeddings（嵌入；用向量表示內容）

Bilinear KG（Knowledge Graph；知識圖譜） models score interactions between a head（頭實體；關係起點）, a relation（關係；對象間的連結） and a tail（尾實體；關係終點）. RESCAL uses a full relation matrix; DistMult restricts it to a diagonal for efficiency.

Recognise（辨識；從資料找出物件或模式） this in a question: Predict a missing relation, entity（實體；被描述的對象） embedding, relation-specific（關係專屬；依關係使用不同設定） projection（投影；轉到選定方向的座標）

Choose from the scenario

Choose by the relation pattern: efficient symmetric（對稱；交換方向仍相同） scoring may be suitable for some links but fails to distinguish directed roles.

What this tells us: No amount of training（訓練） can make this unchanged scoring expression distinguish those two directions for the same relation. This is an expressiveness issue, not merely insufficient optimisation.

What interactions does a bilinear graph score capture?

  • RESCAL and DistMult score how head and tail features（特徵；描述樣本的屬性） interact under a relation. RESCAL’s full relation matrix can mix different feature dimensions. DistMult keeps only diagonal interactions, so each head component interacts with the corresponding tail component through a relation weight; this reduces parameter cost.
  • The same simplification creates a structural limitation. Multiplying corresponding head and tail values is unchanged when their order swaps, so DistMult gives identical scores to a triple and its reversal under the same relation. This is a problem for fatherOf, greaterThan or any relation where direction should matter.
  • A richer full-matrix or complex-valued model can represent patterns DistMult cannot, but its cost must be justified. The lecture’s RESCAL memory warning is valid in spirit, but relation matrices scale with embedding dimension squared per relation, not simply the number of entities squared. Entity storage is a separate component.

Common wrong answers and the exact correction
  • DistMult’s computational efficiency does not remove its symmetry limitation.
  • KG factorisation is a different task from user–item recommendation（推薦） MF（Matrix Factorization；矩陣分解）.

Apply the distinction

Data, components and application

  • Asymmetric relation → consider ComplEx or a suitable asymmetric model → DistMult swaps head/tail without changing score.
  • Full relation matrices → assess memory/overfitting（過度擬合） → RESCAL has greater parameter cost.

How to evaluate it

Test directional reversals, held-out（留出資料；未參與該階段訓練） link ranks and memory. RESCAL relation-matrix storage depends quadratically on embedding dimension, not simply entity count.

Build the answer in this order

  1. Identify relation pattern.
  2. Explain score interaction.
  3. Compare full and diagonal matrices.
  4. Justify（給出理由；用情境與證據支持選擇） choice and tests.

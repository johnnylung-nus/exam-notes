C025

MR-25 Bilinear（雙線性） / DistMult embeddings（嵌入；用向量表示內容）

Bilinear KG（Knowledge Graph；知識圖譜） models score interactions between a head（頭實體；關係起點）, a relation（關係；對象間的連結） and a tail（尾實體；關係終點）. RESCAL uses a full relation matrix; DistMult restricts it to a diagonal for efficiency.

DistMult: give a score to a triple

Input: a proposed fact, written as (head, relation, tail).

Example structure: (Person A, worksFor, Company B)
Head vector + relation weights + tail vector
             ↓
Multiply matching coordinates, then ADD
             ↓
One compatibility score
  • h: vector for the head entity.
  • r: relation weights, stored as the diagonal of the relation matrix.
  • t: vector for the tail entity.
  • Higher score: the model ranks this triple as a better match under this scoring convention.
  • Not a probability: a score of 95 does not mean 95% chance of truth. Compare candidates under the same model; there is no universal score cutoff.

DistMult’s limitation: swapping h and t leaves the score unchanged. It cannot distinguish the two directions of an asymmetric relation using that score.

RESCAL’s difference: it uses a full relation matrix, allowing cross-coordinate interactions; its relation matrix need not be symmetric.

A formula written hᵀRᵣt is DistMult only when Rᵣ is diagonal. With a general full matrix, it is the RESCAL form. “High score” means model compatibility, not established real-world truth.

Multiplication is symmetric in h_i and t_i, so DistMult cannot distinguish a relation from its reversal solely by this score.

Worked example: h=[1,2], r=[3,4], t=[5,6]. Multiply matching coordinates, then add:

Triple（三元組；主體、關係、客體） directionFirst componentSecond componentTotal
H→relation→T1×3×5=152×4×6=4863
T→same relation→H5×3×1=156×4×2=4863

Result: both directions score 63. This demonstrates the symmetry limitation; the numbers are teaching values.

RESCAL vs DistMult: the key difference

  • RESCAL: one full matrix per relation → can combine different head/tail dimensions.
  • DistMult: one diagonal matrix (stored as a vector) → multiply matching dimensions only.

RESCAL — Pros

  • Richer interactions: the full matrix can learn cross-dimension relationships.
  • Can model asymmetry: reversing head and tail need not keep the same score.

RESCAL — Cons

  • High memory: a full matrix per relation stores more weights than one vector.
  • Slower scoring: matrix multiplication adds work compared with TransE or DistMult.
  • Scalability: many relations and large embedding dimensions increase storage and computation.
  • Overfitting risk: more weights need enough training evidence; check held-out links.

DistMult — limitation to remember

  • Symmetric score: swapping the head and tail leaves the result unchanged.
  • Problem: it cannot distinguish reversed triples for asymmetric relations such as fatherOf or greaterThan using that score.
  • Why: each term is hᵢ × rᵢ × tᵢ; multiplication gives the same result after swapping hᵢ and tᵢ.
Memory formula: what grows quadratically?

Learned parameter storage: RESCAL ≈ E×d + R×d²; DistMult ≈ E×d + R×d.

E
Number of entities.
R
Number of relation types.
d
Embedding dimension (assuming equal entity/relation dimensions here).
  • The lecture’s memory warning is important.
  • Its wording says quadratic in entity count; for the learned relation matrices, the quadratic factor is d².
  • An uncompressed relation slice has E×E positions; that is a different object.
  • Keep these counts separate.

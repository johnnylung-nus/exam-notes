C112

CNN（Convolutional Neural Network；卷積神經網路） convolution（卷積）, padding（填充）, stride（步幅）

Convolution learns local filters and reuses each filter across an image. Padding controls border handling; stride is how far the filter moves between positions. Different filters produce different output channels.

Recognise（辨識；從資料找出物件或模式） this in a question: Image CNN, padding/stride, feature maps（特徵圖；某層輸出的空間表示）, pooling（池化）, huge dense layer（全連接層；各輸入連至各輸出）

A convolution response

response = Σ(patch value × kernel（核函數） value) + bias（偏置／偏差；須看語境）
Σ
sum across the spatial（空間的） patch and input channels
bias
one learned offset per output filter
  1. Multiply corresponding3×3 entries.
  2. Add1+6+6+0+3+0+4+1+2=23 before bias.
  3. For8×8 input,3×3 kernel,stride1,no padding: output side=8−3+1=6.
  4. Four filters produce6×6×4 output; one cell padding per side gives8×8×4.

Interpret the result: Kernel size determines local coverage（涵蓋率；能服務的使用者或項目範圍）; filter count determines output channels.

What this tells us: Changing stride or padding changes positions and computation, but not the count of filter weights（權重） in this example.

Which input patch contributes to each convolution output?

  • A standard convolution filter covers a small spatial patch across all input channels. It multiplies corresponding values, adds them, and produces one response; reuse across positions makes the same learned detector available throughout the image.
  • The number of filters determines the output channels, while kernel size determines each local receptive patch. Moving by stride two skips more positions and reduces output size; padding inserts border values so filters can still cover edge locations.
  • State the padding convention before calculating. If padding means one added cell on each side, total added size is two. The lecture shape formula uses total padding, so silently inserting the per-side value would give the wrong result.

Implementation steps and their purpose
  1. Write input height, width and channels
  2. Choose filter size and number of filters
  3. Choose padding and stride
  4. Slide filters across all input channels
  5. Add one bias per filter and apply activation（激活函數；轉換神經元輸出）

Use the result and check it

Data, components and application

  • Shrinking maps lose border detail → add padding → retain coverage
  • Excessive stride loses small features（特徵；描述樣本的屬性） → reduce stride → preserve spatial detail
  • Too many filters → reduce channel counts → control capacity and cost

How to evaluate it

Check output dimensions and compare held-out（留出資料；未參與該階段訓練） recognition quality against computation and memory requirements.

Build the answer in this order

  1. State the required visual patterns
  2. Specify filters, padding and stride
  3. Calculate output shape
  4. Justify（給出理由；用情境與證據支持選擇） the trade-off

When would this calculation be useful?

Use when local spatial patterns such as edges or shapes matter; weight sharing avoids a separate weight for every image position.

Where this is tested in the sample papers

ISY5002 Q2(a) — Lean CNN redesign, parameter arithmetic, activations and loss（損失函數；衡量預測錯誤）

What the question requires

  1. Locate the parameter bottleneck.
  2. Propose a smaller classifier tail（尾實體；關係終點） while preserving required outputs.
  3. Recalculate weights plus biases and total reduction.
  4. Choose activations/loss consistent（一致性） with the classification（分類；預測類別） task.
  5. Validate accuracy（準確率）, imbalance and lean deployment constraints（約束條件）.

Proposed answer points

  • The original tail is Flatten9408 → Dense256 → Dense128 → Dense918. Its Dense parameter counts（參數數量） are 2,408,704, 32,896 and 118,422; with 18,960 convolution parameters the total is 2,578,982. The first Dense alone accounts for about 93.4%, so the actual bottleneck is the flattened-to-dense connection.
  • A defensible replacement is Flatten9408→Dense64→Dense918. Unchanged convolutions:18,960; Dense64:602,176; output:59,670; total:680,806. Reduction:1,898,176≈73.6%.
  • Use ReLU（Rectified Linear Unit；修正線性；負數歸零） in the hidden layers（隱藏層；中間處理層）, softmax（機率正規化；轉成總和為1的權重） over the 918 mutually exclusive combined classes（類別；分類目標）, and categorical cross-entropy（類別交叉熵；多類分類損失）. Smaller is not automatically better: check held-out quality.

Avoid: 5,000 unevenly spread images raise overfitting（過度擬合） and class-imbalance concerns; those are related but different problems. The combined 918-way output is one design, not the only possible factorized output architecture（架構）.

Vector / Embedding Representation

Encode items or concepts as vectors in a shared representation space. Relationships can then be compared geometrically through similarity or pattern matching; vector coordinates are not automatically human-readable facts.

What to draw / write: Vector / embedding representation

King  → [0.3, 1.7, …]
Queen → [0.2, 1.8, …]
Vector coordinates
Numbers representing an item/concept in the learned feature space.
…
The remaining coordinates; the displayed vectors are partial.
Shared space
Use the same representation model before comparing vectors.
  • Exam answer: Show item/text → embedding model → vector, then the comparison/retrieval step if required.
  • Do not label a similarity score as a probability.
  • Do not invent semantic names for individual coordinates unless the lecture/model defines them.

Used Cases:

The use-case names come from the lecture. The short scenarios below explain how to recognize them in an exam; they are teaching examples, not quoted exam questions.

Lecture use caseWhat it meansExample / clue in a question
Deep learning（深度學習）Learn numerical representations useful for a task.An encoder maps input images to vectors used by a classifier.
Retrieval systems（檢索系統）Compare a query vector with stored item/document vectors.Different wording with similar meaning retrieves the relevant approved answer, provided the representation captures the similarity.
LLMs — Large Language Models（大型語言模型）Represent tokens/content with learned vectors.Text tokens become vectors processed by the model; the coordinates are representations, not a table of verified facts.

Choose by the required job: explain what knowledge is stored and how this representation helps with the scenario. A use-case name alone is not a sufficient reason.

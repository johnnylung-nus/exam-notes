MR-04 Uniform-cost search（一致成本搜尋；先選累積成本最低者） / Dijkstra

Uniform-cost search, called Dijkstra in the route example, expands the frontier（待探索節點集） path with the lowest accumulated cost from the start. It uses no goal-distance estimate.

What this tells us: Accepting the first generated G would return cost 11. Updating B and G yields cost 3. Selection from the frontier, not mere appearance in it, is the decisive event.

Why must Dijkstra compare every waiting path cost（路徑成本）?

  • Uniform-cost search orders waiting paths by the entire cost already paid.
  • A newly generated goal is only a candidate: a cheaper unfinished path may still lead to a better goal.
  • The guarantee comes when the least-cost frontier path is removed, under nonnegative edge costs.
  • If a state is reached by a cheaper route, its best cost and predecessor must be updated.
  • Otherwise the system can remember an expensive first discovery and incorrectly reject a later improvement.
  • Frontier entries made obsolete by an update must be replaced or ignored when removed.
  • Dijkstra and BFS（Breadth-First Search；廣度優先搜尋） coincide when every edge has the same cost because accumulated cost then grows directly with depth.
  • When costs differ, Dijkstra may deliberately choose more edges to obtain a lower total.
  • It has no estimate of the destination’s remaining distance, so it may explore cheap but irrelevant directions.
Implementation steps and their purpose
  1. Set start cost to zero.
  2. Keep frontier entries ordered by total cost so far.
  3. Remove the lowest-cost entry.
  4. Relax each outgoing edge: update a state if this path is cheaper.
  5. Stop when the goal is selected from the frontier.

Data, components and application

  • Treating edges equally → use accumulated costs → number of steps can mislead.
  • Repeated states → retain best cost and predecessor → avoid accepting an expensive duplicate.

How to evaluate it

Sum the returned path cost and compare alternatives. With equal edge costs it behaves like BFS; without a heuristic it may explore many nodes.

Build the answer in this order

  1. Identify weighted objective.
  2. Calculate cumulative costs.
  3. Update best paths.
  4. Select goal only when cheapest frontier entry.

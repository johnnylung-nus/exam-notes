IS-19 Multimodal（多模態） representation（表徵；資料的表示方式） and fusion（融合）

Fusion combines evidence（證據；已觀察到的資訊） from sensor（感測器） streams. The lecture distinguishes tightly coupled early/intermediate fusion, loosely coupled restricted fusion and uncoupled late fusion（晚期融合；合併各模型的輸出）.

Recognise（辨識；從資料找出物件或模式） this in a question: Multiple sensors, camera + sound, conflicting measurements, alignment（對齊） · Robot sorting, actions（動作） change environment, reward（獎勵）, safe learning

At which stage should different modalities（模態；資料形式如語音或影像） be fused?

  • The fusion point determines what information the combined model can use. Raw/feature fusion preserves more cross-stream detail but requires stronger alignment and compatible representation.
  • Restricted fusion uses one recognizer to narrow the other’s search space. It is not merely averaging two final class scores.
  • Late fusion combines existing recognizer outputs; it can reuse pipelines but cannot recover details already discarded by those recognizers.
  • An additional sensor helps only if it contributes usable complementary evidence. Correlated（相關；數值一同變化的程度） errors or a poor stream can worsen the result.

Common wrong answers and the exact correction
  • Fusion is not automatically more accurate.
  • Label the fusion point; “combine data” alone is vague.
Apply the distinction

Apply the distinction

Data, components and application

  • Mismatched times/entities（實體；被描述的對象） → align streams → prevents combining unrelated events.
  • Noisy modality dominates → account for input quality → more inputs can worsen results.
  • Existing pipelines costly to rebuild → consider late fusion → reuses separate recognizers.

How to evaluate it

Compare task errors, missing/noisy-stream robustness, latency and added implementation cost.

Build the answer in this order

  1. Why multiple streams?
  2. Choose fusion point.
  3. Handle alignment/quality.
  4. Compare actual benefit.

An answer you could write

  • I choose the fusion point explicitly（明確；直接提供的資訊）: features, recognition-guided restriction or final decisions.
  • I align the streams and compare with each single-modality（單一模態） baseline.
  • I test noisy/missing inputs because fusion gains are conditional, not guaranteed.

ISY5002 Q2(b) — Deep-RL sorting architecture（架構）, reward and safe learning

What the question requires

  1. Define observations/state, actions and task success.
  2. Choose reward terms for correct sorting, safety and time.
  3. Draw hardware, perception（感知；由輸入理解環境）, decision and control loops.
  4. Explain simulation-first training（訓練） and controlled transfer.

Proposed answer points

  • RGB-D（Red, Green, Blue–Depth；彩色加深度影像） + robot sensors → identification/tracking → state → deep-RL policy（策略） → safety/motion checks → arm/gripper（夾爪；機器人抓取物件的部件） action → new observations and reward.
  • Include target objects, obstacles, other robots and people in the environment.
  • Reward correct placement; penalize collisions and unnecessary time. Enforce joint/gripper constraints（約束條件） in control rather than hoping a learned reward guarantees safety.
  • Train in a physics-based（基於物理；模擬運動、接觸等物理規律） simulator（模擬；先在虛擬環境測試或學習）, then validate in controlled low-risk real tests with safety constraints active.

Avoid: A reward penalty is not a hard safety guarantee. Classification（分類；預測類別） of the object（客體；三元組終點） and control of the robot are separate responsibilities.

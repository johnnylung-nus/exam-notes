C058

Symbolic（符號式） / connectionist（連結式） / hybrid（混合式） AI（Artificial Intelligence；人工智慧）

Symbolic AI uses explicit（明確；直接提供的資訊） representations（表徵；資料的表示方式）/rules; connectionist AI learns distributed representations in neural networks（神經網路）. Hybrid systems combine complementary capabilities.

What this tells us: The tutor should not add an exotic model merely to satisfy a fashionable label. Use the smallest coherent architecture（架構） that addresses the requested inputs, knowledge, inference（推論；由依據得出結論） and outputs.

When should a system combine symbols with learned representations?

  • The useful distinction is where knowledge comes from and how it is used. Symbolic systems apply explicit facts, rules and structured relationships; connectionist systems learn distributed representations from data. Neither label alone establishes reliability or suitability for the scenario.
  • A hybrid should connect complementary responsibilities. Perception from images may benefit from a learned model; explicit domain constraints can govern allowed decisions; frames can organise facts and rules can explain consequences. However, a hypothetical useful architecture must not be presented as what the sample case actually implements. The App’s described measurement/formula processing is not evidence of a trained classifier.
  • Exact taxonomy labels and dataflow descriptions should also be separated. Sample Q2(c) supports App output feeding Web input, which can be described as sequential/serial flow; the lecturer’s exact hybrid-type label remains unconfirmed. An honest design answer can show the supported flow while identifying that naming uncertainty（不確定性）.

Common wrong answers and the exact correction
  • Not every reasoning system requires every AI technique.
  • Separate subsystem responsibilities do not prove multiple neural networks.

Apply the distinction

Data, components and application

  • Rule maintenance → expert updates/tests → hand-built knowledge can become stale.
  • Neural opacity/bias（偏置／偏差；須看語境） → validation, explanations and constraints → learnt patterns need system-level checks.

How to evaluate it

Compare task success, explanation quality, knowledge/data requirements and maintenance. The simplest justified design may be sufficient.

Build the answer in this order

  1. Identify task/evidence.
  2. Choose paradigm with reason.
  3. Show hybrid interface if needed.
  4. Explain limits and validation.

An answer you could write

  • “The supported relationship is serial: the App’s RAPD output becomes one Web input alongside doctor-entered findings.”
  • “For Q2(d), I propose patient frames plus specialist rules and forward chaining（前向推理；由資料推向結論）; I do not claim the case already contains a neural classifier or a confirmed taxonomy label.”

Where this is tested in the sample papers

ISY5001 Q2(c) — Hybrid subsystem relationship and data flow

What the question requires

  1. Treat the two subsystems as black boxes.
  2. Draw images → App → RAPD result → Web.
  3. Add doctor-entered profile, symptoms（症狀；患者感受到的不適） and signs to Web.
  4. Label the Web’s diagnostic, urgency and action outputs.

Proposed answer points

  • The App-to-Web relationship is sequential/serial in the proposed data-flow description.
  • A box diagram with labelled arrows is sufficient for the relationship; detailed knowledge internals belong in part (d).

Avoid: Use the lecturer’s exact hybrid taxonomy if prescribed. Do not add an unmentioned trained classifier or compulsory intermediate human gate.

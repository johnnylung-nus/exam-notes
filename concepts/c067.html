Marr’s three levels

Marr’s analysis separates what problem is solved, which representations（表徵；資料的表示方式）/processes solve it, and how the solution is physically implemented.

Recognise（辨識；從資料找出物件或模式） this in a question: Image label（標籤；作比較的正確答案）, object（客體；三元組終點） location, bounding boxes（邊界框；框出物件位置）, pixel area, segmentation（分割）

What must the system deliver?

Use to explain a vision-system design at the right level rather than mixing the goal, algorithm and hardware.

Scenario cueSuitable choiceWhy it fits
Question asks system purposeState goal and required output firstThe computational problem anchors later design choices.
Question asks realizationDiscuss device and runtime constraints（約束條件）Hardware is meaningful after required processing is specified.

How do task, representation and implementation answer different questions?

  • The computational level defines the problem and success criterion. Hardware names do not explain why the task is being solved.
  • The algorithmic level selects representations and processes that can produce that result. Changing the representation can remove information required by the goal.
  • The implementation level realizes the process using cameras, models, devices and interfaces under practical constraints.
  • Marr’s analysis levels differ from the processing sequence（序列；有先後順序的資料） early vision → recognition → cognition（認知；理解與思考）; one is a way to analyze a solution, the other describes processing roles.
Implementation steps and their purpose
  1. Computational level: state the goal and why it matters.
  2. Algorithmic level: choose representations and operations.
  3. Implementation level: identify camera, device and software deployment.
  4. Check that the selected operations actually support（支持度；同時出現的交易比例） the goal.

What this tells us: “Use a camera” answers how evidence（證據；已觀察到的資訊） is captured, not what judgement is required. “Use deep learning（深度學習）” still leaves（葉節點；決策樹的最終輸出） the representation and decision logic unspecified.

Data, implementation and validation

Data, components and application

  • Hardware listed as goal → separate levels → makes the answer address the question.
  • Algorithm without decision criteria → define required compliance knowledge → connects processing to the goal.
  • Over-detailed implementation → match requested abstraction → avoids wasting exam time.

How to evaluate it

Trace one required output through all three levels; check feasibility（可行；符合所有硬性條件） and whether the algorithm answers the stated problem.

Build the answer in this order

  1. What and why?
  2. Representations and processing?
  3. Physical realization?
  4. Does the design meet the goal?

Common wrong answers and the exact correction
  • Do not confuse these three analysis levels with early vision → recognition → cognition.
  • Primal sketch, 2.5D sketch and 3D model are another lecture distinction.

An answer you could write

  • At computational level, the goal is to judge whether required PPE is worn correctly.
  • At algorithmic level, detect items, extract placement/coverage and apply the checklist.
  • At implementation level, realize the pipeline（處理流程） with the camera, model, device and dashboard under response-time constraints.

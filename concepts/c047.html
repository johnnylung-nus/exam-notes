C047

Jaccard similarity（相似度）

Jaccard similarity compares two sets: number of shared elements divided by number in their union. It suits binary interaction sets without counting shared absences as agreement.

Recognise（辨識；從資料找出物件或模式） this in a question: Clicks, views, purchases, implicit feedback（隱式回饋）, unobserved items

Illustrative Jaccard

J(A,B)=|A∩B||A∪B|
A, B
Sets being compared.
|A ∩ B|
Count of shared elements.
|A ∪ B|
Count of distinct elements in either set; count shared elements once.
  1. Shared items are{2,3}:2.
  2. Union is{1,2,3,4,5}:5.
  3. Divide2 by5.

Interpret the result: Jaccard=.4; shared absences are not counted.

What this tells us: B provides a stronger set match than C in this example, but recommendation（推薦） needs additional candidate-scoring logic. The set score itself does not infer（推論；由依據得出結論） how much A would like item4.

How does Jaccard compare two sets of interactions?

  • Jaccard compares sets of observed items rather than numeric（數值型；以數量表示） rating levels. Its numerator counts common observed items and its denominator counts items observed by either user. Shared absences are excluded, so two inactive users do not appear highly similar merely because they both ignored a huge catalogue.
  • This addresses the lecture’s binary all-positive comparison problem. If pairwise-complete cosine considers only positions where both binary users have ones, their compared vectors can be identical and every pair scores one. Jaccard also uses observed items that are unique to either set, preserving differences.
  • Similarity is not automatically a rating predictor（預測輸入變數）. With every observed value equal to one, a conventional weighted average of neighbour ratings still returns one. Use similarity to rank unseen items or another implicit-aware method, and check overlap strength; a perfect set similarity from one event is fragile evidence.
Implementation steps and their purpose
  1. Create each user’s set of observed items.
  2. Find the intersection of the sets.
  3. Find their union.
  4. Divide intersection size by union size.
  5. Use the resulting similarity for neighbour/ranking（排序） logic, with overlap checks.

Use the result and check it

Data, components and application

  • Tiny overlap → minimum evidence/fallback（備援處理） → a perfect score on one event may be fragile.
  • All positive ratings averaged → rank candidate similarities instead → ordinary weighted all-one ratings still predict one.

How to evaluate it

Compare held-out（留出資料；未參與該階段訓練） recommendation relevance（相關性；是否切合問題） and coverage（涵蓋率；能服務的使用者或項目範圍）; state how empty sets are handled.

Common wrong answers and the exact correction
  • Shared missing items are not common likes.
  • Jaccard does not by itself produce meaningful 1–5 ratings.

When would this calculation be useful?

Use when each observed event means presence/interest and standard co-rated（共同評分；兩者都評過的項目） all-one vectors yield unhelpful identical similarities.
